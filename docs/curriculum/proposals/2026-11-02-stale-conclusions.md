# 结论跟着事实变：复盘、课程报告和目标修订

> 来源：11-02 的外部审查（[报告](../../history/2026-11-audit/report.pdf)，括号里是报告的编号）。这里是审查建议先定下来的接口里的"修订接口"在目标和设计书上的部分；复盘和报告读的事实来自 [有效证据](../../learner/proposals/2026-11-02-effective-evidence.md)。修复顺序见 [现在](../../now.md#修复顺序)。

## 问题

- **保存复盘后改判，复盘不失效（L15）：** 老师保存了"通过"的复盘，随后复核把一道题改判为错：阶段报告已经是"没过"，保存的复盘仍是"通过"，你点"进入下一阶段"照常成功，带进下一阶段的风险是 0。`decideReview` 只读保存时的结果，不核对之后的改判、新申诉和题目核查。
- **目标大改后，旧的结课检验还能证明"做到了"（L17）：** 目标的"能做"条目改写时键不变（`c1`），结课检验和课程报告按键对应。条目从"按给定参数计算静水压强"改成"独立设计完整的传热网络并优化运行参数"并重新确认后，不用再测就能写课程报告，这一条显示"做到了"。键说明"是哪一条"，说明不了"这一条现在要求什么"。
- **目标的两次修改同时进行，一次会丢（L10）：** goal 读出版本后异步写入，写入时只把版本加一，不带读取时的内容指纹（core 已经支持 `ifHash`，goal 没用）。你在页面上改事实、老师同时修订目标，两次都返回成功和同一个新版本，先写的那次悄悄没了。读取出错时一律报"目标不存在"，解析失败也一样。
- **学习中的阶段能改设计书，但改完再也确认不了（L07）：** `saveDesign` 不看阶段状态：学习中、测试中、复盘中的阶段也能改，改完清掉"已确认"，阶段仍是学习中；`confirmDesign` 只接受"设计中"的阶段，于是新设计书永远确认不了。修订还会删掉所有没开始的课时、用新 ID 重建，已开始但新稿里没有的课时留着。

## 方案

1. **复盘记下依据（L15）：** 保存复盘时记下这份复盘依据的事实指纹：测试的提交、每道题当前的有效判分、申诉和题目核查的状态。之后有改判、新申诉、题目改正，复盘标"要更新"，复盘卡片说明哪里变了；你点决定时程序重算一遍指纹，变了就不让按旧结论决定，请老师更新复盘。已经决定过的复盘不改，之后的更正作为风险带进下一阶段，并说明来源。
2. **目标条目有语义版本（L17）：**
   - 每条"能做"保留键，另记一个语义版本：改了能做什么、做到什么程度、怎么验证，版本加一；只改错别字和措辞，老师要声明"意思不变"，页面在确认目标时把"改了要求的条目"和"只改了措辞的条目"分开列给你看；
   - 结课检验发布时记下每个条目的语义版本；课程报告只认版本对得上的结果，对不上的显示"目标改过，要重新检验"，不能写"做到了"；
   - 历史的课程报告仍指向当时的目标版本。
3. **目标写入带指纹（L10）：** goal 的每次写入（修订、改事实、改资料、确认）都带读取时的内容指纹；文件在这期间变了，报冲突并返回当前版本，老师工具重读后再改，页面提示"目标刚被改过"并保留你的输入。读取出错时区分"不存在"和"文件解析失败"，后者保留文件、明确报错。
4. **学习中改设计书走修订（L07）：** 设计中的阶段照旧直接改。已确认的阶段：先拒绝原地 `saveDesign`，改走修订——新设计书作为待确认的修订（和路线调整一样），你确认后才生效；生效时按课时的稳定身份更新：已开始的课时保留，没开始的按新稿改、删、调顺序，不全部重建。

## 放弃的方案

- **目标条目一改就换新键：** 改个错别字也会让结课检验失效，阶段对目标的引用也要跟着迁移；键表示"哪一条"，语义版本表示"要求什么"，分开记。
- **改判后自动重写复盘：** 复盘里有老师写给你的话，程序不能替老师改；只标"要更新"并拦住按旧结论做决定。
- **学习中的阶段一律不许改设计书：** 学到一半发现安排不合适是正常的；走修订、你确认，比不许改好。

## 验收标准

1. 保存复盘后改判、新增申诉或改正一道题，复盘卡片显示"要更新"，按旧结论点决定被拦住；老师更新后带进下一阶段的风险和最新事实一致。
2. 扩大一个"能做"条目的要求并确认后，旧的结课检验不再让它显示"做到了"；只改措辞并声明意思不变的，旧结果仍然有效；历史报告仍显示当时的目标。
3. 页面改事实和老师修订目标同时发生：一个成功，另一个报冲突并保留输入，最终两处修改都能落到文件里（重读后再改），没有悄悄丢失；目标文件解析失败时报"解析失败"而不是"不存在"。
4. 学习中的阶段改设计书：生成待确认的修订，你确认后生效，已开始的课时和它们的引用不变，没有孤立的课时 ID 或重复序号；不确认时当前设计书和课时不变。
5. `pnpm typecheck`、`pnpm test`（含 `tests/flow.test.ts`）、`pnpm build` 通过；3182 上合成课程走一遍改判后复盘、改目标后结课。

## 风险

- 老师判断"意思不变"可能偏宽松；确认目标时把每条改动并排给你看，由你把关。
- 设计书修订牵涉讲义（已生成的讲义要不要重新生成）：先只改课时和设计书，讲义沿用；要不要提示重新生成，实现时和你确认。
- 改了 goal 和 curriculum 的数据格式，要迁移，按 [core](../../core/design.md#数据库和升级) 的升级规则写。
