# 调度做深调研

> 2026-10-11 · 对应 PLAN 中 learner 之后的 planner · 状态：证据与反例复核完成，可供设计评审；下文是推荐设计、契约补充建议和验收草案，尚未实现或采纳为正式契约。
> 代码基线：`6eababc`；learner A、B、C 已技术验收。依据：[总体计划](../PLAN.md)、[调度现状](design.md)、[掌握分析现状](../learner/design.md)、[学习流程](../journey.md)、[契约](../stage0/contracts.md)，以及下文的一手研究、官方文档和开源源码。
> 范围：一门课的下一步、复查、跨课程待办、中断后的恢复、期限判断。按 `learning-handoff-review` 核对接续边界，按 `learning-docs` 组织报告，按 `learning-simplify` 只列精简候选；不改产品实现。

推荐按 **A 下一步可信、可接续 → B 有上限的复查 → C 今日安排、回来后的恢复与期限判断** 做深。程序根据各单元的事实选动作，主老师解释和执行教学工作。首轮用明确的规则，不引入新的学习模型、排程服务或工作流引擎。

## 1. 结论与取舍

| 问题 | 推荐项 | 理由与边界 |
|---|---|---|
| 谁决定下一步 | planner 统一给课程、首页和主老师同一份动作；执行仍由对象的主人检查 | 不能出现首页让读教材、主老师让做另一份测试；推荐不是执行授权 |
| 课程推进 | 保留现有学习旅程，先处理正在作答、待复核、等待生成及失败 | 复查不插进未结束的测试，也不掩盖业务错误 |
| 复查依据 | 使用本课 `CourseState`、`next`、`checkFrom`，由 learner 解释资格 | 全局状态不能替代本课验证；时间到了只说明可以检查，不证明遗忘 |
| 复习方式 | 在课时边界做少量短检查，阶段测试继续穿插旧知识 | 不把计算课改造成原题反复打卡；学习练习和独立验证的用途分开 |
| 排序 | 先满足业务条件；主线补救与可选复查分开，复查类型和课程轮转 | 薄弱项不能永久霸占名额；首轮不把任意权重加成“学习收益分” |
| 总量 | 按用户全部课程共用上限；未完成的推荐不逐日累积成欠账 | 题数上限不等于耗时上限，也不保证所有到期需要都能完成 |
| 跨课程 | 相同知识身份避免连续重复问，但证据按课程分别解释 | A 课答对不能自动补齐 B 课的证据；跨课帮助仍会影响独立性 |
| 回来以后 | 给上次停点，继续已有任务；有需要时推荐一两道短检查 | 不重置掌握、不重开整份摸底、不列欠课清单 |
| 期限 | 倒计时保留；能否赶上用有来源的工作量和可用时间区间 | 缺数据时明确“暂不能判断”，不把章节数、聊天时长当作学习耗时 |
| 持久化 | 只存用户选择、已安排的动作关联和恢复所需事实；推荐可重算 | Task、Test、NodeState 各有主人，不在 planner 复制另一套状态机 |
| 依赖 | 复用 TypeScript、core 的 SQLite、DSH 服务与事件 | ts-fsrs 可留作后续对照，首轮不安装；模型不直接生成并执行日程 |

已确认的方向继续成立：只记最后期限、不排死日程；大改目标或路线由学习者确认；复习不淹没新学习；只有作答构成掌握证据；全部单元做深后统一试用。下文的数量和时间默认值都是待验证的产品建议，不是论文给出的最优参数。

## 2. 当前实现核对

以下是源码核对，不能代替这些缺口的运行复现。现有自动测试通过只证明已有行为，没有验证本报告的新策略。

| 位置 | 已有能力 | planner 做深需要处理的边界 |
|---|---|---|
| [planner/index.ts](../../packages/planner/src/index.ts) `step/next` | 按目标、资料、知识图、测试、阶段、课时走完整旅程 | 不读取 learner；没有复查候选、总量控制和恢复安排。`goal.get().catch(() => undefined)` 把读取失败当成“还没有目标”，可能错误建议重新商量目标 |
| 同文件，各类测试分支 | 处理主线上的摸底、前测、小测、阶段测试、结课检验 | 没有统一优先处理本课所有 open 测试，节点详情发起的复查、手动练习和模拟考可能与主线提示冲突。只有阶段测试分支明确把 `abandoned` 当作需要重新发布；其他分支不能用“不是 open”代替“已有效完成” |
| 同文件，教材状态 | 生成中等待，失败一次让老师重试，两次后交还用户 | 等后台、用户操作、已结课都用 `actor: learner`。需要区分状态，保留已验收的失败次数规则 |
| [NextStep / LearnPlanner](../../packages/contracts/src/services.ts) | `actor/title/detail/page/params/countdown`；服务只有 `next` | 缺稳定动作身份、目标对象、等待/阻塞含义、事实版本。不能按标题判断是不是同一件事 |
| [tutor/brief.ts](../../packages/tutor/src/brief.ts) `stepKey`；[notices.ts](../../packages/tutor/src/notices.ts) `deliver` | 每步检查动作变化；进度通知持久化并按下一步决定唤醒 | `stepKey` 只拼 actor 和 title；同名的两份复查或相同标题下对象变了可能不更新。唤醒只看 teacher；若扩充下一步，两个消费者都要接续 |
| [planner/client.tsx](../../packages/planner/src/client.tsx) | 首页、课程卡片、进度页、状态栏、侧栏课程列表 | “继续学习”取第一门 `actor=learner` 的课，没有真正排序；“欢迎回来”是固定标题。前端又为每门课请求 overview；`next=null` 没有保留失败原因 |
| [learner 的证据类型](../../packages/contracts/src/schema/evidence.ts)、[rules.ts](../../packages/learner/src/rules.ts) | 本课状态、依据、`next/checkFrom`；时间经过后读取会计算 `needsReview` | `checkFrom` 对 independent 是最近接触 + 3 天，对 retained 是最近独立答对 + 14 天；assisted、conflict 等没有该时间。它不是所有状态的统一独立测试许可，retained 刚获帮助也不会因此把 `checkFrom` 推后 |
| [assess/check.ts](../../packages/assess/src/check.ts) `quickCheck` | 本课没见过的练习题，优先单知识点，一题复查；复用已有相同节点的 open 检查 | 复用检查之后存在异步读取目标条件，再建 Test、再发 Task；并发请求和“测试已建、任务未发”需要专门验收。不能直接假定这个入口已经能承接可靠自动调度 |
| [assess/index.ts](../../packages/assess/src/index.ts) `dropCheck/withdraw`、对应 endpoint；[client.tsx](../../packages/assess/src/client.tsx) “不做了” | 记题目已见、撤回测试；`test-finished` 使对应任务关闭 | 源码调用链没有发 `learning/handoff`；底层 `withdraw` 是老师操作的语义，用户取消复用它会漏交回。这里只做静态确认，未运行复现 |
| [tutor/index.ts](../../packages/tutor/src/index.ts) `classroom`；[sidechat/index.ts](../../packages/sidechat/src/index.ts) `testOpen` | 主老师对未交的非 practice 测试限制讲题；侧边会话在设置开启时对任意 open 测试限制内容 | 可选复查一旦创建就有教学副作用；仅把它从首页隐藏，不能恢复正常学习。两处限制范围不同，不能在 planner 中自行宣布已解除 |
| [assess/stage.ts](../../packages/assess/src/stage.ts)、[tools.ts](../../packages/assess/src/tools.ts) | 阶段测试可出至多两道旧阶段题，沿用预留池；带来的风险优先 | 旧知识的排序没有接 learner 的到期需要；若接入只能提供候选与理由，不能绕过蓝图、题池和核心覆盖规则 |
| [curriculum/index.ts](../../packages/curriculum/src/index.ts) `publishTask/completeTask` | 任务归 curriculum；测试结束会接到任务完成 | 普通任务完成不等于通过验证；课程内所有 pending task 也不等于“今天都该做”。复查用 Test 的真实结果收尾 |
| [course.ts](../../packages/contracts/src/schema/course.ts) | Goal 有每周投入区间及事实来源；Task 有创建/完成时间；Course 只有创建时间 | 没有统一的最近学习活动、有效耗时、剩余工作量区间。任务发布到完成之间的等待不是学习耗时 |
| [knowledge 服务](../../packages/contracts/src/services.ts) `prerequisites` | 对外提供可执行的先修关系 | planner 应用这个服务，不从展示图里把草案关系当硬约束；同时尊重阶段复盘中用户已选择带着风险继续的决定 |

**最先补的三个边界：** 读状态失败不能伪装成新课；已有测试和待复核必须有正确去向；稳定动作身份与业务状态分开。它们决定新调度会不会让主老师反复做错事。

## 3. 研究证据及外推限制

检索截至 2026-10-10，覆盖间隔学习、交错数学练习、记忆调度、技能追踪、冷启动、任务恢复，以及 2025–2026 年课程推荐研究。优先读论文全文、作者源码和官方文档；只取得摘要的项目明确标出。搜索结果标的抓取时间不当发表时间。

### 3.1 间隔应该服务于保持目标，没有通用的“1、3、7、14 天”

Cepeda 等的研究让 1,354 名参与者学习事实，改变两次学习之间的间隔和最后测验的延迟。最合适的间隔随保持目标变化，而且并非越长越好。全文的任务是简短事实记忆，不能直接推出化工计算题的个人复查日程。[Spacing Effects in Learning（2008，作者全文）](https://www.yorku.ca/ncepeda/publications/CVRWP2008.pdf)

**应用建议：** learner 已采用的 3 天、14 天继续作为可解释规则的起点；planner 不再另写一套不同的数字。接近考试可以提前练习，但必须说明那是备考练习，不能因此宣称满足延迟验证。重复练习更新接触时间，也可能推迟独立新题的延迟验证窗口。

### 3.2 数学交错练习有直接证据，但不是随便打乱题目

Rohrer 等的预注册整群随机试验涉及 54 个七年级班级；研究摘要报告，延迟一个月的未预告测验中，交错组高于成块练习组。干预改变的是同一数学课程中需要不同策略的问题顺序。它没有验证“每天切换多门课”或“每节强制复习两题”。作者 PDF 本次抓取超时，依据论文的官方收录摘要及资助项目结果说明，未核对全部附录。[论文摘要（ERIC，2020）](https://eric.ed.gov/?id=EJ1237752)、[IES 项目结果](https://ies.ed.gov/use-work/awards/efficacy-study-interleaved-mathematics-practice)

**应用建议：** 在学过的相近方法之间安排选择策略的题，例如区分静压关系与流动能量关系。独立检查的题前不要先告诉该套哪条公式；安排仍要有基础和可解题源。交错顺序不能补偿无效题目，也不能代替针对卡点的讲解。

### 3.3 对复杂计算，反复做到正确的收益未必像背事实一样大

Rawson 等三项实验涉及 431 名大学生、四类概率题；一周后做新题，多次分散再学的综合优势较小。这里只核对出版社摘要，未读付费全文。[All Good Things Must Come to an End（2020）](https://link.springer.com/article/10.1007/s10648-020-09528-y)

**应用建议：** 保留变式、选择方法、完整任务等检查维度；复查失败先定位问题，而非无限复制“再隔一天做原题”。没有只考某一点的题时，综合题答错不能让 planner 自己认定这个点已遗忘，仍服从 learner 的证据解释。

### 3.4 记忆预测、调度最优与学习有效是三件事

| 工作 | 实际支持什么 | 本项目不能据此声称什么 |
|---|---|---|
| [HLR，Settles 与 Meeder（ACL 2016）](https://aclanthology.org/P16-1174/) | 用语言学习日志拟合回忆概率；报告预测改进及上线参与度变化 | 参与度提高不等于独立迁移提高，单词半衰期也不是计算技能掌握度 |
| [Memorize，Tabibian 等（2018 版本）](https://arxiv.org/abs/1712.01856v2) | 在给定记忆模型和优化目标下推导调度，使用合成和 Duolingo 数据评估 | “最优”取决于模型及目标，不证明能直接优化我们的整门课程、题源约束和期限 |
| [DAS3H，Choffin 等（2019，全文）](https://arxiv.org/pdf/1905.06873) | 三组数学数据上的预测比较，把多技能标签和不同时间窗口纳入模型 | 论文把实际技能调度策略列为后续工作；较好 AUC 不等于已经有有效的上线复习器 |

DAS3H 尤其贴近我们：一道题可涉及多个技能，选中一个技能之后，还得找到不会过早激活其他技能的题。它也指出加性模型可能让一个技能的强表现补偿另一个技能的不足。**应用建议：先选验证需要，再由 assess 判断题是否适合；选不到是业务结果，不是让模型凭空编题并发布的理由。**

### 3.5 冷启动和新研究没有消除校准需求

2024 年 adaptive fact learning 研究使用约一亿次作答、近十四万名学习者的数据做模拟；依据题目难度的初值通常优于只依据学习者能力的初值。本次核对开放全文的摘要与研究范围；这是事实学习的冷启动评估，不是本项目的个体参数来源。[Knowing “what” matters more than knowing “who”（2024）](https://link.springer.com/article/10.1007/s11257-024-09401-5)

2025 年 MWO 课程排序工作报告 OULAD 与优化基准上的结果，含时间、覆盖和学习风格等目标。本次只核对作者摘要；没有据此获得“对实际学习者采用该排序会更好”的证据，也不采纳学习风格匹配。[MWO（2025）](https://arxiv.org/abs/2506.13092v1)

2026 年 Learning in Blocks 报告 180 名 A2 英语学习者、8 周、三组干预；本文核对 v2 全文 §5.2、§6.2。较强的一组同时增加针对性复习和掌握门槛，进度也更慢：末周多数停在第七块，比较组已到第八块。结果支持继续研究结构化教学组合，不能单独归因于间隔算法；文中末周表现也不是停止帮助后的长期保持检验。[Learning in Blocks（2026-07 v2）](https://arxiv.org/html/2604.22770v2)

**应用建议：** 首轮规则对照应同时看独立新题表现、复查负担、主线推进及中断次数。不引入多 Agent 或任意“70% 掌握门槛”，也不因新论文的推荐分数高就替换已验收的 learner。

### 3.6 恢复应提供停点，但“离开七天就测两题”是产品假设

Leroy 与 Glomb 的四项研究支持：简短记录如何恢复被中断任务，可以减轻对插入任务的注意残留影响。本次核对出版社摘要；它研究工作中断，不能直接证明隔周学习恢复的效果。[Tasks Interrupted（2018）](https://pubsonline.informs.org/doi/10.1287/orsc.2017.1184)

**应用建议：** 回来时摆出“上次读到哪里、哪份测试没结束、下一件可做的事”。欢迎文字本身不调用模型。短检查来自具体证据需要和当前先修，不仅来自缺席天数；用户可以继续原任务或暂不检查，选择要记住。

### 3.7 区间必须说明它是什么

NIST 区分平均响应的不确定性与单个未来观测的预测不确定性，后者还包含新观测本身的变动。这是统计解释原则，不能把其回归公式直接套到没有耗时观测的课程上。[NIST：预测单个未来观测](https://www.itl.nist.gov/div898/handbook/pmd/section5/pmd512.htm)

**应用建议：** 首轮展示“按这些投入和工作量假设估算”的情景范围；未经历史检验不叫置信区间，也不给“赶上概率”。样本、任务可比性或未设计阶段的工作量不够时，保留未知部分，不填一个看似保守的数字。

### 3.8 直接调度实验：最终表现、效率和任务范围必须分开读

以下补足“某种调度是否真的改善学习”的证据；不能只拿记忆预测论文回答这个问题。

| 研究与读取范围 | 比较与结果 | 对 planner 的含义及限制 |
|---|---|---|
| [Lindsey 等，2014，出版社摘要](https://journals.sagepub.com/doi/abs/10.1177/0956797613504302) | 中学外语一学期，在复习时间匹配的条件下比较个性化、统一间隔和集中复习；学期后累计考试，摘要报告个性化优于另外两种方式 | 有直接学习结果，不能说“自适应只有预测证据”。作者全文镜像抓取失败，样本分配、完整分析与增益计算未核实，因此不引用具体增益数字、不用于设产品参数；外语回忆不等于计算迁移 |
| [Mettler 等，2020，七页全文](https://escholarship.org/content/qt7fj233kb/qt7fj233kb_noSplash_33c90de0b46be4c3c092857eaf2219b1.pdf) | 两实验各 48 名大学生，辨认 24 个非洲国家，一周后测验。实验一 ARTS 少练很多、单位练习收益较高，原始测验进步却低于随机组；实验二双方都移除达标项目，ARTS 平均 183 次、随机 231 次，效率较高，测验进步未见显著组间差异 | 论文摘要的优势主要要按“效率”理解，不能说最终保留量必然更高。反应时来自短识别任务，不能把本项目的长计算作答速度直接当熟练度 |
| [Lyle 等，2022，开放全文](https://link.springer.com/article/10.1007/s10648-022-09677-2) | 工科微积分，235 人入课、180 人完成全部研究任务；24 个目标、每目标三题，学生内对照并随机平衡目标分组。分散到三次双周小测，期末正确率 77% 对 71%，练习期平均反而 78% 对 81% | 支持把旧知识放进后续课时；练习当下正确率不适合作唯一调度目标。只分析完整参与者，试题主要是同一题的算法变式；这不是个性化策略比较，也未证明陌生综合题迁移 |
| [Cao、Carvalho，2025，会议单页摘要原件](https://escholarship.org/content/qt4kc1n6k1/qt4kc1n6k1_noSplash_3e3c2f200b9a2351ca883731a477446f.pdf) | Algebra I 的十个目标，六个用 SM2 调度、四个为不加练对照；两条件间未见显著差异。低初始正确率的目标得到更密集练习，高初始正确率的目标练得较少、间隔较长，后者前后测有提升 | 不能凭这条相关模式断言“多练无效”或“拉长间隔导致提升”；摘要没有足够样本和设计细节，也不能把不显著解释为等效。它至少阻止我们把卡片算法迁入数学后直接宣称有效 |

**设计推论：** 把“学会更多”“以较少负担保持同等水平”“更愿意继续学”分别评价。优先安排独立新题不意味着减少所有有帮助的学习练习；为等到验证窗口而禁止补讲，会把取得证据凌驾于学习本身。自动化先保证少打断、资格正确和可恢复，效果优势留待比较。

### 3.9 上限只能截住负担，不能让超量需求自动消失

[Reddy 等，KDD 2016，全文 §3–4](https://arxiv.org/html/1602.07032v2) 把 Leitner 卡片复习建成排队网络：在给定记忆模型和平均回忆近似下，需求超过处理能力会积压。331 人、15 分钟的词汇/手语卡片实验观察到新项目引入过快时产出下降；“掌握”是实验末卡片位置，且采用自评分，并非延迟独立迁移测验。其稳定性条件和数值阈值不能直接当作本项目的学习上限。

**设计推论：** 不生成欠账任务能减少界面负担，却不能消除尚未验证的知识。假设每天新增 5 个相互独立的需要，每题只能解决一个、没有其他活动补齐，每天最多处理 3 个；即使从不失败，七天仍多出至少 14 个未处理需要。这是容量算术，不是遗忘模型。持续超量时展示覆盖不足，并让用户选重点、增加投入或调整范围；不能把上限内的清单叫“已覆盖全部复习”。单纯降低任务创建速度，也不等于降低学习需求。

### 3.10 证据能支持到哪一层

| 判断 | 本次把握 | 尚不能声称 |
|---|---|---|
| 在后续学习中分散练习旧知识值得保留 | 有直接课堂干预支持，数学证据比单纯词汇外推更贴近 | 对任何内容、学习者和间隔都有同样收益 |
| 个性化排序可能节省练习或改善保持 | 有直接实验，但结果取决于对照、停止条件、任务与指标 | 本报告的规则优于简单间隔基线，或 FSRS 一定更好/更差 |
| 资格检查、幂等、退出和交回必须先可靠 | 当前源码与已确认的数据约定直接支持 | 自动测试通过就证明教学效果 |
| 每边界 1 题、每天 3 题、回归 7 天 | 仅是待校准的产品起点 | 论文最优值、耗时保证或个人遗忘规律 |
| 根据个人节奏预测完课时间 | 当前缺数据，只能做条件情景 | 经验证的预测区间、赶上概率或考试通过率 |

以上是围绕设计问题的定向证据核查，不是按完整数据库检索和偏倚评估流程完成的系统综述。未取得全文的结果不承担关键数值结论；检索停止的依据是主要方案已有支持、反例和验证办法，而非论文数量。

## 5. 推荐设计

本节给接续开发者可评审的方案，不改变 [design.md](design.md) 中的已实现行为。

### 5.1 把“能不能做”“为什么做”“谁来做”分开

一次查询从各主人读取事实，先产生课程主线动作和少量教学候选，再进行筛选。推荐只读，不因首页刷新而出题、发布任务、推进阶段或唤醒模型。

建议下一步带稳定的动作种类与目标引用，区分 `actionable / waiting / blocked / complete`，可执行时才有 teacher 或 learner。返回给用户的一句话和给老师的执行说明分开；内部 ID 可以在结构化目标中，不能落进用户文案。动作键包含课程、动作种类、对象身份和影响执行的版本，不能只用标题。

| 优先检查 | 输出或处理 | 明确不能做 |
|---|---|---|
| 课程不存在、归档、关键状态读取失败 | 不存在/只读/无法判断，附具体原因 | 把异常吞成“商量目标”；归档课进入今日任务 |
| 本课有未结束测试 | 保留恢复入口；限时的按真实截止时间处理；可选检查可由用户经 assess 关闭后继续，正式测试沿用其结束规则 | 自动再开复查，替用户交卷/撤回，跳过已保存答案；把一份可选复查永久当成整课门槛 |
| 结果待复核、申诉未结 | 指向 assess 的复核工作 | 当成已通过或直接安排下一次相同验证 |
| 已确认流程的必需步骤 | 目标/路线/设计确认、已有阅读、小结、复盘等照常推进 | 以复查为由绕过用户确认，改写已选的补课/带风险继续决定 |
| 后台生成中或失败 | 等待、重试或交还用户；保留原有失败规则 | 把“等生成”写成“轮到你完成”，无限重试 |
| 合适的课时边界 | 在主线之外选一个有价值且可执行的复查 | 插入作答中、未完成的阅读中或用户明确说继续当前任务时 |
| 已结课 | 无新课主线；可选维护复查仍在总量内 | 自动重开结课检验、取消结课状态 |

非阻塞的教材报错仍由 tutor 的提案节处理，不应让一条无关提案永远挡住学习。先修只用 knowledge 提供的有效关系；“未探测”不等于“不会”，到期不等于“未满足先修”，也不要求所有先修都达到“已延迟验证”才许读下一节。发现当前任务确有基础缺口时，提出短检查或补讲，结构性改课仍走 curriculum。

同一快照和同一时刻，结果应该相同；相同条件用稳定的键破同分。执行动作时重新检查课程、测试、目标和题源，不信任浏览器提交的旧快照。tutor 的逐步更新与进度通知都消费同一个动作身份和可执行状态。

### 5.2 复查候选按“要补什么证据”产生

| 本课事实 | 建议动作 | 时间与失败处理 |
|---|---|---|
| `untested`、没有本课状态 | 只有与当前目标/先修有关时做诊断 | 不自动把全图未探测节点变成复习债 |
| `not-yet` | 定位卡点、给补讲或练习 | 未学会的内容不只靠延长间隔；补讲后再安排独立新题 |
| `assisted` | 撤去帮助后验证 | 需要 learner 给当前条件下的最早独立时间；不要把 `checkFrom` 缺失解释为“随时有效” |
| `conflict` | 单点检查或先解释矛盾 | 先解决未复核判分；若已明确不会，先补讲，不能连发检查直到碰巧答对 |
| `independent` | 在 `checkFrom` 之后做延迟新题 | 中间做题/得到帮助后，重新读取窗口；没到时可练习，但不得标为延迟验证 |
| `retained` 且需要复查 | 维护性新题检查 | `checkFrom` 是复查建议时间；最近帮助仍可能使今天的结果不独立，需要单独的资格说明 |
| `doubtful` | 与当前内容相关时检查疑点 | 不扣掌握，不因过去一次提问而永久优先 |

建议 learner 补一个只读的“检查需要”视图，给出用途、最早有效时间、理由、依据版本，以及近期帮助/接触是否阻碍本次验证。掌握与独立性的规则留在 learner；planner 不 import `rules.ts`，不复制 24 小时、3 天、14 天。现有 `next` 是展示文字，不能解析里面的日期作为程序条件。

`checkFrom` 和 `needsReview` 也要区分用途：前者是时间，后者是附加标记，边界是否含等号由 learner 统一说明。到期查询只读取时钟，不往证据日志写“忘了”或“复习完成”。没有证据变化时跨午夜也要刷新可做项；恢复可见或到达最近时间边界时重读即可，不需要常驻高频轮询。

### 5.3 排序和上限应防止复习吞掉主线

候选先排除未到有效时间、已延期、在 open 测试中、课程已归档和没有可用题的项目。当前任务确需的诊断/补讲属于主线补救；不把图上所有 conflict 或 doubtful 都变成永久最高优先级。短检查失败转入教学，不在同一边界自动连发，相关掌握仍由 learner 解释。

可选复查在“首次延迟验证”和“维护复查”之间轮转；两类都有合格候选时，不让前者一直压住后者。每类再跨课程轮转，保留上次实际获得名额的位置，不能每天归零后总选同一门课；课内优先等待更久者，同分再按当前相关性及稳定键选。用户本日主学选择可覆盖推荐，但仍保留其他候选及其原因。公平性只承诺在持续实际分配可选名额、资格持续满足、用户未延期且活动课程数有限时得到推荐机会，不承诺用户会执行或在容量不足时全部完成。仅刷新页面不推进轮转位置。

**首轮建议默认值：** 一个课时边界建议 1 题；全部课程每天由系统发起的短检查至多 3 题（包括主线短诊断与回归检查）；回归最多 2 题并计入总量，逐题选择是否继续。正式小测、阶段测试按既有流程，不伪装成这 3 题已经覆盖的负担。数量可在 planner 的 volatile Config 中调整，0 关闭自动短检查；主动“考我一下”由用户决定。自动建议不等于自动建 Test，开始或明确委托老师执行才占名额。

额度按真实、去重的创建意图计：同请求重试/复用不多扣，取消不退还当日名额；前一日留下的自动 open 检查计入今日负担，即使今天做完也不再次腾出这份名额。失败且没有留下测试时不扣，若测试已创建则保留关联，按 §5.4 恢复。读取不写账；借助安排关联和 Test 的创建/结束事实计算跨日占用，不能靠只在页面内累加。多个入口并发创建时，上限检查与名额预留也要一致，不能只有 Test 去重却总额度超发。

**题数不是耗时控制。** 三道长计算题可能用完一整次学习时间。没有可核查的题目工作量时只报题数、不称“只要五分钟”；候选不满足短检查条件时，归为用户可选的练习，不能借这个分类由系统继续自动派题。每题后可停止并继续主线；给了今日时间预算但无法判断是否放得下时，只推荐逐项选择，不自动承诺都能完成。这些数量仍是试用起点，不是研究最优值。

保留正常课程推进机会，不要求清空复查才继续。若主线短诊断持续耗尽额度、维护候选持续得不到名额，报告覆盖不足，不能把分类轮转说成已解决超载；增加投入、选重点或调整范围由用户决定。相关工作不会为了轮转在每道题之间强制切换课程。

延期只改变候选的显示/安排时间，不改证据、原始到期时间和题目新旧。候选每日重新计算，不为离开的每一天补建一条任务。相同知识身份若当天已在另一门课检查，避免连续重复问；本课需要的证据仍保留，不能标为已补齐。

### 5.4 出题、复用与关闭交给现有单元

1. planner 给课程、目标知识点、检查用途、所需条件和稳定请求键；不把答案或预留题暴露给首页与教材。
2. assess 提供只读可用性查询：是否有合适的新练习题、是否已有覆盖该需要的 open 测试。查询不能标题目“见过”。有多知识点题时明确它能验证什么、失败不能定位什么。
3. 用户选择开始，或主老师执行同一个推荐时，assess 重新校验并确保同一请求只建一份 Test；curriculum 复用对应 Task。需要对象方的唯一约束或幂等接口，单靠 planner 的内存锁不够。
4. 并发的页面/工具、请求超时和重启后，按照请求键找回 Test/Task。测试已建但任务发布失败，应补任务；不能再出一题。操作状态归所属单元，planner 只保存关联和用户选择。
5. 用户点“不做了”、提交答案后，已有主人关闭测试并发出通知；planner 从结果重算。取消不算答错，也不算复习通过；已经展示的题保留“见过”。当前 `dropCheck → withdraw → test-finished → completeTask` 没有 handoff，页面也未补发；实施时由 assess 的用户动作入口交回，老师自行撤回仍不交回。重复取消只通知一次，不能只看任务关了就认为主老师已收到交回。

可选检查必须能退出后继续主线。当前主老师和侧边会话都会受 open 测试影响（限制范围见 §2），因此不能提前批量建立“稍后再做”的复查。要先由 assess 正常关闭，再重算下一步；planner 不直接把 open 改成完成，也不擅自放宽其他单元的测试限制。

**没有新题：** 候选转为“需补题”，归老师备题工作；用户还能继续不依赖该检查的学习。相同题库版本只尝试一次自动备题建议，失败后等待显式重试或题库变化，不能每次打开首页都花模型费用。练习池耗尽不能借用测试预留池；题目家族尚未实现时，报告仍沿用按题目 ID 判新，明确改编题可能高估新颖性。

复习融入课时可先用已有 `review` 测试在边界承接；不另做背卡页。后续课时小测需要包含旧点时，由 assess 接收复查目标并检查题数、条件、帮助窗口，不另加一份重复复查。阶段测试中的旧题仍用预留池、服从蓝图；planner 只能建议旧节点的顺序，不能替换核心题或承诺这一道一定满足延迟验证。

### 5.5 今日安排是选择，不是所有任务的汇总

首页推荐一个当前最可做的动作，再列少量可选课程；正在计时的测试优先显示恢复入口。正在等待生成的课显示进度，推荐位可给其他可执行课程。完成、归档和错误分别呈现，不能混为“没有下一步”。课程内下一步与首页动作共用来源；“任务总数”与“今天建议做的数”分开。

用户可选今天主学哪门课、把复查推后、先继续当前课。改变教学安排的选择由 planner 持久保存，不能只存在 `useLocalState`。不强制用户先填写时间表；如果愿意给今天可用时间，未有耗时估计的任务只说明“尚不知是否能在这段时间内完成”。

自动建议不能不断抢走焦点。新事件发生后更新理由与可选项；只有原任务完成、失效或用户切换时，才改变正在操作的主任务。相关工作不会因公平轮转在每个题目间强制切换课程。

### 5.6 回归由真实停点触发

建议先用“距本课上次有效活动 7 天以上”作为可调整的显示阈值。有效活动包括用户保存/提交作答、完成阅读、提交学习汇报；后台生成、SSE 刷新、主老师自动通知不算。旧数据无法完整还原时写“上次记录”，不能根据课创建时间猜缺席天数。离线学习未知，允许用户说明已经在别处学过，再以短检查核验。

回来时先显示上次停点与保存的答案；如果有未结束测试，直接恢复，由 assess 处理过期计时，不另开回归测试。没有 open 测试时，从当前相关且具备资格的节点中选一两道；若短检查已被本次小测/复查覆盖则复用。失败进入对应卡点的教学，不触发整课重学。用户暂不做后，同一次回归不再自动弹出。

恢复摘要以现有课时记录、测试、任务和时间为事实，不另生成一份可能过期的“学习记忆”。可显示“上次完成了什么，今天先做什么，为什么”，不对缺席作负面评价。何时触发、用户是否选择检查、已用的复查额度需要跨刷新和重启保存。

### 5.7 期限判断：先提供可核查的假设，再比较区间

现在能可靠展示的是日期与路线完成情况。每周投入已经是 goal 的事实类字段，但没有可靠的剩余工时。因此首轮不能按“剩三个阶段，每阶段两小时”自动判断赶不赶得上。

建议把期限视图分为：**缺输入 / 假设下可安排 / 时间偏紧 / 明显不足 / 日期已过**。日期未获用户或资料确认、剩余阶段尚未估量时，明确缺哪项；不能只因 goal 已 confirmed 就把所有字段当作已核实。

| 输入 | 来源与责任 | 约束 |
|---|---|---|
| 期限、每周投入 | goal，保留 `facts` 的来源 | 自动估计不能覆盖官方考试日期；假设与用户确认分开 |
| 剩余教学范围、确认步骤、已完成部分 | curriculum、assess、textbook | 未设计阶段仍有未知量；阶段大小不等，不能直接平均 |
| 工作量区间 | 后续由 curriculum 提供阶段/课时估量，或以可比较的完成记录形成粗估；附依据 | 老师估量明确标为假设；生成等待和后台判分时间不算学习投入 |
| 真实投入样本 | 如需要，新增由 planner 保存的可选粗略投入记录 | 不拿页面打开时长监控用户；不把发布到完成的历时当有效分钟数 |
| 全局可用时间 | 用户给出的总体投入，或明确各课投入是否互斥 | 同一晚的两小时不能在三门课里各算一次；只知道单课投入时，跨课可行性未知 |

在范围完整且假设明确时，用剩余工作量 `[W低, W高]` 与期限内可投入 `[C低, C高]` 比较：`W低 > C高` 表示按这些假设也不足；`W高 <= C低` 表示工时容量可容纳，仍须核对日历约束；其余为不确定/偏紧。区间包含复习、测试、复核与必要返工，不只包括读教材；延迟验证的最早日期还是单独的日历约束，不能靠今天多学几小时消除。

“假设下可安排”还要求已检查先后关系和最早完成日期；单看工时区间只能说工时容量容纳。若两个环节必须先后完成、各自又要等待有效验证，应该沿真实依赖检查日历是否可容纳，不能把可并行的等待全相加，也不能把所有等待当成零。

这不是考试通过率，也不是对未来的保证。实施首轮可以先做“缺输入 + 可编辑假设”的完整路径；没有历史数据时不得声称已依据个人节奏校准。积累样本后按时间回测，报告预测是否覆盖实际完成时间和估计偏差，仍保留未完成任务，避免只拿做得快的完成样本估计。

赶不上时给具体选择：增加可投入时间、缩小目标范围、调整课程里程碑；分别交 goal/curriculum 的现有修订流程。planner 不因考试临近自动删除先修、跳过独立验证或修改正式目标。考试日期已经过去时停止输出负数容量，转为确认是否继续学习或更新目标。

### 5.8 用反例检查推荐是否自洽

下表是人工推演，未运行模拟器或产品；用于设计评审和后续验收，不是实测结果。

| 场景 | 容易出错的规则 | 推荐结果与可观察标准 |
|---|---|---|
| 每天出现新的首次验证；一项维护复查一直合格 | 首次验证永远优先；每天重置课程排序 | 在持续有可选名额时，类型与课程轮转最终给维护机会；不能无限被后来项插队 |
| 某题连续失败，而每天上限只有 1 | 最薄弱永远排第一 | 结束自动检查链，转补讲/练习；维护覆盖不足明确保留，不虚称全部照顾 |
| 三道题预计分别 2、20、40 分钟 | 三题等于少量复习 | 不自动把全部塞进 20 分钟；估量来源不可靠时说未知，逐题选择并保留继续主线 |
| 昨天两份自动复查未交，今天上限 3 | 跨午夜给三份全新额度 | 先恢复旧题；处理后当天最多再创建一份，旧题完成/取消也不释放当日占用；仍服从本课有 open 时不自动开新题的约束 |
| 两个页面各看到还剩一个名额，开始不同节点 | 只对相同节点去重 | 只允许一个新自动检查取得名额；另一请求得到刷新后的安排，不先出题再补救 |
| retained 节点到期，十分钟前得到讲解 | 到期即具备独立资格 | 学习仍可继续；独立检查按 learner 的当前条件等待，不记成有效延迟验证 |
| 今日只剩一题，同时覆盖两个节点，其中一个刚获帮助 | 按题目 ID 新就把两个需要都勾掉 | assess 说明覆盖和条件，learner 分别解释证据；不为凑数消费不合适的独立检查 |
| 用户取消可选复查，题已见、Task 已关闭 | 页面消失等于老师已接回 | 无掌握升级；assess 发一次 handoff，tutor 再按新的主线动作决定是否唤醒 |
| 期限三天，工时足够，但必需验证最早在四天后 | 只比较工时就标可安排 | 标明日历限制；可练习但不伪造提前验证，不自动改目标 |
| 一周没有登录，但后台每天生成内容 | 系统活动就是学习活动 | 不把后台日志当学习时间；只在可靠的用户活动记录上判断恢复，缺数据就保持未知 |

还有一个无法靠排序消除的限制：按题目 ID 判新的方式，不能保证改编题对学习者陌生。不同参数或题号的重复模板不应被研究报告叫作迁移证据；在题目家族可靠之前，效果评价需人工核对预留题的独立性。

## 6. 契约与数据归属建议

以下名称表达能力范围，不是要求照抄的 API 清单。实施前先定最小必要字段，再按 AGENTS.md 补 contracts.md §11。

| 所属单元 | 建议补充 | 不能顺手接管的事 |
|---|---|---|
| planner | 稳定动作视图、跨课程推荐、延期/本日选择、回归处理记录、已安排动作关联、带来源的期限情景 | 不直接改 NodeState、Test、Task 或目标文件；不存全量证据副本 |
| learner | 按课程读取检查用途、最早有效时间、近期帮助约束、理由与规则/证据版本 | 不选题，不定每天额度，不用计划完成来升级掌握 |
| assess | 检查题可用性、覆盖关系、幂等创建与关闭、按用途校验条件 | 不把未知题目质量当可用；不让每日推荐查询消耗题目 |
| curriculum | 任务发布幂等、测试任务关联恢复；需要期限估量时提供范围和估量依据 | 不再建一张 planner_tasks，已确认路线继续由它维护 |
| tutor | 消费新的动作键与状态，解释建议、备题及补讲；用户动作按现有 handoff 接回 | 不实现另一套复习优先级，不被每次只读查询唤醒 |
| core / knowledge / goal | 沿用日志、课程状态、有效关系、身份解析、目标事实来源 | 不为一个推荐把这些事实复制到 planner |

跨午夜、夏令时、系统时区变化及设备时钟回拨要有明确语义：证据间隔按真实时间比较，“今日”按选定的本地日历日；日期型期限按目标日期解释。错误时不产生负的间隔。没有事件的时间流逝也能更新到期项；不能只依赖 `learning/node-state-changed`。

planner 的持久化先覆盖不可从现状还原的用户选择和创建意图。已安排记录保留用途、原始到期、延期、请求键和真实 Test/Task 关联；完成由主人查得。过期快照在执行时拒绝并返回新建议，用户的延期和选择不能被无关事件冲掉。规则改变后重算推荐，不伪造历史安排或改旧证据。

## 7. 按 learning-simplify 梳理的候选

这份清单不授权删代码；“尚未实现”本身不是删除理由。

| 候选 | 生产者与消费者证据 | 拟减少什么 | 失去什么、风险与保留理由 |
|---|---|---|---|
| 用稳定动作身份取代标题身份 | planner 生产 title；tutor `stepKey` 消费 actor/title；页面也显示 title | 文案变化与状态变化耦合、同名动作被吞 | 丢掉标题作为业务键的隐式兼容，需要迁移旧简报投影；显示标题必须保留 |
| 首页的一次性统一视图 | planner.home 给 course/next；client 对每课再读 curriculum.overview 并本地找第一门课 | 客户端二次排序、重复状态读取、三处状态解释 | 不能只是把所有课程数据搬进后端大响应；保留 sidebar 所需的轻查询，按实际规模决定是否拆列表与详情 |
| 推荐从权威状态现算 | 目前 planner 没有持久工作流；状态在各主人 | 避免新建“下一步表”及全套失效事件、补偿工作流 | 用户延期、今日选择、创建意图不能现算，必须保留；纯内存方案不合格 |
| 正式测试与快速检查共用恢复入口 | assess.quickCheck 建 Test/Task；planner 主线另外挑测试 | 重复出题、回归检查/课时复查/考我一下三套实现 | 原“考我一下”的主动性和取消语义要保留；同一底层测试仍须区分用途与请求来源 |
| 不引入第二套排程引擎 | 已有课程状态服务与 learner 规则，无日程求解需求 | 序列化状态机、外部求解服务和运行维护 | 放弃复杂全局最优排程与动态记忆参数；以后有实据再比较，并非永久否定 |

**打回的候选：** 合并 planner 与 learner（把“会不会”和“何时做”混为一谈）；删掉 `checkFrom` 只留自然语言（消费者必须解析文案）；把复查 Task 删除只留 Test（失去 curriculum 的统一任务入口）；删除阶段测试的旧题（已经是已验收的学习旅程能力）。

## 8. 分批开发和验收草案

### A：下一步可信、可接续

范围：结构化动作与状态、现有主线边界、所有消费者对齐。先不增加自动复查。

1. 目标文件读取失败显示错误，不返回“商量目标”；不存在/归档课处理一致。
2. 主线小测以外的 open 复查、练习、模拟考都能恢复；已有作答和草稿不丢。多份 open 有稳定顺序，限时测试不被其他推荐覆盖。用户取消可选检查经 assess 关闭并交回，不会一直挡住主线；老师撤回不发用户 handoff。
3. 摸底、前测、小测、阶段/结课测试分别覆盖 abandoned、graded、pending-review、申诉；不会把结束等同于成功完成。
4. 后台运行、首次失败、连续两次失败和结课分别有正确动作，主老师不会无限重试或被等待状态误唤醒。
5. 两个同标题不同目标的动作，tutor 能更新；只改显示文案不重复执行。首页、进度页、简报、状态栏使用同一身份。
6. 读取 next/home 多次，数据库、证据、Test/Task 数和模型调用数不变；旧快照点击后执行端重新核对。
7. `tests/flow.test.ts` 及 curriculum/tutor 已有确认、补课、结课路径持续通过。

### B：有上限、能产生有效证据的复查

范围：learner 检查需要、assess 可用性和幂等创建、课时边界安排、全局额度和延期。

1. 本课没有作答而另一课 retained，不直接视作本课已验证；共享身份的帮助仍影响资格。
2. 首次独立完成未到 `checkFrom` 不安排延迟验证；中途练习/帮助后窗口更新。retained 到期但刚获帮助，不声称今天能独立复查。
3. 刚好到边界、超过边界、跨午夜、离线数周再开，结果符合 learner 统一语义；不新增伪造证据。
4. 一千个到期节点、十门课程仍遵守全局上限，主线短诊断和回归题计入；复查不阻塞无限多轮主线，也不会每个课程各用一份全局额度。覆盖跨日遗留、取消、不同节点并发抢最后名额，具体反例见 §5.8。
5. 只读候选不占新题；无题输出补题原因；有题但不适合单点归因时明确限制；练习池不足不会取预留题。
6. 两个并发请求、页面与工具同时请求、创建后响应丢失，只有一份 Test 和对应 Task。Test 已有而 Task 发布失败，重启补齐原关联。
7. 用户延期、取消、已做、改判、题目停用、节点合并/撤销后重算正确；不恢复旧的无效推荐，不把取消计为掌握或错误。
8. 当前小测或阶段测试已经覆盖复查需要时，按用途与条件复用；未满足延迟条件不能仅因“题里出现过该点”消掉需要。
9. 公开题源/模型失败后同一状态不自动反复备题；课时和全局推荐中不显示预留题题干答案。
10. 持续有名额和合格候选时，维护复查不被新候选永久挤掉；轮转位置跨日/重启保留。没有短题或只有长计算题时不假报耗时；失败不在原边界自动反复重测。

### C：今日安排、回来后的恢复与期限判断

范围：跨课程选择、恢复摘要、用户选择持久化、期限的未知/情景/风险路径。

1. 生成中的课不会占据唯一“继续”入口；归档课不入今日安排；已结课可选复查不改变结课状态。
2. 用户继续当前课时，不被另一个课程的事件抢走；刷新和重启保留延期、本日选择及已处理的回归提示。
3. 后台生成/系统通知不更新最近学习时间；旧数据缺活动时间不捏造缺席天数；保存的答案与停点可恢复。
4. 回归已有 open 测试时恢复同一份，不强加两题；没有相关可用题时仍能继续；检查失败引向补讲，不清空已有掌握。
5. 缺每周投入、日期未核实、后续阶段未设计、任务耗时不可比时，显示具体未知量，不输出精确完课日期。
6. 合成的工作量/容量区间分别覆盖完全可容纳、相交、完全不足及日期已过；复习/测试/等待延迟验证计入适当约束。
7. 同一份跨课时间不能重复分配；增加投入、缩范围、改里程碑都通过对象主人，既有用户确认不被跳过。
8. 有个人节奏估计时做时间顺序回测；包含停滞和未完成情况。未经校准的情景范围不写为统计置信度。

**验证方法：** 跨单元使用真实单元的 harness，时钟、外部网络和模型在边界替换；关键案例验证外部返回、任务、测试及日志，不只测排序函数。规则做边界反例，尤其是查询意外写入、额度跨课重置、同名动作、重复创建与等待窗口被最近帮助污染。将来改 Config/依赖/DSH 接入后，要在只有合成数据的 3182 实测加载、老师接续与真实模型表现；UI 按 `learning-ui-review` 做六种尺寸/颜色组合并留 Claude/用户审美复核点。本轮没有实现这些测试。

规模验收应先按 `learning-perf` 写测量卡片，再用合成数据测首页、课程 next、候选筛选及重启恢复；不把 learner 已有的重算耗时当作 planner 性能。在没有测量前，不承诺毫秒指标或先上缓存。

### 调度效果怎样验证，什么结果会让我们改建议

这部分是后续研究方案，本轮未做模拟、学习实验或真实数据回放。技术可靠和教学有效分别验收，不能把前者的通过数当成后者的证据。

| 层次 | 对照和输入 | 能回答什么 |
|---|---|---|
| 确定性反例与负载推演 | 合成候选，额度 0/1/3/6；需求低于/等于/高于处理能力；不同课数、缺席、帮助、题池耗尽与跨日并发；比较固定优先、单纯最早到期、类型/课程轮转 | 重复创建、超额、无效资格、长期排不上、主线被打断、未覆盖需求。合成“正确率”不证明人学得更好 |
| 历史只读回放 | 每步只看当时已有的事实和版本，不泄漏后来的改判与作答；固定比较规则 | 当时会推荐什么、资格是否正确、负担如何变化；不能知道用户对从未出过的题会怎样作答，不能靠日志宣称因果收益 |
| 后续学习比较 | 规则方案与简单间隔/最早到期方案比较；固定题源、反馈、证据规则、目标范围和可投入预算，仅改变调度；先覆盖一种计算内容 | 延迟表现是否改善，或在预先约定的可接受差异内降低负担。单人短期试用主要校准可用性，不能宣称统计上优于另一算法 |

评价在比较开始前约定，不能看见结果再换指标：

- **主要学习结果：** 预先安排的延迟检查、独立作答、经核对的新题家族和相同评分标准；检查日期由共同学习起点/目标日期确定，同时记录距最后练习的实际间隔。另看近变式与综合迁移，不把 learner 因为多做题而多获得的 retained 数直接当效果。评估题仍遵守练习池与预留池分离。
- **负担与覆盖：** 练习次数、可选自报投入、恢复/取消次数、主线推进机会、最长合格等待、未被覆盖的目标。题数和时间分别看；没有可靠时间记录就不声称单位时间收益。
- **比较完整性：** 同一知识身份、先修与跨课程帮助可能互相影响，不能把这些项目当独立样本；若做随机比较，按不会互相污染的内容组设计，并记录基线与题目难度。使用相同目标范围，避免只让新策略测容易题。
- **退出与缺测：** 报告开始人数/项目数、未完成和未参加后测情况，不能只保留顺利完成的人；也不能把缺测自动写成不会。小样本或范围变化时保留不确定结论，不硬报“提高百分之多少”。

**改变推荐的条件：** 轮转若在相同预算下没有减轻最长等待，反而增加切课和负担，退回更简单的到期排序；题数上限仍经常吞掉主线，就先减少自动推荐或加入有依据的投入约束；以后出现可靠的个人/题目历史，且记忆模型在时间外验证中校准较好，再为合适的小项目比较 FSRS。任何预测改进都还需负担和学习结果验证，不直接替换 learner。

## 9. 接续时需要明确的取舍

- 本报告推荐首轮用规则，FSRS/学习排序模型留作后续对照；没有要求另开付费服务。
- 建议的 1 题/边界、3 题/全局日、7 天回归阈值要作为可调整的产品参数定案，统一试用后再校准；题数不保证耗时，类型/课程轮转也不消除容量不足。
- 需要 learner 给检查资格、assess/curriculum 给幂等创建及恢复能力；不能只改 planner 页面便宣称调度完成。
- 期限预测所缺的数据由谁提供，要在 C 开工前定清。可以先交付诚实的未知状态和有来源的情景比较，不能把它报告成已经验证的个人完课预测。
- 改变已确认方向的事仍需用户决定：硬性排每日课表、禁止带风险继续、把掌握改成概率、自动缩小目标。本报告均不推荐。

本轮起点检查、文档检查和运行环境限制记在 [验证记录](../stage0/compatibility.md#planner-做深调研与起点检查10-10codex)。后续实施者从这里和当前源码接续，不应照搬 learner 旧调研中已被最终设计舍弃的方案。

**调研完成的边界：** 主要设计选择已有当前源码依据、一手研究、适用限制、反例及检验办法，足以进入设计评审；这不是对调度学习效果的验收。仍缺本领域的参数校准、可靠的耗时/题目家族数据、长期学习比较，以及部分论文全文。继续做实现前先定这些不确定项如何呈现，不能在实现中悄悄把假设写成保证。
