# 知识模型（knowledge）

> 代码：[`packages/knowledge`](../../packages/knowledge) · 接口：[契约](../stage0/contracts.md) §4.4、§5.1

知识模型是一张像 Obsidian 那样的知识网：有哪些知识、它们之间什么关系、从哪份资料来。你会了什么（掌握状态）由 [learner](../learner/design.md) 根据证据算出来，知识模型负责把它画在图上。

## 两层 + 证据

| 层 | 回答什么 | 内容 |
|---|---|---|
| **掌握层** | 你会了什么 | 知识节点和它们之间的关系；节点的颜色/标记表示你的掌握状态 |
| **来源层** | 知识从哪来 | 资料、资料片段（章节/页）、例题、题目，连到它们讲解或考查的知识节点 |
| 证据（在节点详情里） | 凭什么说你会 | 你的作答记录：哪一次、哪道题、是否独立完成、隔了多久 |

报告提醒过：不同的视图不要硬塞进同一张大网。所以默认只显示掌握层，来源层可以一键叠加；证据在点开节点后的详情面板里看，不画成节点。

## 节点

**知识节点分四种，用形状区分：**
- **知识**：概念、事实。
- **技能**：可以动手操作的步骤。
- **综合能力**：把多项知识和技能协调起来使用。
- **完整任务**：在真实场景下的整合表现，例如"独立读懂一篇论文的方法部分"。

**掌握状态用文字 + 颜色表示，不用百分比。** 各种状态的含义和推算规则见 [learner](../learner/design.md)。

和当前目标无关的课程外节点淡化显示，不会把一大片未知节点都画成"不会"。有考试的课程，节点上还会标出"考试范围内/外"（见 [goal](../goal/design.md)"考试档案"）。

## 关系（每条连线都要有类型和出处）

| 关系 | 含义 |
|---|---|
| 组成 | A 是 B 的一部分（完整任务 ← 技能 ← 知识） |
| 先修 | 不会 A 就做不了 B（结构上必需） |
| 建议先学 | 先学 A 会让 B 更顺（只是教学顺序，可以绕开） |
| 相关 | 有联系，但没有先后要求 |
| 讲解 / 例题 / 考查 | 从来源层指向知识节点 |

报告强调过：不是所有连线都是先修关系。只有"先修"会硬性影响排课，其他关系都可以协商。

## 全局 vs 课程

- **知识身份可全局共享。** A 课的记录在 B 课可见，但条件能否迁移仍需验证；不能因为共享身份直接认定本课已掌握。能力不应该绑死在某一门课的目录里。
- **但名字相同不等于同一种能力。** 跨课程合并节点的方式是：系统自动给出合并建议，由你确认。每条证据都要记下"是在什么条件下做到的"。
- **主界面显示全局图：** 可以按课程、状态、类型筛选，可以搜索，可以分组着色。
- **课程界面显示局部图：** 本课节点，加上向外 1–2 跳的相关节点，相当于 Obsidian 的"局部图"。

## 谁能修改知识模型

- **结构（节点和连线）：** Agent 在调研和设计时提出修改，附上理由和出处，记入变更日志，你可以撤销。你也可以手动修改。修改走[统一的修改流程](../journey.md#所有修改都走同一条路)。
- **掌握状态：** **只能由证据规则算出来。** Agent 和你都不能直接把一个节点"设为已掌握"。你可以说"这个我会，考我一下"，然后走快速验证。

## 关键决定

- **知识模型采用 Obsidian 式网状图：掌握层 + 来源层；主界面显示全图，课程界面显示局部图**（10-03，你）。
- **跨课程合并知识节点：系统自动建议，由你确认**（10-03，你）。
- **知识图谱用 sigma.js**（10-03，阶段 0 调研）。
- **关系允许课程或任务限定；按 A 数据与修改 → B 图与详情 → C 合并与受控抽取分批；老师先建课程粗图、按当前阶段小节细化**（10-07，你同意调研建议）。
- **图谱的画法：箭头一律从先学指向后学；同一时刻颜色只表示一件事（掌握状态或课程）；筛选只隐藏、不重排；位置作为界面偏好记在本机**（10-07，Claude 按调研设计）。
- **合并保留被合并的节点和全部作答记录，learner 透过合并读证据，并按课程分别计算掌握状态；按小节抽取的结果直接作为一组可撤销的修改加入本课，关系一律是草案**（10-08，Claude 按调研设计）。

完整的决定和来源见[决策记录](../decisions.md)。

## A 批：数据、修改和撤销

本节记录已实现的 A 批规则和验收标准；技术验收通过，使用效果仍待你试用。

### 身份与课程归属

新节点总有新 ID；标题、别名只用于查找候选，多个匹配返回歧义而不取第一条。本课已关联的身份可显式复用；跨课复用由学习者在页面选择已有身份，老师不能仅凭同名自行共享。老师在本课新建的节点，名称不能和本课已有节点的名称或别名相同：是同一项就复用，含义不同就改用能区分的名称。同一课里重名会让按名称引用出现歧义，教材段落也挂不上其中任何一个；学习者在页面上仍可有意建立同名身份。重复请求用操作标识去重，不用标题去重；同一标识带不同内容会报错。

节点记录含义、领域和表现条件。修订说明、别名与标题不改变身份；类型或所指能力改变时创建新身份。课程成员记录角色、考试范围、活动状态和版本；退出课程不影响别课。全局节点停用保留详情与历史，不删证据。

### 关系与来源

关系分全局、课程、任务三种范围；任务范围还带所属课程。`requires` 保持“起点需要终点”的存储方向。来源、理由、条件和版本都可查看；状态分草案、有效、有争议、遗留待复核和停用。只有有理由、有可引用片段依据的有效先修才进入执行查询；程序验证定位和状态，语义是否支持仍要核对原文。

硬先修与组成各自检查环，按全局 + 课程 + 某个任务的实际组合检查；不同任务的边不混在一起误报环。相关关系对称去重，允许环；建议先学不当硬约束。旧关系保留原 ID 与方向，标为遗留待复核，不直接成为执行先修。

来源连线保存资料片段、题目或教材块的身份与版本。登记时向主人服务检查目标存在；资料须已入库、可引用，课程限定关系的资料须关联本课。停用的连线通过变更记录撤销恢复，后台重复索引不启用它。题目与教材正文不复制入知识表，测试预留题不在详情泄露。出处不能充当掌握证据。

### 修改与整组撤销

一次添加或修改对应一个操作组，组内的节点、关系、成员、来源连线写在同一事务里。core 保存每个对象的完整前后值、课程及操作组；knowledge 保存操作身份与去重收据，并负责结构回退。提交后才发变更推送；页面完成操作再交回主老师，老师的工具调用不额外交回。没有实际变化的操作（教材重复索引、复用已在本课的身份）不留记录，以免把真正的修改挤出变更记录；教材索引一个文件时，出处连线合成几组登记（每组最多 100 条），不按段落各记一组。

编辑提交读取时的版本，过期版本报冲突。撤销也先检查所有对象仍处于该操作写出的版本；有后续修改则整组拒绝，不覆盖。恢复旧内容时生成新版本、新日志；撤销创建采用停用或退出课程，原 ID、来源与证据保留。恢复有效关系前重新检查端点、出处与环。

### A 批验收标准

- 两课同名异义不共享；别名歧义有候选；显式本课复用与页面跨课复用可用；重试同一请求不重复创建，标识冲突与批量错误不留半份结果。
- 关系方向、作用域、反向相关去重和环路径正确；无出处、未知端点、资料未就绪或不属于本课不能写成有效先修；草案、争议和遗留关系不进执行查询。
- 修改与成员退出有版本和日志；一个课程的退出不改另一个课程；来源登记检查主人服务；停用和撤销不修改任何学习证据。
- 一次操作可看影响并整组撤销；并发修改或恢复后的先修环导致整组失败；失败不发成功推送，重复撤销不重复生成记录。
- 从旧骨架合成库升级保留 ID、关系、成员、出处和证据；再启动不重复迁移，缺依据结构明确标记。
- 列表能搜索标题与别名、打开节点详情、查看关系条件和出处、编辑说明与关系、退出课程、查看历史并撤销。掌握读取失败显示不可用，不显示成未探测。三种宽度、深浅两色截图，保留用户或 Claude 审美复核点。
- 类型检查、自动测试、构建、最小学习流程持续通过；3182 的真实 DSH 加载、页面及老师工具用合成数据验收。

## B 批：图谱、局部探索和出处

本节是 B 批的设计和验收标准（10-07，Claude 按[调研](research.md)第 9、10 节和已确认方向细化），实现前写定。

### 页面

- 侧栏的"知识模型"在主界面和课程里都有：主界面是所有课程的知识网（全局图），课程里是本课图。
- 页面默认显示图谱，可以切回分组列表，选择记在本机。浏览器画不了图（没有 WebGL）时自动用列表，并说明原因。
- 图谱左边是画布，右边是边栏：
  - 没有选中时，边栏是可搜索的节点列表，每项写着类型和状态，可以用键盘选；
  - 选中节点后，边栏显示简要详情（状态和理由、含义与条件、关系句子、出处、所属课程），可以打开完整详情或就此提问。

  窄窗口里边栏放到画布下面。
- 画布上方的工具：
  - 搜索；
  - 关系筛选（全部、先修和建议先学、组成、相关）；
  - 选中节点后的局部范围（一跳、两跳、全部）；
  - 叠加出处；
  - 放大、缩小、复位和重新排布。

  全局图另有课程筛选和着色方式（掌握状态或课程）。

### 怎么画

- **形状：** 四种节点用形状区分：知识是圆，技能是方块，综合能力是菱形，完整任务是三角。图例写明形状和颜色。
- **颜色：** 同一时刻颜色只表示一件事。
  - 默认表示掌握状态，和列表的状态颜色一致，未探测是灰色。
  - 课程图里，多门课共享的节点用灰色，注明"本课条件待验证"。
  - 掌握状态读不到时，节点全部灰色，并提示"状态暂不可用"。
  - 全局图切到"按课程着色"时，颜色表示课程；多课共享的节点用灰色，图例列出课程。
- **不只靠颜色：** 悬停或选中节点时，标签旁写出状态文字；边栏列表每项都有状态文字。
- **箭头方向：** 一律从"先学"指向"后学"。先修从被需要的能力指向需要它的能力；建议先学从先学的指向后学的；组成从部分指向整体；相关没有箭头。列表里的关系也按这个顺序写。有效关系画实色，草案、有争议、待复核的画淡色细线。
- **课外相关：** 课程图默认只画本课节点。通过全局关系连到的课外节点算"课外相关"，默认不画；工具栏写出数量，可以一键显示（淡化）。
- **局部范围：** 选中节点后，按局部范围突出它的一跳或两跳邻居，其余节点淡化但不隐藏。被筛选隐藏的节点数写在工具栏旁。
- **出处：** 叠加出处时，每份资料画成一个空心小圆，本课教材合成一个，连到它讲解的节点。点资料，边栏列出相关片段；点片段，在旁边打开原文。题目不画进图里，测试预留题照旧只写"测试预留题"。

### 布局和生命周期

- 初始位置由节点 ID 决定，再用 ForceAtlas2 在 worker 里排布，有时间上限，排完就停。节点大小随数量缩小。
- 位置记在本机（属于界面偏好），下次打开不重排；"重新排布"按钮重算。
- 结构变化（新节点、新关系）时，只给新节点找位置（放在已有邻居附近），已有节点不动。掌握状态推送只改颜色，视角和选中都保留。
- 窗口或分屏改变尺寸时，画布跟着调整。标签页隐藏时暂停排布；关闭标签页时释放渲染器、worker 和监听。深浅色切换时重读颜色。

### 证据和接口

- 完整详情的"掌握证据"列出这个节点的作答和帮助记录：时间、哪类测试、结果、是否用了帮助、作答条件（开卷闭卷、计算器、限时）。有测试的记录可以打开那次测试。
- learner 增加只读接口 `learner.evidence`，读证据日志，不改任何记录。
- knowledge 增加两个只读接口：
  - `knowledge.global`：所有课程的节点、关系和课程名；
  - `knowledge.sources`：节点的出处，按资料汇总。

### B 批验收标准

- 主界面能看所有课程的知识网，可以按课程筛选，按掌握状态或课程着色。课程里能看本课图，课外相关节点的数量看得到，也能显示出来。
- 搜索名称或别名，能在图上定位并选中。同名节点在列表里能靠领域或课程区分。图和列表的选中同步，键盘能在列表里选择。
- 四种形状、状态颜色和文字一致，箭头方向和关系句子一致，非有效关系和有效关系看得出区别。
- 选中节点后，一跳、两跳、全部切换正确；筛选后隐藏的节点数看得到。
- 叠加出处时，资料节点和片段能打开原文，不泄露测试预留题。
- 完整详情能列出真实的证据记录和条件，有测试的能打开测试。
- 状态更新时，视角、选中和位置不变；新节点不打乱已有布局；读取失败时显示不可用。
- 在 1440、1024、760 宽度和深浅两色下截图核对，包括分屏、隐藏标签再打开；没有 WebGL 时列表可用。
- 合成的 50、500、2000 节点图，记录首屏、排布和状态更新的时间，关闭后资源释放；排布期间页面可以操作。

## C 批：合并建议与受控抽取

本节是 C 批的设计和验收标准（10-07，Claude 按[调研](research.md)第 7、8、11、12 节和已确认方向细化），实现前写定。

### 合并建议从哪来

- **系统建议：** 两个节点类型相同，名称或别名规范化后相同（忽略大小写、空格、全角半角、标点和括号里的补充说明），而且不属于同一门课，就列为一组建议。名称相同只说明值得比较，不说明是同一项；页面不显示"相似度"。
- **主老师建议：** 主老师发现两门课的节点可能是同一项时，用工具提出建议并写明理由，等你确认。老师不能自己合并；理由会原样给你看，带内部编号的理由会被拒绝。
- **你自己发起：** 在节点详情里选"和其他节点合并"，搜索另一个同类型的节点。
- **不是同一项：** 你选"不是同一项"后，记下这一对和当时两边的版本。两边都没修订就不再推荐；任何一边修订后会重新比较。撤销一次合并也记为"不是同一项"。

### 比较和确认

- 两列并排列出：名称、类型、领域、含义、表现条件、别名、所属课程、关系和出处的数量、全部课程的掌握记录。不同的地方标出底色，并写明为什么推荐。
- 合并前选保留哪一个（默认保留课程多的，一样多时保留建得早的），先看合并会做什么：
  - 被合并的节点加入了哪些课程；
  - 哪些关系改连到保留的节点，哪些和已有的同一关系合成一条（依据合在一起，状态和理由以已有的为准，不会因此变成有效关系），哪些变成了节点连自己而停用；
  - 哪些出处移过去。
- 合并后会形成先修或组成循环时不能合并，页面写出循环经过的节点，先把其中一条关系改为草案。
- 确认时带上比较时两边的版本；有一边已被修改就报冲突，要重新比较。类型不同的节点不能合并（类型变了本来就是另一个身份）。

### 合并做了什么

- 被合并的节点不删除：标为停用，并记下"已合并到某节点"。旧链接仍能打开，页面写明合并去向。
- 它的课程归属、关系和出处改到保留的节点上，前后内容都记进同一组变更，可以整组撤销。撤销前检查这些对象之后没有再被修改（例如又合并了一次）；改过就整组拒绝，说明要先撤销后来的修改。
- 作答、帮助记录和题目都不改编号。learner 计算保留节点的状态时，把合并进来的节点的记录一起读，按记录去重，判分更正和帮助的关联照旧。
- 撤销后两边按各自的记录重新计算；合并期间产生的新记录留在记录时的节点上。
- 按节点出题时，也会选合并进来的节点的题。图谱搜索能用旧名称找到保留的节点；主老师用旧编号或旧名称查找，会得到保留的节点。

### 按课程看掌握状态（learner 的最小改动）

- learner 除了算全部记录的状态，还按课程分别算：只用这门课里的作答记录，规则不变。帮助记录不分课程，一律参与判断，避免把有帮助的作答算成独立完成。
- 课程页里，只属于本课的节点照旧显示；多门课共用的节点显示本课的状态。本课还没有记录、其他课有记录时，显示"本课条件待验证"，并写出全部课程的记录是什么状态。
- 主界面的全局图显示全部记录的状态。主老师的简报也按课程区分。

### 按小节抽取

- **谁发起：** 主老师用工具一次提交几个小节；你也可以在本课知识模型的"按小节抽取"页选小节。一个小节一个后台任务，同时最多运行 2 个。
- **给模型什么：** 本课骨架教材（或本课的其他资料）这一小节的正文片段，不含习题和答案；本课已有节点的名称和类型。小节太长（超过约 24000 字）时不抽取，提示改用下一级小节。
- **模型：** knowledge 的"知识抽取"角色（设置页可以换，不设置时用默认模型），一次调用，返回 JSON。
- **程序检查：**
  - 节点要有合法类型和名称，引用至少一个本小节的片段；
  - 关系的两端必须是本批节点或本课已有节点，类型合法，写明理由；
  - 不在本小节里的片段编号丢掉；
  - 和本课已有节点同名同类型的，当作已有节点，只补出处；
  - 同名不同类型、重复关系、节点连自己，跳过并写明原因。
- **写入：** 通过检查的内容作为一组修改加入本课：新节点、给已有节点补的出处、关系一律是草案。整组可以在变更记录里撤销。回复被截断、为空、不是 JSON，或者没有一项通过检查时，什么都不写，任务记为失败并写明原因。
- **任务记录：** knowledge 自己记下每个任务的资料、小节、片段指纹、状态、结果和失败原因。同一小节已经抽过、片段没变时不重复抽取；资料重新解析后片段变了，显示"资料已更新"，可以再抽一次（只补新内容）。任务可以取消、重试；程序重启后，没完成的任务继续。
- **完成后：** 给主老师发进度通知，写明新增几个节点、几条草案关系、跳过几项；关系都是草案，主老师核对原文后再改为有效。
- 主老师的工作方式相应调整：先按目录建课程粗图，进入某个阶段时再按小节抽取细化。

### C 批验收标准

- 两门合成课程里同名异义、同名同义的节点都列为建议，但都不自动合并；同一门课里的同名节点不推荐。主老师的建议带理由出现在建议列表。选"不是同一项"后不再出现，任一边修订后重新出现。
- 比较页能看出两边的差异；确认时有一边已被修改会报冲突；类型不同不能合并。
- 合并后：被合并节点的旧链接能打开并指向保留的节点；课程归属、关系、出处都在保留的节点上；重复关系合成一条且依据不丢；节点连自己的关系停用；会形成循环的合并整组拒绝并写出路径。
- 原作答记录的数量和内容不变；同一条记录不重复计数；判分更正和帮助关联不丢；状态可以删除后重算出同样结果。
- 整组撤销恢复原样；合并期间的新记录保留在原节点上；有后续修改时撤销被拒绝。
- 多门课共用的节点在本课没有记录时显示"本课条件待验证"，不把其他课的状态当成本课的；本课有记录时显示本课的状态；有帮助的作答不会因为按课程计算变成独立完成。
- 抽取用假模型回归：正常结果、截断、空回复、非 JSON、引用不在本小节的片段、未知端点、和已有节点同名、重复关系、取消、重试、重启后继续、同一小节不重复抽取；失败时图里没有任何改动。
- 抽取完成给主老师发一次进度通知；页面上确认合并也交回主老师；老师自己调用工具不额外交回。
- 用 DeepSeek 在 3182 的合成小节上抽取一次，逐条核对产出的节点和关系，记录错误的关系，不只看 JSON 是否合法。
- 类型检查、测试、构建通过；最小学习流程不受影响；在 3182 用真实 DSH 加载，截图核对合并页、抽取页和节点详情（三种宽度、深浅两色）。
