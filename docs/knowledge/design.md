# 知识模型（knowledge）

> 代码：[`packages/knowledge`](../../packages/knowledge) · 调研：[research.md](research.md) · 契约：[contracts.md](../contracts.md)

## 概要

知识模型是一张像 Obsidian 那样的知识网：有哪些知识、它们之间什么关系、从哪份资料来。主界面是所有课程的知识网，课程里是本课图和侧栏局部图。你会了什么由 [learner](../learner/design.md) 按证据算出来，知识模型只负责画；Agent 和你都不能直接把节点设为已掌握。结构的每次修改都是一组可以整组撤销的变更。

## 两层和证据

- **掌握层**（默认显示）：知识节点和关系，颜色表示掌握状态。
- **来源层**（可以一键叠加）：资料片段、讲义段落、题目，连到它们讲解或考查的节点。出处不能充当掌握证据。
- **证据** 不画成节点，在节点详情的"掌握证据"里看（作答和帮助记录、条件、为什么算或不算），有测试的记录可以打开那次测试。

## 节点和关系

- **四种节点：** 知识（概念、事实，圆）、技能（可操作的步骤，方块）、综合能力（协调多项知识和技能，菱形）、完整任务（真实场景下的整合表现，三角）。节点记含义、领域和表现条件。
- **关系：** 组成、先修（不会 A 就做不了 B，排课时唯一的硬约束）、建议先学（只是教学顺序）、相关（有联系没有先后）。来源层的连线是讲解、例题、考查。
- **范围：** 关系分全局、课程、任务三种，任务范围还带所属课程。
- **状态：** 草案、有效、有争议、遗留待复核、停用。只有有理由、有可引用片段依据的有效先修才进入执行查询；程序检查定位和状态，语义是否支持仍要核对原文。新关系默认是本课草案；骨架阶段的旧关系保留原 ID 和方向，标为遗留待复核，不直接成为执行先修。
- **环：** 先修和组成各自检查环，按全局 + 课程 + 某个任务的实际组合检查，不同任务的边不混在一起误报；相关关系对称去重、允许环。

## 身份和课程

- 新节点总有新 ID；名称和别名只用来找候选，多个匹配返回歧义，不取第一条。改说明、别名、标题不改变身份，改类型或所指能力就建新身份。
- 本课已关联的身份可以显式复用；跨课复用由你在页面上选，老师不能凭同名自行共享。老师和抽取在本课新建的节点不能和本课已有节点同名（是同一项就复用，含义不同就改名），否则按名称引用会有歧义、讲义段落也挂不上；你在页面上可以有意建同名身份。
- **同名：** 一个的名称是另一个的名称或别名（忽略大小写、全角半角、空格和标点）。括号里的说明只有两边都有、又不一样时才算区别：压力（表压）和压力（绝对）是两个，雷诺数（Re）和雷诺数是一个。两个节点共用一个符号别名（μ）不算同名。
- 课程成员记角色、考试范围、活动状态和版本；退出课程不影响别的课。全局停用保留详情和历史，不删证据。
- **全局和课程：** 知识身份可以跨课程共享，A 课的记录在 B 课可见，但条件能不能迁移仍要验证。learner 按课程分别算状态：多门课共用的节点在本课只看本课的作答（帮助不分课程），本课还没有记录时显示"本课条件待验证"。主界面显示全部记录的状态。

## 合并

- **建议从哪来：** 类型相同、名称或别名规范化后相同（忽略大小写、空格、全角半角、标点和括号里的补充）的两个节点，同一门课里的也算（老师和抽取不会再建出这种节点，有就是以前留下的或你有意建的，你说不是同一项就不再列）；主老师用工具提的建议（理由原样给你看，带内部编号的拒绝）；你在节点详情里发起。名称相同只说明值得比较，页面不显示"相似度"。
- **不是同一项：** 记下这一对和当时两边的版本，两边都没修订就不再推荐。撤销一次合并也记为"不是同一项"。
- **比较和确认：** 两列并排，差异标底色。先选保留哪一个（默认课程多的，一样多时建得早的），再看合并会做什么：加入哪些课程、哪些关系改连或合成一条（依据合在一起，状态和理由以已有的为准）、哪些变成自己连自己而停用、哪些出处移过去。会形成先修或组成循环时不能合并，写出循环经过的节点；确认时带比较时的版本，有一边改过就报冲突；类型不同不能合并。
- **合并做了什么：** 被合并的节点停用并指向保留的节点，旧链接仍能打开。它的课程、关系、出处改到保留的节点上，作为一组变更可以整组撤销（之后又改过就拒绝）。作答和帮助记录不改编号：learner 读保留节点时把合并进来的记录一起读、按记录去重；撤销后各按各的记录重算。按节点出题、搜索旧名称、老师用旧编号查找，都会落到保留的节点。
- **之前存下的决定：** 阶段的核心知识点、复盘、带过来的风险、试卷和讲义的块索引都不改编号，读的时候经 `currentIdentities` 解析成当前身份：阶段设计、组卷、前测、复查和课程报告都按当前身份算，报告按当前身份写。连续合并落到最后一个；撤销后回到原来，这份试卷的报告里两个节点分开写。试卷和证据日志存的编号不变。复盘保存后身份变了，结果并没有变，所以不挡你决定，复盘卡片和简报写明哪个知识点受影响。

## 修改和整组撤销

- 一次添加或修改是一个操作组，组内的节点、关系、成员、来源连线写在同一个事务里，失败时没有半份结果。core 保存每个对象的完整前后值、课程和操作组；knowledge 保存操作身份和去重记录，并负责结构的撤销。重复请求按操作标识去重，同一标识带不同内容报错。
- 修改要带读取时的版本，过期报冲突。撤销先检查组内所有对象仍是这组写出的版本，有后续修改就整组拒绝；恢复旧内容生成新版本，撤销创建用停用或退出课程代替删除；恢复有效关系前重新检查端点、出处和环。
- 没有实际变化的操作（讲义重复索引、复用已在本课的身份）不留记录；讲义索引一个文件时，出处连线合成几组登记（每组最多 100 条）。
- 提交后才推送；页面上完成操作再交回主老师，老师的工具调用不交回。

## 来源连线

保存资料片段、题目或讲义段落的身份和版本；登记时向主人服务检查目标存在，资料要已入库、可引用，课程限定关系的资料要关联本课。题目和讲义正文不复制进知识表，测试预留题不在详情里露出。讲义段落按本课唯一的标题关联，有歧义时不自动挂。

讲义段落的连线记下主人（`textbook`），每次重新索引一个文件时整组替换（`replaceLinks`）：段落不再讲的停用，又讲到时恢复，段落没了的也停用。没有主人的是手工建的，不动；你手工停用的，索引不会恢复。

## 按小节抽取

- 主老师用工具一次提交几个小节，你也可以在"按小节抽取"页选。一个小节一个后台任务，同时最多 2 个。
- 给模型这一小节的正文片段（不含习题和答案）和本课已有节点的名称、类型；小节超过约 24000 字不抽，提示改用下一级小节。用"知识抽取"角色的模型，一次调用，返回 JSON。
- 程序检查：节点类型和名称合法、至少引用一个本小节的片段；关系两端是本批或本课已有的节点、类型合法、有理由；不在本小节的片段编号丢掉；重复关系、自己连自己跳过并写明原因。
- **查重在写入时做：** 模型回来后，在写入的事务里按本课现在的节点比较（同时抽的另一节可能刚加了同一个概念）。和一个已有节点同名同类型的就是它，只补出处；同名但类型不同、或同名的有几个的进"待区分"，不写入。
- **待区分：** 按小节抽取页列出来，知识模型页有提示，简报也写给老师。你或老师（`settle_same_name`）读过两边的出处后说明：是同一项（只补出处）、是另一项（建成新节点，老师要给一个不同的名称）或不要。
- 通过的内容作为一组修改加入本课，关系一律是草案，主老师核对原文后再改为有效。截断、空回复、不是 JSON 或没有一项通过（也没有待区分的）时什么都不写，任务记为失败。
- 同一小节片段没变时不重复抽；资料重新解析后显示"资料已更新"，可以再抽一次。任务可以取消、重试，重启后继续。完成后给主老师发进度通知（新增几个节点、几条草案关系、跳过几项）。
- 主老师的做法：先按目录建课程粗图，进入某个阶段时再按小节细化。

## 图谱

- 知识模型页默认显示图谱，可以切回分组列表；没有 WebGL 时用列表并说明原因。右边的边栏没选中时是可搜索的节点列表，选中后是简要详情（状态和理由、含义与条件、关系句子、出处、所属课程）；窄窗口里边栏在画布下面。
- 工具：搜索定位、关系筛选、选中后的局部范围（一跳、两跳、全部，其余淡化不隐藏）、叠加出处、缩放和复位、重新排布；全局图另有课程筛选和着色方式。被筛选隐藏的节点数写在工具栏旁。
- **怎么画：** 同一时刻颜色只表示一件事：掌握状态（默认），全局图可以按课程，课程图可以按阶段（核心知识点所在阶段的颜色，其余灰色）。掌握状态读不到时全部灰色并提示。悬停或选中时写出状态文字，不只靠颜色。箭头一律从先学指向后学（组成从部分指向整体，相关没有箭头）；非有效关系画淡色细线。课外相关的节点默认不画，写出数量、可以一键淡化显示。叠加出处时每份资料是一个空心小圆，点资料列出片段，点片段打开原文；题目不画。
- **怎么动：** 布局用 d3-force 持续模拟：节点互相排斥，连线把两端拉到一定长度，一股力往中心拉。第一次打开从按 ID 定的位置散开，镜头框住整张图直到你缩放或拖动；位置记在本机，再打开几乎不动。拖一个点，相连的点被拉着走，画布不平移。拖动、改力度、"重新排布"时重新动起来；新节点放在已连着的节点旁边；状态推送只改颜色，筛选只隐藏，都不让图动。标签在后台时暂停，关闭时释放；系统要求减少动态效果时先算好再画。
- **怎么看：** 连线越多的节点越大（有上限），大小按图上的距离计；屏幕上够大才写名称，放大后写出更多，选中、悬停、局部范围里的总写。悬停只亮它和相连的节点、连线；边栏列表悬停一项，图上同样高亮。
- **怎么操作：** 单击选中，双击打开详情，Ctrl+单击新标签，右键有打开详情、新标签打开、就此提问；`+`、`-` 缩放，方向键平移。画布右上角的齿轮里有显示（节点大小、连线粗细、名称显示）和力度（中心力、排斥力、连线拉力、连线长度）七个滑杆，记在本机，可以恢复默认。

## 侧栏局部图

课程里点"知识模型"图标展开侧栏（主界面直接打开所有课程的知识网）。它跟着当前标签：打开讲义的一个课时时是那一节讲到的知识点（段落关联的，按出现顺序；没写好时用那一节原文资料对应的），打开知识详情时是这个知识点，在图谱页选中节点时是选中的，其他页面是当前阶段的核心知识点。显示这些知识点加一跳（可切两跳）的相邻节点，下面列出它们和掌握状态，底部是"本课知识图谱全页"。点节点在主标签打开详情，Ctrl+点击新标签；侧栏画布小：节点画得比页面上大，只给跟随的知识点写名称，放不下的以"…"收尾；每换一个跟随对象重新散开，不记位置；没有 WebGL 时只有列表。

## 考试范围

课程成员可以标考试范围内、范围外但有助理解、考试范围外。老师用 `mark_exam_scope` 按骨架教材的小节或章标（出处在范围内的标范围内，都在范围外的标范围外，没有骨架教材出处的列给老师逐个判断，"有助理解"不会被改掉），整批可撤销；你在节点详情的"课程归属"里改。课程图有"考试范围"筛选，简报写出各类的个数。

## 数据与接口

- **服务** `learnKnowledge`：候选查找、局部图、全局图、来源层、详情、有效先修、身份和当前身份（`currentIdentities`）、增改节点和关系、成员和考试范围、来源连线（含按主人替换的 `replaceLinks`）、操作历史和撤销、合并建议和合并、按小节抽取和待区分。
- **表：** `knowledge_nodes`、`knowledge_edges`、`knowledge_course_nodes`、`knowledge_links`、`knowledge_operations`、`knowledge_operation_courses`、`knowledge_merge_reviews`、`knowledge_extractions`。
- **页面接口** `/api/learning/knowledge.<方法>`：`graph`、`global`、`sources`、`candidates`、`detail`、`history`、`operation`、`add`、`editNode`、`editEdge`、`setMembership`、`link`、`unlink`、`revert`、`mergeSuggestions`、`mergePlan`、`merge`、`keepSeparate`、`extractions`、`extract`、`cancelExtraction`、`sameName`、`settleSameName`。局部图的知识点来自 `textbook.lessonNodes`。
- **事件：** `learning/identity-changed`（合并或撤销后，learner 重算）、`learning/extraction-changed`；页面上合并、撤销合并时给每门相关课程发 `learning/handoff`，抽取任务结束时也发。
- **老师工具：** `find_knowledge_nodes`、`get_knowledge_node`、`add_knowledge_nodes`、`revise_knowledge_node`、`revise_knowledge_edge`、`extract_knowledge_sections`、`settle_same_name`、`suggest_knowledge_merge`、`mark_exam_scope`。查找、详情和添加的结果最多 5000 字符；简报最多列 40 个节点。
- **设置项：** `model`（"知识抽取"角色）。图谱的位置、显示和力度、着色、侧栏深度是浏览器本地的界面偏好。

## 关键决定

- **Obsidian 式网状图：掌握层 + 来源层；主界面全图，课程里局部图**（10-03，你）。
- **跨课程合并：系统建议，你确认**（10-03，你）。
- **绘制用 sigma.js**（10-03，阶段 0 调研）。
- **关系允许课程或任务限定；老师先建课程粗图、按当前阶段的小节细化**（10-07，你同意调研建议）。
- **箭头从先学指向后学；同一时刻颜色只表示一件事；筛选只隐藏不重排；位置是本机的界面偏好**（10-07，Claude 按调研）。
- **合并保留被合并的节点和全部作答记录，learner 透过合并读证据并按课程分别计算；抽取结果直接作为一组可撤销的修改加入本课，关系一律是草案**（10-08，Claude 按调研）。
- **布局改用 d3-force 持续模拟，补拖动、悬停高亮、按连线数定大小、放大才写名称、七个滑杆和按阶段着色；局部图放进侧栏**（10-12 你的试用反馈"还没做到 Obsidian 的水平"，10-15 定方向，10-16 Claude 按[调研](research.md#15-图谱手感obsidian-和-logseq-的做法10-16)设计）：差在"手感"，绘制保留 sigma。放弃了 Logseq 新版的"算好再画、拖动时整片平移"和 graphology-layout-force（排不了大图）、有时限的 ForceAtlas2。

- **抽取不排队，写入时按当前的节点查重；旧身份读的时候解析，不改写引用；讲义关联由 knowledge 按主人整组替换**（11-04，Claude 按 11-02 审查的提案）：排队让整本书的抽取时间翻倍，老师和页面同时发起时仍会撞上；引用散在阶段、试卷、复盘和日志里，改写会破坏历史，撤销合并还要回滚；讲义直接删 knowledge 的表违反"每张表一个主人"。

## 已知限制与以后再做

- 合并建议只比较名称和别名，说法不同的同一项要靠老师提出或你发起；要不要用语义检索推荐（会调用付费的向量服务），等合并建议用起来再看。
- 旧骨架里已被几门课按名称共用的节点还不能拆分；拆分时要保留原证据，不复制掌握状态。
- 上千个节点的图散开后是一团，只能靠搜索、悬停和放大看，看不出整体结构（以后按课程或章节聚合）；同一对节点之间的多条关系画成重叠的直线（等真实课程里出现再定画法）。
- 任务限定的关系只能由服务和老师工具建，页面表单只建本课或全局关系；课程角色和全局停用有服务，页面只有退出、恢复本课和考试范围。
- 节点名称里的公式按原文显示。
