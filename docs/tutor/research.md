# 主老师做深调研

> 2026-10-09 · 对应 PLAN 中 `annotation + sidechat` 之后的 `tutor` · 状态：调研完成；推荐设计、契约补充与验收草案尚未实现。
> 依据：[总体计划](../PLAN.md)、[主老师现状](design.md)、[学习流程](../journey.md)、[契约](../stage0/contracts.md)、[侧边会话调研](../sidechat/research.md)，以及下文的一手研究、官方文档和开源代码。
> 范围：只调研主老师的教学动作、课程简报、会话衔接、交回通知、帮助记账、课时小结和修改提案。Claude 同时实现 textbook；本报告不修改其代码、文档、构建产物、锁文件、profile 或运行进程，也不验收其进行中的实现。

推荐按 **A 可靠接课与简报 → B 帮助、检查与课时收尾 → C 提案评估与受控应用** 做深。主老师根据真实状态教下一步，程序负责约束动作、保存依据和恢复失败；聊天里的“会了”“已完成”“已接受”不能代替业务记录。

## 1. 结论与取舍

| 问题 | 推荐项 | 依据和限制 |
|---|---|---|
| 主老师定位 | 一个教师角色；教学决策与业务动作分开 | 保留 DSH 会话和各单元服务，不增加 Agent 团队或另一套学习工作流 |
| 最少有效帮助 | 按卡点给可执行支持；无基础或反复同错时及时讲解 | 帮助等级描述实际给过什么，不是每两轮自动升级的阶梯 |
| 独立测试 | 主老师、侧边会话和所有相关工具使用同一动态政策 | 不能只限制侧边窗口；交卷、复核、测试条件转换仍归 assess |
| 帮助记账 | 关联实际回复、发生边界和可信对象，及时落账并能补账 | 不等小结或侧边总结；没有归因结果时不能默认“无帮助” |
| 课程简报 | 当前动作、必要事实、待处理事项常驻，详细内容按需读取 | 长上下文不证明能可靠遵循所有旧状态；总预算要计入工具和历史 |
| 交回主老师 | 持久待处理通知，加按状态对账；合并只是减少打扰 | DSH 的持久 inbox 不能补回尚未送入它的内存事件 |
| 会话衔接 | 保留每阶段一个会话，以持久事实构成阶段开场 | 阶段介绍是否完成不能只由内存 Set 判断 |
| 课时小结 | 程序给事实，老师解释；学习者汇报有原消息依据 | 完成课时不等于掌握；缺前置条件不得直接推进 |
| 修改提案 | core 保存；tutor 评估；所属单元检查、执行和撤销 | 接受不等于应用，失败不写“已应用”；大改仍由学习者确认 |
| 依赖与服务 | 复用 DSH、Node SQLite、zod 和现有模型角色 | 首轮不引入 LangGraph、另一套 ITS、自动记忆服务或新付费 API |

这些是应用建议。既有方向继续成立：只有独立作答能提供掌握证据、证据只追加、课程文件经 core 写入、侧边会话不能直接修改课程、一轮做深后统一试用。新增字段、状态和默认参数要在实施前明确，由实施者按已确认的开发约定取舍并记录；本报告不把建议写成已确认契约。

## 2. 当前骨架：已经有什么，缺什么

核对对象是 10-09 工作树中的 tutor、core、planner、契约、主老师预设及相关测试。下表是源码推导，不是运行验收；textbook 的并行实现不纳入判断。

| [planner/index.ts](../../packages/planner/src/index.ts) | 按业务状态给下一步，课堂骨架能推进 | actor 只有 teacher/learner；“已结课”“等后台”和“等学习者作答”有相同 actor，但应有不同唤醒行为；没有待检查/待提案优先级 |

## 3. 学习研究：支持什么，不支持什么

### 3.1 外层选择任务，内层帮助解决当前卡点

VanLehn 将辅导系统分为任务选择的外层循环与步骤反馈的内层循环。这提供了职责划分依据：planner 选下一件事，assess 保存作答与判断，learner 推算证据状态，tutor 负责解释、引导和反馈。可核对的是出版社摘要，作者站全文受访问限制，本报告不据此声称已读到所有实验细节。[The Behavior of Tutoring Systems（2006）](https://journals.sagepub.com/doi/10.3233/IRG-2006-16%283%2902)

**应用建议：** 主老师可以提出“先检查这一项”的教学请求，由 planner 与 assess 接到正式流程；不要在 tutor 写第二套长期复习、排课或掌握算法。一次只推进一个需要学习者行动的步骤，不等于一次只能调用一个工具：为同一个步骤读资料、检查备题、发布任务可以连续完成。

### 3.2 帮多少、何时讲，并无万能固定规则

Koedinger 与 Aleven 的综述把给信息与保留探索机会之间的平衡称为 assistance dilemma；最佳条件与参数仍是开放问题。出版社摘要支持“要权衡帮助”，不支持固定的三次反问或按失败次数自动升级。[Exploring the Assistance Dilemma（2007）](https://link.springer.com/article/10.1007/s10648-007-9049-0)

Renkl 等研究逐步撤掉示例中的解答步骤。公开摘要报告了对学习过程的研究，同时没有找到其假设的自我解释增多效应；不能简化成“少讲一定使学习者主动推理”。本次未取得付费全文。[How Fading Worked Solution Steps Works（2004）](https://link.springer.com/article/10.1023/B%3ATRUC.0000021815.74806.f6)

**应用建议：** 已有解题方向时给一句具体提示；缺背景时示范起点；同错反复时解释条件或误区；进展恢复后把下一步留给学习者。普通学习允许主动请求完整讲解，之后换一题撤掉帮助验证。不给求助设置“先证明努力”的硬门槛。

### 3.3 正确反馈需要指向目标、现状和下一步

Hattie 与 Timperley 的反馈综述区分任务、过程、自我调节与个人层面的反馈，并围绕目标、当前进展与后续动作组织反馈。泛泛表扬不承担具体纠错作用；综述不能给本产品的聊天长度或即时反馈频率定最佳常量。[The Power of Feedback（2007，大学托管全文）](https://educacion.udd.cl/files/2018/04/The-Power-of-Feedback.pdf)

**应用建议：** 小结说明“在哪道新题、什么条件下做到什么”“用了什么帮助”“还缺哪项验证”“下一节先处理什么”。不只写“表现很好、继续加油”，也不把一次正确扩大成已经稳定掌握。老师可以评价一次任务表现，持久掌握状态仍归 learner。

### 3.4 有工具表现与撤掉工具后的表现必须分开

Bastani 等在近千名高中数学学习者中比较普通 GPT-4 帮助、受约束 tutor 与对照。普通帮助提高练习表现，但撤去工具后的独立考试平均表现下降；受约束 tutor 的负面效应基本被消除，独立考试相对对照的提升不显著。受约束版本还给模型教师写的解答与常见错误，并非只加一句“苏格拉底式教学”；研究主要测即时结果。[Generative AI Without Guardrails Can Harm Learning（2025，作者全文）](https://hamsabastani.github.io/education_llm.pdf)

**应用建议：** 帮助不是扣分，但必须记清；回答看起来正确仍要看是否独立、新题、符合测试条件。不能把“要求永不透露答案”整套搬来，覆盖本项目已确认的可请求完整讲解方向。

### 3.5 正面试验里的教学结构不能省略

Kestin 等对 194 名大学物理学生的两个课题进行随机交叉比较，AI 教学条件的即时后测优于课堂主动学习。论文说明，仅靠系统提示不能可靠安排多部分问题的顺序，平台于是逐部分引导，并给模型详细参考解答。比较同时涉及在家自定节奏和课堂环境，未证明任意模型聊天或长期整门课程都有同等收益。[AI tutoring outperforms in-class active learning（2025，全文）](https://www.nature.com/articles/s41598-025-97652-6.pdf)

**应用建议：** 用业务状态约束推进顺序，给可核验解答与资料，不靠老师“记得流程”。对话外层已是本项目的任务系统，无需照搬该平台界面。

Tutor CoPilot v2 的随机试验让真人教师获得 AI 建议，退出小测通过率约增加 4 个百分点；它是教师使用建议的混合系统。引导问题增多和直接给答案减少的分析，也不能单独证明其中一种语言动作造成了全部收益。[Tutor CoPilot（2025-01 v2）](https://arxiv.org/html/2410.03017v2)

**应用建议：** 把“识别卡点、给可行动支持、保留下一步推理”作为评审维度，不能用 CoPilot 的结果声称本产品自主主老师已经有效。

### 3.6 2026 年新证据仍需保留外推边界

StudentBench 2026-09 v1 报告 2383 名英语成人的一小时 GRE 辅导，合并 AI 组与真人组的即时学习增益通过其设定的等效检验。作者明确未测数月保持、未测中文或不同部署环境，也没有单独的只练习 GRE 题对照。它是预印本，不能作为本项目的模型排名、费用承诺或化工教学效果结论。[StudentBench（2026-09-23 v1）](https://arxiv.org/html/2609.28470v1)

**应用建议：** 学习收益用无帮助新题验证，并把即时、延迟保持和迁移分开。速度、对话数量、满意度与学习结果分别记录；“更快回复与更多参与相关”不能变成“更快必然学得更好”。

Aleven 等的求助模型分析同样明确提醒：提示点击与学习结果的关联不证明因果。[Toward Meta-Cognitive Tutoring（2006，作者全文）](https://pact.cs.cmu.edu/koedinger/pubs/Aleven_ea_IJAIED2006.pdf) 本产品不因求助多而惩罚，也不把求助少当掌握。批注、自我解释和侧边答疑的详细证据见[配套调研](../sidechat/research.md#3-真人研究能支持什么)，不在本报告重写其总结与锚点方案。

## 5. 最小职责边界与教学动作

### 5.1 不复制别的单元的真相

| tutor 要完成的事 | 从谁读，交给谁做 |
|---|---|
| 知道下一步、是否应自动继续 | planner 的结构化结果；当前只是 NextStep，后续补充唤醒语义 |
| 知道做到哪、有什么待确认 | goal/curriculum 的当前版本和状态，汇总经 course-brief |
| 解释一次表现 | assess 的作答/复核结果、learner 的证据说明；不自行改分或写掌握状态 |
| 讲解 | library 的有效资料，必要时检索、读小节；计算走 assess 的受限 calculate |
| 给帮助和发现误解 | 保存原回复/原话依据，经 core 追加 help/signal；检查题由 assess 练习池产生 |
| 写小结 | tutor 管课时记录的教学部分；完成课时/任务经 curriculum；文件经 core |
| 处理修改 | tutor 评估，core 管提案，目标、路线、教材、图谱、题目各由主人执行 |

一般读后闲聊、批注以及“我会了”不证明掌握。学习者在正式测试页外给出解题步骤，可以作为待检查材料或普通练习；需要形成作答证据时走 assess 的正规保存/判分入口，不能由 tutor 直接追加一条 `attempt.graded`。

### 5.2 教学动作依据真实情境选择

| 情境 | 推荐动作 | 后续验证 |
|---|---|---|
| 有进展，没有求助 | 等待，不因静默时间猜测卡住 | 页面完成或学习者消息到来再推进 |
| 方向对但遗漏适用条件 | 指出相关条件，给一个能继续的提示 | 用户续写下一步；关联该次帮助 |
| 不知道从哪里开始 | 拆出已知/未知，示范一个局部起点 | 留下一小步给用户，不连续逼问 |
| 同一错误反复出现 | 直接讲清概念差异、适用条件，必要时用对照例子 | 另发同类新题，撤掉帮助 |
| 明确要求完整讲解 | 普通学习允许，说明这次用了讲解 | 记完整解答/答案暴露；原题不作独立新题 |
| 说“我会了” | 记录陈述，短题验证 | 检查请求关联陈述；通过与否来自 assess |
| 说了可能错误的观点 | 看原话是否引用、假设、否定或已经改口 | 候选误解有依据；检查结果回来后再解释 |
| 质疑题目/教材 | 查原件、条件与计算，承认老师也可能出错 | 题目走 assess 报错/申诉；教材走提案 |
| 正在独立测试 | 只给允许的操作说明；概念帮助先按 assess 政策转换条件或离开测试 | 旧测试条件和已暴露帮助保留，不能暗中换成练习 |

完整帮助不能只按“是否出现最后一个数值”分类。步骤、公式变形、关键条件甚至答案选项的排除，都可能已经提供解决当前题的必要信息。分类是教学判断，题池、课程归属、确认权限和独立测试边界是程序约束。

## 6. 简报与会话衔接

### 6.1 当前事实在前，细节可以取得

推荐常驻四组内容：当前阶段/课时及版本；planner 下一步和需要谁行动；本步所需的目标与证据；待复核、待检查、待提案及失败事项。资料目录、全图、全部旧测试与侧边全文只给数量、主题和可读取入口。

各单元继续提供自己的 BriefSection。tutor 只排序、预算、标记来源与形成快照，不解析业务正文来猜测试是否可交、路线是否已确认。缺关键事实时明确缺少哪一节，不把它当成空状态继续做修改；非关键节失败可以降级为带原因的简报。

详细内容必须有真实可用的取法。现有 read_section、get_test_result、read_lesson_textbook、get_knowledge_node 可以复用；提案详情、帮助依据等新入口尚未存在，应和实现一起补，不在简报里写一个模型无法调用的工具名。

总输入预算包括 persona、完整工具 schema、简报、当前消息、历史和结果，还要为思考及输出预留空间。优先保留当前政策、版本、未完成事项与事实出处；整行/完整小单元截取，保留公式条件和取更多信息的方法，不能硬截成无意义半句。具体字符或 token 默认值由合成请求测量后决定。

长上下文研究在多文档问答和键值检索中观察到位置影响，提供了测试“关键事实放前、中、后”的理由；它没有验证本项目的当前 DeepSeek 版本，也不能证明固定首尾布局必然最好。[Lost in the Middle（TACL 2024）](https://aclanthology.org/2024.tacl-1.9/)

### 6.2 缓存不是“模型已经看到”的证明

`lastBrief` 可以保留为优化，但缓存键应包括会话生命周期/压缩边界和状态版本；消息真正进入持久请求后才确认已注入。取消、首轮构造失败、压缩与重启均要重新核对。首批宁可注入一份较小的当前快照，也不因旧的内存比较漏掉进度。

同一轮工具执行可能改变课程状态。完整简报不必每个工具步骤重塞，但执行修改工具时必须读取最新版本、归属和政策；在需要决定后续动作的步骤补一次精简状态。每轮开始的快照无法保证整轮内永远最新。

### 6.3 阶段开场与旧会话分开

保留开课会话与每阶段会话。新阶段的开场从当前目标、设计、上一阶段复盘、风险与待验证节点、待处理事项生成；不复制上一阶段的完整聊天，也不再调用模型另存一份无依据的“永久记忆”。历史会话可读，写入动作需核对当前阶段，避免旧会话继续发布过期任务。

“介绍过这个阶段”用持久消息或明确的开场记录识别，失败不消耗标记。建会话按“登记意图 → DSH 创建 → 配置模型 → 标为可用”恢复；继续前核对 DSH 确实存在。先登记归属的已有方向保留，不以修复失败为由制造孤儿会话。

## 7. 交回通知：先有可靠事实，再决定是否说话

### 7.1 本机 DSH 0.2.0-rc.2 能支持的边界

已查本机 `dsh-agent/lib/types/runtime-types.d.ts`、`dsh-session/lib/types/types.d.ts`、`dsh-api-session-controller/lib/types/history.d.ts`、`dsh-llm/lib/types/message.d.ts`：

- `followup` 进入下一轮并唤醒；`inject` 不唤醒，运行中可能在后续 step 被领取，不等于仅下一轮看到。
- `agent/pre-step` 可拒绝或替换消息；`agent/status` 表示 idle/running；`whenIdle` 等全 Agent 静止，不代表某个通知已处理。
- Session 有持久事件和 seq；history 可冷读分页，follow 可按游标接事件，不必为查历史激活 Agent。
- `agent/assistant-stream` 的 chunk 是进程内发布，提交的 end 关联 `assistant/message` 或 `assistant/attempt`；abandoned 不能当完整回复。不能凭名字把失败片段过滤掉。
- `createUserMessage` 创建新身份，接口明确不接受自填 id。需要重投同一消息时应保存其完整身份，或用 source 中的稳定通知键对账；不能每次新建随机消息就声称有投递幂等。

初稿核到类型与静态行为声明；复查进一步沿运行源码追到了队列领取、取消、持久化和回复提交，见 §7.5。仍未实测事件落盘、清理、压缩及故障恢复的全部路径；不能以源码阅读或 harness 假 inbox 代替真实 DSH 恢复实验。

### 7.2 两道恢复边界

第一道在业务单元：操作已经提交，但发通知前进程退出。tutor 的持久收件箱也收不到尚未发来的事实。关键完成动作需要主人保存可重放的通知意图，或让 tutor/planner 根据当前状态与处理游标对账。不要让 tutor 重建业务结果。

第二道在 tutor：已经收到通知，但尚未送给 DSH。推荐先保存事件身份、课程、事实引用/版本、收到时间和投递状态，再启动合并计时器。1.5 秒继续作为交互合并窗口，不能兼任可靠队列。

事件键对应一次真实业务操作；两次同文操作保留两份事实，一次事件重放只处理一次。合并后的可读通知保留原事件集合，课程之间独立。投递失败、进程退出或 DSH 被取消时，待处理状态可见并可重试。

### 7.3 送入 DSH 不等于教学动作已完成

推荐区别“持久收到”“已排入会话”“被该轮领取”“需要的动作已完成/不需动作”。DSH inbox 与 learning.db 是两个持久边界，不能声称天然跨库恰好一次。采用可重投加对账，真正的 publish_task、写小结和应用提案在主人服务按操作身份和版本拒绝重复。

重投前读 DSH 的消息来源/身份与 seq；已经领取但没有完成业务动作时，从当前课程状态恢复下一步，不能再做一次已成功动作。保留有限重试和具体原因，不能遇到异常便无限唤醒老师。

### 7.4 唤醒政策保持归属

最终是否轮到老师仍按 planner。推荐给 NextStep 补稳定的动作键及可自动继续/应等待/终态的语义，而不是 tutor 用 title 的中文字符串分支。通知到达、排队后开始、执行修改前，都核对当前事实；旧阶段通知仍可作历史事实，不能在新阶段重新发布旧任务。

老师正在对话时通常把通知排在后面，不抢占用户输入。用户明确“先停、今天到这里”时，保存课程级的自动继续暂停状态；后台结果照常保存，待用户回来再继续。取消一次生成与暂停自动教学是两件事，应以明确操作区分。没有该状态前，不声称系统已经尊重所有停止场景。

主老师自己调用工具的动作不发 handoff；页面完成和后台完成继续由主人发。不新增各单元直接给老师发消息的旁路。

### 7.5 运行源码复查：哪些“成功”不能当完成

以下沿本机锁定版本的实际 JavaScript 追踪，不是从接口名猜行为。`.tools` 不进 Git，接续机器须在同版本重查；本轮没有改、加载或执行这些模块。

| 运行入口与路径 | 已核对的执行顺序 | 对推荐方案的修正与硬验收 |
|---|---|---|
| [ReactLoopAgent.send/followup/inject/cancel](../../.tools/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js) | followup → next-turn 且 wake；inject → next-step 不 wake。cancel 默认清空两组 pending，再终止活动；keepInbox 才保留 | “已入队”以后仍可能被取消。恢复要区分用户主动停止与投递故障，不能把用户取消的教学动作自动重投；取消事件不删除原业务完成事实 |
| 同文件 `ReactLoopInbox.claim/preStep/turn` | claim 先追加移除 pending 的 splice 并发布 claimed，然后组装上下文、执行 pre-step；reject 结束为 blocked，没有在该分支自动放回消息 | claimed 不证明 user/message 已保存，更不证明已调用模型。验收须覆盖“领取后拒绝/取消/上下文构造失败”，由事实及处理记录恢复，不能只查 inbox 是否为空 |
| 同文件 `ReactLoopInbox.mutate/inboxProjectionDefinition` | 检查两组当前 pending 的消息 ID 是否重复；新 splice 经 session.append 保存。检查对象是当前 pending | 稳定 ID 可避免同时重复入队，但这段代码不提供全部历史业务操作恰好一次。已经领取或已执行后重投，仍靠操作身份与结果对账；不能把重复 ID 的异常直接当作业务已成功 |
| 同文件 `ReactLoopAgent.step`，及 [checkpoint policy](../../.tools/dsh/node_modules/@deepseek-ai/dsh-session-checkpoint-policy/lib/index.js) | decision.messages 到 step 才追加 user/message；checkpoint policy 在模型 stream 与顶层工具执行前 flush。模型调用前还可能出错 | pre-step 中更新 lastBrief 早于实际输入提交的问题确实存在。区分简报构造、消息提交、请求可用；运行验收还须确认本 profile 实际加载了 checkpoint policy |
| [SessionStore.flush](../../.tools/dsh/node_modules/@deepseek-ai/dsh-session/lib/index.js) 与 [JSONL install](../../.tools/dsh/node_modules/@deepseek-ai/dsh-session-persistence-jsonl/lib/index.js) | flush 等所有 listener，失败会抛出；无 listener 时返回 false。JSONL listener 有 writer 才 drainLive/flush，没有 writer 会直接返回 | Promise resolved 不能单独证明落盘，返回 true 也只证明有 listener。可靠通知验收必须确认持久化后端和该会话写句柄有效，并重启冷读核对；tutor 目前没有检查这些条件 |
| [SessionHistory.follow](../../.tools/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/types/history.js) | 监听 session/event，按 seq 发送后续事件；stream frame 是另一类无持久 seq 的更新。JSONL 在 session/event 先排入缓冲 | 实时收到事件或拿到 seq，不等于这次事件已完成磁盘 checkpoint。投递确认不能直接用浏览器订阅回执或 live follow 代替 flush/冷读 |
| `ReactLoopAgent.step` 的异常结算 | 取消且已有输出时可保存 interrupted 的 assistant/message；一般 stream 异常结算 assistant/attempt，不能依赖它保留完整可见正文 | 帮助不能只监听“正常完整回复”。已发出的教学片段要有生产者补账依据；只记录面向学习者的正文，不以模型内部思考、未展示工具参数或 reasoning 块认定提供了帮助 |

## 8. 帮助、检查与课时收尾

### 8.1 帮助与回复同步，总结只汇总

复用既有 help.given 的四档等级、problemId、LogContext 和 NewLogEntry.at。对象优先来自题目/课时/选择的可信关联，不让模型任意编节点；归因不了时保留待核实，不能把整门课所有节点都标为受帮助。

主老师也有自然语言直接讲解，单设“记帮助”工具不保证每次都会调用。推荐在回复生命周期中捕获待归因内容，以可信上下文和实际文本补账；显式工具元数据可降低歧义，但仍要覆盖绕过工具、出错和截断的回复。普通操作说明不产生概念帮助。

帮助记录与会话、attemptId/消息 seq、帮助项关联，重复监听不重复追加。完整消息的提交证明内容可被提供，不证明用户看懂；隐藏面板、取消前已发出片段与实际可见性沿用[sidechat 对暴露边界的建议](../sidechat/research.md#7-帮助总结和结束恢复)。首批可用保守的“已提供”规则，但不能宣传成“已阅读”。

共同依赖必须解决：assess 保存异步判分前的答案版本与提交时间；learner 比较帮助与该答案锁定边界。只修主老师及时记账，仍不能验收“交卷之后才获得讲解不会影响之前的独立作答”。core/learner 的待归因与更正契约也要一起定；模型分类失败不等于无帮助。

### 8.2 自报、疑似误解和检查是有去向的事项

signal 记录真实原话及来源消息，不从注入简报、老师的话或引用中的错误观点产生学习者误解。检测到“我会了”或候选误解时，形成一项有身份的检查请求：对应节点、原始依据、提出时间、尚未检查/已关联测试/已有结果。这个请求是待办，不是第二份掌握记录。

同一个未处理原句重复消费不重复出题；学习者否定、改口或已纠正时追加澄清依据，不删旧证据。当前测试尚未结束时先遵守独立性政策，不能因误解信号插入带答案的即时教学。

检查题只用 practice 池，不占测试预留题。帮助过的原题和同一原型的简单换数需要考虑见过/关联关系；第一批至少排除原题，更严的同构污染由 assess 明确规则。没有可信题源时说明暂时不能验证并请老师补题，不用模型随手答一道题就当独立证据。

谁保存检查请求、如何加入 planner 的下一步，应在实施前形成小契约。推荐 tutor 保存请求依据，assess 管题及结果，planner 管排入当前步骤，learner 管结果如何影响状态；避免 tutor 自己排一条隐形任务链。

### 8.3 小结事实由程序生成，解释由老师写

保存前核对：teacher 角色、课程/阶段/课时归属、当前课时；有效小测已判完，待复核与相关申诉处理状态；真实学习者汇报或明确选择“暂不汇报”；正文非空及学习者可见格式。选择省略汇报需要一个显式入口与记录，不能让模型伪造，默认节奏仍是汇报再小结。

事实包括本课时有效测试、按节点的结果、作答条件、帮助、尚缺依据。正文用中文名称和题号，不放 ts_/kn_ 内部编号；元数据可以保留 ID。老师写的段落要和这些事实一致，不能把有帮助完成说成独立掌握。

小结存盘成功后才完成课时与对应任务。Markdown 写入与数据库状态不是天然同一事务，应保存可恢复操作身份、内容版本和完成进度，重启后补后一步；写失败时课时不应完成。重复保存同一操作不重复变更，主动修订小结生成新版本。课时完成以后重新改分或更正帮助，展示事实版本已更新；不能保留误导性的旧结论却静默当最新。

本批默认保持既有“阅读 → 小测 → 汇报 → 小结”流程。小测较弱时插入短练习/检查，课时可以完成而节点仍有缺口；阶段是否补课仍按 curriculum 复盘，不由 tutor 拒绝记课时或自动加阶段。预测题作为可选教学动作，先不新增一套小节考试。

## 9. 提案：评估、确认、应用各有证据

### 9.1 不建立第二套修改入口

批注和 sidechat 负责保留原始定位、草稿、用户提交与来源消息；core 保存正式 Proposal；tutor 收件、评估并组织后续；主人服务检查目标、版本、内容约束并执行。侧边总结是线索，不把里面一句建议等同学习者批准。

来源相同的重复提交应返回原提案；原始位置、引用和对象版本可以追溯。已有 accepted/rejected/applied/withdrawn 状态继续区分。需要评估中、等确认、应用中、失败等过程信息时优先增加有归属的执行记录，不把所有临时阶段塞进 ProposalStatus，影响每个消费者。

评估记录至少说明改什么、原文/原状态是什么、为什么、来源是否足够、影响哪些对象、是否需要确认、哪些部分暂不能执行。模型只建议，程序决定权限与状态转换。

### 9.2 小改动按语义影响判断

| 目标 | 可以按既有“小改直接应用”原则考虑 | 必须走已有确认或更严格路径 |
|---|---|---|
| 教材 | 有明确原件依据的文字笔误、出处定位纠正，且没有改变含义 | 公式正负号、单位、成立条件、推导或块拆合：可能影响作答/批注；不能按字符少判小改。具体修订能力由 textbook 提供 |
| 目标 | goal 允许的事实修订，保留来源与待确认标记 | 改目的、程度、能做等选择回到草稿，请学习者确认 |
| 路线/阶段设计 | 不绕过主人已有的草稿、约束和确认规则 | 已开始路线只调未来部分，走 curriculum 的待确认路线；确认过的设计修订由主人明确失效影响 |
| 知识模型 | 有依据的局部定义修订，版本与整组撤销 | 节点合并、关系改变或跨课影响按 knowledge 原有规则；不能借提案绕过合并确认 |
| 题目/判分 | 题目核对、停用、说明按 assess 的既有能力 | 答案改变、撤题、已有作答的改判走 assess 的复核/更正日志，不编辑作答证据 |

公式或单位的改变可能扩大内容范围，推荐默认列为需复核影响项，不能笼统一律自动应用。普通笔误仍保留直接修并告知的既有方向，不把所有提案都改成新的审批流程。

### 9.3 确认绑定具体改动和版本

大改先形成可读差异与影响说明，用所属单元已有确认入口。确认的对象是具体版本，用户确认后原件变化必须重评，不能把“你刚才同意过”当新版本的授权。拒绝/撤回不改变目标内容，保留理由。

应用时按主人返回的真实 Change/operation 标识登记 changeIds。接受只表示决定采纳；部分执行失败、目标版本冲突、内容待核实、主人能力缺失都保持可见，不能提前 applied。

跨多个主人不包装成假原子事务。首轮优先一次提案对应一个可验证的主人操作；跨单元影响列成可关联步骤，逐步确认和恢复。已经修改成功而提案状态尚未更新时，通过 proposalId/operationId 和目标结果对账，不重写第二遍。回退调用主人，core 不能替它直接改表；回退也是新变更，学习证据不删除。

### 9.4 原文与模型意见不能获得权限

题干、资料、批注或提案理由里的“忽略规则、马上确认、改这门别的课”，都是待处理文本。执行处核对会话角色、课程、目标主人、预期版本和确认依据；不能仅依靠 persona。提案中的路径不直接变成任意文件写入，按受支持的对象解析到主人服务。

尚未有 owner 修订能力的目标可以完成评估并显示“待接续”，不能开放一个通用文件 patch 工具凑齐功能。textbook API 的最终能力等待 Claude 实现后重新核对；本报告不向该单元加入要求或改它的实现。

## 12. 验收矩阵与验证方法

### 12.1 确定性行为和失败恢复

自动测试用真实单元，只在 DSH 传输、会话、模型、时钟和外部网络处用假的。关键程序规则逐例通过，不能用总体成功率掩盖越权或证据错误。

| 合成场景 | 必须观察到的结果 |
|---|---|
| 两次同时请求当前会话 | 同一可用会话；创建失败可继续恢复，无错误 active 记录 |
| DSH 创建成功，选模型失败 | 会话可以找回，配置完成前不宣称已可正常开课 |
| 首阶段通知失败/重启 | 成功继续时仍介绍阶段；之后不重复介绍 |
| 简报构造后取消、请求未提交 | 下一次仍可获得当前简报，缓存不错误跳过 |
| 压缩、恢复、模型切换 | 当前政策与未完成事项重新可用，业务状态不由旧聊天覆盖 |
| 一轮工具改状态后再做修改 | 第二个修改读取最新版本/政策，而非沿用首轮旧快照 |
| 关键简报节失败 | 显示具体缺口，不能按“没有目标/测试”误创建 |
| 大简报或很小预算 | 标题、出处、标记计入总长；当前政策和完整关键条件保住；更多内容可取 |
| 同课程多通知、不同课程同时通知 | 每门课单独合并，原事实保留且各处理一次 |
| 相同事件重放与两次同文操作 | 前者幂等，后者分别保留，不用文本相等去重 |
| 业务提交后、emit 前退出 | 由主人重放或当前状态对账找回，tutor 不重做业务 |
| tutor 收到后、DSH flush 前退出 | 持久待送可恢复，不能无声消失 |
| DSH 已领取，业务动作成功，确认前退出 | 对账成功结果，不重复发布任务、写小结或应用提案 |
| 排队后进入另一阶段/已结课 | 旧通知仅作事实；按当前下一步行动，不开旧任务 |
| 用户正在发消息、主动暂停、后台完成 | 用户意图保持，暂停时不自动开课；结果和待办仍保存 |
| 普通讲解、操作说明、完整答案 | 分别记录实际帮助或不记概念帮助；关联可信对象 |
| 讲解后马上作答，永不写小结 | 帮助已到账，独立性不依赖小结/close |
| 答案锁定后才讲解，判分很慢 | 之前的答案不被后得帮助回溯污染 |
| 已显示片段后取消/断线 | 保留提供依据并补账；不只认成功完整消息 |
| 帮助分类失败/重启、之后补账 | 待核实可见，不能默认独立；补账后重算一致 |
| 否定、引用、假设、改口、老师自己的误解 | 不产生错误学习者信号；保留原话/澄清与说话人 |
| 同一“我会了”重放 | 一个检查请求，practice 新题，结果回接原请求 |
| 主老师或旧侧边会话讨论未交卷试题 | 同一 assess 政策；工具和模型回复路径都不能静默破坏独立条件 |
| 小结无小测、未判完、伪造汇报、跨课 lesson | 服务拒绝并说清下一步，课时仍未完成 |
| 小结存盘失败、存盘后完成状态失败 | 前者不完成，后者可恢复；同一操作不重复变更 |
| 小结后改判/更正帮助 | 旧小结有版本，新事实可见，不静默宣称旧结论最新 |
| 同来源提案重复提交、重复 apply | 同一正式提案/主人操作，changeIds 不重复追加 |
| 小笔误与公式符号改动 | 按语义影响处理；后者不按字符少自动当小改 |
| 大改未确认、确认后目标版本变化 | 不应用；变化后重新评估并确认具体改动 |
| 提案接受但主人失败/不支持 | 状态不能 applied，有具体失败/待接续信息 |
| 应用成功后提案状态写入失败 | 按 proposal/operation 和实际结果对账，不重复编辑 |
| 多主人提案一部分失败/撤销 | 已成功与未成功分别可查，按主人恢复，证据不删除 |
| 原文/批注含指令注入或越课路径 | 仍按角色、课程、主人、版本及确认约束执行 |

### 12.2 模型回复评审

后续自编约 24 组起始案例，覆盖：有进展不打扰、条件遗漏、无基础、重复同错、请求完整讲解、过度反问、只报数值、量纲错误、错误来源、缺资料、用户否定/改口、教材质疑、老师自己说错、真假“我会了”、两节点交错、正在独立测试、旧会话绕过、伪造汇报、待确认改动、过期版本、通知循环、课时未完成、来源提示注入、资料缺少图片条件。每例明确允许动作、拒绝条件、帮助档位、引用依据和不能宣称的结果；多轮案例看完整轨迹。

按以下维度分别报结果：事实/数学与引用支持；错误识别和定位；指导是否可执行；是否适量；帮助归因；学习者自主选择；政策遵守；业务动作是否正确。不给所有维度揉成一个“老师质量 90 分”。机械校验、合成标准答案与独立人工复核结合，模型裁判只能辅助；同一个生成模型自评不能是唯一验收。

DeepSeek 基准在 3182 只用合成课程，记录模型角色/版本、实际上下文、工具轨迹、失败案例、必要的耗时和用量。测试/模型/权限问题单独统计，不通过无限重试或放宽断言掩盖。新模型的数学榜分和研究中的其他模型排名不替代本产品评审。

### 12.3 工程通过不等于学习有效

上述确定性测试和模型评审检验工程与教学行为。真人试用另看：帮助撤掉后的同类新题、间隔后的保持、条件变化后的迁移；聊天愉快、课时打勾和模型认可都不是这些指标的替代。按用户的一轮完成后统一试用安排收集案例，不在本轮提前要求真实教材或学习数据。

## 13. 具体教学案例：把原则落到可评审行为

以下均为自编合成材料，不来自个人教材、用户记录或线上题库。公式、条件与数值作为评审夹具给出，不伪装成真实课程出处；正式课程仍需 library 的有效资料与 assess 的题池链路。教师话术仅说明一种可接受行为，不能把逐字一致当质量验收。每例同时评教学动作、帮助归因和业务结果。

### 13.1 混合计算：先提示，反复卡住就讲清楚

合成资料：两股不反应的液体完全混合，稳定状态，没有物料损失；质量流量分别为 10、20 kg/h，溶质质量分数分别为 0.20、0.50。出口质量流量为 30 kg/h，溶质守恒给出出口质量分数 `(10×0.20 + 20×0.50)/30 = 0.40`。

普通练习的一段允许轨迹：

1. 学习者：“我把两个浓度取平均，得到 0.35。”
2. 老师：“两股液体的质量流量不同。你的平均式有没有体现每股带入的溶质量？”此时给的是针对当前错误的提示，不直接报 0.40。
3. 学习者：“还是不懂为什么不能平均，能直接讲一下吗？”
4. 老师：“第一股每小时带入 2 kg 溶质，第二股带入 10 kg；混合后每小时共有 30 kg 液体，其中 12 kg 是溶质，所以质量分数为 0.40。直接平均隐含了两股质量流量相等，这里不成立。”

第二次求助后应解释，不再逼问“你自己再想想”。这次包含完整解答，应关联原题和两次帮助，不能只记最后一次“提示”。原题改对不能算新的独立证据。

之后的评审用新题：同样条件下，12 kg/h、0.10 与 18 kg/h、0.40 混合，参考结果为 0.28。题目仍由 assess 练习池提供；本报告的纸面例子不直接写成学习证据。是否过于接近原题，按 assess 的见过/同构规则判断；通过一道新题也只证明这次对应能力，不外推到反应、挥发或非稳定系统。

### 13.2 单位错误：纠正当前错误，不替学习者包办后半题

合成资料：`Re = ρvD/μ`，给 `ρ=1000 kg/m³`、`v=0.10 m/s`、`D=0.010 m`、`μ=2.0 mPa·s`。统一到 SI 单位后 `μ=0.0020 Pa·s`，参考 `Re=500`。

学习者在普通练习中写：“代进去 1000×0.10×0.010/2，得到 0.5。”一种允许回复是：“先核对黏度：题目写的是 mPa·s，公式里其他量用了 SI 单位。把它换成 Pa·s 后再算一次。”这已提供了当前题需要的单位线索，记为提示；不是“我没说答案就没有帮助”。

若学习者自己换算并得到 500，可以肯定这次单位与计算正确，不额外灌入压降、摩阻系数或流态结论。若其仍把 milli 当成 10³，就解释前缀并示范换算，帮助升级为讲解；只有继续展开到完整题目解答时才归完整解答。等级取决于实际内容，不按回复次数升级。

### 13.3 同一问题在独立测试中，允许动作不同

沿用 13.2 数值，但当前是未交卷的独立测试。学习者问：“这个黏度怎么换算？”老师此时不能复用上例的换算提示，那会提供当前题的关键帮助。

允许回复只说明选择：“这次是独立测试。你可以按现有条件先提交；如果想现在学习换算，我们先按测试允许的流程处理这次作答条件，再讲解。”具体退出、转换或提交能力以 assess 实际提供的入口为准；没有转换能力就不能口头承诺“已经切成练习”。

处理成功前不给换算信息；处理失败说明原因并等待。若帮助已经泄露，保存实际提供事实，由 assess/learner 按条件处理；不能删除聊天或漏记帮助来保留“独立”标签。程序拒绝不合规工具调用和回复是否泄露应分开验收，不能把前者通过当后者也通过。

### 13.4 学习者自述：先认清句子的意思

| 学习者原话 | 允许处理 | 不应发生 |
|---|---|---|
| “这类混合题我已经会了，换一题吧。” | 关联原话形成快速检查请求，由 assess 选练习新题；请求重放不重复出题 | 直接提高掌握、跳过正式证据 |
| “我不是说我会了，我只是背出了这个式子。” | 承认区别，问或查他不理解的量/条件；必要时针对性解释 | 关键词匹配“会了”就触发自报通过，或自动断言某个具体误解 |
| “书里举的错误解法是直接平均，我知道它只在等流量条件下成立。” | 看引用与条件；没有其他矛盾时不判成学习者仍持有直接平均误解 | 把被引用的错误解法当成学习者观点 |

上述三句可以作为模型归因的对照组：对象、说话人、否定和时态变化，输出应不同。检查未通过时解释实际缺口；不会因“之前说过会”训斥或降低求助意愿。

### 13.5 小结：有帮助做完，与后来独立做对分开说

合成事实：原混合题通过完整讲解完成；随后另一道题独立做对；第三题的单位换算仍需提示；学习者真实汇报“现在知道要按溶质量算，但单位还会弄混”。这些事实均须有原题、作答条件、帮助和原消息引用，不能由小结模型补造。

一种合格小结：“你在另一道无帮助的新题中正确列出了混合物的溶质守恒式；原题是在完整讲解后完成的。单位换算仍需要提示，暂时不能说已经独立处理稳定。下一次先用一道带不同单位的短题检查这一点。”这里不把教学建议写成已经发布的任务，也不把混合成功扩成所有物料衡算已掌握。

反例：“本节全部掌握，可以放心进入下一章。”它隐去了帮助和缺口，也越过 learner/curriculum 的归属。

再加时间对照：作答 A 在 T0 锁定答案，老师 T1 才讲解，T2 才完成异步判分，且 `T0<T1<T2`。帮助不应回溯污染 A 的已锁定答案；对 T1 之后提交的相关作答仍要检查影响。不能一律按判分落日志的时间判断。门控看有效测试、处理状态与真实汇报，小结写盘失败不完成课时。

### 13.6 一字之差也可能是实质修订

合成教材在“两股流量分别为 10、20 kg/h”的例子里误写 `x=(x₁+x₂)/2`，学习者要求改为按质量流量加权。这不是标点或排版修正：它改变解法、答案和成立条件，可能影响已经做过的题及已有解释。

老师先展示待改表达式、依据和影响：等流量条件下的直接平均成立；当前例子应按溶质量与总质量流量求出口质量分数。按 §9 的推荐把它列为需复核影响的实质改动，不能因为替换的文字短就静默应用。存在已完成测试的相关影响时列出，交 assess 核对，不由 tutor 修改旧作答证据。

确认必须绑定所展示的教材版本。等待确认期间原件被主人改了，重新读当前版本、重评差异；既不能覆盖新版本，也不能让旧确认自动授权另一个改法。主人尚无受支持的修订入口时，保留评估与待接续状态，不用 core 通用文件写入绕过 textbook 的结构化校验。

以上六例把教学选择落成可比较的轨迹，但仍不证明真实模型会遵守、帮助分类准确或学习收益提高。进入实现前，先把这些案例与 §12 的失败矩阵转成该批验收；模型联调和后续真人试用再回答它们实际是否成立。
