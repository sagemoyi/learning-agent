# 主老师（tutor）

> 代码：[`packages/tutor`](../../packages/tutor)；老师的角色提示词在 [`packages/app/cordis.patch.yml`](../../packages/app/cordis.patch.yml) · 接口：[契约](../stage0/contracts.md) §5.1、§7 和 §11"协同修整""Agent" · 调研：[做深调研](research.md)（Claude 的复核见下文） · 做法：[提示词与工具说明技能](../../.agents/skills/learning-prompts-tools/SKILL.md)

主老师是你唯一的老师：开课、发布任务、决定给多少帮助、写课时小结、处理修改提案。各单元只是代码的分块方式，对你来说只有一个主老师，侧边会话是同一个老师的"课间答疑窗口"。

## 现状

- **做深（10-10）：** Claude 复核调研后分三批：A 可靠接课与简报、B 课堂记录与课时收尾、C 修改提案，三批都**已技术验收，待你试用**（设计和验收标准见下文各节，验证见[验证记录](../stage0/compatibility.md#tutor-ab可靠接课与课堂记录10-10claude)和 [C 的验证](../stage0/compatibility.md#annotation-与-sidechat-的复核和-tutor-c10-10claude)）。C 和 annotation 一起做：目前提案只来自教材批注里的报错。
- **骨架：**
  - **会话：** 开课时一个会话（目标、摸底、路线、第一阶段设计），之后每个阶段一个。阶段就绪后，第一条进度通知进入新的阶段会话，老师先介绍这个阶段。新建课程后老师自动开场，不用你先说话。
  - **课程简报：** 每轮对话前，把课程现状按"下一步 → 目标 → 资料 → 路线与任务 → 教材 → 测试 → 知识节点 → 掌握状态"的顺序拼好给老师，只在内容变化时注入。
  - **交回主老师：** 你在页面上做完一件事，或后台任务结束，负责的单元发一句话的通知；老师在当前会话里收到【进度通知】（1.5 秒内的几条合成一条）。下一步轮到老师时直接接着上课，否则只作为背景信息。老师自己调用工具做的事不发通知。
  - **课时记录：** 你的汇报和老师的小结写进课时记录，课时记为完成。
  - **工具：** 老师挂 7 个单元的工具（目标、资料库、知识模型、课程设计、教材、测试、主老师自己的：写课时小结、处理修改提案）。
  - **模型：** 设置页里的"主老师"角色；改了之后，正在进行的会话下一条消息就换过去。
- **对话里的卡片：** 某些工具调用成功后，对话里显示负责单元画的卡片（插槽 `learning.chat-card`，按工具名）。目前只有目标单元的候选终点卡片：你点"选这个"就发出一条消息，"改一改"把这句话放进输入框；你回复以后卡片标出所选项。调用被退回时不显示卡片（goal B）。
- **还没做：** 你在对话里直接提的大改（目标、路线）不经过提案，老师用各单元的工具存成草稿或待确认的调整；提案只来自教材报错和侧边提问交来的修改建议。

## 会话与课程状态

- **每个阶段一个主老师会话。** 新阶段开始时开一个新会话，把上一阶段的复盘结论和当前课程状态作为开场上下文带进去。
- 课程的真实状态始终保存在文件和数据库里，每一轮都从那里读取（"课程现状简报"），不依赖聊天记录来"记住"进度。
- 简报由各单元往同一个拼装事件里添自己的那部分（契约 §5.2 `learning/course-brief`），`tutor` 不需要认识其他单元。
- 是否唤醒老师由 `tutor` 按 [planner](../planner/design.md) 的下一步决定，其他单元不直接给老师会话发消息。

## 调研复核（10-10，Claude）

Codex 的[调研](research.md)对骨架的核对基本属实，下面这些问题都在代码里确认过：

- 老师从不记帮助：老师讲过的题，之后答对仍算独立完成；
- 简报是否注入靠内存里的上一份比较。DSH 默认开着上下文自动压缩，长的阶段会话被压缩后，简报可能已经不在模型眼前，但内容没变就不会再注入；重启后又会无谓地重发一遍；
- 待送的进度通知和"阶段第一次课"的标记只在内存里，投递失败就丢，正是第一次试用时"老师没反应"的那类问题；
- 开课会话在 DSH 建会话失败后，关联记录留下来，以后一直指向一个不存在的会话；
- 课时小结不查课时是不是这门课的、小测是否交卷判完、汇报是不是你说的；课时记录里还写了测试的内部编号。

**取舍：**
- **采纳：** 简报按已落盘的事件判断是否注入；通知存库、失败重试；老师的帮助及时记账，帮助时间取老师回复的时间；你的自述、提问和可能的误解要有原话；测试期间的规则写进简报；小结在执行处检查。
- **调研漏了的：** DSH 自带"会话投影"，它的时间提示插件就是这样判断上次注入过什么。用它判断简报是否还在模型眼前，比调研建议的"内存缓存加生命周期标记"简单可靠。
- **不采纳：**
  - 各单元保存可重放的通知、跨数据库的恰好一次投递；
  - 通用的提案状态机和执行记录、小结的操作编号和版本；
  - "暂停自动上课"、给"下一步"加动作键、24 组模型评审案例集。

  原因：这是你一个人在本机用，这些失败窗口都在毫秒级，或者现在没有使用方，成本大于收益。
- **C 和 annotation 一起做：** 做 A、B 时还没有任何地方产生提案，所以先不搭没有使用方的流程。annotation 做完后，提案的来源是教材批注里的报错，C 就按这个来源端到端做（见下文"修改提案（C）"）。你在对话里直接提的修改，老师照旧用各单元自己的工具改。

## 可靠接课与简报（A）

**简报只在模型看不到最新一份时注入：**
- 每轮第一步前照旧拼简报。会话里已落盘的上一份简报（DSH 会话投影）内容相同就不重复；上一份被上下文压缩掉了，或者上一轮在简报落盘前就取消了，就重新注入。重启不影响判断。
- 一轮里老师调用工具后，如果"下一步"变了（比如写完小结，下一步变成发布下一节的阅读任务），下一次调用模型前补一条一行的【下一步更新】。轮到老师的步骤可以接着做，轮到你时停下。

**进度通知不丢：**
- 收到的通知先存进数据库，再按课程合并（1.5 秒）送进老师当前的会话，送成功才标为已送。
- 送失败后，分别隔 2 秒、15 秒、1 分钟重试，三次都失败就放弃。简报的"下一步"仍会告诉老师进度，只是老师不会自动接着上课。
- DSH 重启后，12 小时内没送出的通知重新送。
- 是否唤醒老师仍按送出那一刻的"下一步"。"这个阶段的第一次课"看阶段会话里老师是否已经说过话，不再用内存标记。

**会话创建：** 在 DSH 建会话失败时，撤销刚登记的会话关联。切换模型失败只记警告，会话先用默认模型。

**对话页：** 只有你自己发的消息显示成你的话；简报、【下一步更新】等系统加的内容一律显示成可展开的系统信息。

**A 的验收标准：**
1. 简报：同一份不重复注入；内容变了、上一份被压缩掉、上一份没落盘时重新注入。
2. 一轮中途"下一步"变了，补一行更新；没变不补。
3. 通知：
   - 投递失败后重试成功；
   - 重启后补送没送出的通知，送成功的不重复送；
   - 几条通知合并后，每门课各一条。
4. 新阶段会话第一次唤醒时介绍阶段，老师已经说过话的会话不再介绍。
5. 开课会话在 DSH 建会话失败后，下次能建出可用的会话。
6. 最小学习流程测试照常通过。在 3182 上用 DeepSeek 走一遍：交卷后老师自动接着上课；写完小结后，老师接着发布下一节的阅读任务。

## 课堂记录与课时收尾（B）

**课堂记录：**
- 老师每说完一轮，程序把这一轮新增的对话（你的话和老师的回复，不含简报和通知）交给一次性模型，即设置页的"课堂记录"角色。模型整理出：
  - 帮助：老师哪条回复给了哪一档帮助（提示、讲解、完整解答、看答案），关于哪些知识点、哪道题。只说怎么操作、布置任务、复述成绩、表扬的不算；
  - 你自己说的"会了 / 不会"、就学习内容提的问题、你的说法里可能的误解。引用、假设、否定、已经改口的不算。
- 程序校验后写进学习证据：
  - 知识点只能从当前课时、本阶段和列出的题目涉及的节点里选，题只能是列出的题；
  - 自述、提问和误解要逐字引用你的原话，对不上就丢掉；
  - 帮助的时间记成老师那条回复的时间，不是整理完的时间，所以你紧接着去作答，也能正确算"有帮助"；
  - 帮助带上当前课时和会话，针对某道题时带上题和测试；讲到没交卷的测试考的知识点时，即使没点名哪道题，也带上那份测试。
- 帮助怎么影响掌握状态由 learner 的规则决定，和侧边会话里的帮助一样。
- 处理进度按会话记下：整理失败的，下一轮连同新对话一起补，不漏记也不重复记；同一段连续失败 3 次就跳过，不让整份记录卡住。
- 每次最多整理 12 行对话，长的分几次；这个功能上线前就有的会话，只补最近 24 行。
- 每轮多一次模型调用，只在这一轮有你的话或老师说了一段话时调用。

**测试期间：** 有独立测试（练习以外的测试）没交卷时，简报的"课堂"一节写明：你问到这份测试里的题，老师只说明怎么作答和交卷，不讲思路、公式或答案；你想先学会再做，可以先交卷或点"不会"，交卷后再讲。这条只靠提示词，但老师讲了的话，课堂记录会把帮助记到那道题上，那次作答算"有帮助"。

**"我会了"要验证：** 你说会了、之后还没作答过的知识点，连同原话列在简报的"课堂"一节；老师在合适的时候用练习题（`start_test(kind="practice")`）验证。说会了不改变掌握状态。

**课时小结：**
- `write_lesson_summary` 在执行处检查：
  - 课时属于这门课；
  - 本课时有小测，已交卷，没有待复核的判分；
  - 汇报能在这次对话里你说过的话中逐字找到。老师只能照录，你不想说时，就照录你的那句话。

  不满足时退回，并说清下一步。
- 课时记录分两部分：
  - 程序写的事实：小测每题的结果（写题号，不写内部编号）、本课时记下的帮助、相关知识点现在的掌握状态；
  - 你的汇报和老师小结。

**B 的验收标准：**
1. 课堂记录：
   - 讲解、提示、完整解答各记对档位、知识点和时间；
   - 只说操作、复述成绩的回复不记；
   - 引用对不上的自述和误解被丢掉；
   - 整理失败后下一轮补记，不重复。
2. 你在老师讲解后马上答对，这次作答算"有帮助"。
3. 测试没交卷时，简报里有测试期间的规则；交卷后没有。
4. 说会了、还没作答的知识点出现在简报里，作答之后消失。
5. 小结：没有小测、小测没交卷、有待复核、汇报不是你说的、别的课程的课时都被拒绝，课时仍未完成；课时记录里没有内部编号。
6. 在 3182 上用 DeepSeek：问老师一个概念、请老师讲一道练习题，看课堂记录的结果；测试期间问测试里的题，看老师怎么回应。

## 修改提案（C）

方向沿用 [journey.md](../journey.md#所有修改都走同一条路)：core 保存提案，主老师核对，所属单元执行。来源有两个：你在教材上报的错（[annotation](../annotation/design.md)），和侧边提问起草、你点"交给主老师"的修改建议（[sidechat](../sidechat/design.md) C，目标是一节教材、一个阶段的设计书、课程路线、目标说明或一个知识点）。

- **老师在简报里看到：** 有待处理的提案时，简报多一节"待处理的修改提案"：提案 ID、来源、目标（教材写成课时，路线、目标说明、设计书、知识点写名称）、你的话（报错还有你选的原句），以及处理办法——先对照资料核对，拿不准就问你；教材报错先读那一段，确实有错就用"修改教材段落"改；侧边提问的修改建议先问清你的想法，用对应的工具改，要你确认的修改等你确认后再记录；改好记为"已改"，用一句话告诉你改了什么；不改记为"不改"并写清理由；你在做测试或阅读时不打断。简报只写有的那种来源的处理办法。
- **记录结果在执行处检查**（`decide_proposal`）：
  - 只能处理本课程、还没处理过的提案；
  - "已改"要求提案之后对它的目标（课时文件）确实有改动，程序把这些改动记在提案上；没改就记"已改"会被拒绝，所以修改失败不会被记成完成；
  - "不改"必须写理由。
- **你看到结果：** 处理后发 `learning/proposal-decided`。报错的批注随之记为处理完，批注上显示老师的决定和说明（"老师核对后改正了……"或"老师核对后没有改……"）；侧边提问交来的建议在右侧栏那条建议下显示"老师已改"或"老师核对后没改"和说明。
- **不做：** 通用的提案状态机、"已接受待执行"的中间状态（老师核对和修改在同一轮里完成；要你确认的修改，提案一直待处理到改动落盘）。

**验收标准：**
1. 报错出现在简报里，带课时、段落和你的原话；处理后从简报里消失。
2. 没有改动时记"已改"被拒绝；改了以后记"已改"，提案上记着那次改动；"不改"没写理由被拒绝；别的课程的老师处理不了。
3. 批注上显示老师的决定和说明，并记为处理完。
4. 在 3182 上用 DeepSeek：报一处错后问老师，看它是否先核对资料、再改、再记录。

## 关键决定

- **每个阶段一个主老师会话**（10-03，你）。
- **主老师、侧边会话等角色用 DSH 的 Agent 预设实现**（10-03，阶段 0 调研）：每个角色只挂自己需要的工具（V4 实测）。
- **"交回主老师"**（10-04，你的试用反馈；Claude 设计）：第一次试用时，页面上交卷、读完、确认设计、加资料，或者教材生成完，老师都没有反应，要你说"我做完了"才继续。
- **做深的取舍**（10-10，Claude 复核调研后定，你授权）：见"调研复核"。
- **修改提案只记"已改"和"不改"两种结果**（10-10，Claude）："已改"要有提案之后的改动作证据，"不改"要有给你看的理由；不另设"已接受待执行"。

完整的决定和来源见[决策记录](../decisions.md)。

## 待定问题

- 课堂记录判断帮助的档位准不准、每轮多一次调用值不值，等试用时看。
- 课时里的讲解按 learner 现在的规则（同一课时的帮助算数），会让本课时小测上相关知识点的作答算"有帮助"，和侧边会话一样。这对掌握状态是否过严，等 learner 做深时定。
- 你说"今天到这里"以后，后台任务完成时老师仍会接着说话（你回来时会看到）。要不要加"暂停自动上课"，等试用反馈。
