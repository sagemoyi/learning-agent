# 目标（goal）

> 代码：[`packages/goal`](../../packages/goal) · 接口：[契约](../stage0/contracts.md) §4.3、§5.1

目标负责和你商量"学来做什么、要做到什么程度、怎么验证"，写成一份目标说明，并管理它的版本。后面的路线、测试和教材都以它为准。

## 现状

- **骨架：**
  - 老师用工具起草目标说明（`goal.md`）：六要素和可选的考试档案写在文件开头的元数据里，说明文字在下面。
  - 你在课程进度页确认；确认后发事件，交回主老师。
  - 版本来自 `core` 的变更日志。修改已确认的目标算大改动，目标回到草稿，等你再确认。
- **还没做：** 先给几个候选终点让你挑选的协商方式；确认目标时同时调研、确定来源清单；考试档案带来的各环节附加动作。

## 目标确认（Agent 同时在调研）

**协商方式：**
- 你先说一个模糊的愿望。
- Agent 不发长问卷，而是**先给出几个候选终点**，例如"科普级理解 / 能做题 / 能用于工程"，每个都配上"学成后你能做什么"的样例，由你挑选或修改。
- Agent 只追问会改变路线的问题（比如"想做应用还是做研究"），不问"你是视觉型还是听觉型"这类问题。

**产出目标说明（六要素）：**
- 目的
- 使用场景
- 学成后能做什么
- 要做到什么程度
- 怎么验证
- 边界：不学什么、测试时允许用什么工具、打算投入多少时间
- 可选：最后期限、考试档案（见下文）

你确认后目标说明生效。之后要修改就走[修改流程](../journey.md#所有修改都走同一条路)，并保留版本。

**同时进行的调研：** Agent 先查资料库，不够时再按"来源清单"联网找权威资料（做法见 [library](../library/design.md)"联网找权威资料"），然后搭出**初版知识模型**，并收集**题源**（教材习题、往年题、公开课作业）。这门课的权威来源清单也在这一步确定，由你确认。

## 有考试的课程：考试档案

报告里的"考试类目标"并不是另一个产品版本，而是给目标额外加的几条要求。所以我们只有一套流程。确认目标时，如果发现有考试，就给目标挂上**考试档案**，流程中相关的环节会自动多做一些事；没有考试，这些都不出现。

**考试档案的内容：**
- 考试范围
- 题型和分值
- 考试时间和条件（开卷还是闭卷、能不能用计算器）
- 往年题
- 最后期限

一切以官方原文为准，比如学校的教学大纲和老师公布的考试范围。

**挂上考试档案后，各环节多做的事：**

| 环节 | 多做什么 |
|---|---|
| 目标确认 | 问你的侧重：只求通过、兼顾理解，还是以理解为主。报告提醒过，考试范围和真正有用的能力不完全重合，不能让"考试"悄悄替代你真正的目的 |
| 知识模型 | 节点上标出"考试范围内/外"；有些节点不在考试范围里，但对理解有帮助，会单独标出来，学不学由你决定 |
| 题库 | 往年题列为一级题源；阶段测试的题型向真题靠拢 |
| 临近期限 | 加做模拟考：限时、整卷，格式与真题一致 |
| 复盘 | 按考试的板块报告准备情况，比如"传热部分的计算题还不稳" |
| 排期 | 只按最后期限判断能不能赶上（见 [planner](../planner/design.md)） |

化工原理就属于这种情况：目标是"期末考试 + 真正理解"，学校的往年题是最好的题源。

## 关键决定

- **考试不单独做一个版本，而是目标的可选属性（考试档案）；挂上后相关环节自动多做几件事**（10-03，报告 + Claude 建议）。
- **有期限时只记一个最后期限，不排死日程**（10-03，你）。
- **第一门课是化工原理，目标基本由课程决定：通过期末考试，并且真正理解**（10-03，你）。

完整的决定和来源见[决策记录](../decisions.md)。
