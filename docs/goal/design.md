# 目标（goal）

> 代码：[`packages/goal`](../../packages/goal) · 调研：[research.md](research.md) · 契约：[contracts.md](../contracts.md)

## 概要

目标负责和你商量"学来做什么、要做到什么程度、怎么验证"，写成一份目标说明 `goal.md`，并管理它的版本；后面的路线、测试和讲义都以它为准。每条事实都注明来源（资料里读到的、你说的、老师推测的），推测的标"待确认"。有考试时目标挂上考试档案，相关环节自动多做几件事；没有考试，这些都不出现。

## 怎么商量出目标

- 你先说一个模糊的愿望。老师不发长问卷，先用 `offer_goal_options` 给 2–4 个候选终点（例如"能读懂原理 / 能做课后习题 / 能用于工程计算"），每个写学成后能做的 1–3 件事、可选的一道样题（取自本课资料，带出处，写明选这个终点时能做到哪一步）、时间上的取舍、学成后的感觉（只帮你想象，不算证明），可以标一个推荐项。
- 卡片显示在主老师对话里这次工具调用的位置：点"选这个"直接发"我选「……」。"；"改一改"把这句话放进输入框，你补充后再发。你回复后卡片标出所选项，按钮不再可用。卡片不另存数据，选择就是一条消息，老师按它起草目标说明，并把候选终点和你的选择写进正文。程序检查个数、每项至少一件能做的事、样题片段属于本课资料、没有内部编号；不合格的调用不显示卡片。
- 老师只追问会改变路线的问题：终点、有没有考试、期限、每周投入、不学什么；已有基础交给摸底来测。不问"你是视觉型还是听觉型"这类问题。
- 有考试时，老师先在资料库里找教学大纲、考试通知，按原文写考试档案；找不到就列进资料清单请你提供，拿到后再改。
- 你在进度页上确认后目标生效，交回主老师。之后要改，走[修改流程](../journey.md#所有修改都走同一条路)并保留版本。

## 目标说明

- **六要素：** 目的、使用场景、学成后能做什么、要做到什么程度、怎么验证、边界（不学什么、测试时允许用什么工具、打算投入多少时间）；可选的最后期限、考试档案、资料清单。字段写在文件开头，说明文字在下面。
- **"能做"条目** 每条有一个短键（`c1`、`c2`……），老师在简报里看得到，你看不到。改写文字时键不变；删掉的条目的键不再分配给新条目。阶段和结课检验按键引用。每条可以单独写"怎么验证"。每条另有一个要求版本：改了能做什么、做到什么程度或怎么验证就加一；老师声明"只改措辞、意思不变"（`sameMeaning`）才不变。结课检验记下发布时的要求版本，对不上就不算数；确认框把"要求改了"和"只改措辞"的条目分开列。
- **每周投入** 文字之外记一个小时数区间；老师写"每周 4–6 小时"时程序自动读出。
- **事实和来源：** 测试条件、每周投入、最后期限，以及考试档案的日期、范围、题型和分值、成绩构成、考试条件，各记一个来源：官方（从本课资料里读到的，必须附资料片段，页面显示"依据《书名》"和页码）、你（你说的，或你在页面上确认、修改过的）、推测（老师没有依据时写的，页面标"待确认"；没写来源的都算推测）。推测的事实不拦确认，只标出来。
- **版本：** 每写一次加一；内容和当前版本相同时不写新版本。每次写入都带读取时的内容指纹：页面上改事实和老师修订同时发生时，后写的一方被拒（"目标说明刚被改过"），重读后再改，两处修改都不丢。`goal.md` 读不出来（头部字段不全或格式坏了）时报"读不出来"，不当成"还没有目标"，也不被新草稿覆盖。较早的 `goal.md`（"能做"是纯文字、没有版本号）照常读出：条目按顺序编键，版本按已有的写入次数算，下次写入时补齐。
- **什么时候回到草稿：** 已确认的目标改了目的、场景、能做、程度、验证方式、不学、考试侧重或说明正文，回到草稿等你重新确认；只改事实（测试条件、时间、日期、考试档案的其他项）或资料清单，仍是已确认的。

## 考试档案

- **内容：** 考试范围（文字，加骨架教材的小节号）、题型（每种的分值、题数和说明）、成绩构成（例如平时 30%、期末 70%）、考试日期、考试条件（开卷还是闭卷、能不能用计算器和公式表、考试时长）、往年题、你的侧重（只求通过、兼顾分数和理解，还是以理解为主）。
- 一切以官方原文为准，比如学校的教学大纲和老师公布的考试范围。考试日期写在考试档案里；"最后期限"是你自己另定的完成日期，可以不设。
- **挂上考试档案后各环节多做的事：**

| 环节 | 多做什么 |
|---|---|
| 目标确认 | 问你的侧重。考试范围和真正有用的能力不完全重合，不能让"考试"悄悄替代你真正的目的 |
| 知识模型 | 节点标考试范围内、范围外但有助理解、范围外（见 [knowledge](../knowledge/design.md)"考试范围"）；有助理解的学不学由你决定，不学就移出本课 |
| 题库和测试 | 往年试卷按题号进题库；阶段测试、模拟考和结课检验按考试条件；模拟考按题型、题数、分值和时长组卷（见 [assess](../assess/design.md)） |
| 课程路线 | 每个阶段写明支撑哪几条"能做" |
| 下一步 | 写距考试还有多久，以及照现在的节奏能不能赶上（见 [planner](../planner/design.md)） |

## 资料清单

- 老师列出这门课还需要的资料，每份写是什么、为什么要、在资料库里算哪一类（骨架教材、参考、往年题），由谁来找（你提供，或老师联网找）。本课已有的资料自动列出。
- 状态：已有（对应到本课的一份资料）、等你提供、老师会联网找、你说没有。你在进度页上把加入的资料选成"就是这份"，或点"没有这份"：改动记为你的，不需要再确认目标，交回主老师。往年题对应上资料后自动记入考试档案的往年题，取消对应时移出。
- 老师修订清单时，同名的条目保留已对应的资料和"没有"的标记；新条目的键不复用。还有资料没到也可以确认目标，确认框里写明还差几份。

## 老师怎么写

- `save_goal_draft` 写整份目标，可以带考试档案、事实来源和资料清单；同样的"能做"文字保留原来的键。
- `revise_goal` 带版本号，只改传入的字段："能做"传完整列表，带键的是改写，不带键的是新条目，没列出的删除；考试档案按项合并，还没有档案时要写全范围、考试条件和侧重；`removeExam` 去掉档案。
- **程序检查**（只检查老师的写入，不调用模型）：
  - 退回：没有"能做"；某条以"理解、了解、熟悉、掌握、知道"这类词开头；没写验证方式；学习者能读到的文字里有内部编号；标为官方的事实没有附片段，或片段不在本课资料里；每周投入的最少小时数大于最多。
  - 提醒但照常保存：提到了考试却没有考试档案；验证方式里的百分比门槛没写依据；给没有值的事实写了来源。

## 进度页上的目标

- **草稿：** 全部展开。待确认的事实旁有"待确认"、"对"和"改"。确认框里写明哪几项是老师的推测，以及（改过的目标）和你上次确认相比改了什么、会影响哪些环节。
- **已确认：** 折叠成目的和几个标签（测试条件、考试日期、期限、"N 项待确认"、"老师改过 N 处"）。老师在你确认后只改了事实时，展开能看到改了什么，点"知道了"。
- **你直接改事实：** 测试条件、考试条件（含时长）、每周投入、最后期限、考试日期可以直接改；日期接受 2027-01-10、2027/1/10、2027年1月10日。改完记为你的，不需要再确认目标，交回主老师。考试范围、题型只能确认，要改请告诉老师。
- 每条"能做"后面写对应的阶段（"第 1 阶段"），排了路线却没有阶段对应的条目标出来。
- 版本记录写每一版是谁、什么时候、为什么改的。

## 测试条件

`start_test` 不写开闭卷时：阶段测试、模拟考和结课检验按考试档案的考试条件（只有模拟考带考试时长），其他测试按目标里的默认条件；老师写了开闭卷，只覆盖这一项。没有目标说明时用闭卷、可用计算器、不带公式表。

## 数据与接口

- **文件：** `goal.md`（frontmatter：六要素、`canDo` 条目和键、`facts` 来源、`exam` 考试档案、`sources` 资料清单、`version`、状态）。
- **服务** `learnGoal`：`get`、`view`（页面用：事实及来源、和上次确认相比的差异与影响、版本记录、往年题名称）、`saveDraft`、`revise`、`setFacts`、`setSource`、`acknowledge`、`confirm`、`conditions`（按测试种类给测试条件）。老师的写入没通过检查报 `learning/goal/check`，版本不对报 `learning/goal/stale`。
- **页面接口** `/api/learning/goal.<方法>`：`get`、`view`、`confirm`、`setFacts`、`setSource`、`acknowledge`。目标区块放在课程进度页的 `learning.course-section` 里，候选终点卡片注册在 `learning.chat-card`。
- **事件：** `learning/goal-confirmed`；你确认、改事实、对应资料后发 `learning/handoff`。
- **老师工具：** `offer_goal_options`、`save_goal_draft`、`revise_goal`（考试范围的 `mark_exam_scope` 属于 knowledge）。

## 关键决定

- **考试不单独做一个版本，是目标的可选属性；挂上考试档案后相关环节自动多做几件事**（10-03，报告 + Claude 建议）。
- **期限只记一个，不排死日程**（10-03，你）：期限怎么用见 [planner](../planner/design.md)。
- **第一门课是化工原理，目标基本由课程决定：通过期末考试，并且真正理解**（10-03，你）。
- **事实还没经官方确认时目标照常确认，待确认的标出来；你在页面上只直接改事实类字段；候选终点在对话里显示成卡片**（10-08，你选了调研的推荐项）。
- **候选终点不另存数据，选择就是一条消息；资料清单写在目标说明里，增减不让已确认的目标回到草稿；考试范围多一档"范围外但有助理解"，按小节标时保留它；阶段对应目标条目按键记在阶段上**（10-08，Claude 按调研）。
- **只改事实时已确认的目标保持确认，改了目的、能做、程度等选择才回到草稿；"能做"的键用过就不再分配；程序检查不调用模型**（10-08，Claude）。
- **键说明"是哪一条"，要求版本说明"这一条现在要求什么"；写入带内容指纹**（11-03，11-02 审查 L17、L10）：键不变时，大改要求后旧的结课检验仍能证明"做到了"；两次同时修改原来都返回成功，先写的那次悄悄没了。

## 已知限制与以后再做

- 按考试板块复盘（"传热部分的计算题还不稳"）还没做。
- 确认目标时由老师提出本课的权威来源清单还没做：现在用资料库内置的网站规则加你在设置页设的网站级别。
- 老师每轮多看到的工具说明：目标的三个工具约 7500 字符，加上考试范围工具和路线的条目参数，比最初多约 7400 字符。真实对话里老师用得对，暂不合并；上下文成问题时，可以把起草和修订合成一个工具。
- 老师有时把公式写进知识节点名称（如 `$p=\rho g h$`），图谱和详情按原文显示；名称不写公式还是页面渲染公式，要在 knowledge 里决定。
- 老师声明"意思不变"可能偏宽松：确认目标时你会看到每条改动，由你把关。
