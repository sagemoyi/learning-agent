# 目标做深调研

> 2026-10-08 · 对应 PLAN 阶段 1 的 `goal` · 状态：调研完成，方向待学习者确认。
> 依据：十月研究报告 §3、§5、§7、§9、§11，[总体计划](../PLAN.md)、[已确认设计](design.md)、[契约](../stage0/contracts.md)，3180 上一份真实目标说明，以及下文的研究、开源实现和产品参照。

建议把目标说明做成后面每一步都要对照的约定。每条"学成后能做"写清条件和验证方式；考试日期、范围、开闭卷这类事实，逐条注明来自官方原文、学习者，还是老师的推测。协商时，老师给出几个配有真实样题的候选终点，只追问会改变路线的问题。研究显示，把目标写得更好并不会自动带来更好的达成，所以力气不放在润色文字上，而是放在让目标驱动测试条件、考试档案、路线和期限判断上。

六要素、考试档案作为目标的可选属性、只记一个最后期限，这些已确认的设计都保留。

## 1. 结论与实施建议

| 问题 | 建议 | 原因 |
|---|---|---|
| 目标说明写什么 | 六要素不变。每条"学成后能做"写成可观察的动作，带条件和验证方式，并有一个稳定的条目键，让阶段验收和结课能引用 | 逆向设计和证据中心设计要求"目标 → 证据 → 任务"对齐；只有一段文字时，后面的环节无法对照 |
| 事实从哪来 | 考试日期、范围、题型、开闭卷、计算器、公式表、期限，逐条记来源：官方原文（带出处）、学习者说的，或老师推测（待确认） | 报告 §3.5 要求区分已确认的事实和待确认的信息；3180 上的目标把老师推测的测试条件写成了确定值 |
| 怎么协商 | 老师给 2–4 个候选终点，每个配"学成后能做什么"和一道从资料里取的样题；只追问会改变路线的问题，其他先用默认值，并写明是默认值 | 样例配合对话能帮助理解标准；按信息价值提问，能少问而不漏问；长问卷和学习风格问题不改变路线 |
| 质量怎么保证 | 用程序检查：每条"能做"是不是可观察的动作、有没有验证方式、有考试却没有档案、哪些事实还是推测、有没有内部编号。不另调模型评审 | 对话智能体的反馈能提高目标的写法，但不提高达成；便宜的程序检查已经够用 |
| 怎么修改 | 老师按版本修订个别字段，不整份重写；学习者确认改动时，看到和上次确认版的差异，以及会影响哪些环节 | 报告 §3.3 要求目标版本化；整份重写时，老师会把要点只写进正文（3180 上已发生） |
| 考试档案 | 记考试范围、题型和分值、条件、日期、成绩构成和往年题，尽量取自教学大纲和任课老师公布的信息。挂上档案后，测试条件、知识范围标记和期限判断都接上 | 化工原理就是考试课程；档案的字段已经定义，但现在写不进去 |
| 来源清单 | 目标阶段列出要用的资料：已经有的，需要学习者提供的（教学大纲、往年题、公布的考试范围），以及要联网找的。和目标一起确认 | 已确认的设计；资料本身仍归 library 管 |
| 怎么分批 | A 目标说明可信、可改、接到测试条件 → B 协商卡片和来源清单 → C 考试档案接到知识图、路线和期限 | 每批都能单独验收；A 先修正已发现的数据问题 |

### 3180 上的一份真实目标说明

这份目标说明来自学习者第一次试用，下面只记和设计有关的观察：

- **协商方式本身可用。** 老师给了三个候选终点："读懂原理"、"能做课后习题"、"工程选型和设计"。学习者选了"以能做课后习题为主、读懂原理打底"，正文记下了这个选择。
- **考试课程却没有考试档案。** 这门课的目标是通过期末考试，但工具没有档案参数，考试日期、范围、题型都没有记下。
- **推测被写成了确定值。** "闭卷、可带计算器、不带公式表"是老师推测的，正文里请学习者纠正，但从字段上看不出它是推测。
- **要点只进了正文。** 正文写了"不要求推导""不专门做工程设计""每周 4–6 小时"，但字段里"不学"是空的，时间投入也没填。后面的环节只读字段，这些信息就用不上了。
- **门槛没有依据。** 验证方式写了"正确率 80% 以上才算过关"，是老师自己定的，没有说明理由。报告 §5 提醒，门槛应该按目标的风险和测量误差来定，不能制造假精确。
- **"能做"写得不错。** 6 条大多是带条件的可检验动作，例如"结果与书后答案一致"。其中"闭卷能写出并解释 6 个方程"是一张记忆清单，在闭卷考试下是合理的。

## 3. 学习科学：目标说明是对证据的约定

### 先定证据，再排学习

- **逆向设计**先确定期望的结果，再确定可以接受的证据，最后安排学习（报告文献 [11]）。它的第二阶段把证据分成两类：让学习者在新情境里运用所学的表现任务，以及小测、观察这类其他证据。[NSW 教育部的 UbD 第二阶段说明](https://education.nsw.gov.au/teaching-and-learning/professional-learning/teacher-quality-and-accreditation/strong-start-great-teachers/refining-practice/planning-a-sequence-of-lessons/determine-acceptable-evidence.html)
- **证据中心设计**把能力主张、证据和任务连成一条链（报告文献 [12]、[13]）。
- **Knowles 的学习契约**写五件事：目标、资源和策略、完成的证据、证据怎么评判、目标日期。它和本项目的"六要素 + 来源清单 + 期限"几乎一一对应。[Hiemstra 对学习契约的整理](https://roghiemstra.com/contract.html)

**本项目建议：** 每条"能做"是一条能力主张，"验证方式"说明用什么证据判断。阶段设计书写明本阶段的验收支撑哪几条，结课时逐条对照。为此"能做"要有稳定的条目键：只改文字时键不变，学习者看到的是"目标第 2 条"这样的说法，看不到键。

### 把目标写好，本身帮助有限

| 研究 | 结果 | 局限 |
|---|---|---|
| Morisano 等 2010：书面的个人目标设定程序 | 85 名学业困难的本科生，4 个月后成绩明显好于对照组 | 样本小，对象是学业困难的学生 |
| Schippers 等 2020：分阶段的书面目标设定（4–6 小时） | 2928 名一年级本科生，目标设定队列的学业表现比对照队列高 22% | 准实验，不是随机分组 |
| Van Jaarsveld 等 2025（LAK）：对话智能体引导设目标并给自适应反馈 | 引导加反馈对目标质量的提升最大；但对目标达成没有显著影响，目标质量和达成也不相关 | 5 周，学业目标，不是某一门课的掌握程度 |
| Wang 等 2021：心理对照加执行意图（MCII）的元分析 | 21 项研究，对目标达成有小到中等的效果（g = 0.336），有人互动时更强 | 作者提示存在发表偏倚 |

来源：[Morisano 等 2010](https://archive.otis.edu/sites/default/files/GoalSettingJAP2010.pdf)、[Schippers 等 2020](https://repub.eur.nl/pub/123006/Schippers-et.al-2020-CEP.pdf)、[Van Jaarsveld 等 2025](https://research-portal.uu.nl/en/publications/scaling-goal-setting-interventions-in-higher-education-using-a-co/)、[Wang 等 2021](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2021.565202/full)。

**本项目建议：**
- 目标对话控制在几轮之内，不追求文字完美，力气放在让目标真正驱动测试、路线和期限判断。
- 程序检查给老师具体的修改意见，这相当于研究里的"反馈"，成本很低。
- MCII 这类"预想障碍、写好应对计划"的做法暂不加入：它会拉长协商，而学习者已明确希望由 Agent 主导规划。以后如果"回来后接续"成了问题，再在 planner 里考虑。

### 学习者决定终点，Agent 决定做法

学习者控制权的元分析发现，把更多教学操作交给学习者选择，并不必然提高成绩（报告文献 [17]）。报告 §3.4 的建议是：学习者保留目标、投入、节奏、工具条件和是否接受方案的最终决定，学习顺序、练习方式、测量和复习由 Agent 决定。

**本项目建议：** 协商只涉及终点、程度、工具条件、投入、期限和不学什么。学习顺序、题型比例这些不拿来问学习者，但学习者随时可以问"为什么这样安排"。

### 样例让抽象的程度变具体

一篇覆盖 40 项研究的系统综述发现，分析不同质量的样例能帮助学生理解评价标准；但只给样例不够，要配合对话。[To、Panadero、Carless 2022](https://doi.org/10.1080/02602938.2021.2011134) 报告 §3.2 也建议：目标终态同时呈现能力、证据和体验，体验只用来帮助想象终点，不证明掌握。

**本项目建议：** 每个候选终点配一道从资料里取的样题（带出处），说明"选这个终点，学成后这道题你能独立做到哪一步"。例如同一道管路计算题，"读懂原理"只要求说清用到了哪些方程，"能做题"要求独立算对，"工程应用"还要求判断设计是否合理。体验描述可以写一句，放在候选卡片上，不写进目标说明的字段。

## 4. 怎么问：只问会改变路线的问题

近两年有几项研究让智能体按信息价值决定要不要提问：

- SAGE-Agent 用"完全信息的期望价值"给每个候选问题打分，在含糊的任务上覆盖率提高 7–39%，提问次数减少到原来的 1/1.5–1/2.7。[ACL 2026 Findings](https://arxiv.org/html/2511.08798v1)
- 信息价值框架在推理时权衡提问的收益和学习者的负担，不需要调参数。[ACL 2026](https://preview.aclanthology.org/ingest-acl/2026.acl-long.1987/)
- 主动任务消歧用贝叶斯实验设计生成澄清问题。[Kobalczyk 等，ICLR 2025](https://arxiv.org/abs/2502.04485)

这些研究的任务是工具参数和代码，不是学习目标；它们支持"按决策价值提问"这个原则，但不提供可以直接搬用的模型。

**本项目建议：** 不实现概率模型，而是把"会改变路线"的问题写成固定清单，由老师判断哪些还没有确定：

| 问题 | 会改变什么 | 没问到时 |
|---|---|---|
| 终点：理解、做题还是应用 | 节点粒度、测试题型、阶段数 | 必须问 |
| 有没有考试；考试日期、范围、开闭卷、计算器、公式表 | 考试档案、测试条件、期限判断 | 有考试就问；学习者也不清楚的，先按推测记下，标为待确认 |
| 最后期限 | 能不能赶上、复习安排 | 不设期限 |
| 每周大概投入多少 | 期限判断 | 不估算，等学习者说 |
| 不学什么 | 知识图的范围 | 不排除任何内容 |
| 已经会什么 | 摸底从哪里开始 | 不问，由摸底来测 |
| 学习风格、喜欢看视频还是读书 | 不改变路线 | 不问（PLAN §8） |

程序记下每条关键事实的来源，老师在简报里能看到"还待确认的事实"。

## 6. 数据建议

### 数据归属

- **goal** 拥有 `goal.md`（字段和正文），版本来自 core 的变更日志。
- **资料本身归 library。** 来源清单只引用资料 ID，或者记一条"等学习者提供"的条目。
- **考试范围标记**写在 knowledge 的课程成员上（字段已有）；goal 只提供范围本身和它的出处。
- **每次测试的条件归 assess。** 默认值来自 goal：有考试档案时，阶段测试和模拟考用考试条件，其他测试用目标里的默认条件。

### A 批的最小补充

- **"能做"条目：** `{ key, text, evidence? }`。`key` 是短的稳定标识，只改文字时不变；`evidence` 写这一条怎么验证，不写时沿用整体的验证方式。
- **事实的来源：** 测试条件、期限和考试档案里的每条事实，记 `basis`：`official`（带资料出处）、`learner`（学习者说的）或 `assumed`（老师推测，待确认）。
- **时间投入：** 保留文字，另记每周小时数的区间，供 planner 判断期限。
- **考试档案：**
  - 范围：文字，加可选的小节列表；
  - 题型：`{ 题型, 分值, 说明 }` 的列表；
  - 成绩构成：例如平时和期末各占多少；
  - 条件、日期、往年题、侧重，这几项已有。
- **版本：** 头部记 `version`，每次写入加一；另记最后确认时的版本，确认改动时据此列出差异。

### 程序检查

老师保存或修订时，程序逐项检查，不通过的写进返回给老师的说明，由老师改正后再存：

- 每条"能做"以可观察的动作开头，例如"能算出……""能解释……"，不是"理解……""熟悉……"；
- 有验证方式；
- 有考试的课程（正文或字段提到期末、考试）却没有考试档案；
- 写成 `official` 的事实没有出处；
- 学习者能看到的文字里有内部编号（`kn_`、`ck_` 等）；
- 日期格式和期限的先后（考试日期不能晚于期限）。

还要提醒但不拦下的：门槛里有百分比，但没有写依据。

### 修改与确认

- **老师修订：** 新增 `revise_goal`，带版本和理由，只改传入的字段；"能做"按 `key` 合并。
- **学习者确认改动时：** 进度页列出和上次确认版的差异，以及可能受影响的环节，例如"测试条件变了，之后的测试按新条件"。
- **学习者自己改事实：** 考试日期、开闭卷、计算器、公式表、期限、每周投入，学习者可以在页面上直接改，记为 `learner`，不需要再确认，并交回主老师。终点、"能做"、程度这些改动会影响路线，仍然通过老师。

## 7. 分批范围与验收草案

### A：可信、可改，接到测试条件

范围：上面第 6 节的数据补充；`save_goal_draft` 能写考试档案；新增 `revise_goal`；程序检查；进度页标出待确认的事实，确认改动时显示差异，列出版本记录；学习者在页面上改事实类字段；assess 不传条件时用目标的条件；简报写入考试档案和待确认的事实。

验收草案：
- 老师按"期末考试，闭卷可带计算器"写目标时，考试档案写得进去；没有出处的考试条件显示为"待确认"。
- 把"能做"写成"理解伯努利方程"会被程序退回，并说明怎么改。
- 老师只改期限，其他字段不变，"能做"的键不变。
- 确认改动时，页面列出改了哪几项；版本记录能看到每次是谁、为什么改的。
- 学习者在页面上把考试日期改成某天，这条事实变成"学习者确认"，主老师收到一句进度通知。
- 老师发布阶段测试时不写条件，测试按考试档案的条件。
- 旧的 `goal.md`（没有键、没有来源）能正常读出，下一次写入时补上。
- 自动测试只用假模型；真实模型只用合成课程验一遍目标对话。

### B：协商卡片和来源清单

范围：
- 新工具 `offer_goal_options`：2–4 个候选终点，每个写"学成后能做什么"、一道带出处的样题、时间上的取舍。对话里显示成卡片，学习者点选或改写后，选择作为一条消息发回老师。
- 来源清单：老师列出已有的资料，以及需要学习者提供的（教学大纲、往年题、公布的考试范围）。进度页显示这张清单，可以直接去资料库上传；确认目标时一起确认。
- 考试档案从大纲里取，事实带片段出处。
- 改写主老师提示词里"目标确认"这一步。

验收草案：
- 合成课程里，老师的候选终点各有一道能打开原文的样题。
- 点选卡片后，老师在下一轮按选择起草目标，不重复提问。
- 上传一份合成的教学大纲后，考试档案的题型和成绩构成带出处，标为官方。
- 来源清单里"往年题，等你提供"的条目，在资料加入课程后变成"已有"。

### C：考试档案接到各环节

范围：
- knowledge：老师按考试范围（小节）标记节点；学习者可以改；图上能筛出"考试范围内"。范围外但对理解有帮助的节点单独标出，学不学由学习者决定。
- curriculum：阶段设计书写明本阶段的验收支撑目标的哪几条；进度页的目标区显示每条有没有对应的阶段。
- planner：有考试日期时，简报和进度页写"距考试还有几周、已完成几个阶段"。能不能赶上的区间估计，等路线有了时间估计后，留给 planner 做深。

往年题作为一级题源、模拟考、按考试板块复盘，留给 assess 和 curriculum 做深时完成。

## 8. 需要讨论的取舍

1. **还有待确认的事实时，能不能先确认目标？** 建议可以。目标照常确认，待确认的事实标出来；老师在用到它之前（例如第一次阶段测试、按期限判断进度）再提醒。否则拿不到教学大纲时，整个流程会卡住。
2. **学习者能不能在页面上直接改目标？** 建议只开放事实类字段（考试日期、测试条件、期限、每周投入）。终点、"能做"、程度这些改动会影响路线，仍通过老师，老师会说明影响。
3. **候选终点放在哪里？** 建议在对话里显示成卡片，点选后自动发给老师，不另开页面；选择的记录写进目标说明的正文。
4. **分批顺序：** A → B → C，先修正已发现的数据问题，再改协商体验，最后接到其他单元。
