# 侧边会话（sidechat）

> 代码：[`packages/sidechat`](../../packages/sidechat) · 接口：[契约](../stage0/contracts.md) §5.1、§5.3（侧边会话链路）、§6.4（页面上下文）、§11 末尾的补充 · 调研：[做深调研](research.md)（含复核：[复核](review.md)）· 验证：[A](../stage0/compatibility.md#sidechat-a可靠入口与边界10-10grok-bot)、[B 与 C](../stage0/compatibility.md#annotationsidechat-b-与-c10-11claude)

侧边会话是同一个老师的"课间答疑窗口"：在任何页面都能打开，带着你正在看的内容提问，不打断主老师的课程。界面上叫"侧边提问"，在右侧栏。

## 现状

- **A 可靠入口与边界：已技术验收，待你试用。** Grok Bot 实现，Claude 10-10 复核后保留；在 3182 上用 DeepSeek 实测过从批注的疑问打开侧边提问、回答、结束并总结。见下文"可靠入口与边界"。
- **B 可靠的学习记录：已技术验收，待你试用。** 每轮回答完就把帮助、提问和可能的误解记进证据日志；结束时从这些记录拼出总结，每条都有消息依据；笔记里不出现内部编号。见下文"可靠的学习记录（B）"。
- **C 后续行动：已技术验收，待你试用。** 侧边会话可以起草修改建议，你点"交给主老师"才交给老师处理；记下的误解由 [planner](../planner/design.md) 安排检查；主界面上也能提问（先选一门课）。见下文"后续行动（C）"。
- B、C 用自动测试（假模型）和真实 DSH（3182，合成数据）验收。10-11 Claude 在本机 3182 上用 DeepSeek 联调：每轮回答后的整理、按原话记误解、起草修改建议 → 你交给老师 → 老师改好教材并记"已改"、测试期间只说明操作、主界面选课提问都按设计工作（见[验证记录](../stage0/compatibility.md#annotationsidechat-b-与-c-的真实模型联调10-11claude)）。
- **骨架：**
  - 直接输入第一个问题，发送时才打开会话；从教材段落、资料原文、知识节点、题目点"就此提问"会带上选中的内容，选中内容可以一键移除，改成针对整门课提问。
  - 与主老师的会话隔离；侧边会话的工具只能查本课资料库和起草修改建议（见下文）。
  - 设置页里可以单独指定"侧边提问"和"侧边会话总结"的模型。"侧边会话总结"也是每轮整理对话的模型，输出额度留 8000。
- **页面：** 打开会话后发送失败，页面刷新并显示这次会话，问题留在输入框里，失败原因显示在输入框旁；回答还没写完时点"结束并总结"会说明要等它写完；设置页"资料服务"里有"测试进行中只说明怎么操作"开关（默认开）。右侧栏在会话总结后、以及收到 `learning/annotation-changed` 时重新读取当前会话（批注的"在侧边提问"开的会话靠它显示出来；事件名列在 `src/refresh.ts`，由 `tests/annotation.test.ts` 保护）。
- **还没做：**
  - 一次会话同时问几门课：现在每次会话属于一门课，主界面上提问也要先选课；
  - 总结的纠正（"这不是我的意思"）和历史会话列表：结束后只在笔记里看得到；
  - 提问时的版本快照：批注开的会话带批注自己的原句，其他选中内容按当时的正文讲；
  - 回答写到一半被取消时，已经显示出来的部分不记帮助（只整理落盘的完整回复）；
  - 用合成会话量整理对话的召回和误判（知识点列表现在按优先顺序取前 60 个，没有测过召回）。

## 设计

- **自动带上下文。** 打开侧边会话时，会自动带上：
  - 当前页面
  - 你选中的内容：教材里的一段、资料原文的一段、知识图里的一个节点、课程进度里的一个阶段、刚做完的一道题
  - 你的学习状态摘要
- **与主老师会话隔离。** 侧边会话的内容不进入主课程会话的上下文，也不打断本课的流程。
- **结束时写总结。** 每次侧边会话结束后，系统把一条总结写进课程文件夹里的固定文件（`notes/side-chats.md`）。总结包含：
  - 时间、针对什么
  - 问了什么、得出什么结论
  - 涉及哪些知识点、可能存在什么误解（带你的原话）
  - 给了什么帮助、起草了哪些修改建议

这些记录有三个用途：
1. **学习信号。** 问到的知识点会在对应节点上标"有疑点"；记下的误解由 planner 安排一道检查题。
2. **帮助记账。** 侧边会话里得到的讲解记为对该节点的"帮助"，紧接着的作答算"有帮助完成"（不扣分）。
3. **修改提案。** 例如你在"课程进度"页问"为什么阶段 3 要先学这个，能不能调换"，侧边会话起草一条修改建议。你点"交给主老师"，主老师就按[统一的修改流程](../journey.md#所有修改都走同一条路)核对和修改。

主老师不会每一轮都读这些总结，只在课时小结、阶段复盘和阶段设计时读。

**侧边会话本身不直接修改任何课程内容，** 只有主老师能改，这样可以避免多处同时修改造成冲突。测试期间的侧边会话有额外限制，见 [assess](../assess/design.md)"测试类型与独立性"。

## 可靠入口与边界（A）

- **工具在执行时判断。** 侧边会话的预设挂的是整个资料库工具包，所以限制在工具运行的那一刻判断：资料库的四个工具和起草修改建议开头调用 `learnSidechat.checkTool(sessionId, tool)`，侧边会话只能用 `search_library`、`read_section` 和 `draft_proposal`，联网找资料和加入资料一律拒绝，原因作为工具的错误回给模型。不是侧边会话的会话照常放行；没有侧边会话单元时也放行。
- **测试进行中只说明怎么操作。** 课程里有 `status` 为 `open` 的测试（问 `learnAssess.tests`）时，侧边会话一个工具也不能用，打开会话时的上下文里不放题目和资料内容，每轮第一步还会提醒模型"只说明怎么交卷、计时、拍照作答，不讨论题目"。想讨论题目，就先交卷（不会的题点"不会"），交卷后讲的不影响这次作答。这条限制由单元配置 `restrictDuringTests` 控制，默认开，设置页可关，避免遗留的未交卷测试把答疑一直锁住。只限制本课程的侧边会话，主老师不受影响。
- **首轮上下文以持久记录为准。** 会话记录里已有上下文消息就不再注入，进程里的集合只是缓存，重启后不会重复。上下文生成失败时，这一轮不带上下文继续（不让学习者的提问失败），也不标记为已注入，下一轮重试。
- **创建失败回收归属。** 登记会话归属后创建会话或选模型失败，归属立即关闭，不会留在"可以回去继续的会话"里。

## 可靠的学习记录（B）

**每轮回答完就记账**（[`ledger.ts`](../../packages/sidechat/src/ledger.ts)）：
- 侧边会话的回答写完（DSH 的 `agent/status` 变成空闲），程序把上次整理之后的新消息（你的话、助手的回复、打开时带的上下文；不含测试提醒）交给"侧边会话总结"模型，每次最多 12 行。模型整理出：
  - 你问了什么（一句话概括，加你的原话）；
  - 讲清楚了什么（每条注明出自哪条消息）；
  - 助手哪条回复给了哪一档帮助（提示、讲解、完整解答、看答案），关于哪些知识点、哪道题；只说明操作、打招呼、表扬的不算；
  - 你的说法里可能的误解（一句话加你的原话）。引用别人的话、提问、假设、已经改口的不算。
- 程序只留能核对的：知识点和题只能从给出的列表里选；原话要逐字（不计空格和标点）出现在你的某条消息里；结论和帮助指向的消息要存在，帮助必须指向助手的回复。
- 记进证据日志的：
  - `help.given`：时间是那条回复的时间，带会话；针对某道题时带题，讲到没交卷的测试考的知识点时带那份测试；
  - `signal.question`：一次会话里每个知识点最多一条（同一次答疑里反复问是一回事），时间是你那条消息的时间；
  - `signal.misconception`：只记有你原话、有自己知识点的，正文写成"误解（原话："…"）"。
- 这一段整理的结果（问题、结论、帮助、误解，各带消息编号）存进 sidechat 自己的表，记账和存段落在同一个事务里，所以不会漏记也不会重记。整理失败时什么都不记，下一轮连同新消息一起再整理；同一段连续失败 3 次就跳过，结束时总结里写明有一段没整理成功。
- 给模型的知识点列表：打开会话时选中的内容挂的知识点在前（教材段落、节点、题目、阶段、批注所在段落），然后是列出的题目、当前阶段的知识点，最多 60 个。题目列表是没交卷的测试和最近两份判完分的测试，选中的题在前。

**结束时从记录拼总结：**
- 回答还没写完时拒绝结束（`learning/sidechat/still-answering`），截点就是最后一条落盘的消息，不会把一条回答截成两半。
- 结束时先把截点之前还没整理的消息整理完（失败就报错，可以再点；第 3 次失败跳过这一段），然后把各段拼成总结：问题、结论、误解去重，知识点和帮助合并。总结记下截点（`upTo`）。之后会话里如果还有回复，照样记账，但不改总结。
- 结束时不再另外调用模型；整理都在每轮之后做过。
- 关闭可以重复执行：同一会话的并发关闭合并成一个任务；笔记用隐藏的标记 `<!-- side-chat:<会话 ID> -->` 去重（也认得旧笔记里的 `- 会话：<ID>`）；已存总结但会话没关或没通知的，下一次关闭补上。没有你的消息的会话不写笔记，只关闭。

**笔记**（`notes/side-chats.md`）每次会话一节，标题是时间和针对的内容，下面依次是问了什么、结论、可能的误解（带原话；没有找到原话的写"只作参考"）、得到的帮助（按档位列知识点）、涉及的知识点、修改建议和它们交没交给老师。正文不出现内部编号。

## 后续行动（C）

**修改建议：**
- 你明确想改课程的某处时，侧边会话用工具 `draft_proposal` 起草：改什么、为什么、改哪里。"哪里"由程序定，不让模型编：
  - `selection`：打开会话时选中的内容。教材段落或批注所在段落 → 那一节教材的文件；阶段 → 它的设计书；知识点 → 这个知识点。选中的是题目时拒绝（题目有问题要在测试页点"这题有问题"），是资料原文时拒绝（资料里的错误在资料库页处理），没选中内容时拒绝并请模型问清楚；
  - `roadmap`：课程路线；`goal`：目标说明。
- 草稿存在 sidechat 自己的表里，显示在右侧栏会话上方。同样的内容再起草一次还是同一条。测试进行中不能起草。
- 你点"交给主老师"，草稿变成来源为"侧边会话"的提案（`core.proposals`），并交回主老师一次；点"不用了"草稿就不再显示。交过的草稿显示老师的处理结果和说明。草稿交不交只能由你在页面上决定，模型不能替你交。
- 主老师在简报里看到它，按 [tutor](../tutor/design.md) 的修改提案流程处理：先问清你的想法、对照资料，用对应的工具改好再记"已改"（要有提案之后的改动），或者记"不改"并写理由。要你确认的修改（路线、目标）等你确认后才能记"已改"。
- 总结记下交给老师的提案；笔记里列出这次会话起草的修改建议，写明结束时交没交。

**误解的检查：** 侧边会话（和主老师的课堂记录）记下的误解进入证据日志，[learner](../learner/design.md) 把这个知识点标"有疑点"，并在帮助过后 24 小时起可以检查；[planner](../planner/design.md) 把这类检查排在其他复查前面建议，出一道你没做过的练习题。独立做对了，疑点就消了。侧边会话不自己出题，也不判断你掌握了没有。

**主界面上提问：** 在主界面打开右侧栏时，先选"问哪门课"（默认上次选的课；在某门课的页面上选了内容时就是那门课），之后和课程里一样。这次会话、笔记和证据都属于那门课。

## 关键决定

- **侧边会话在所有页面可用，与主会话隔离，总结写入固定文件，修改只能通过主老师执行**（10-03，你）。
- **侧边会话里的讲解算作"帮助"**（10-03，你）。
- **侧边提问不用先点"开始提问"：直接输入第一个问题，发送时打开会话**（10-04，Claude 设计）。
- **A 批的范围和做法按调研复核采用**（10-10）：只读工具和测试期间的限制放在工具执行处判断，关闭的幂等不靠数据库的 UNIQUE 而靠步骤可重复，首轮上下文以持久记录为准，误解必须带原话（见上文"可靠入口与边界"）。
- **总结里没有原话依据的误解仍写进总结和笔记，只是不记信号**（10-10，按复核"原话找不到就不记信号"）：笔记里标"只作参考"。
- **每轮回答后就整理和记账，结束时只补没整理的部分**（10-11，Claude 按调研 B 批）：等结束才记，聊完马上去作答就会被算成独立完成；不结束的会话永远不记。做法和主老师的课堂记录一样，用会话的持久消息序号做截点。放弃了"结束时再整体总结一次"：那会让同一份帮助有两套来源。
- **一次会话里每个知识点最多一条提问信号**（10-11，Claude）：答疑里连着问几句是同一次疑问；按条记会让一次答疑就把知识点标成"有疑点"。
- **回答没写完时不能结束**（10-11，Claude）：截点只取落盘的完整消息，不在回答中途截断。
- **"离开测试"就是交卷**（10-11，Claude）：assess 没有、也不另做"暂停测试"的动作；想讨论题目就先交卷（不会的点"不会"），交卷之后的讲解按时间不影响这次作答，和主老师在测试期间的做法一致。
- **修改建议由侧边会话起草、你决定交不交，目标由程序认定**（10-11，Claude 按调研 C 批）：不扩提案的状态（不加"草稿"状态），草稿归 sidechat 自己存；题目和资料原文不走提案，各自有现成的处理入口。
- **主界面上提问先选一门课**（10-11，Claude 按调研推荐）：真正跨课程的会话（帮助怎么分到几门课）等边界明确后再做。

完整的决定和来源见[决策记录](../decisions.md)。

## 待定问题

- **整理对话的准确度。** 每轮多一次模型调用（只在这一轮有你的话或助手说了一段话时）；帮助的档位、误解的判断准不准，要用合成会话和你的试用来看，再决定要不要缩小知识点列表、调整整理的窗口。10-11 联调的 4 次会话里帮助档位、提问和明显的误解都判对了；有一条偏宽：你建议教材用"轮胎冬夏对比"举例（老师指出轮胎近似定容），也被记成了可能的误解。
- **作答独立性按提交时间判断**依赖 assess 记的交卷时间（`attempt.graded` 的 `at`）和 learner 的帮助窗口，侧边会话只负责把帮助的时间记对。
