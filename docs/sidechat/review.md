# 侧边会话调研报告复核

> 2026-10-10 · 复核对象：[侧边会话做深调研](research.md)（Codex，10-09）· 批注部分的复核见[批注复核](../annotation/review.md)，方法和范围相同。

## 结论

报告对代码缺口的判断属实，A 批（可靠入口与边界）的取舍可以采用。开发时要补三处报告没有写到的细节（下面第 1、4、5 条），其余按报告执行。

## 已核实的断言

| 报告的说法 | 核对结果 |
|---|---|
| `open` 先登记会话归属，再创建 DSH 会话、选模型；后两步失败会留下 active 记录 | 属实（`sidechat/src/index.ts` 的 `open`；`active` 只看 `closedAt`） |
| 首轮上下文用进程内 Set，且先加入再取上下文 | 属实；失败后这个会话再也不会注入上下文，重启后又会重复注入 |
| 侧边预设挂的 library 工具包注册四个工具，其中 `add_web_sources` 写入资料库 | 属实；`addWeb(…, 'teacher')`，提示词里的"两个只读工具"没有代码保证 |
| `close` 并发会重复生成并追加文件，已存总结时提前返回不修复后半段 | 属实（读代码得出，实现时用并发和故障注入测试复现） |
| `help.given` 的时间是关闭会话的时间 | 属实（`log.append` 没有传 `at`） |
| 总结把所有会话节点套给每条误解，误解没有原话依据 | 属实 |
| `linkOf` 只检查有课程，不检查角色和测试政策 | 属实 |
| 客户端 `open` 成功后 `sendPrompt` 失败，页面不刷新 | 属实 |

## 报告遗漏或需要补充的地方

1. **工具限制放在执行处，不放在预设里。** 预设挂的是整个 library 工具包，工具注册也是全局的，所以限制必须在工具运行时按会话角色和课程的测试状态判断。契约里用 `learnSidechat.checkTool(sessionId, tool)` 表达，library 的四个工具开头调用它；没有侧边会话单元时放行。
2. **测试状态能直接问 assess。** `learnAssess.tests(courseId)` 的 `status === 'open'` 已经够判断"有测试在进行"，不需要页面标题猜测，也不需要新契约。`restrictDuringTests` 是侧边会话的 `.volatile()` 配置项（默认开），避免遗留的未交卷测试把答疑永远锁住。
3. **首轮上下文以持久记录为准。** 持久会话里已有上下文消息就不再注入；Set 只是缓存。上下文生成失败时不标记已注入，下一轮重试。
4. **关闭的幂等不靠数据库的 UNIQUE。** 同一会话的并发关闭合并成一个任务；笔记文件里用 `- 会话：<ID>` 作标记，已有就不再追加；总结行和日志在同一个事务里写；已存总结但会话没关或通知没发的，下一次关闭补上。
5. **误解必须是学习者的原话。** 总结里每条误解带原话和自己的节点；原话在学习者消息里逐字找不到就不记信号。节点列表仍是全课程节点（报告建议缩小，需要先在合成会话上测召回，留在后续批次）。
6. **"提问时的版本"不另存。** 批注开侧边会话时，`Selection` 带的是批注自己的原句和说明（`page: 'annotation'`），由 annotation 的 `describe-selection` 补上；通用的版本快照留到 B 批。

## 本批（A）采用的范围

- 只读工具和测试期间的限制；创建失败时回收归属；首轮上下文可重试、重启后不重复。
- 关闭可重复执行；帮助按助手消息的时间记账；误解有原话和自己的节点。
- 页面：发送失败后刷新并保留草稿；设置页里 `restrictDuringTests` 的开关。
- 不做：及时记账（回复形成时记，不等关闭）、固定截点和分段总结、提案草稿与提交、主界面和跨课程会话、测试中"离开测试"的转换（依赖 assess）、按提交时间判断作答独立性（依赖 assess、learner）。
