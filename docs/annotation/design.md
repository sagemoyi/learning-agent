# 批注（annotation）

> 代码：[`packages/annotation`](../../packages/annotation) · 接口：[契约](../stage0/contracts.md) §4.5（Block、Annotation）、§5.1（`learnAnnotation`）和 §11 末尾的"批注与侧边会话做深的接口补充" · 验证：[验证记录](../stage0/compatibility.md#annotation-a批注的记录定位和界面10-10grok-bot)、[Claude 复核](../stage0/compatibility.md#annotation-与-sidechat-的复核和-tutor-c10-10claude) · 调研：[做深调研](research.md)、[复核](review.md)

批注负责你在教材和资料上划线、写批注：记下你选的原句，教材改过之后还能找到它，并把批注转成侧边会话、修改提案或"有疑点"信号。

## 现状

- **A 批已技术验收，待你试用：** Grok Bot 实现（后端、教材里的批注、"批注"页），Claude 10-10 复核后保留后端，重做了界面（正文里标出原句、段落下一行一条、批注页按课时分组），补上报错的去向（主老师核对后改正或说明理由，见 [tutor](../tutor/design.md) C）。在 3182 上用 DeepSeek 实测了报错→老师改正→批注显示结果，以及疑问→侧边提问→总结。批注转侧边会话后，右侧栏会自己显示新会话：`annotation` 在会话建好、批注关联上它之后发出 `learning/annotation-changed`，sidechat 的页面监听这个事件重新读取当前会话，见 [sidechat](../sidechat/design.md)。
- **还没做：**
  - 资料阅读器上的批注：资料页只有画布和出处框，没有文字层，PDF 文字和区域批注不在这一批；接口已支持资料片段锚点，页面入口还没有；
  - 跨段选区：一条批注只属于一个段落；
  - "我的理解"的模型反馈（对照资料评价你的解释，发现误解）；
  - 段落的历史版本：只存创建时的内容指纹，不存正文快照，更完整的历史归 textbook；

## 怎么用

- **写批注：** 在教材页点一段，或在段落里拖选一句话，再点"就这段提问"旁的"批注"，选疑问、我的理解、重点或报错。疑问、理解、报错写完点保存；重点选了就存，之后可以补一句。没选文字就是给整段批注。选中的文字碰到公式，会连整条公式一起选上（见下文"选区"）。
- **看批注：** 批注过的原句在正文里直接标出来：重点是黄色底，疑问是浅蓝底，我的理解是绿色点线，报错是红色波浪线。段落下每条批注一行（图标和内容），点开看全文和操作：编辑、删除（页面上去掉，已记下的疑问信号保留）；疑问可以转侧边提问、标为已解决。侧栏的"批注"页按课时分组列出本课所有批注，可按类型筛选，已解决的疑问默认收起；点"在教材里看"打开那一节并滚到那一段。
- **位置对不上的批注：** 教材改过以后，原句还在就跟着走；原句旁边的字改了、原句多处出现分不清、原句被改写，批注会标"位置待确认"，显示现在相近的文字，由你点"就是这里"。原段拆成几段、几段都有这句话时，从候选段落里选一段。原句已经不在教材里的，只留批注和你划的原句。待确认的数量显示在侧栏"批注"按钮上。
- **疑问：** 点"在侧边提问"，把你写的问题带着原句和所在段落转到侧边会话；同一条批注的会话还开着时，再点回到它。
- **报错：** 位置确定时自动交给老师（生成修改提案，目标是这段所在的课时文件，说明里带你的话、段落和原句）；位置不确定时等你确认位置后再交。老师在简报里看到它，对照资料核对：确有错就改那几段，批注上显示"老师核对后改正了"和改了什么；没有错就写明理由，批注上显示"老师核对后没有改"和理由。处理过的报错照常显示在批注页，不收起。资料片段里的错误没有可改的教材目标，明确拒绝并引到资料库页处理。

## 怎么运作

- **批注对象：** 课程、锚点（教材段落的块 ID 加创建时的内容指纹，或资料片段 ID）、块内的选区（原句和前后各约 24 字）、类型、内容、位置状态、去向（侧边会话、提案）、处理和隐藏时间。数据存在 `annotation` 的数据库表里，批注是信号，不是证据。
- **只信原句。** 块 ID 只说明去哪个段落找；位置不存偏移，每次读取时从原句和前后文推算（[`anchor.ts`](../../packages/annotation/src/anchor.ts)）：
  - 比较用的文字：Unicode NFC（不用 NFKC，上标和连字在公式里有意义），去掉不可见字符，空白合并为一个，中文字之间的换行不算空格；
  - 原句在段落里只出现一次，并且紧挨着它的前一个字和后一个字没变，才自动显示；"能忽略"变成"不能忽略"这种原句仍是子串的改动，也要你确认；
  - 出现多次，只有前后文明确偏向一处才自动显示，没有前后文或打平时由你确认；
  - 原句被改过，用编辑距离找最相近的一段当建议，只作建议，从不自动采用；
  - 段落被拆开或重写，沿 textbook 记的去向（最多 6 层）找新段落，几段里都找到就要你选；
  - 你确认过的位置在段落没有再变时一直有效。
- **读取时重新核对，不发事件。** `list` 每次按当前正文重新算位置，变了就静默保存；只有你的操作（新建、编辑、处理、隐藏、确认、转会话、提交提案）发 `learning/annotation-changed`，否则每个打开的页面都会因此无限刷新。
- **选区。** 页面上选中的是渲染后的文字，服务端比较的是教材 Markdown 去掉标记后的文字，两边要一致（[`selection.ts`](../../packages/shell/src/client/selection.ts)）：
  - 公式在页面里是 KaTeX 的标记，选区里一律还原成 `$…$` 源码；选区碰到公式的一部分，就扩成整条公式；服务端拒绝只含半个公式的选区；
  - 引用标签（出处小标签）不算正文，选区里不含；
  - 批注只属于一个段落：选区的一端落在段落外时在段落边界截断；从一个段落拖选到另一个段落时，页面不会改选中项。
- **疑问信号。** 疑问批注所在段落有知识点时，追加一条 `signal.question`，`ref` 为 `annotation:<批注 ID>`，每条批注最多一条；没有知识点的段落不记也不猜。编辑、隐藏、处理批注不改日志。
- **幂等。** 页面写一条批注时带 `requestId`，双击或重试得到同一条；疑问转会话同一时刻只开一个；报错每条批注最多一个提案。
- **侧边会话的上下文。** 批注转会话时选区是 `page: 'annotation'`、`selected.kind: 'text'`、`selected.id` 为批注 ID，`annotation` 补上你的批注内容、原句、位置状态（位置对不上时明说"以你划的原句为准"）和所在段落。
- **新批注的原句要逐字在段落里**（空白不计）：只是相近的文字直接拒绝，不会生下来就"位置待确认"。
- **正文里的标记**（[`marks.ts`](../../packages/annotation/src/marks.ts)）：用浏览器的 CSS Custom Highlight API 给原句上色，不改动教材的 HTML。页面按服务端读 Markdown 的方式读渲染后的段落（公式还原成源码、出处标签不算、空白同样处理），找到原句再画；公式是一个整体，选到就整条标出。只标位置确定、还没处理完的批注；浏览器不支持时不画，段落下的列表照常显示。
- **界面接入。** 教材阅读器只留 `learning.reader-notes` 插槽，批注菜单、段落下的批注和正文里的标记由 `annotation` 画；没有 `annotation` 时这个插槽为空，阅读器照常使用。批注页和阅读器共用一个模块级的读取，一个课时的许多段落只读一次。页面读到的批注带着报错的处理结果（状态和老师的说明）和疑问的侧边会话是否还开着。

## 关键决定

- **只存原句和前后文，位置推算出来**（10-10，复核）：块 ID 加原句才算找到；保守，宁可让你确认也不挂错。放弃了"锚定到块 ID 所以修订后不会丢"的说法：记录不会丢，位置要看原句是否还在。
- **疑问信号靠 `ref` 幂等，不扩日志格式；报错提案的目标是课时文件**（10-10，复核）。
- **内容版本只存创建时的指纹**（10-10，复核）：`Block.hash` 加 textbook 的段落去向够用；完整历史版本留给 textbook。
- **原句标在正文里，段落下一行一条**（10-10，Claude 复核时改，取代 Grok Bot 的"只放在段落下"）：读教材时卡片式的批注会把正文切碎；用 CSS Highlight 标原句不碰教材 HTML，公式和出处标签按服务端同样的读法处理，测试覆盖了这种对应。
- **"已解决"只给疑问，删除就是隐藏**（10-10，Claude）：重点和理解没有"处理完"一说；删除后记录和已记下的信号保留，你在页面上看不到。处理过的报错由老师的决定收尾，照常显示结果。
- **教材页只留插槽，批注界面归 annotation**（10-10）：教材不 import 批注代码，选区转换放在共享的 Markdown 渲染里。

完整的决定和来源见[决策记录](../decisions.md)。

## 待定问题

- 一段里批注很多时，段落下的列表要不要折叠成"N 条批注"；等试用。
- 没写字的"重点"在批注页里信息很少，要不要合并显示；等试用。
- 点正文里标出的原句要不要直接打开那条批注；先看试用时是否需要。
- 资料阅读器的文字层和区域批注，等资料库页面有文字层之后再做。
- "我的理解"的模型反馈要不要做、用什么量规，见[调研](research.md)第 3 节；做之前要先有合成数据评价。
