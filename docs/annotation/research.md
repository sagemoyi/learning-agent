# 批注做深调研

> 2026-10-09 · 对应 PLAN 的 `annotation + sidechat` · 状态：调研完成，推荐设计和验收草案尚未实现。
> 依据：[总体计划](../PLAN.md)、[批注设计](design.md)、[学习流程](../journey.md)、[契约](../stage0/contracts.md)，以及下文的一手研究、标准和开源源码。侧边会话的帮助记账、总结与提案链路见[配套调研](../sidechat/research.md)。
> 范围：只研究批注定位、四类批注、学习信号、资料阅读和交互。不修改产品代码、Curriculum 或共用进度文档；不读取真实学习数据，不调用模型或付费服务。源码结论来自 10-09 工作树的相关单元；并行开发的 Curriculum 不在本报告验收范围内。

推荐先做到两件事：**批注始终能找回原件；系统只有在能确认位置时才把它挂到当前正文。** 在此基础上，疑问和自我解释进入答疑与检查流程，报错进入修改提案流程。划线、批注字数、模型认可和“已处理”都不能成为掌握证据。

## 1. 结论与取舍

| 问题 | 推荐项 | 理由与限制 |
|---|---|---|
| 数据归属 | annotation 持有批注及定位结果；textbook 持有块身份和修订对应；library 持有资料与快照 | 批注单元不重建教材索引、资料解析器或第二份证据日志 |
| 教材锚点 | 课程、块身份、内容版本，加原文及前后文；位置偏移只作为加速提示 | 保留块 ID 能保住段落身份，不能保证段内原句还在 |
| 导入资料 | 绑定原始快照与片段；PDF 区域绑定原始页面坐标 | 重解析和缩放不应把旧批注转挂到不同内容 |
| 重定位 | 唯一且可验证的匹配才自动定位；多候选或语义变化请用户确认 | 相似度最高不代表原意相同，理工公式尤其敏感 |
| 自我解释 | 在关键推导、条件判断和常见误解处有选择地用 | 不要求每段写心得；解释流畅仍需独立作答验证 |
| 四类后续 | 疑问可转侧边提问；理解可产生待核实信号；重点供导航；报错生成提案 | 分清批注、帮助、证据和修改权限 |
| 高亮显示 | 优先评估原生 CSS Highlight，保留可访问的列表入口和降级显示 | 先验证实际浏览器能力；规范草案中的接口不能直接当作可用能力 |
| PDF 实现 | 复用现有 PDF.js、出处定位与坐标转换，逐步补文字层和区域选取 | 当前阅读器只有画布和出处框，尚无可选中文字层 |
| 引入依赖 | 参考 Hypothesis 算法和用例；暂不整套引入注释客户端或另一套 PDF 阅读器 | 保留本产品的信息架构，避免双份 PDF.js、状态和样式 |

本表是应用建议，不能直接当作已经采纳的契约。涉及版本、区域锚点、操作幂等和信号更正的字段，应在开工时形成最小契约补充。

批注设计中“锚定到段落块 ID，所以教材修订后批注不会丢”需要拆成两项验收：**记录和原件可恢复；当前正文位置可正确确认。** 两者可能分别成功和失败。报告不把静态缺口写成已复现事故。

## 3. 学习科学：批注怎样帮助学习

### 自我解释应针对因果、条件和推理

Bisra 等 2018 年元分析汇总 64 篇报告的 69 个效应，随机效应平均效应量为 `g = 0.55`。自我解释要求学习者生成概念联系或推理，而非照抄原句。本次可核对的是出版社公开摘要，未取得付费全文，不能据此指定某种中文理工提示的最佳长度或频率。[Inducing Self-Explanation: A Meta-Analysis](https://link.springer.com/article/10.1007/s10648-018-9434-x)

**应用建议：** “我的理解”优先放在为什么可以忽略某项、公式适用条件、变量变化如何影响结果、两种概念如何区分等位置。老师可邀请学习者解释一个关键步骤，再反馈一个明确问题；不把每个段落都变成必填表单。

例如合成材料里的流动模型，可以问“这里为什么能忽略高差？条件变了会怎样？”回答先保存为学习者陈述。若回答缺少稳态、适用范围或量纲等条件，记录具体的待核实点，再由后续独立题验证；不能因模型说“理解正确”就提升状态。

### 更贴近数字学习的证据，以及反例

Tan 等 2025 年三层元分析纳入 56 项研究、204 个效应，报告总体 `g = 0.46`，延迟测量 `g = 0.35`；概念或混合知识的效果强于程序知识。其对照是没有自我解释的条件，不等于所有研究都控制了额外学习时间或比较同时间的主动练习。本次只核对出版社公开摘要，不能把调节分析直接变成个人的提示频率算法。[数字学习环境中的自我解释元分析](https://link.springer.com/article/10.1007/s10648-025-10001-x)

Zhang 与 Fiorella 2024 年物理反馈实验分别有 131、110 名参与者。第二个实验中，有具体支架的自我解释改善错误纠正和近迁移，普通解释提示未显著优于无提示对照；没有观察到远迁移优势。出版社全文读取未成功，本次结论限于公开摘要，不推测未读到的操作细节。[Effects of self-explaining feedback on learning from problem-solving errors](https://doi.org/10.1016/j.cedpsych.2024.102326)

Harders 等 2026 年预注册研究最终分析 208 人，控制学习时间，比较解释虚构事实与重复阅读，并测即时及两周后的事实记忆；未发现两种策略有显著差异。正确推论的数量与表现相关，但这个相关关系不证明要求多写推论会提高成绩。任务与本项目的理工推导不同，不能据此否定所有自我解释。[No Causal Self-Explanation Effect for Factual Knowledge](https://onlinelibrary.wiley.com/doi/full/10.1002/acp.70174)

**应用建议：** 保留自我解释，但限定它要完成的推理动作。概念关系、适用条件、错误原因值得解释；孤立名词、记忆事实或学习者已经能独立完成的机械步骤，不默认加一条“写下你的理解”。让学习者可以跳过；没有思路时先给最少支架，不把一份空白解释判成不会。

这些结果并不矛盾：对照活动、学习时间、解释质量和测量目标不同。可采纳的是“有选择地促成可核对的推理”，不能采纳“凡是写批注都有增益”或某个元分析效应量就是本产品的承诺。

### 评估解释需要小型量规，不能只比较相似度

2024 年 BEA 的 EXPLAINIT 研究使用课堂中的编程解释、教师量规和示例答案，比较微调与少样本模型；论文把跨学科、概念级反馈及学习效果列为后续工作。2025 年物理解释评分研究使用三道题的逐项量规，针对初始误判补充说明，并比较五次评分的一致性；这些条件不能简化为“给一个标准答案，通用模型就会诊断理解”。[Assessing Student Explanations with Large Language Models](https://aclanthology.org/2024.bea-1.33.pdf)、[Grading explanations…](https://journals.aps.org/prper/pdf/10.1103/PhysRevPhysEducRes.21.010126)

EDM 2025 的学习策略评分工作把复述、概念桥接、扩展、监控和误解等维度分别标注。不同维度的表现差异很大；同一模型“误解”分类的高分不能推成整体解释质量已可靠。其主要实验依赖标注数据微调，不是本项目未训练模型的零样本保证。[One Model to Score Them All](https://educationaldatamining.org/EDM2025/proceedings/2025.EDM.short-papers.109/index.html)

推荐的量规如下，全部是应用草案，不形成掌握分数：

| 检查维度 | 合成示例与判定边界 | 面向学习者的反馈 |
|---|---|---|
| 是否只是复述 | “稳态时不随时间变”重复定义，没有解释为何此处能用 | 允许记录为笔记；需要解释时再问具体条件，不扣分 |
| 是否建立正确关系 | “控制体质量不积累，因此总流入等于总流出”，要核对质量/体积区分 | 指出已说明的关系与尚缺条件 |
| 是否保留条件 | 从某个特例推广到所有流动，忽略密度变化或外部做功 | 原句、缺条件与一个可检验反例，不笼统标“理解差” |
| 是否有符号和单位依据 | 使用近似相同字形或未定义变量 | 不根据文字流畅推断数学正确；无法核对就标待核实 |
| 是否为学习者自己的观点 | “书上说不成立，我原来以为成立”包含引用和旧观点 | 分开引用、旧观点和当前结论 |
| 原文是否足以判断 | 来源没有覆盖所讨论条件，或资料之间冲突 | 保留未知和缺口，不因模型知道答案而补出处 |

只输出可追溯的“已有依据、缺少说明、与依据冲突、无法判断”等反馈。学习者提出另一种正确推导时不能因不贴标准措辞判错；语言简略、错别字、混合符号和中文表达都要进入评估。后台分类只作候选，不把评分模型的自报置信度当正确概率。

最小交互可以是：选一条关键原句 → 邀请说明一个因果或条件 → 反馈一个具体缺口 → 必要时进入侧边答疑 → assess 后续无帮助新题。提供过解释或例子就记帮助；对事实记忆直接安排检索练习，不额外要求写长解释。

### 重点标记适合找回内容，学习收益需要另一种验证

Dunlosky 等 2013 年综述将划线、突出重点的普遍学习效用评为较低，自我解释为中等，练习测试与分散练习为较高。结论不等于划线在所有情境无用，也没有否定它的导航价值。[Improving Students’ Learning With Effective Learning Techniques](https://journals.sagepub.com/stoken/rbtfl/Z10jaVH/60XQM/full)

**应用建议：** 重点批注提供快速回看、过滤和出处跳转。不要因划线数量、颜色、阅读时长或重访次数而提升掌握。复习安排由 planner 按证据决定，批注只提供“这里需要关注”的线索。

### 误解是可检验假设

“如果压力一样，是不是速度也一样？”是探索性问题；“书上说这个不成立，我不懂为什么”是引用加疑问；“我之前认为这个成立，但现在知道条件不满足”包含已纠正的旧观点。三者都不能直接写成“学习者相信压力相等必然速度相等”。

推荐给待核实信号保留学习者原句、目标知识点、原件位置、判定理由和后续检查状态。提出检查题的流程见[sidechat 调研](../sidechat/research.md#8-误解检查与修改提案)。批注单元不另建题库，不凭信号认定缺乏掌握。

## 4. 标准与开源实现

### W3C：选择内容与指定版本分别处理

Web Annotation 用 selector 描述资源的一部分，用 state 描述资源的表示状态；TextQuote 保存原文及前后文，TextPosition 保存文字位置，并提醒位置对内容变化敏感。文字选择基于规范化后的文本。标准也讨论多个匹配，并不要求所有产品都采用“歧义则拒绝自动挂载”。[Web Annotation Data Model，§4.2–4.3](https://www.w3.org/TR/annotation-model/)

**应用建议：** 使用与本产品相适应的小型契约，不引入整套 JSON-LD。由于错挂可能影响误解判断和教材修改，本产品应选择更保守的自动定位政策：多个候选标为“需要确认位置”。这是产品取舍，不是 W3C 的强制规定。

### Hypothesis：多种选择器与逐步回退

HTML 实现先尝试范围和位置，再用原文核验，必要时回退到 quote；quote 匹配结合前后文和位置提示，也容许近似字符匹配。源码提供了比“全文搜索第一次出现”更完整的处理方式。[HTML anchoring](https://raw.githubusercontent.com/hypothesis/client/main/src/annotator/anchoring/html.ts)、[quote matcher](https://raw.githubusercontent.com/hypothesis/client/main/src/annotator/anchoring/match-quote.ts)

**应用建议：** 借鉴匹配分层和反例，保留确定性校验。近似匹配只产生候选位置，不能直接越过符号、否定词或数值变化。本项目无需照搬它的编辑距离阈值。

Hypothesis 的 PDF 实现处理页文字缓存、页间定位和尚未渲染的页面，但依赖它所适配的 PDF viewer 结构，不是可以直接放进当前 canvas 阅读器的函数。主 LICENSE 使用两条款再分发条件，annotator 部分另有 MIT 条款；若复制代码，应逐文件确认适用许可并保留声明。[PDF anchoring](https://raw.githubusercontent.com/hypothesis/client/main/src/annotator/anchoring/pdf.ts)、[LICENSE](https://raw.githubusercontent.com/hypothesis/client/main/LICENSE)

### 把开源参考追到实际调用链

Hypothesis 固定核对提交 `b4d085a2f893aa6de3b61d8b8bc3ae4d0f24fc1a`。HTML anchor 收集选择器，以位置作为 quote 提示，并在 Range/Position 成功后检查所取文字与 exact；失败才继续回退。规范化工具同时维护规范化前后位置映射，PDF 路径使用页文字缓存和 quote/offset 缓存。[固定版 HTML anchor](https://raw.githubusercontent.com/hypothesis/client/b4d085a2f893aa6de3b61d8b8bc3ae4d0f24fc1a/src/annotator/anchoring/html.ts)、[规范化与偏移](https://raw.githubusercontent.com/hypothesis/client/b4d085a2f893aa6de3b61d8b8bc3ae4d0f24fc1a/src/annotator/util/normalize.ts)、[PDF anchor](https://raw.githubusercontent.com/hypothesis/client/b4d085a2f893aa6de3b61d8b8bc3ae4d0f24fc1a/src/annotator/anchoring/pdf.ts)

**应用建议：** 复用“候选定位后再次核验”和“规范化仍能映回原文”的原则。不要直接将其 Unicode 分解当作本产品所有数学文本的等价关系：例如兼容规范化可能改变上标表示，必须由公式适配器保住语义。缓存应以目标资料/版本区分，不能把浏览器里另一份 PDF 的同页内容拿来恢复锚点。

PDF.js 本身也值得先比较。`v6.3.289` 的 TextLayerBuilder 通过 streamTextContent 构建文字层，把文字节点与原文字项关联；render、update、cancel 与缩放和节点清理相互配合，复制文字还有 Unicode 规范化。TextLayer 与 viewer builder 的职责不同，不能只加几个透明 span 就假定选择、缩放和生命周期都已正确。[TextLayerBuilder](https://raw.githubusercontent.com/mozilla/pdf.js/v6.3.289/web/text_layer_builder.js)、[TextLayer](https://raw.githubusercontent.com/mozilla/pdf.js/v6.3.289/src/display/text_layer.js)

内置 HighlightEditor 已有 quadPoints、页面位置、旋转和序列化，但关联 editor layer、UI manager 和 viewer 行为。它适合参考几何和选取用例，整套接入仍需把数据转为本产品的批注、快照和课程情境，不能让内置 PDF 备注成为第二份主人数据。[HighlightEditor](https://raw.githubusercontent.com/mozilla/pdf.js/v6.3.289/src/display/editor/highlight.js)

后续原型应比较三条路线的净维护成本：现有 canvas + 同版本 TextLayer + 本产品覆盖层；接入同版本原生编辑层；整套第三方高亮阅读器。比较实际需要的胶水、主题、键盘、撤销、虚拟页和持久化转换，不按 README 功能数选。首选第一条是当前规模下的推荐，尚无原型证明它成本最低。

## 5. 推荐的锚定与恢复规则

### 目标身份、选择范围、定位结果分开

目标回答“哪一份材料的哪个版本”；选择器回答“其中哪一段文字或区域”；定位结果回答“当前视图能否可靠展示”。推荐的数据责任如下，字段名称只是契约候选：

| 信息 | 主人 | 最小内容 |
|---|---|---|
| 教材目标 | textbook 提供，annotation 引用 | courseId、blockId、内容版本或可回溯版本键、当时内容指纹 |
| 资料目标 | library 提供，annotation 引用 | chunkId 所属的 source/snapshot 身份；旧快照可读 |
| 文字选择 | annotation | exact、prefix、suffix；规范化算法版本；可选位置提示及其单位 |
| PDF 区域 | annotation；通过 library 定位原件 | 原快照、物理页序号、原始页坐标、坐标单位和基准；允许多个矩形 |
| 学习情境 | annotation | 批注产生于哪门课、课时或题目；独立于原件是否跨课程共用 |
| 定位结果 | annotation，可重算 | 可定位、需要确认、只可看原件、原件不可用；原因、候选和确认记录 |
| 后续关联 | 各主人服务 | 会话、提案、日志关联；重复点击不会多建一份 |

不要把屏幕像素、DOM XPath 或当前段落序号当成持久目标。当前 chunk 锚点没有课程字段，应在批注记录的情境里补充课程归属；不能因为资料在多门课共用，就把一次疑问广播给所有课程。

### 规范化必须可以解释和回溯

原始 Markdown、实际可见文字和 KaTeX 的视觉/辅助表示并不相同。推荐共享选择适配器输出一份可检索文本，并维护到源内容及 DOM 的映射：排除块标记、界面按钮和重复数学表示；引用标签作为显示内容时有一致的处理。

必须明确空白、换行、HTML 实体、Unicode 和偏移单位。JavaScript UTF-16 偏移不能直接冒充标准中的字符计数；中文、组合字符和代理对要进入测试。算法升级应带版本，旧选择仍能解释。

公式保留语义敏感信息。`p` 与 `ρ`、正负号、上下标和单位不能靠宽松文本相似度等同。不能可靠映射部分公式时，允许明确选择“整条公式”或“整段”，界面展示实际范围；不要宣称保存了用户划出的半个公式。

### 重定位按证据回退

1. 在原目标、原版本上验证 quote 和范围，保住当时读到的内容。
2. 对当前仍有同一身份的块，核对内容版本；位置提示须重新验证 quote。
3. 在同一目标内寻找 exact，结合前后文排除重复候选；唯一且一致才自动显示。
4. 目标已拆分、合并或替换时，先用 textbook 的修订对应缩小范围，再验证原句；对应关系本身不证明句子语义未变。
5. 只有近似候选、多个候选或选中句已删除时，保留原引文和原件入口，让用户确认或重新定位；不得默认取第一个结果。

批注记录可以保存成功，而当前定位失败。界面应明确这两个结果；用户回看和纠正位置不应再产生一条提问信号。

### PDF：原件坐标与语义选择分别验证

文字 PDF 需要文字层及其 Range 到页坐标的映射；跨行或跨页选取保存多个矩形。显示坐标由当前 viewport 推算，缩放或旋转后重新计算。页码标签可能不同于物理页序号，应同时保留显示页码和明确的定位基准。

扫描 PDF 没有可靠可选文字时，可选择已有解析片段或圈选区域。区域保存不需要另接 OCR；若学习者针对图中内容提问，使用 library 提供的原件/裁剪和既有图片输入链路。OCR 文本与页面不一致时，以所保存的区域和原件为准，并显示待核实文字。圈到同页习题或答案区域时，需遵守[测试边界](../sidechat/research.md#5-只读权限与测试独立性)。

## 6. 四类批注的作用链

| 类型 | 保存与反馈 | 转化规则 | 不允许的推断 |
|---|---|---|---|
| 疑问 | 原文、问题、情境；可标已处理 | 关联节点有依据时追加一次提问信号；用户可一键打开隔离会话 | 问一次就不会；问题解决就已掌握 |
| 我的理解 | 保留学习者自己的解释，反馈指出具体条件或推理 | 必要时形成待核实误解，交后续检查；仅批注编辑不重复计信号 | 模型认可即独立作答成功 |
| 重点 | 可以无文字，供筛选和跳转 | 不自动产生帮助、误解或掌握证据 | 划线多即理解多 |
| 报错 | 原句、错误描述和可选依据，标明涉及教材或题目 | 自动形成修改提案，归 core 保存、tutor 评估，主人单元修改 | annotation 直接改教材、答案、图谱或课程 |

疑问批注打开 sidechat 时，传用户实际选中的 quote、批注问题和原件版本。双击、网络重试和刷新恢复以同一请求身份复用关联；“本问题已关联一个会话”和“再开一个新问题”应是不同的操作。

报错自动形成提案是已确认方向；定位不清时先明确目标，不能猜一个节点或题目硬凑 `targets`。提案的待评估、被拒绝和已应用状态应可见。“我的理解”得到讲解时，由 sidechat 或实际给帮助的单元记账，annotation 不重复记录同一回复。

理解反馈优先复用关联的 sidechat，避免新建另一套答疑提示、帮助档位和消息历史。若需要后台初筛，只输出有原句依据的候选，通过 kit.complete、parseJsonReply 和所属角色的 roleModel 调用；没有依据时保留未知。后台结果不自动变成面向学习者的讲解。若 annotation 自己直接提供教学帮助，现有 help.given.via 没有 annotation 值，需要先明确最小契约扩展，不能冒写为 teacher。

批注正文可以编辑，显示状态可以收起或恢复；已经写入的学习证据不可改删。若需要纠正错误信号，追加更正并由 learner 按版本规则重算，当前日志尚无通用信号撤销契约，需先补设计。单纯隐藏批注不得悄悄撤销历史证据。“已处理”只说明批注流程完成。

## 7. 交互与无障碍建议

正文划选后出现靠近选区的四类入口；键盘也能从块菜单或批注列表建立整段批注。点击出处仍打开原件，选取文字时不误触整块提问。跨块范围首批可拆成多个目标或明确限制，不能静默截掉后半段。

保存成功、定位失败、提案生成失败分别在操作位置提示，并保留草稿。列表至少可按类型、未处理和定位问题筛选；打开项可返回原位置。重叠高亮通过列表选择具体批注，不依靠颜色区分类型；深浅主题都能看清选中、焦点和当前项。

760 宽度下批注编辑器与侧边答疑按同一外壳规则打开，避免两个弹层遮住正文。关闭面板只收起界面，不能等同于结束会话或解决批注。共享控件、字号和颜色遵守 [learning-ui-review](../../.agents/skills/learning-ui-review/SKILL.md)，实际实现后再做三宽度、两主题截图与键盘验收。本次没有做视觉验证。

## 8. 精简候选与保留项

按 [learning-simplify](../../.agents/skills/learning-simplify/SKILL.md)只列候选，不执行删除。

| 候选及归属 | 生产者 → 使用者证据 | 可减少什么 | 保留理由、损失及条件 |
|---|---|---|---|
| 教材“前 200 字”伪选区，textbook | 教材点击生成 Selection.quote；sidechat 的教材 describe-selection 读取整块，未使用 quote | 用真实范围或明确整段选择替代，减少两种含义不一致的选区 | 整块点击入口有用，应保留；更换前要同时验收 quote 消费，不能只改字段 |
| 多套选取逻辑，shell/各页面 | 已有 Markdown 块和 shell Selection；PDF 有独立坐标工具 | 共用 Selection 交接与选择反馈，避免每页重新实现浮动菜单 | DOM 文字与 PDF 坐标必须保留各自适配器；仅统一菜单不能省掉映射 |
| 另建 PDF 阅读器或批注证据库 | 当前 library 是原件主人，core 是日志主人 | 不新增第二份资料状态、证据库和 worker 管理 | 属于排除的架构备选，不是现有可删代码；区域能力不足应补主人接口 |

四类批注、版本追溯、待确认定位、proposalId 和 sideChatSessionId 是有意保留的设计，不因当前无包或无消费链而删接口。把错误候选直接丢弃也不属于精简。

## 9. 推荐验收矩阵

这些是开工前草案，全部尚未执行。确定性规则由自动测试验证，选区与几何由浏览器验证，模型反馈另用合成数据评价。

| 场景 | 必须观察到的结果 |
|---|---|
| 同段或不同段重复出现同一句 | 位置提示失效后不默认匹配第一处；有歧义显示待确认 |
| 未变段落移动、前面插入内容 | 保持目标身份，quote 对应原句；偏移变化不导致错挂 |
| 只修改块内一小句 | 未改原句仍可定位；被改原句保留原版本并要求确认 |
| 公式负号、指数、数值或“不能”被修改 | 不以近似匹配自动宣布原义一致 |
| 段落拆分、合并、删除、再恢复 | 修订对应与 quote 一起验证；没有唯一结果时可看原件且记录不丢 |
| KaTeX、引用、表格、中文代理对与换行 | 保存范围和实际可见选择一致，数学表示不重复，规范化可回溯 |
| Unicode 上标、连字、组合字符及规范化升级 | 可以映回原字符；位置单位明确；数学含义不被折叠 |
| PDF 在不同缩放及 0/90/180/270 度旋转 | 原页位置不变，显示矩形正确，无屏幕坐标持久化 |
| PDF 换页、缩放中取消、重复打开另一本资料 | 旧任务不回写新页，文字层与画布一致，缓存不跨目标污染 |
| 跨行、跨页文字及扫描区域 | 保存完整范围或明确限制；扫描图没有伪造精确文字锚点 |
| 资料重解析、解析服务停用 | 旧批注仍指向原快照；不自动迁往新片段 |
| 批注保存重试，疑问双击转会话，报错重试 | 每次逻辑操作一份记录和关联，信号、会话与提案不重复 |
| 写完“我的理解”或标重点 | 掌握状态不提升；模型反馈和知识证据分别显示 |
| 引用错误观点、反问、已纠正陈述 | 不确定诊断误解；检查假设保留原句与理由 |
| 正确但措辞不同的解释、纯复述、资料不足 | 分别反馈，不因相似度低判错，不因表达流畅认定正确 |
| 编辑或隐藏已经形成信号的批注 | 证据历史仍在；需要更正时追加记录，重算可解释 |
| 非本课块、共享片段和无课程范围 | 验证权限与情境，不向所有课程散播信号 |
| 保存成功但提案/会话创建失败 | 批注可找回，失败有具体原因，重试不会重新计数 |
| 键盘、窄屏、双主题和高亮 API 不支持 | 可建立、定位、编辑批注；列表仍可用，焦点可见 |

完整的“教材修订后定位”验收依赖 textbook 的稳定身份与历史版本能力。没有该能力时只能验收固定版本的批注，不应关闭修订恢复验收项。

## 10. 下一步的推荐边界

两个单元的联合分批和跨单元依赖统一写在[sidechat 调研](../sidechat/research.md#10-推荐分批与依赖)，本报告不另写一套计划。annotation 的首要工作是可恢复的批注与可解释的定位，然后接疑问、自我解释和报错作用链。

后续需要验证：本机 Chrome 对高亮与命中接口的支持；公式选择适配器；PDF.js 6 的文字层和原页坐标往返；扫描区域输入模型的实际效果。没有这些实测，不选定新依赖，不宣称批注改善了保持或迁移。

## 11. 证据覆盖与调研停止点

这是定向的设计前调研，不是声称穷尽文献的系统综述。检索覆盖了自我解释效果及反例、反馈支架、解释评估、锚定标准与实现、PDF 选取和高亮候选；只用论文、标准、作者公开资料及官方源码支持技术结论。语言词汇 gloss、多人社交批注与视频批注的收益不直接用于本项目单人理工阅读，未据此扩展功能。

| 要决定的问题 | 本报告已有依据 | 仍需验证，不能预先关掉的项 |
|---|---|---|
| 批注能否直接当掌握证据 | 既有 PLAN 和证据规则；解释研究没有提供这个授权 | 独立作答、保持与迁移仍由后续证据验证 |
| 怎样恢复位置 | 标准、固定源码、目标版本与数学反例 | 真实 DOM/PDF 范围映射、重叠批注和改写恢复 |
| 自我解释是否应强制每段 | 多项效果证据、主动对照反例、近/远迁移差异 | 本人使用时的负担与帮助程度，统一试用时观察 |
| 怎样评估理解 | 学科量规研究、逐维标注及明确误判反例 | 中文理工模型的逐项精确率、召回率和拒判表现 |
| 用哪套 PDF 批注实现 | 已追源码、版本及数据主人边界 | 三路线原型的兼容、交互和净维护成本 |

2018、2025 两篇自我解释元分析仅核对公开摘要；2024 反馈实验限于公开摘要及索引中的结果。2026 主动对照实验、解释评分论文、标准和所列源码可读取更完整内容。报告明确保留访问和实验限制，不能把“查到一篇论文”算作理解了全部实验细节。
