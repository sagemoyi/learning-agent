## 报告遗漏或需要修正的地方

1. **"原句在原段里就算找到"会错挂。** 报告的验收矩阵要求负号、否定词、数值被改时不自动宣布一致，但只讲了近似匹配。精确子串匹配同样会错：原句"能忽略"在改成"不能忽略"后仍然作为子串出现。定位时必须同时核对紧挨原句的前后一个字，改了就要用户确认。
2. **重新计算定位不能发事件。** 页面的 `useLoad` 默认收到任何 `learning/` 推送就刷新，列表读取时若因定位变化发事件，会让每个打开的页面无限刷新。定位结果只静默保存，用户的操作（新建、编辑、确认）才发 `learning/annotation-changed`。
3. **公式只能整条选。** 页面上选中的是 KaTeX 渲染出的文字，和教材 Markdown 里的 `$…$` 源码不是同一串字。报告说"选半个公式要明确限制"，需要再落到数据上：quote 里的公式一律是源码，客户端选区碰到公式就扩成整条公式。
4. **"疑问"信号的幂等需要落地。** 日志的 `signal.question` 已有 `ref` 字段，用 `annotation:<批注 ID>` 就能做到每条批注最多一次，不用扩日志格式。信号挂的是批注所在块的知识点；没有知识点的段落不记信号，也不猜。
5. **报错提案的目标。** `ChangeTarget` 没有"教材段落"一类，教材段落由它所在的课时文件承载，用 `{ kind: 'file', courseId, path }`；资料片段的报错没有可改的目标，应明确拒绝并指向资料库页，不能硬凑。
6. **版本字段的取舍。** 报告建议"内容版本或可回溯版本键"。当前 `Block.hash`（内容指纹）加 textbook 的 `revisions`（段落去向）已经够做固定版本验收和拆分后的查找；更完整的历史版本留给 textbook。批注只保存创建时的指纹，不另存正文快照。
7. **测试期间的限制缺一个动作。** 报告和 assess 设计都写"离开测试后可讨论，这次作答记为有帮助"，但 `assess` 目前没有"学习者离开测试并记帮助"的接口，只有教师的 `withdraw`。侧边会话本批只做到：测试进行中只说明操作；"离开测试"的转换依赖 assess，记为待接续，不在侧边会话里自造。
8. **模型回复的时间。** 报告把"帮助发生时间"归为核心缺口，核实后，DSH 的会话事件自带 `seq` 和毫秒时间，帮助日志可以用它作 `at`，不需要新契约。

## 与已有设计的矛盾

## 本批（A）采用的范围

采用报告第 10 节的 A 批，并按上表调整：
