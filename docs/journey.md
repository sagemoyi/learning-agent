# 一门课的完整流程

> 从你的角度，把一门课从建课到结课走一遍。每一步的具体设计写在负责它的单元文档里，这里只写流程本身，以及跨多个单元的两件事：一个课时怎么走、所有修改怎么走。

```
建课 ─→ 目标确认 ─→ 摸底 ─→ 课程路线 ─→ ┌──────── 阶段循环 ────────────────────────┐ ─→ 结课
 │      （含调研）  （探边界）（粗，到阶段级）│ 阶段设计 → 教材 → 课时×N → 阶段测试 → 复盘  │
 │                                       └──────────↑ 复盘决定下一阶段怎么写 ─────────┘
 └ 导入资料（随时可以补充）
```

| 步骤 | 做什么 | 设计在哪 |
|---|---|---|
| 建课 | 在主界面新建课程，一门课对应一个项目文件夹 | [core](core/design.md) |
| 导入资料 | 随时可以补充；也可以先不导入，由老师在调研时推荐 | [library](library/design.md) |
| 目标确认 | 先给几个候选终点让你挑，写成目标说明；同时调研、搭初版知识模型、收集题源 | [goal](goal/design.md) |
| 摸底 | 一次一题，沿先修关系往上探、往下查，十题以内探出你的知识边界 | [assess](assess/design.md) |
| 课程路线 | 切成几个阶段，只写到阶段标题和目标 | [curriculum](curriculum/design.md) |
| 阶段设计 | 先定阶段验收和测试蓝图，再定内容（逆向设计），写下本阶段的核心知识点，你确认后生成教材；老师按小节把这一阶段的知识细化进知识模型。从第 2 阶段起，开头先做三五道前测 | [curriculum](curriculum/design.md)、[knowledge](knowledge/design.md)、[assess](assess/design.md) |
| 阶段教材 | 为你定制，每块都有出处 | [textbook](textbook/design.md) |
| 课时 × N | 按小节推进，学一节停一次（见下文） | 本文件 |
| 阶段测试 | 程序按核心知识点组卷，独立完成，含没见过的新题、一道完整任务题和前面阶段的题；结果按知识点逐个给出 | [assess](assess/design.md) |
| 阶段复盘 | 程序按核心知识点摆出结果和默认建议，老师写复盘，你决定先补课（插入一个补课阶段，只补没过的知识点）还是进入下一阶段（没过的记为风险，有对有错的带进下一阶段补验证）；需要时调整后面的路线或重新审视目标 | [curriculum](curriculum/design.md) |
| 复习与回归 | 课时之间按掌握证据建议做一道没做过的题（每天有上限，可以不做），阶段测试带前面阶段的题；隔几天回来先回顾上次学到哪，再接着学 | [planner](planner/design.md) |
| 结课 | 所有阶段完成后，程序按目标的每条"能做"出结课检验（没见过的新题，完整任务题优先，再加一两道以前带过来的风险）；老师按条目写课程报告：做到了、做到了但还缺证据、还没做到、没测到，各附依据；课程标为已结课，之后加新阶段还可以接着学 | [curriculum](curriculum/design.md)、[assess](assess/design.md) |

有考试的课程会给目标挂上"考试档案"，上面不少环节会多做几件事，见 [goal](goal/design.md)"考试档案"。往年试卷按题号进题库，考试临近时可以做限时的模拟考，题型、题数、分值和时长按考试档案，结果按题型给分（[assess](assess/design.md)）。

学习过程中，你随时可以在右侧开[侧边会话](sidechat/design.md)提问，在教材上写[批注](annotation/design.md)；你会了什么由[掌握分析](learner/design.md)根据证据算出来，显示在[知识模型](knowledge/design.md)上。

## 一个课时怎么走

一个阶段不是一口气学完的。比如一章作为一个阶段，就按小节推进：**一个小节就是一个课时**。具体怎么切分，在阶段设计时决定。每学完一小节，停下来做一次小测和汇报，然后这一小节记入课程进度。

主老师在对话里发布任务，同一个任务也会以卡片形式出现在"课程进度"页。一个课时的典型节奏：

```
（可选）预测题：如果你已有基础，先试着猜一猜、做一做，再去读
         报告的依据：先尝试后教学，对有基础的人有效
   ↓
阅读任务：「读教材 1.3 节，读到"管内流动阻力"停下」
   ↓  阅读期间随时可以批注、开侧边会话提问
小节小测：凭记忆作答，2–5 题（开卷还是闭卷由老师定）
   ↓
练习：卡住时老师给刚好够用的提示 → 答对后换一道同类题，再独立做一次
   ↓
汇报：你用一两句话说说这节学到了什么、哪里还没弄清楚
   ↓
小结：老师结合小测和你的汇报，写出这节学会了什么、还缺哪些证据、下一节为什么这样安排
   ↓
记入课程进度：这一小节在阶段时间线上打勾，附上小测结果和小结
```

为什么要汇报：报告支持"有选择的自我解释"。用自己的话复述一遍，能帮你发现自己以为懂、其实没懂的地方；老师也能从中看出可能存在的误解。

报告补充的几条规则：
- **自我解释要有选择地用。** 只在关键处偶尔请你"用自己的话写一句批注"，不要求每段都写。
- **卡住时分情况处理：**
  - 你还在推进 → 先不打扰。
  - 方向对了但漏了条件 → 给一句提示。
  - 同一个错误反复出现 → 直接讲清楚。
  - 你随时可以选"我想直接看讲解"。
- **看答案不算失败。** 但这道题会记为"有帮助"，随后换一道题让你独立再做。

骨架里能走通的部分：阅读任务 → 小测 → 汇报 → 小结 → 记入进度。预测题、练习和分级给提示还没做（见 [tutor](tutor/design.md)、[planner](planner/design.md)）。

## 所有修改都走同一条路

可以修改的对象：目标说明、课程路线、阶段设计书、教材、知识模型、题库。

```
提案来源：你直接提出 / 侧边会话生成的提案 / 批注里的报错 / 阶段复盘
   ↓
主老师评估：改什么、为什么改、会连带影响什么（比如改了目标，路线可能也要变）
   ↓
小改动：直接应用并告诉你
大改动（目标、路线、阶段设计）：等你确认后再改（路线在第一个阶段的设计确认后，改动先存为待确认的调整）
   ↓
生成新版本，记入变更日志，可以回退
```

侧边会话本身不直接修改任何课程内容，只有主老师能改，这样可以避免多处同时修改造成冲突。

现在：提案由 `core` 保存，课程文件的每次写入都记进变更日志。批注里的报错会变成提案，主老师在简报里看到后核对、修改教材，再记下结果，你在批注上看到老师的决定（见 [tutor](tutor/design.md) C）；侧边会话可以起草修改建议，你点"交给主老师"后同样成为提案，处理结果显示在右侧栏（见 [sidechat](sidechat/design.md) C）。修改已确认的目标会让目标回到草稿，等你再确认（见 [goal](goal/design.md)）。
