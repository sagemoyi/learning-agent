# 设置（settings）

> 代码：[`packages/settings`](../../packages/settings)；设置项的读取在 [`packages/kit/src/settings.ts`](../../packages/kit/src/settings.ts) · 调研：[research.md](research.md) · 接口：[契约](../stage0/contracts.md) §11"设置项与设置页" · 验证：[验证记录](../stage0/compatibility.md)"设置与插件接口只读探查""设置页实施"各节

设置页管运行环境：模型、在线服务和密钥、外观、数据位置和发往在线服务的内容、插件。它不管学习安排：目标、节奏、测试条件、给多少帮助，都和主老师商量，修改走[统一的修改流程](../journey.md#所有修改都走同一条路)；也不提供"学习风格"选项。DSH 的命令行、沙箱、子智能体、权限预设这类编程功能的设置不显示。

## 页面

入口在图标栏底部（齿轮，和"外观"并排），主界面和课程里都能打开，在当前标签打开。左侧是分区列表，右侧是内容；窗口窄时分区列表变成页面顶部的一行。

| 分区 | 内容 |
|---|---|
| 模型 | 默认模型和思考强度；各单元登记的角色各自选模型（主老师、课堂记录、侧边提问、侧边会话总结、写教材、核对教材、判分、识别手写、知识抽取），不选就跟随默认。模型服务一张卡片一家：DeepSeek 可以填密钥、改接口地址；"添加模型服务"可以接 DSH 认识的厂商（国内常用的排在前面，只填密钥），或兼容 OpenAI / Anthropic 接口的服务（填地址和密钥、获取模型、勾选要用的）。每家都能"测试连接"，接上的模型马上能分给角色 |
| 资料服务 | 解析方式、本机服务地址、MinerU 和 Voyage 的密钥、语义检索开关，都能测试连接。这一块由 [library](../library/design.md) 自己提供。导入 PDF 时缺 MinerU 密钥，会提示"去设置" |
| 外观 | 跟随系统、浅色、深色 |
| 数据与隐私 | 学习库位置；哪些内容会发往哪个在线服务（DeepSeek：对话和资料片段；MinerU：PDF 原件；Voyage：资料片段和检索问题）；密钥存在哪 |
| 插件 | 学习单元（含设置页本身）的名称、说明、图标、运行状态，哪些角色用它的工具，有设置项的带链接；学习单元都是必需的，不能单独关掉。DSH 自己的组件折叠显示，只看不改 |
| 关于 | 学习工作台和 DSH 的版本 |

"测试连接"会发一次很短的真实请求（MinerU 只查用量，Voyage 只嵌入四个字）。DSH 只给出厂商的英文 ID，常用厂商的中文名称由设置页维护。

## 设置存在哪、归谁

- **每个单元声明自己的设置项。** 学习者能改的选项写成单元 Config 里加了 `.volatile()` 的字段，设置页按分区汇总，模型角色汇总成一张表。以后新增的单元声明了设置项，也会出现在页面上。默认值写在代码里；选回默认值时保存为"未设置"，以后单元改了默认值，你自动跟上。
- **设置由 DSH 写进已安装 profile 的 `cordis.patch.yml`。** 改了下一次使用就生效，不用重启；重启 DSH、重跑安装脚本后仍在。
- **学习工作台是 DSH 组合包 `@learning-agent/app`：** 单元和老师预设都在组合包里，profile 自己的 `cordis.patch.yml` 只留给你的设置。单元的插件行不带配置，设置项也不放进老师预设这类带大段配置的行，因为 DSH 保存一项设置时会把这一行的整份配置固定在你那一层。
- **角色模型写作 `厂商/模型`，** 没设置时用 DSH 的默认模型。一次性调用每次都读当前设置；改了主老师或侧边提问的模型（或它们跟随的默认模型），正在进行的会话也会换过去。
- **密钥不写进配置文件：** 每次使用时向 DSH 的密钥服务按名称读取，启动环境（`.env`）里的优先，页面上显示为"来自启动环境，不能修改"；其次是在设置页保存的，存在 `.dsh-home/.credentials.yaml`（本机明文，和 `.env` 一样）。页面和接口都不回显密钥。
- **学习库位置仍用环境变量 `LEARNING_HOME`。** 学习库在启动时打开数据库，运行中不能换；设置页只显示位置。

## 关键决定

- **新增设置页和插件管理，保留 DSH 插件系统的特色**（10-04，你）。
- **自己做设置页，直接调用 DSH 的设置、密钥、模型和插件服务，设置项由各单元声明；插件管理分三步：清单与设置、可选功能开关、安装第三方插件**（10-05，Claude 调研建议）：DSH 自带的设置页和插件页依赖它自己的布局，内容也是编程助手的功能。
- **插件管理这次只做清单与设置；密钥可以在页面填写；其他模型厂商这次一起做**（10-05，你选择"只做清单与设置""可以在页面填写""这次一起做"）。
- **学习工作台改成 DSH 组合包，profile 的配置文件只留给你的设置**（10-05，Claude 按调研实施，3182 验证）：安装脚本每次都覆盖 profile 的配置文件时，你保存的设置会丢。
- **设置页入口和布局**（10-05，Claude 决定，你授权审美取向）：入口在侧栏底部；资料服务的设置由资料库单元通过插槽提供；国内常用厂商排在前面。
- **模型由你在设置里配置；插件以 DeepSeek 为基准设计**（10-03，你）：模型策略见 [PLAN](../PLAN.md)"模型策略"。
