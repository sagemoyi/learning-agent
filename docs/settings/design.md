# 设置（settings）

> 代码：[`packages/settings`](../../packages/settings)；设置项的读取在 [`packages/kit/src/settings.ts`](../../packages/kit/src/settings.ts) · 调研：[research.md](research.md) · 契约：[contracts.md](../contracts.md)

## 概要

设置页管运行环境：模型、在线服务和密钥、外观、数据位置和发往在线服务的内容、插件。它不管学习安排：目标、节奏、测试条件、给多少帮助，都和主老师商量，修改走[统一的修改流程](../journey.md#所有修改都走同一条路)；也不提供"学习风格"选项。DSH 的命令行、沙箱、子智能体、权限预设这类编程功能的设置不显示。设置页直接读写 DSH 的设置、密钥、模型和插件服务，不读别的单元的业务字段；3180 和 3182 共用同一份设置和密钥。

## 页面

入口在图标栏底部（齿轮，和"外观"并排），主界面和课程里都能打开，在当前标签打开。左侧是分区列表，右侧是内容；窗口窄时分区列表变成页面顶部的一行。

| 分区 | 内容 |
|---|---|
| 模型 | 默认模型和思考强度；各单元登记的角色各自选模型（主老师、课堂记录、侧边提问、侧边会话总结、写讲义、判分、识别手写、知识抽取），不选就跟随默认。思考强度的档位一律写中文。模型服务一张卡片一家：DeepSeek 可以填密钥、改接口地址；"添加模型服务"可以接 DSH 认识的厂商（国内常用的排在前面，只填密钥），或兼容 OpenAI / Anthropic 接口的服务（填地址和密钥、获取模型、勾选要用的）。每家都能"测试连接"，接上的模型马上能分给角色。每张卡片底部有"高级设置"（见下） |
| 资料服务 | 各单元往插槽 `learning.settings.services` 登记自己的一块：资料库（解析方式、本机服务地址、MinerU 和 Voyage 的密钥、语义检索开关、联网搜索的首选服务和密钥、网站级别，都能测试连接；导入 PDF 时缺 MinerU 密钥会提示"去设置"）、讲义（联网补充讲解）、侧边提问（测试进行中只说明怎么操作）、复查提醒（每天建议几道） |
| 外观 | 跟随系统、浅色、深色 |
| 数据与隐私 | 学习库位置；哪些内容会发往哪个在线服务（DeepSeek：对话和资料片段；MinerU：PDF 原件；Voyage：资料片段和检索问题；搜索服务：搜索问题和打不开的网址），以及关掉或删密钥后不再发送、已发的收不回、正在跑的任务停在哪；密钥存在哪 |
| 插件 | 学习单元（含设置页本身）的名称、说明、图标、运行状态，哪些角色用它的工具，有设置项的带链接；学习单元都是必需的，不能单独关掉。DSH 自己的组件折叠显示，只看不改 |
| 关于 | 学习工作台和 DSH 的版本；桌面版另有知微的版本、更新状态和"检查更新" |

**首次启动引导：** 没有能用的模型服务时，设置单元往 `learning.welcome` 放一层盖住整个窗口的引导，分三步：学习库位置（桌面版能换，换了外壳用新位置重启 DSH）、DeepSeek 密钥（测试连接通过才能下一步，别的服务去设置页）、MinerU 密钥（可以跳过）。是否显示按打开时有没有能用的模型判断，不另存标记；"稍后再说"后状态栏留"还没连接模型，去连接"。桌面版的更新进度、下载失败和"已下载，重启更新"也显示在状态栏。桌面版的这些能力由外壳的 preload 以 `window.microsight` 提供，网页版没有。

"测试连接"会发一次很短的真实请求（MinerU 只查用量，Voyage 只嵌入四个字）。DSH 只给出厂商的英文 ID，常用厂商的中文名称由设置页维护。

## 模型的高级设置

每张模型服务卡片底部有"高级设置"，默认收起（调研见 [research.md](research.md#模型的高级设置10-16)）：

- **DeepSeek：** 接口地址；思考"支持 / 不支持"（档位固定为不思考、低、高、最高，中转站不支持思考时选"不支持"，所有请求都不思考）；再选模型改上下文窗口和最大输出。
- **其他厂商和自定义接口：** 选模型，改上下文窗口、最大输出和思考档位（一排复选框：不思考、最低、低、中、高、很高、最高；一档都不选表示不支持思考）。选了哪几档，"思考强度"下拉框里就有哪几档。
- 留空表示用默认值，输入框里灰字显示现在生效的值；可以写 128K、1M（K 是 1000，M 是 100 万）。"保存"写入，"恢复默认"删掉对这个模型的修改；改过的模型在选择框里标"已改"。
- 写讲义、判分这类一次性调用的输出额度不超过这个模型设的最大输出；因此被截断时，提示里说去哪里调大。

- **写在哪：** DeepSeek 写进 `llm-deepseek` 的 `models`（整张列表，和内置的一样时删掉）和 `thinking`；自定义接口写进 `llm-pi-ai` 路由的 `models`；DSH 认识的厂商写进 `modelOverrides.<模型>`，恢复默认后删掉。读取用学习者那一层的原值，不把 DSH 补上的默认值写回去。
- 输入"abc"、0、最大输出大于上下文窗口时，原地说明原因，不能保存；DSH 拒绝写入时显示它的原因。
- 关掉 DeepSeek 的思考时，默认模型的思考强度如果不是"不思考"就一并去掉；去掉某个档位后，默认的思考强度不再提供时也去掉。

## 设置存在哪、归谁

- **每个单元声明自己的设置项。** 学习者能改的选项写成单元 Config 里加了 `.volatile()` 的字段，设置页按分区汇总，模型角色汇总成一张表。以后新增的单元声明了设置项，也会出现在页面上。默认值写在代码里；选回默认值时保存为"未设置"，以后单元改了默认值，你自动跟上。
- **设置由 DSH 写进已安装 profile 的 `cordis.patch.yml`。** 改了下一次使用就生效，不用重启，手工改这个文件也一样；重启 DSH、重跑安装脚本后仍在。
- **学习工作台是 DSH 组合包 `@learning-agent/app`：** 单元和老师预设都在组合包里，profile 自己的 `cordis.patch.yml` 只留给你的设置。因此单元的插件行不带配置，写法见 [packages/AGENTS.md](../../packages/AGENTS.md)"组合包与 profile"。
- **角色模型写作 `厂商/模型`，** 没设置时用 DSH 的默认模型。一次性调用每次都读当前设置；改了主老师或侧边提问的模型（或它们跟随的默认模型），正在进行的会话也会换过去。
- **密钥不写进配置文件：** 每次使用时向 DSH 的密钥服务按名称读取，启动环境（`.env`）里的优先，页面上显示为"来自启动环境，不能修改"；其次是在设置页保存的，存在 `.dsh-home/.credentials.yaml`（本机明文，和 `.env` 一样）。页面和接口都不回显密钥。
- **学习库位置仍用环境变量 `LEARNING_HOME`。** 学习库在启动时打开数据库，运行中不能换；设置页只显示位置。

## 数据与接口

- **页面接口** `/api/learning/settings.<方法>`：`about`（学习库位置）、`testModel({ model? })`（用指定模型或默认模型发一次很短的请求，返回耗时；截断和空回复也算连通；测的是默认模型时带上它的思考强度）、`modelLimits({ provider, model })`（这个模型现在生效的上下文窗口和设了的最大输出，`null` 表示不知道）。
- **前端** 直接调用 DSH 的 `settings`、`credentials`、`llm`、`session`、`pluginInventory`、`pluginManager` 服务；"资料服务"由各单元往插槽 `learning.settings.services` 登记区块。
- **模型服务：** DeepSeek 用 DSH 的 `llm-deepseek`（密钥、接口地址）；其他厂商和兼容接口写进 `llm-pi-ai` 的 `providers`，密钥名按 DSH 的约定（`minimax-cn` → `MINIMAX_CN_API_KEY`），和 DSH 自己的模型页一致。

## 关键决定

- **新增设置页和插件管理，保留 DSH 插件系统的特色**（10-04，你）。
- **自己做设置页，直接调用 DSH 的设置、密钥、模型和插件服务，设置项由各单元声明；插件管理分三步：清单与设置、可选功能开关、安装第三方插件**（10-05，Claude 调研建议）：DSH 自带的设置页和插件页依赖它自己的布局，内容也是编程助手的功能。
- **插件管理这次只做清单与设置；密钥可以在页面填写；其他模型厂商这次一起做**（10-05，你选择"只做清单与设置""可以在页面填写""这次一起做"）。
- **学习工作台改成 DSH 组合包，profile 的配置文件只留给你的设置**（10-05，Claude 按调研实施，3182 验证）：安装脚本每次都覆盖 profile 的配置文件时，你保存的设置会丢。
- **设置页入口和布局**（10-05，Claude 决定，你授权审美取向）：入口在侧栏底部；资料服务的设置由资料库单元通过插槽提供；国内常用厂商排在前面。
- **模型由你在设置里配置；插件以 DeepSeek 为基准设计**（10-03，你：用普通模型时体验要好，用高级模型时要有发挥空间）：每个功能都按 DeepSeek 设计和测试。DSH 自带两个模型，上下文都是 100 万 token：`deepseek-flash`（文字和图片，DSH 的默认模型，识别手写要用它）、`deepseek-v4-pro`（只有文字，推理更强）。让普通模型也做对的写法见 [packages/AGENTS.md](../../packages/AGENTS.md)"调用模型"；给高级模型的空间是每个角色可以单独选模型。
- **每个模型服务有"高级设置"：上下文窗口、最大输出、思考档位，按模型改**（10-16，你提出，Claude 按调研设计）：写进 DSH 原本存这些值的地方（DeepSeek 的模型列表、自定义接口的模型列表、DSH 认识的厂商的按模型覆盖项）；一次性调用的输出额度不超过设的最大输出；"测试连接"测默认模型时带上它的思考强度。没做思考参数的写法、思考的 token 预算和输入类型。

## 已知限制与以后再做

- 添加 Kimi、通义这类常见厂商需要真实密钥，没有实测；改了思考档位后，真实厂商和中转站收到的思考参数也没实测。
- 中转站接收思考参数的写法和 OpenAI 不同时，思考可能不生效；思考参数的写法、思考的 token 预算和输入类型都还不能在页面上设。
- 改 Kimi 这类内置厂商的思考档位后，发给接口的参数按档位名写，个别模型原本的特殊写法会被替换；不改档位就没有影响。
- 不按模型的能力换做法：上下文长的直接读整节、看图强的读懂插图、推理强的少拆几步，能力不够时退回基础流程，都还没做，所有模型走同一套流程；只有"识别手写"在模型目录写明不能看图时直接报错。
- 可选功能的开关、安装第三方插件，等真有这类插件时再做。
- 学习工作台暂不做成别的 DSH 用户能安装的插件（10-17，你；11-01 再确认）。DSH 的插件页能按包名、Git 地址、压缩包或本地目录装组合包，0.2.1 起还有插件市场；`pnpm dist` 打出的 tgz 能装进全新的 profile，但只给知微自己的安装包用（见[安装包提案](proposals/2026-11-05-windows-installer.md)）；要给别的 DSH 用户还缺：发布到 npm 或插件索引；组合包的 `engines.dsh` 写死 `0.2.2-rc.1`，DSH 装插件和启动时按它检查，别的版本会拒绝；组合包关掉了 DSH 的插件页，学习工作台里没有回到 DSH 的入口（DSH 的 `pluginManager.setBundleEnabled` 可以做）。
