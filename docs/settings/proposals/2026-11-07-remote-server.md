# 提案：把知微部署到服务器，桌面和手机远程连接，学习库可以迁移

## 问题

知微现在只能在装了它的那台 Windows 电脑上用：外壳在本机起一个 DSH 子进程，监听回环地址上的随机端口，窗口打开带 token 的地址（[`apps/desktop/src/main.ts`](../../../apps/desktop/src/main.ts)）。用户希望（11-07，见 throughts.md）：

- 在自己的 Oracle 服务器上部署一份知微；
- Windows 上的知微能直接连到这份服务器上的知微；
- 手机也能远程用（网页或 APP）；
- 本机学习库和服务器之间能迁移；
- README 没写端口。

### 现状

- **端口：** 从源码运行时 DSH 默认 3080，开发约定用 3180、3182、3184（[development.md](../../development.md#三个端口)）；桌面版每次启动取一个空闲端口，只监听 `127.0.0.1`，学习者看不到也不需要知道。README 两种都没写。
- **鉴权（DSH 0.2.2-rc.1 自带，读过 `dsh-web-app`、`dsh-client-connection`、`dsh-host-webserver` 的说明）：**
  - 每个进程启动时生成一个随机 token，打印在 `dsh web: http://…/?token=…` 这一行；浏览器用它换一个签名 cookie，之后每个接口和 WebSocket 都要这个 cookie。
  - cookie 的签名密钥存在 `$DSH_HOME/.credentials.yaml`，所以 **DSH 重启后 cookie 仍然有效**，有效期默认 30 天；cookie 绑定主机名和端口，`HttpOnly`、`SameSite=Strict`。
  - 只有一个身份（owner），没有账号、没有退出登录；撤销全部会话要删掉密钥记录再重启。
  - 默认只监听回环地址。`--host` 只接受某个具体 IP，拒绝 `0.0.0.0`；`--trusted-host` 放行反代后的域名，`--public-url` 只改打印出来的地址；`--tls-cert`/`--tls-key` 可以直接提供 HTTPS，但不申请、不续期证书。Host/Origin 校验防 DNS 重绑定和跨站请求，不代表身份。
- **数据：** 学习库（`LEARNING_HOME`）是 Markdown 文件加 `.learning/learning.db`（SQLite）；DSH 的会话和附件在 `DSH_HOME`，按课程文件夹路径分目录；密钥在 `DSH_HOME/.credentials.yaml`。`core` 已有备份和恢复（[core](../../core/design.md#备份和恢复)）：备份带数据库快照、学习库文件、本库的 DSH 会话和附件，不带密钥；恢复先校验清单，只恢复到新文件夹。备份要求 DSH 停着。
- **对远程不友好的地方：** 导入 PDF、拍照作答都走浏览器的文件选择，远程也能用；本机 MinerU 服务只认回环地址（服务器上要用云端 MinerU）；学习库位置和更新状态靠桌面外壳的 `window.microsight`，网页里没有；手机布局只做过检查，没在真机上用过（README"支持范围"）。

### 服务器现状（11-07 只读查看）

Ubuntu 24.04、aarch64、4 核、23 GB 内存（约 10 GB 空闲）、`/data` 剩 40 GB；Node 24、pnpm 11 都有，仓库在 `/data/home/selfworks/learning-agent`，`.tools/dsh` 已装。已经有 nginx、certbot、cloudflared（在跑隧道）、docker，没有 Tailscale、Caddy。防火墙只放行少数端口，新端口要改 iptables 和 Oracle 安全列表。

**已经有现成做法：** 一个通用 DSH 只监听 `127.0.0.1:3080`，由 cloudflared 隧道接到你的一个子域名（`--public-url https://<子域名> --trusted-host <子域名>`），已经跑了 17 天。知微可以照这个做，不开新端口，也不用自己管证书。3180、3182、3184 现在都空着；以后自动开发的代理也要在这台机器上跑测试。

## 方案

### 结构：服务器上的知微是唯一的一份数据

```
手机浏览器 ─┐                       ┌─ cloudflared ─ 127.0.0.1:3190 ─ dsh learning（服务器）
            ├─ https://learning.<你的域名> ┤                            ├─ 学习库 /data/…/microsight/学习库
Windows 知微 ┘   （Cloudflare Access 登录）  └─────────────────────────── └─ DSH_HOME（会话、密钥）
```

- **服务器跑完整的知微：** 和桌面版同一个组合包、同一个 DSH 版本，只是没有 Electron。用 `systemd` 管：开机启动、崩溃重启、日志进 journal。监听 `127.0.0.1:3190`（不和开发用的 3180–3184、通用 DSH 的 3080 撞），启动参数 `--host 127.0.0.1 --port 3190 --public-url https://learning.<你的域名> --trusted-host learning.<你的域名>`。
- **单独的系统用户：** 知微用自己的 Linux 用户（例如 `microsight`）跑，学习库、`DSH_HOME` 和密钥只有它能读。自动开发代理的 worker 以它自己的用户、完全权限运行（[自动开发提案](2026-11-06-auto-dev.md)），分开用户它就读不到你的学习记录和密钥。
- **Windows 知微多一个"连接方式"：** 本机（现在的行为）或远程服务器（填地址）。远程时外壳不起 DSH，窗口直接打开服务器地址；页面、学习库、设置都是服务器上的。外壳只剩窗口、更新和"切换连接方式"这几件事。
- **手机：** 手机浏览器打开同一个地址。加上网页清单（manifest）和图标，就能"添加到主屏幕"，像 APP 一样全屏打开。
- **不做双向同步。** 学习证据只追加、DSH 会话是文件夹、数据库是 SQLite，两边同时写再合并很难做对。同一时间只有一份在用的学习库，"迁移"是把它整份搬到另一边。

### 网络和安全

知微的智能体能调用模型、读写学习库，拿到 cookie 就等于拿到全部权限，而 DSH 只有 token 和 cookie 一层鉴权。所以推荐在它前面再加一层登录：

| 选项 | 怎么做 | 好处 | 代价 |
|---|---|---|---|
| **A. Cloudflare 隧道 + Access（推荐）** | 现有隧道加一条 `learning.<你的域名>` → `127.0.0.1:3190`；Cloudflare Zero Trust 里给这个子域名加 Access 策略（只允许你的邮箱，邮箱验证码登录，免费） | 不开端口、证书自动、和服务器上已有做法一致；陌生人连登录页都过不去，token 泄露也不够用 | 依赖 Cloudflare，国内网络有时慢；Access 登录每隔一段时间（可设，例如 30 天）重新验证一次 |
| B. Tailscale | 服务器、Windows、手机都装 Tailscale；`tailscale serve` 给 `<机器名>.<tailnet>.ts.net` 发 HTTPS 证书并反代到 3190 | 不暴露到公网；连接加密 | 每台设备都要装、开着 Tailscale；国内可能要走中继，慢 |
| C. nginx + certbot 公网直连 | nginx 反代到 3190，证书用 certbot；可加 HTTP Basic 认证 | 不依赖第三方 | 要开 443 以外的配置、自己管证书续期；暴露在公网扫描下，Basic 认证在手机上体验差 |

不管选哪个：

- DSH 只监听回环地址，不直接暴露端口；
- 外面一律 HTTPS（手机"添加到主屏幕"、相机这类功能也要求 HTTPS）；
- 启动地址里的 token 只在服务器上看（`journalctl` 或我们写的 `microsight-server url`），不发到聊天和文档里；
- 服务器上的密钥在设置页重新填，备份和迁移都不带密钥。

### 第一次连接和"配对"

DSH 的 token 每次重启都会换，但 cookie 30 天有效、重启不失效，所以每台设备每 30 天只要用带 token 的地址登录一次：

1. **先用最简单的：** 服务器上运行 `microsight-server url` 打印带 token 的地址，在手机或 Windows 知微里打开一次。
2. **再做方便的：** 已登录的设备在 设置 › 关于（或"数据与隐私"）里显示"添加设备"二维码，手机扫码即登录。这要服务端插件能拿到当前 token 或签发 cookie，DSH 没有公开这个接口，**要先调研**；做不到就保留第 1 种。
3. cookie 过期时页面会收到 401，桌面版远程模式显示"需要重新登录"和怎么拿新地址，不显示成"服务停止了"。

### Windows 知微的远程模式

- 应用设置（`%APPDATA%\Microsight\settings.json`）加 `connection: { mode: 'local' | 'remote', url?: string }`。
- 远程模式：不起 DSH，不做升级前备份（学习库不在本机）；`origin` 设为服务器地址，现有的"只显示自己页面、外链交给系统浏览器"规则照用；Cloudflare Access 的登录页要放行（它在另一个域名下）。
- `window.microsight` 只对服务器页面回答版本和更新；"换学习库"在远程模式下隐藏（学习库在服务器上，换位置在服务器上做）。
- 首次启动引导多一个选项"连接到我的服务器"：填地址、在窗口里完成 Access 登录和 token 登录，之后跳过本机的学习库和密钥步骤。
- 连不上时显示"连不上服务器"、重试、改用本机三个按钮，而不是报错退出。
- 页面来自服务器，所以服务器更新后桌面不用跟着更新；只有外壳的桥接接口变了才要求双方版本配套（外壳读服务器的版本号，不配套时提示）。

### 手机

- 先做网页：给外壳加网页清单、图标和主题色，iOS 和 Android 都能添加到主屏幕。
- 真机过一遍最常用的几页：首页"下一步"、主老师对话、读讲义、做题（含拍照作答）、侧边提问。窄屏和触控的问题记进各单元的"已知限制"，先修挡住使用的。
- 原生 APP 先不做：网页能做的它都能做，打包和上架还要额外维护；以后需要推送提醒再说。

### 迁移

迁移就是现有的备份和恢复，加上"传到另一边、换过去"：

| 方向 | 怎么做 |
|---|---|
| 本机 → 服务器 | Windows 知微（本机模式）在 设置 › 数据与隐私 点"迁移到服务器"：外壳停掉本机 DSH，用 `core` 的 `backup` 打一份备份并压缩，重新启动本机 DSH；把压缩包上传到服务器的导入接口；服务器校验清单，恢复到新文件夹，写进服务器配置后重启服务换过去；最后外壳切到远程模式 |
| 服务器 → 本机 | 远程模式下点"把学习库下载到本机"：服务器短暂停服务打备份（一般几秒到一分钟），再启动；外壳下载、恢复到本机新文件夹，换过去并切回本机模式 |
| 手工 | 不做界面也能迁：`pnpm backup` → 拷过去 → `pnpm restore`，第一步就写进说明 |

- **只搬不合：** 目标只能是新的空文件夹，不覆盖在用的学习库；旧的那份原样留下，迁移完在旧位置写一个"已迁到 …（时间）"的标记，再打开时提醒，避免两边各学各的。
- **密钥不跟着走：** 迁移后在新的一边重填，界面上明说。
- **跨系统的路径：** 备份清单里的路径都是正斜杠的相对路径，DSH 会话按会话号找回，但从 Windows（`D:\…\学习库`）恢复到 Linux 没测过，要先用 Windows 上打的合成备份做恢复测试（`tests/fixtures/` 里加一份）。
- **服务器停服打备份：** 服务器进程由 systemd 管，导出时由一个小的服务端脚本停服务、备份、再启动；页面先提示"会断开一会儿"。

### README 的端口

README 加一段"端口和访问方式"：桌面版每次自动选一个本机端口，不用管；从源码运行默认 3080，开发约定见开发说明；服务器部署用 3190、只监听本机，经反代访问。

### 分步

1. **文档和手工部署**（不改代码）：README 写端口；`docs/development.md` 加"在服务器上运行"（系统用户、目录、systemd 单元、cloudflared 和 Access 的配置、`pnpm backup`/`restore` 手工迁移）。按它在你的服务器上部署一次，用合成课程验证手机和电脑浏览器都能用。
2. **服务端打包和更新：** `pnpm dist` 的产物加一个 Linux 服务器用的启动脚本和 `microsight-server`（`url`、`backup`、`update`、`status`）；更新跟随 GitHub Release，更新前自动备份，和桌面版的规则一致。在 aarch64 上跑一遍冒烟测试。
3. **Windows 知微的远程模式：** 连接方式设置、首次引导里的"连接到我的服务器"、连不上和需要重新登录的页面。
4. **手机：** 网页清单和图标，真机走一遍常用页面，修挡路的问题。
5. **应用内迁移：** 两个方向的按钮、服务器的导入导出接口、跨系统恢复测试、"已迁出"标记。
6. **（调研后再定）扫码添加设备。**

每步单独验收；第 1 步做完你就能先用起来，后面几步是让它更省事。

## 放弃的方案

- **两边各跑一份、自动同步：** 数据库、只追加的证据和 DSH 会话文件夹都要合并，冲突难以正确处理；你一个人用，同一时间只在一处学，整份迁移足够。
- **服务器只做同步存储（例如网盘、Syncthing 同步学习库文件夹）：** SQLite 在同步盘上会损坏，手机也跑不了 DSH。
- **DSH 直接监听公网 IP 或自己配证书：** DSH 拒绝 `0.0.0.0`，只能绑具体 IP；明文 HTTP 会暴露 cookie；证书要自己续期。服务器上已有 cloudflared，没必要。
- **先做原生手机 APP：** 网页加"添加到主屏幕"已经够用；APP 要单独打包、签名、上架，还得处理同样的鉴权。
- **自己做账号系统：** 你一个人用，Cloudflare Access 或 Tailscale 已经解决"只有我能进"；多用户是另一件大事，不在这次范围。

## 验收标准

- 服务器上的知微只监听 `127.0.0.1:3190`，外网扫描看不到这个端口；没登录 Access（或不在 Tailscale 里）时打不开页面。
- 手机浏览器打开 `https://learning.<你的域名>`，能看首页、和主老师对话、读讲义、做题并拍照作答；能添加到主屏幕并全屏打开。
- Windows 知微切到远程模式后，看到的是服务器上的课程；服务器重启后不用重新登录；30 天后 cookie 过期时提示重新登录而不是报错。
- 合成学习库从 Windows 迁到服务器、再迁回 Windows，所有表逐行一致、文件一致、会话能接着聊（扩展现有的恢复演练测试）；迁移不带密钥，旧的那份留着并有"已迁出"提醒。
- 服务器更新前自动备份，更新失败能回到上一版。
- README 写明了端口和三种访问方式。

## 风险

- **cookie 是唯一的身份：** 没有退出登录；手机丢了要删 DSH 的签名密钥并重启服务器上的知微，让所有设备重新登录（写进说明）。推荐的 Access 能挡住大部分风险。
- **国内访问 Cloudflare 可能慢或不稳：** 你已经在用同样的方式访问服务器上的 DSH，可以先看实际体验；不行再换 Tailscale 或 nginx。
- **aarch64：** DSH 和组合包是纯 JavaScript（数据库用 Node 自带的 `node:sqlite`），服务器上已经跑着 DSH，问题应该不大，但被裁剪掉的包和本机 MinerU 在 ARM 上没验过；服务器用云端 MinerU。
- **两台设备同时打开：** DSH 允许多个浏览器同时连同一个会话，但两边同时给主老师发消息的行为没测过，先在说明里写"同一时间在一处学"。
- **和自动开发代理共用服务器：** 要靠分开的系统用户隔离；代理跑测试时内存和 CPU 会和知微抢（现在约 10 GB 空闲，知微本身占几百 MB）。
- **跨系统恢复：** Windows 路径恢复到 Linux 没测过，第 5 步前不推荐用应用内迁移，手工迁移也要先拿合成数据试。
- **扫码添加设备可能做不了：** 依赖 DSH 是否允许插件拿到 token 或签发 cookie。

### 需要你决定

1. **网络方式：** A（Cloudflare 隧道 + Access，推荐）、B（Tailscale）还是 C（nginx 公网）？用 A 的话子域名叫什么（例如 `learning.<你的域名>`）？
2. **学习库以哪边为主：** 推荐以服务器为主，Windows 平时也连服务器；还是平时用本机，服务器只给手机用（那就要经常迁移，不推荐）？
3. **手机：** 先做网页加"添加到主屏幕"（推荐），还是一定要原生 APP？
4. **迁移做到哪一步：** 先只要手工命令（第 1 步就有），还是要应用内按钮（第 5 步）？
5. **服务器跟哪个版本：** 跟 GitHub Release（推荐，和桌面版一致），还是跟 main 的最新提交？
6. **系统用户：** 同意给知微单独建一个 Linux 用户吗？
