## 0. 一句话

一个本地运行的个人学习工作台，**一门课就是一个"项目"**。

Agent 当老师：和你确认目标，摸清你的知识边界，一个阶段一个阶段地为你写教材，发布学习任务，用权威题目测试你。你随时可以在侧栏提问、在教材上批注。所有学到的东西都沉淀在一张像 Obsidian 那样的知识网里：你真正会了什么，凭什么这么判断，这些知识从哪里来。

判断"学会"只看一个标准（报告的核心）：**撤掉帮助后你能独立做出来，隔一段时间还会，换一道题也会。**

### 0.1 第一门课：化工原理

- **学习者是你本人。** 你正在上这门课，手上有教材。
- **对设计的影响：**
  - **目标基本由课程决定：** 通过期末考试，并且真正理解。这门课的"考试档案"就是学校的教学大纲、考试范围、往年题，以及老师的课件和作业。
  - **和课堂的关系很简单：** 不同步课表。课程进度页只回答两件事：学到哪了、接下来学什么。
  - **期限：** 如果在确认目标时说明了有期限（比如期末考试），只记一个最后期限，不排死日程（§4.10）。
  - **教材是骨架：** 阶段大致按教材章节划分（流体流动、流体输送机械、传热、蒸馏、吸收……以你的教材为准）。
  - **题目以计算为主：** 带单位的数值计算、查图表（摩擦系数图、物性表等）、图解法（如逐板计算的图解）。因此：
    - 判分要支持"数值 + 允许误差 + 单位"。
    - 改编题要用计算工具独立验算。
    - 作答界面要能写解题步骤；**第一版就支持拍照上传手写解答**（DeepSeek 本身支持图片输入）。
  - **做过的作业题不算新题：** 你上课时会做教材习题，这些题对你已经不是"新题"了。测试时可以标记"这题作业做过"来换一道题（§5.4）。
  - **教材是电子版：** 不确定是扫描版还是文字版，所以两种都要支持，解析器能自动处理（§9.3）。

## 1. 设计原则（从报告提炼，全系统通用）

1. **先定目标，后排课程。** 先说清学来做什么、要做到什么程度、怎么验证，再安排课程。
2. **先定"怎么考"，再写"怎么教"。** 每个阶段先确定阶段测试，再写教材（逆向设计）。
3. **只有作答能证明掌握。** 阅读量、聊天、批注、提问都只是"信号"，不会直接提升掌握状态。
4. **帮助要记账。** 看了提示、问过侧边会话之后马上答对，只算"有帮助完成"，之后还需要一次独立完成的证据。提问不扣分，只是这一次不算独立。
5. **状态用文字，不用假精确的数字。** 界面上不会出现"掌握 87%"或"还需 12 小时"。
6. **帮助只给刚好够用的量。** 新手多讲，熟手少讲。可以直接给答案，但给完之后要撤掉帮助，让你独立再做一遍。
7. **一切可追溯。** 每个知识点、每段教材、每道题都能点开看到出处。
8. **Agent 主导，你可以协商。** Agent 默认替你做规划，你随时可以问"为什么"，也可以要求修改。修改走统一流程，并保留版本。
9. **只有一个老师。** 插件只是代码的分块方式，不是多个 Agent。对你来说只有一个主老师，侧边会话是同一个老师的"课间答疑窗口"。

## 2. 界面结构

### 2.1 两级：主界面 / 课程界面

和 VSCode 里"工作区 → 项目"的关系一样：主界面管理全局，打开一门课就进入课程界面。

| 页面 | 主界面 | 课程界面 |
|---|---|---|
| 首页 | 课程列表 + 今日待办（跨课程的复习） | — |
| 知识模型 | 全部节点 | 本课节点 + 相关节点 |
| 资料库 | 全部资料 | 本课关联的资料 |
| 课程进度 | — | 目标说明、课程路线、阶段 → 小节时间线（每个小节附小测结果和小结）、当前任务、阶段测试结果 |
| 课程教材 | — | 当前及历史阶段的教材（阅读 + 批注） |
| 主老师对话 | — | 本课的主会话 |
| 测试 | — | 摸底、课后小测、阶段测试 |
| 侧边会话 | ✓ | ✓ |
| 设置 | ✓ | — |

**通用组件只做一次，两处共用。** 知识图、资料库、侧边会话各自是同一个插件，只是"范围"参数不同（全局 / 本课）。

### 2.2 布局（参考 VSCode / Obsidian）

```
┌────────────────────────────────────────────────────────────────────┐
│ 顶栏：主界面 › 概率论入门 › 教材·第2阶段            [Ctrl+P 命令面板] │
├──┬──────────────┬─────────────────────────────────┬────────────────┤
│  │ 左侧栏        │ 主区：标签页，可左右分屏           │ 右侧栏          │
│活│ ─ 课程目录     │ [教材 2.3] [主老师] [知识模型]     │ ┌ 侧边会话 ┐    │
│动│   阶段1 ✓     │                                  │ │ 绑定当前页面 │   │
│栏│   阶段2 ●     │  （例：左边读教材，右边开主老师）    │ │ 和选中内容  │   │
│  │    2.1 2.2…   │                                  │ └──────────┘    │
│  │ ─ 本课资料     │                                  │  大纲 / 批注列表 │
├──┴──────────────┴─────────────────────────────────┴────────────────┤
│ 状态栏：阶段 2/5 · 今日任务 1/3 · 待复查 4 · 当前模型                 │
└────────────────────────────────────────────────────────────────────┘
```

- **活动栏：** 在主界面时是「首页 / 知识模型 / 资料库 / 设置」；进入课程后换成「进度 / 教材 / 主老师 / 测试 / 知识模型 / 资料」。
- **主区：** 用标签页，可以分屏。常见组合是"教材 | 主老师"和"知识模型 | 资料"。
- **右侧栏：** 固定放侧边会话，在任何页面都能打开。
- **测试进行中：** 主区锁定为测试页。教材和侧边会话按目标说明里约定的工具条件受限（见 §5.3）。

### 2.3 前端原则：做我们自己的产品，不在 DSH 界面上小修小补

- **为什么不改 DSH 的界面：** DSH 是一个成熟的编程 Agent 产品，界面是围绕"对话 + 写代码"设计的。我们的核心是"课程 + 教材 + 知识图"，目标不一样。所以前端的外壳、信息架构和交互都由我们自己设计。
- **方案（阶段 0 调研结论，详见 [stage0/research.md](stage0/research.md)）：**
  - **后端：** 使用 DSH `web-app` 组合里的服务端部分（HTTP 服务、认证、会话接口），负责模型、会话、工具和 Agent 循环。
  - **前端：** 跑在 DSH 的客户端内核上（启动加载、连接认证、会话流、热重载），**整个页面由我们接管**。DSH 的渲染器只渲染一个 `root` 插槽，谁占了它谁就拥有整页布局；DSH 自己的 `dsh-client-ui-*` 界面插件全部不装。我们的外壳和各个页面都是我们自己的前端插件，所以前端同样是插件化的。
  - **前端零件：** 停靠布局用 dockview，知识图谱用 sigma.js，原文 PDF 用 pdf.js。React 版本跟随 DSH（目前是 18）。
  - **备选：** 如果实测发现内核方案处处受限，就改成独立的 Vite 应用，直接调用 DSH 的 HTTP 和 WebSocket 接口。
  - **桌面版：** 先做 Web。之后用 Electron 包一层就是桌面版，DSH 自己的桌面版也是这么做的。
- **第一原则：DSH 的设计不能拖累我们的功能。** 只复用不限制我们的 DSH 内核零件；只要某个零件会限制我们的功能，就自己写。
- **视觉风格向 DSH 看齐。** DSH 的简约风格很好，我们参考它，必要时直接复用它的设计变量（颜色、字体、间距）。DSH 是 MIT 协议，允许这样用。

## 3. 知识模型（Obsidian 式网状图）

### 3.1 两层 + 证据

| 层 | 回答什么 | 内容 |
|---|---|---|
| **掌握层** | 你会了什么 | 知识节点和它们之间的关系；节点的颜色/标记表示你的掌握状态 |
| **来源层** | 知识从哪来 | 资料、资料片段（章节/页）、例题、题目，连到它们讲解或考查的知识节点 |
| 证据（在节点详情里） | 凭什么说你会 | 你的作答记录：哪一次、哪道题、是否独立完成、隔了多久 |

报告提醒过：不同的视图不要硬塞进同一张大网。所以默认只显示掌握层，来源层可以一键叠加；证据在点开节点后的详情面板里看，不画成节点。

### 3.2 节点

**知识节点分四种，用形状区分：**
- **知识**：概念、事实。
- **技能**：可以动手操作的步骤。
- **综合能力**：把多项知识和技能协调起来使用。
- **完整任务**：在真实场景下的整合表现，例如"独立读懂一篇论文的方法部分"。

**掌握状态用文字 + 颜色表示，不用百分比：**
- **未探测**（空心灰）：还不知道你会不会，**不等于不会**。
- **有帮助完成**
- **已独立完成**
- **已延迟验证**：隔一段时间后仍能独立完成。
- **证据冲突**：需要再检查一次。
- 另外两个附加标记：**待复查**（很久没练）、**有疑点**（在侧边会话或批注里反复问到）。

和当前目标无关的课程外节点淡化显示，不会把一大片未知节点都画成"不会"。

### 3.3 关系（每条连线都要有类型和出处）

| 关系 | 含义 |
|---|---|
| 组成 | A 是 B 的一部分（完整任务 ← 技能 ← 知识） |
| 先修 | 不会 A 就做不了 B（结构上必需） |
| 建议先学 | 先学 A 会让 B 更顺（只是教学顺序，可以绕开） |
| 相关 | 有联系，但没有先后要求 |
| 讲解 / 例题 / 考查 | 从来源层指向知识节点 |

报告强调过：不是所有连线都是先修关系。只有"先修"会硬性影响排课，其他关系都可以协商。

### 3.4 全局 vs 课程

- **知识节点全局共享。** 在 A 课学会的东西，在 B 课里直接可见，不用重学。报告的观点是：能力不应该绑死在某一门课的目录里。
- **但名字相同不等于同一种能力。** 跨课程合并节点的方式是：系统自动给出合并建议，由你确认。每条证据都要记下"是在什么条件下做到的"。
- **主界面显示全局图：** 可以按课程、状态、类型筛选，可以搜索，可以分组着色。
- **课程界面显示局部图：** 本课节点，加上向外 1–2 跳的相关节点，相当于 Obsidian 的"局部图"。

### 3.5 谁能修改知识模型

- **结构（节点和连线）：** Agent 在调研和设计时提出修改，附上理由和出处，记入变更日志，你可以撤销。你也可以手动修改。
- **掌握状态：** **只能由证据规则算出来。** Agent 和你都不能直接把一个节点"设为已掌握"。你可以说"这个我会，考我一下"，然后走快速验证。

## 4. 一门课的完整流程

```
建课 ─→ 目标确认 ─→ 摸底 ─→ 课程路线 ─→ ┌──────── 阶段循环 ────────────────────────┐ ─→ 结课
 │      （含调研）  （探边界）（粗，到阶段级）│ 阶段设计 → 教材 → 课时×N → 阶段测试 → 复盘  │
 │                                       └──────────↑ 复盘决定下一阶段怎么写 ─────────┘
 └ 导入资料（随时可以补充）
```

### 4.1 建课与导入资料

- 在主界面新建课程，一门课对应一个项目文件夹。
- 通过资料库（Open Notebook）导入资料：PDF、教材、讲义、网页、视频等。也可以先不导入，由 Agent 在调研时推荐。
- 资料导入后会被切成可以定位的片段（章/节/页），之后教材和题目都能引用到具体位置。

### 4.2 目标确认（Agent 同时在调研）

**协商方式：**
- 你先说一个模糊的愿望。
- Agent 不发长问卷，而是**先给出几个候选终点**，例如"科普级理解 / 能做题 / 能用于工程"，每个都配上"学成后你能做什么"的样例，由你挑选或修改。
- Agent 只追问会改变路线的问题（比如"想做应用还是做研究"），不问"你是视觉型还是听觉型"这类问题。

**产出目标说明（六要素）：**
- 目的
- 使用场景
- 学成后能做什么
- 要做到什么程度
- 怎么验证
- 边界：不学什么、测试时允许用什么工具、打算投入多少时间
- 可选：最后期限、考试档案（见 §4.12）

你确认后目标说明生效。之后要修改就走修改流程，并保留版本。

**同时进行的调研：** Agent 先查资料库，不够时再按"来源清单"联网找权威资料（具体做法见 §9.4），然后搭出**初版知识模型**，并收集**题源**（教材习题、往年题、公开课作业）。这门课的权威来源清单也在这一步确定，由你确认。

### 4.3 摸底：探知识边界

- **出题方式：** 只出少量、有区分度的题。从中等难度开始，沿着知识图往上探（会了就跳到更高层），或者往下探（不会就查它的先修）。这样十几道题就能大致定位你的边界。这是报告里提到的 ALEKS "知识空间"思路。
- **你说"这个我会"时：** 系统既不直接采信，也不逼你重学，而是出一两道短题快速验证。
- **心理预期：** 明确告诉你这只是摸底，不算成绩，答不出来很正常。
- **产出：** 在知识图上标出三类区域：已会 / 边界（正好可以开始学的部分）/ 未探测。

### 4.4 课程路线（粗略）

- 把目标切成若干**阶段**，每个阶段围绕一个"完整任务"来组织。这是报告里的 4C/ID 思路：学完一个阶段，你能完成一件完整的事，而不只是背下几个知识点。
- 路线只写到"阶段标题 + 阶段目标"这一层，**只有当前阶段会做详细设计**。后面的阶段会根据实际学习情况调整。
- 时间只给区间估计，不给精确的小时数。

### 4.5 阶段设计（每个阶段一份，认真设计）

顺序很重要，这是逆向设计：
1. **先定阶段验收。** 学完这一阶段能做到什么，再加上阶段测试蓝图：考哪些节点、用什么题型、在什么条件下考、哪些是新题。
2. **再定内容。**
   - 列出要覆盖的知识节点。
   - 已经有独立证据的节点，压缩成回顾。
   - 之前暴露出来的薄弱点，重点展开。
   - 穿插前面阶段内容的复习。
3. **听取你的要求。** 比如"按我导入的那本教材的顺序和讲法来""多给例题""先做个小项目"。
4. **产出阶段设计书。** 一页纸，包括目标、节点清单、课时安排、测试蓝图和要用到的资料。你确认后，再生成本阶段的教材。

### 4.6 阶段教材

- **一个阶段一份完整教材。** 不一次性写完整门课，也不学一点写一点。
- **为你定制：** 已经会的内容跳过或压缩，薄弱的内容展开。如果你指定了某本教材做骨架，就遵循它的结构。
- **由带固定 ID 的段落块组成：**
  - 每个块挂到对应的知识节点上，并标注出处（来自哪份资料的第几页）。
  - 批注锚定在块 ID 上，所以教材修订后批注不会丢。
- **不采信模型自身的知识：** 每个块都必须有资料出处。
  - 找不到出处的内容，先联网找权威资料补上（§9.4）。
  - 仍然找不到，就不写进教材；或者标为"待核实"，并提示你。
  - 生成完成后，逐条回查：引用的原文是否真的支持这句话。
- **例题和小问题：** 例题优先使用资料或权威来源里的题目。教材里还会嵌入少量"读完就答"的小问题，要求凭记忆作答，这是报告里证据最充分的学习手段之一。
- **文件形式：** 教材是 Markdown 文件，存放在课程文件夹里，你也可以直接打开看。

### 4.7 课时：按小节推进，学一节停一次

一个阶段不是一口气学完的。比如一章作为一个阶段，就按小节推进：**一个小节就是一个课时**。具体怎么切分，在阶段设计时决定。每学完一小节，停下来做一次小测和汇报，然后这一小节记入课程进度。

主老师在对话里发布任务，同一个任务也会以卡片形式出现在"课程进度"页。一个课时的典型节奏：

```
（可选）预测题：如果你已有基础，先试着猜一猜、做一做，再去读
         报告的依据：先尝试后教学，对有基础的人有效
   ↓
阅读任务：「读教材 1.3 节，读到"管内流动阻力"停下」
   ↓  阅读期间随时可以批注、开侧边会话提问
小节小测：凭记忆作答，2–5 题（开卷还是闭卷由老师定）
   ↓
练习：卡住时老师给刚好够用的提示 → 答对后换一道同类题，再独立做一次
   ↓
汇报：你用一两句话说说这节学到了什么、哪里还没弄清楚
   ↓
小结：老师结合小测和你的汇报，写出这节学会了什么、还缺哪些证据、下一节为什么这样安排
   ↓
记入课程进度：这一小节在阶段时间线上打勾，附上小测结果和小结
```

为什么要汇报：报告支持"有选择的自我解释"。用自己的话复述一遍，能帮你发现自己以为懂、其实没懂的地方；老师也能从中看出可能存在的误解。

报告补充的几条规则：
- **自我解释要有选择地用。** 只在关键处偶尔请你"用自己的话写一句批注"，不要求每段都写。
- **卡住时分情况处理：**
  - 你还在推进 → 先不打扰。
  - 方向对了但漏了条件 → 给一句提示。
  - 同一个错误反复出现 → 直接讲清楚。
  - 你随时可以选"我想直接看讲解"。
- **看答案不算失败。** 但这道题会记为"有帮助"，随后换一道题让你独立再做。

### 4.8 阶段测试

- **每个阶段结束都一定有阶段测试。** 必须独立完成，测试条件按目标说明里约定的工具条件执行（例如闭卷、可以查公式表等）。
- **测试组成：**
  - 本阶段核心节点的题目，其中一部分是**练习中没见过的新题**，用来防止背题、检验能否迁移到新情境。
  - 一道本阶段的"完整任务"题。
  - 少量**前面阶段的题**，用来检验隔一段时间后是否还会，也就是延迟验证。
- **开放题判分：** Agent 按评分标准初判，并标注自己的把握程度。把握低的标为"待复核"，不会直接判错。你也可以申诉。

### 4.9 阶段复盘 → 决定下一阶段

- **综合两类信息：**
  - 这段时间的学习过程：练习表现、用了多少帮助、在侧边会话里问了什么、写了哪些批注。
  - 阶段测试的结果。
- **给出结论和建议：** 逐个节点说明状态变化和理由，然后在以下几种做法中提出建议：
  - 进入下一阶段
  - 先插一个补课单元：**阶段测试没通过时默认这样做**
  - 调整后续路线
  - 重新审视目标
- **衔接下一阶段：** 你同意后进入下一阶段的设计（§4.5），这次复盘的结论会写进新的设计书。
- **通过标准不是一个固定的数字。** 关键的先修节点需要更多独立证据。如果你坚持往前走也可以，但系统会标明风险。

### 4.10 复习与回归

- **复习融入日常。** 复习穿插在后续课时和阶段测试里，不单独做成"背单词"式的功能。复习量有上限，不会把你淹没。
- **隔几天再回来时：** 先欢迎回来，做一两道短检查，然后接着学。不会给你列一张"欠课清单"。
- **有期限时（比如期末考试）：** 只有一个最后期限，不排死每天的日程。系统只判断"照现在的节奏能不能赶上"，用区间表示，不报精确数字。赶不上时会直接说明，并给出选择：缩小范围、增加时间或调整里程碑。

### 4.11 结课

- 用目标说明里约定的验证方式做最终检验，通常是一个完整任务。
- 生成课程报告：学会了什么（附证据），哪些还有待验证。
- 学到的节点留在全局知识模型里，之后其他课程可以复用；planner 也会偶尔安排复查。

### 4.12 有考试的课程：考试是目标的可选属性，不分两个版本

报告里的"考试类目标"并不是另一个产品版本，而是给目标额外加的几条要求。所以我们只有一套流程。确认目标时，如果发现有考试，就给目标挂上**考试档案**，流程中相关的环节会自动多做一些事；没有考试，这些都不出现。

**考试档案的内容：**
- 考试范围
- 题型和分值
- 考试时间和条件（开卷还是闭卷、能不能用计算器）
- 往年题
- 最后期限

一切以官方原文为准，比如学校的教学大纲和老师公布的考试范围。

**挂上考试档案后，各环节多做的事：**

| 环节 | 多做什么 |
|---|---|
| 目标确认 | 问你的侧重：只求通过、兼顾理解，还是以理解为主。报告提醒过，考试范围和真正有用的能力不完全重合，不能让"考试"悄悄替代你真正的目的 |
| 知识模型 | 节点上标出"考试范围内/外"；有些节点不在考试范围里，但对理解有帮助，会单独标出来，学不学由你决定 |
| 题库 | 往年题列为一级题源；阶段测试的题型向真题靠拢 |
| 临近期限 | 加做模拟考：限时、整卷，格式与真题一致 |
| 复盘 | 按考试的板块报告准备情况，比如"传热部分的计算题还不稳" |
| 排期 | 只按最后期限判断能不能赶上（§4.10） |

化工原理就属于这种情况：目标是"期末考试 + 真正理解"，学校的往年题是最好的题源。

## 5. 题目与测试

### 5.1 题目来源分级

你提出"尽量用权威题，不要让 Agent 自己编"，报告也支持这一点。下表在此基础上补充了权威题不够用时的办法。

| 级别 | 来源 | 可用于 |
|---|---|---|
| 1 | 你导入的资料里的习题/例题（教材课后题、讲义） | 所有场景，包括阶段测试 |
| 2 | 公认的权威来源（官方真题/样题、知名教材习题集、公开课作业） | 所有场景，包括阶段测试 |
| 3 | 改编题：在 1/2 级题目基础上改数字或情境，标注原题出处，答案用计算工具独立验算 | 所有场景，包括阶段测试；界面上明确标注"改编" |
| 4 | Agent 原创题，并明确标注 | 只用于练习和即时检查，不进入阶段测试 |

每道题都要记录：
- 出处（精确到页码/题号）
- 答案及答案来源（原书答案，或 Agent 解答但未经核对）
- 考查哪些知识节点
- 你是否见过这道题

### 5.2 练习题和测试题分开

练习用的题和阶段测试里的新题要从不同的题池里出。同一道题练过之后再出现在测试里，只能算"复现"，不能算迁移。权威题的数量有限，所以在做阶段设计时，就要先为测试预留好题目。

### 5.3 测试类型与独立性

| 类型 | 何时进行 | 是否算独立证据 |
|---|---|---|
| 摸底 | 建课时 | 算，但只用于定位边界 |
| 小节小测 | 每学完一小节 | 算（闭卷作答的前提下） |
| 练习 | 课时中 | 用了提示就记为"有帮助" |
| 阶段测试 | 每个阶段末尾 | 算，而且是最重要的证据 |
| 复查 | 回来时，以及阶段测试里的旧题 | 算，用来确认"已延迟验证" |

**测试期间的侧边会话：** 只回答操作类问题，不讨论题目内容。如果你主动退出测试去提问，这道题记为"有帮助"。退出测试永远是允许的，不会被拦着。

**工具条件：** 每门课单独约定。每次测试由老师选择开卷还是闭卷，默认值写在目标说明里。

### 5.4 换题与报错

- **来源标签：** 每道题都显示来源：原题（附出处）、改编（附原题）或原创。
- **"这题有问题"按钮：** 作答界面上随时可以点，原因分五种：题目有错 / 条件不全 / 超出范围 / 答案存疑 / **这题我做过**（作业或课上做过）。
- **点了之后怎么处理：**
  - 这道题不计分，系统从同一知识节点、相近难度的题池里换一道。
  - 报"有错"的题进入待核查：老师回查原书或重新验算。
    - 确实有错 → 修正或下架，并告诉你结果。
    - 题目没错 → 向你解释清楚。
- **"这题我做过"：** 这道题会被标记为你见过，以后不再当"新题"用。你在上课做作业，所以这一点很关键。
- **换题规则：**
  - 换题不扣分。
  - 为了保证测试仍然有效，一次测试的换题次数有上限。报错不限次数；超过上限后，该题跳过，不判错。
  - 看过的题即使被换掉，也记为"见过"。

### 5.5 判分

- **客观题**（数值、选择）：按规则判分。数值题判断"数值 + 允许误差 + 单位"。
- **开放题**：由 LLM 按评分标准判分，附上理由和把握程度；把握低的标为"待复核"。
- **拍照手写作答：**
  1. 你拍照上传解答。
  2. 看图模型把照片转写成文字和公式。
  3. **你先确认转写结果。** 有识别错的地方可以直接改，避免因为识别错误被判错。
  4. 按上面的规则判分：结果按数值规则判，解题步骤按评分标准判。
- **掌握状态的计算：** 由规则根据累积的证据算出，不采用 LLM 自己报的"掌握度"。

## 6. 侧边会话与批注

### 6.1 侧边会话（每个页面都能用）

- **自动带上下文。** 打开侧边会话时，会自动带上：
  - 当前页面
  - 你选中的内容：教材里的一段、知识图里的一个节点、课程进度里的一个阶段、刚做完的一道题
  - 你的学习状态摘要
- **与主老师会话隔离。** 侧边会话的内容不进入主课程会话的上下文，也不打断本课的流程。
- **结束时写总结。** 每次侧边会话结束后，系统会自动把一条结构化总结写进课程文件夹里的固定文件（例如 `notes/side-chats.md`）。总结包含：
  - 时间、所在页面
  - 问了什么、得出什么结论
  - 涉及哪些知识节点、可能存在什么误解
  - 给了什么帮助、有没有修改建议

这些总结有三个用途：
1. **学习信号。** 问到的知识点会在对应节点上标"有疑点"；推测出的误解会触发一道针对性的检查题。
2. **帮助记账。** 侧边会话里得到的讲解记为对该节点的"帮助"，紧接着的作答算"有帮助完成"（不扣分）。
3. **修改提案。** 例如你在"课程进度"页问"为什么阶段 3 要先学这个，能不能调换"，聊完后侧边会话会生成一份修改提案。你点"提交给主老师"，主老师就按统一的修改流程（§7）评估和修改。

主老师不会每一轮都读这些总结，只在课时小结、阶段复盘和阶段设计时读。

### 6.2 批注

- **批注对象：** 可以在教材上划线、写批注，也可以在导入的资料上批注。批注锚定到段落块 ID。
- **四种类型：** 疑问 / 我的理解 / 重点 / 报错（教材或题目有误）。
- **不同类型的后续处理：**
  - 疑问 → 可以一键转成侧边会话。
  - 报错 → 自动变成修改提案。
  - 我的理解 → 当作自我解释来评估，可能借此发现误解。
- 批注只是信号，不会直接提升掌握状态。

## 7. 修改流程（所有修改都走同一条路）

可以修改的对象：目标说明、课程路线、阶段设计书、教材、知识模型、题库。

```
提案来源：你直接提出 / 侧边会话生成的提案 / 批注里的报错 / 阶段复盘
   ↓
主老师评估：改什么、为什么改、会连带影响什么（比如改了目标，路线可能也要变）
   ↓
小改动：直接应用并告诉你
大改动（目标、路线、阶段设计）：等你确认后再改
   ↓
生成新版本，记入变更日志，可以回退
```

侧边会话本身不直接修改任何课程内容，只有主老师能改，这样可以避免多处同时修改造成冲突。

## 8. 数据：文件 + 数据库

**文件（存放在课程文件夹里，人可以直接阅读）：**
- 目标说明、课程路线、阶段设计书、阶段教材、侧边会话总结、课程报告
- 全部是 Markdown，组织方式类似 Obsidian 仓库。

**数据库（全局共用）：**
- 知识节点与关系、来源索引、题库
- 作答、帮助记录、证据、掌握状态
- 变更日志

**课程与 DSH 工作区的对应：**
- 一门课对应一个文件夹。
- 调研发现，DSH 的"工作区"正好就是"一个注册过的文件夹，带有它自己的会话"，和"课程 = 项目"的设想完全吻合。所以计划让课程直接复用 DSH 工作区，这一点在阶段 0 验证。

**会话与状态的关系：**
- **每个阶段一个主老师会话。** 新阶段开始时开一个新会话，把上一阶段的复盘结论和当前课程状态作为开场上下文带进去。
- 课程的真实状态始终保存在文件和数据库里，每一轮都从那里读取，不依赖聊天记录来"记住"进度。

**核心数据对象：**

| 对象 | 说明 |
|---|---|
| Course | 课程，对应一个文件夹/工作区 |
| Goal | 目标说明（六要素，带版本） |
| Roadmap / Stage | 课程路线与阶段（包括阶段设计书、测试蓝图） |
| Lesson / Task | 课时与任务（阅读、小测、练习等） |
| Node / Edge | 知识节点与关系（全局） |
| Source / SourceChunk | 资料，以及资料中可以定位的片段 |
| Block | 教材段落块（固定 ID，挂到节点上，带出处） |
| Problem | 题目（出处、答案来源、考查节点、所属题池） |
| Attempt | 作答 |
| Exposure | 帮助记录（提示、讲解、看答案、侧边会话里的讲解） |
| Signal | 信号（批注、提问、标记） |
| Evidence → NodeState | 证据，以及由证据推出的掌握状态 |
| Proposal / Change | 修改提案与变更日志 |

## 9. 技术底座与插件划分

### 9.1 底座：DSH（cordis）

DSH 本身就是"一切皆插件"的设计：一个 profile 由一层层 bundle 补丁叠加而成，可以按 id 增删插件。我们做自己的 bundle，**不 fork DSH 仓库**，只挑选需要的官方插件，再加上自己写的插件。

调研到的 DSH 能力，以及我们打算怎么用：

| DSH 能力 | 我们用来做什么 |
|---|---|
| 工作区与会话（`ui-workspace`、`ctx.sessions`、`ctx.agents.create`） | 课程 = 工作区；主老师会话；侧边会话（作为独立会话） |
| 系统提示组装（`ctx.systemPrompt`）、预设（`ctx.agentPresets`） | 设定主老师和侧边会话的角色与规则，注入课程状态 |
| 工具注册与限制（`ctx.tools`） | 学习领域的工具；不开放 shell、文件写入等危险工具 |
| 联网工具 `web_search` / `web_fetch`（背后的提供者可以通过 `ctx.web` 替换） | 把博查、Exa 等搜索源注册为提供者，用于调研和寻找题源（§9.4） |
| 后台任务（`ctx.jobs`） | 生成阶段教材、导入资料等耗时任务 |
| `web-app` 的服务端 + 客户端内核；`root` 插槽整页接管（§2.3） | 我们的前端跑在 DSH 内核上，界面全部自己写 |
| 类型化 RPC（`@Remote` + gateway；树外插件能否生成待实测）/ 认证通道上的自定义 HTTP 路由（备选） | 前端调用我们的后端插件 |
| Agent 预设（`agent-preset` + `persona`） | 主老师、侧边会话、判分、调研各一个预设：各自的工具、人设、模型 |
| 多模型适配（`llm-deepseek`、`llm-pi-ai`） | DeepSeek 为基准；其他厂商由你在设置里添加 |
| Node 自带 `node:sqlite`（DSH 存储也用它） | 我们的数据库；已实测中文全文检索可用，可以加载向量扩展 |

**要裁掉的：** shell/bash、文件写入、通用代码执行（`run_code`）、浏览器和电脑操控、子代理团队、工作流等。它们对学习产品没用，而且带来风险。

**验算怎么办：** 化工原理需要验算数值答案，我们自己写一个只能做数学计算、不能碰文件和网络的受限计算工具，而不是开放通用代码执行。

### 9.2 我们的插件

一个"功能单元" = 后端插件 + 对应的前端页面，开发时作为一个整体来做深。

| 功能单元 | 后端插件 | 前端 | 职责 |
|---|---|---|---|
| 存储 | `store` | — | 数据库、课程文件读写、版本与变更日志 |
| 资料库 | `library` | 资料库页、原文阅读 | 解析、切块、检索、带引用回答、联网找权威资料（§9.3、§9.4） |
| 知识模型 | `knowledge` | 知识图页 | 节点/关系/出处；全局图与课程局部图的查询 |
| 目标 | `goal` | 进度页·目标区 | 目标协商、调研、目标说明的版本管理 |
| 题库与测试 | `assess` | 测试页 | 题源分级、题池、摸底（探边界）、组卷、判分 |
| 课程设计 | `curriculum` | 进度页·路线/阶段区 | 课程路线、阶段设计书、课时与任务、复盘 |
| 教材 | `textbook` | 教材阅读器 | 生成阶段教材、管理段落块和出处 |
| 批注 | `annotation` | 阅读器内 | 批注锚定、分类，转成信号或提案 |
| 侧边会话 | `sidechat` | 右侧栏 | 带页面上下文的隔离会话、写总结文件、生成提案 |
| 主老师 | `tutor` | 主老师对话页 | 发布任务、决定给多少帮助、课时小结、处理提案 |
| 掌握分析 | `learner` | 知识图上的状态、节点详情 | 汇总作答/帮助/信号 → 证据 → 掌握状态 |
| 调度 | `planner` | 首页·今日、状态栏 | 安排下一步、复习、回来后的恢复 |
| 外壳 | — | 独立前端应用：布局、活动栏、状态栏 | 在主界面和课程界面之间切换（§2.3） |

插件之间通过 cordis 的服务和事件通信。例如：
- `assess` 发出"作答已判分"事件 → `learner` 更新掌握状态 → `knowledge` 的图上节点变色。
- `sidechat` 写完总结 → 发出信号/提案事件 → `learner` 和 `tutor` 分别接收。

### 9.3 资料库：自建 NotebookLM 式资料库（不用 Open Notebook）

**目标：** 做到 NotebookLM 的核心体验：回答和教材只依据资料，每一句话都能点开，跳到原文的那一页、那一段。

**为什么不用 Open Notebook 和同类现成产品：**
- **我们要的比 NotebookLM 多：** 页码级出处、从教材里抽题、把资料片段挂到知识节点、权威分级。现成产品都没有这些功能，即使接进来，也得在外面再包一层。
- **Open Notebook 和我们是两套系统：** 它需要 Docker + Python + SurrealDB，有自己的界面和数据库；而且它自己承认引用功能还比较基础。
- **真正的难点是把扫描版教材读准：** 公式、表格、图都要识别正确。这一块，专门的文档解析器比任何 NotebookLM 替代品都强，而且可以直接接入。

**方案：** 全部放在我们的 `library` 插件里。每个环节都是可替换的零件，换零件不影响上层插件。

| 环节 | 做法 | 可替换为 |
|---|---|---|
| 解析 | MinerU（4.0，协议是在 Apache 2.0 基础上附加条件）。**在本地跑还是调用官方云 API，由你在设置里选择**：本地跑隐私好，只用 CPU 也能运行；云 API 省事，但文件要上传。文字版和扫描版 PDF 都能处理，扫描件走中文 OCR。输出 Markdown/JSON，每块都带"第几页第几块"的定位，公式转成 LaTeX | PaddleOCR-VL、DeepSeek-OCR-2 等 |
| 切块 | 按教材结构切分（章、节、例题、习题、附录表），保留页码和块的定位 | — |
| 检索 | SQLite 全文检索（中文用 trigram 分词）+ 向量检索（sqlite-vec 或 LanceDB），混合排序，可以加重排模型 | — |
| 向量模型 | 需要单独配置，因为 DeepSeek 官方文档没有列出向量接口。尽量兼容所有主流服务（BGE-M3、Qwen3-Embedding 等），你填了哪家就用哪家（规则见下方"服务兼容"）。注意：更换向量模型后，资料要重新建索引 | 任意 |
| 回答/写作 | 只依据检索到的片段生成，强制附带引用；生成后逐条回查"引用的原文是否真的支持这句话" | 长上下文模型可以直接读整节 |
| 阅读 | 原文按页显示；点击引用跳到对应页并高亮 | — |

### 9.4 联网找权威资料

**你的要求：** 一定要联网补充，只信权威资料，不信模型自己生成的内容。

**结论：** 只接 Exa、Tavily 这类搜索接口确实不够。它们决定的是"能搜到什么"，而最终质量主要取决于"搜什么、信谁"。所以要做成一条管线：

```
① 先查资料库（你的教材、课件）：对这门课来说这是最权威的
   ↓ 不够用时
② 按"来源清单"定向搜索：清单在确认目标时由老师提出，你来确认
   ↓
③ 同时使用多个搜索源（可插拔）
   ↓
④ 抓取全文 → 按我们自己的规则评定权威级别 → 关键事实交叉核对
   ↓
⑤ 存入资料库（带出处和权威级别，你可以审核）→ 之后教材和题目只引用资料库里的资料
```

**来源清单示例（化工原理）：**
- **一级：** 你的教材，你们学校的课件、作业和往年题。
- **二级：** 其他高校同名课程的教材和课程网站（出版社、edu.cn）、国家级精品课和中国大学 MOOC、国家/行业标准、经典手册（如 Perry 化学工程师手册）。
- **三级：** 国外开放课程（MIT OCW、NPTEL、LibreTexts 等）、正式发表的论文。
- **不采信：** 内容农场、未署名的博客、问答网站上的回答。这些可以当线索，但不能当出处。

**搜索源（全部做成可插拔的提供者）：**

| 类型 | 候选 | 说明 |
|---|---|---|
| 中文网页 | 博查（Bocha）、秘塔（Metaso） | 中文效果好；据博查自己介绍，它是 DeepSeek 官方联网搜索的供应商 |
| 英文网页 | Exa、Tavily、Brave | Exa 擅长语义搜索；Brave 有自己的独立索引，速度快 |
| 学术 | OpenAlex、Semantic Scholar（都有免费的官方 API） | 谷歌学术没有官方 API，只能通过第三方抓取服务（如 SerpAPI）调用，而且对本科课程帮助有限，作为可选项 |

**模型知识的定位：** 可以用来想出该搜什么、怎么组织内容，但不能当出处。

**服务兼容（搜索服务、向量模型、解析服务都适用）：**
- **尽量兼容所有主流服务。** 你在设置里填了哪家的 key，就用哪家。
- **多家都配了时，按效果排序使用：** 默认顺序来自我们的实测结果（阶段 0 和资料库单元的调研），你也可以手动调整。
- **排在前面的失败或超时时，自动换下一家。**
- **中文和英文分开排序：** 中文搜索和英文搜索各有一份排序，可以同时使用多家。

### 9.5 模型策略：以 DeepSeek 为基准

**你的要求：** 用普通模型时体验要好，用高级模型时要有发挥空间，以 DeepSeek 为例。

**基准：** 所有功能都以 DeepSeek 为基准来设计和测试。DSH 默认提供两个模型：

| 模型 | 输入 | 上下文 | 适合的角色 |
|---|---|---|---|
| `deepseek-flash` | 文本 + 图片 | 100 万 token | 大多数角色；拍照手写识别（只有它能看图） |
| `deepseek-v4-pro` | 仅文本 | 100 万 token | 重推理：阶段设计、复杂判分、调研 |

上下文达到 100 万 token，意味着一整章甚至一整本教材都能直接放进上下文。资料库可以采用"检索定位 + 长上下文通读"的组合。

**让普通模型也好用：**
1. 能用程序解决的就不用模型：数值题判分、单位换算、答案验算、掌握状态推导，都用规则或程序来做。
2. 把大任务拆小：教材按段落块逐块写，判分按维度逐项判，调研按步骤逐步走。
3. 要求模型按固定格式输出，自动校验，失败就重试。
4. 检索时给足资料，不依赖模型自己的记忆。

**给高级模型留空间：**
- **按"任务角色"配置模型：** 主老师、侧边会话、教材写作、判分、调研、资料解析，每个角色都可以用不同的模型。默认全部用 DeepSeek，比如 flash 跑轻任务，pro 跑重任务。
- **按模型能力开关功能：**
  - 支持长上下文 → 直接读整节内容，而不只读检索出来的片段。
  - 看图能力更强 → 手写识别和教材插图理解得更准。注意：拍照手写作答本身是第一版的基础功能，DeepSeek 已经支持图片输入。
  - 推理能力更强 → 少拆几步，调研做得更深。
- **能力不够时自动退回基础流程：** 功能不会缺失，只是实现方式不同。

**验收方式：** 每个用到模型的环节都配一小组标准样例，用 DeepSeek 跑通才算验收通过。

## 10. 开发路线

开发方式由你确定：先定大方向 → 拆成插件 → 一个插件一个插件地做深。我在中间补了一步"薄骨架"，避免第一个插件做深了之后才发现接口不对。

### 阶段 0：底座、契约、骨架

> **进度（10-03）：** 调研已完成，见 [stage0/research.md](stage0/research.md)。下一步是动手验证 V1–V10（清单见该文第八节），需要你先准备 DeepSeek key、教材电子版和几张手写照片。

1. **技术验证**（只做验证，不做产品）：
   - **DSH 当后端：** 锁定版本 `0.2.0-rc.2`，确认以下几件事能否实现：
     - 去掉 DSH 的界面插件后，我们的前端插件能占用 `root`，并且能发消息、流式接收回复、管理会话
     - 前端能调用我们自己插件的接口（typert；不行就用备选的 HTTP 路由）
     - 课程复用工作区
     - 用程序创建会话（侧边会话、每阶段一个的主老师会话）
     - 把自己的搜索提供者注册到 `ctx.web`
     - 限制工具，只开放我们的工具
   - **资料解析：** 用 MinerU 解析你的化工原理教材（本地和云 API 各跑一次），检查公式、表格、页码定位的质量；测一下中文检索效果。
   - **搜索：** 用 10 个化工原理的真实问题，对比几个搜索源的结果质量，得出默认排序。
   - **拍照手写：** 用 DeepSeek 识别几张手写解答照片，检查公式和数字的识别准确率。
   - **前端：** 选定停靠布局库，参考 DSH 的视觉风格，做一个空壳（能切换主界面/课程界面，有标签页和右侧栏）。
   - 产出：一页"能做 / 不能做 / 需要绕开"的清单。
2. **定契约**：§8 的数据对象、插件之间的服务和事件、课程文件夹的结构。
3. **搭薄骨架**：每个功能单元先做最简版本，跑通下面这条线：
   - 建课 → 确认目标 → 3 道摸底题 → 一页阶段设计 → 一节教材
   - → 发布阅读任务 → 小测 → 更新掌握状态 → 一次侧边会话写入总结

### 阶段 1 起：按学习旅程的顺序逐个做深

`library` → `knowledge` → `goal` → `assess` → `curriculum` → `textbook` → `annotation` + `sidechat` → `tutor` → `learner` → `planner`

**为什么按旅程顺序：** 每做深一个单元时，它需要的输入已经由前面的单元真实产生出来了。

**为什么 `learner` 放在后面：** 到那时作答、帮助、信号、批注都已经是真实数据，规则可以对着真实情况来设计。在此之前，先用骨架里的简单规则顶着。

**每个单元做深的固定步骤：**
1. **专门调研：** 找这个单元的最佳做法（相关研究、开源实现、可用的库和服务）。本 PLAN 只给方向，具体做法以调研结果为准。
2. **讨论设计**
3. **写验收标准**
4. **实现并测试**
5. **你自己用一遍**
6. **更新本 PLAN**

## 11. 明确不做（报告红线 + 当前范围）

- 不把"读完了 / 聊得顺 / 打卡天数 / 图谱好看"当作学会。
- 不显示假精确的掌握百分比和剩余小时数。
- 不把模型自身的知识当作出处。
- 不在 DSH 的界面上小修小补来当我们的前端。
- 不按"视觉型/听觉型"这类学习风格做个性化。
- 不做多个 Agent 互相讨论，不做强化学习。
- 不让系统根据日志自动改写课程结构，所有修改都走 §7 的流程。
- 第一版只做本地、单用户；不做多用户、公网部署、积分排行。
- 第一版的代码是通用的，但只在一个领域上打磨质量。
