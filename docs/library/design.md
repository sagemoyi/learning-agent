# 资料库（library）

> 代码：[`packages/library`](../../packages/library) · 调研：[research.md](research.md) · 接口：[契约](../stage0/contracts.md) §5.1 和 §11"资料库 A/B" · 验证：[验证记录](../stage0/compatibility.md)里的"资料库"各节

资料库负责把你的教材和其他资料变成可以引用的片段：解析、切块、检索、出处定位，以及联网找权威资料。目标是做到 NotebookLM 的核心体验：回答和教材只依据资料，每一句话都能点开，跳到原文的那一页、那一段。

## 现状

- **已验收：**
  - **PDF 导入与出处定位（批次 A）：** 从页面选择或拖入 PDF，后台解析；任务能取消、重试，程序重启后能恢复；同一内容不会重复导入；原件和完整解析结果都保存；用 PDF.js 阅读原文，点出处翻到对应页并高亮区域，缩放、旋转后仍对齐；能校正书上页码和 PDF 页码的固定偏移；重新解析生成新快照，旧的出处仍然有效。
  - **在线解析：** 默认用 MinerU 云端，长书自动分段提交，失败的页段拆小重试、只补缺页。
  - **混合检索（批次 B）：** 关键词 + 语义检索，再用重排模型打相关度；资料里没有答案时明确说"资料里没有"。老师的 `search_library` 工具和资料库页面的检索框都用这一套。
  - **设置：** 设置页"资料服务"里能切换解析方式、填写密钥、开关语义检索、测试连接。
  - 日常库里你的化工原理教材已整本解析（488 页），语义索引已建好。
- **待你试用：** 整本教材的出处定位，以及用它生成教材的效果。
- **还没做：**
  - 联网补充（批次 C，见下文"联网找权威资料"）。
  - 检索结果的上下文扩展（命中一段后取相邻段落或整节）、引用证据接口。
  - PDF 以外格式的原文阅读；不规则的页码对应（罗马数字前言、插页）。
- **已知限制：** 解析会把个别公式符号认错，复杂题号的分组靠规则推断。原文对照和核对提示都有，但"解析完成"不等于"内容已核实"。

## 为什么不用 Open Notebook 和同类现成产品

- **我们要的比 NotebookLM 多：** 页码级出处、从教材里抽题、把资料片段挂到知识节点、权威分级。现成产品都没有这些功能，即使接进来，也得在外面再包一层。
- **Open Notebook 和我们是两套系统：** 它需要 Docker + Python + SurrealDB，有自己的界面和数据库；而且它自己承认引用功能还比较基础。
- **真正的难点是把扫描版教材读准：** 公式、表格、图都要识别正确。这一块，专门的文档解析器比任何 NotebookLM 替代品都强，而且可以直接接入。

## 怎么运作

全部放在 `library` 里，每个环节都是可替换的零件，换零件不影响其他单元。

| 环节 | 做法 | 可替换为 |
|---|---|---|
| 导入 | 设计上要支持 PDF、教材、讲义、网页、视频等，已实现的只有 PDF：在资料库页面选择或拖入。也可以先不导入，由老师在调研时推荐。导入任务由 `library` 保存，DSH 的后台任务负责运行；完成后才算可用，再交回主老师 | — |
| 解析 | MinerU（4.0，协议是在 Apache 2.0 基础上附加条件），按设置项 `parser` 选择：`cloud`（默认）上传到 MinerU 云端，省事、快，但文件要上传；每份最多 200 页，长书按页段提交、按原页码合并。`local` 用本机 MinerU（`pnpm mineru:start`），隐私好，但整本书要近一小时。文字版和扫描版都能处理，扫描件走中文 OCR；每块带"第几页、在哪个位置"，公式转成 LaTeX | PaddleOCR-VL、DeepSeek-OCR-2 等 |
| 切块 | 按教材结构切分（章、节、例题、习题、附录表），保留页码和块的定位；跨页的题干和答案归为一组。教材和题目都引用到具体位置 | — |
| 检索 | 关键词：SQLite 全文索引（中文用三字切分，不足三个字的词用子串匹配）。语义：Voyage AI 的 `voyage-4`（1024 维），需要单独配置，因为 DeepSeek 官方没有向量接口；向量存在 `library` 自己的表里，不同模型的向量分开存、不混用，换模型时自动重建索引。两路结果按名次融合（RRF），前 24 条用 `rerank-2.5` 重排；最高相关度低于 0.5 判为"资料里没有"，低于 0.3 的片段不返回。语义检索关闭、缺密钥或服务出错时退回关键词检索，并说明原因 | 其他向量和重排服务（见"服务兼容"） |
| 回答和写作 | 只依据检索到的片段生成，强制附带引用；生成后逐条回查"引用的原文是否真的支持这句话"（逐条回查还没做，归 [textbook](../textbook/design.md)） | 长上下文模型可以直接读整节 |
| 阅读 | 原文按页显示；点出处在旁边打开原文，翻到对应页并高亮区域；缺坐标信息时只定位到页 | — |

**发往在线服务的内容：** 云端解析会把 PDF 原件上传到 MinerU；语义检索会把资料片段和检索问题发给 Voyage AI。这是你选择的方式，页面上有提示。用真实教材验收在线服务前，先问你。

精确的接口、数据表和事件见契约 §11"资料库 A 做深补充""资料库 B 与在线服务"。

## 联网找权威资料（未实现，批次 C）

**你的要求：** 一定要联网补充，只信权威资料，不信模型自己生成的内容。

**结论：** 只接 Exa、Tavily 这类搜索接口确实不够。它们决定的是"能搜到什么"，而最终质量主要取决于"搜什么、信谁"。所以要做成一条管线：

```
① 先查资料库（你的教材、课件）：对这门课来说这是最权威的
   ↓ 不够用时
② 按"来源清单"定向搜索：清单在确认目标时由老师提出，你来确认
   ↓
③ 同时使用多个搜索源（可插拔）
   ↓
④ 抓取全文 → 按我们自己的规则评定权威级别 → 关键事实交叉核对
   ↓
⑤ 存入资料库（带出处和权威级别，你可以审核）→ 之后教材和题目只引用资料库里的资料
```

**来源清单示例（化工原理）：**
- **一级：** 你的教材，你们学校的课件、作业和往年题。
- **二级：** 其他高校同名课程的教材和课程网站（出版社、edu.cn）、国家级精品课和中国大学 MOOC、国家/行业标准、经典手册（如 Perry 化学工程师手册）。
- **三级：** 国外开放课程（MIT OCW、NPTEL、LibreTexts 等）、正式发表的论文。
- **不采信：** 内容农场、未署名的博客、问答网站上的回答。这些可以当线索，但不能当出处。

**搜索源（全部做成可插拔的提供者）：**

| 类型 | 候选 | 说明 |
|---|---|---|
| 中文网页 | 博查（Bocha）、秘塔（Metaso） | 中文效果好；据博查自己介绍，它是 DeepSeek 官方联网搜索的供应商 |
| 英文网页 | Exa、Tavily、Brave | Exa 擅长语义搜索；Brave 有自己的独立索引，速度快 |
| 学术 | OpenAlex、Semantic Scholar（都有免费的官方 API） | 谷歌学术没有官方 API，只能通过第三方抓取服务（如 SerpAPI）调用，而且对本科课程帮助有限，作为可选项 |

阶段 0 实测过 Exa 和 Tavily：Exa 明显更好，指定 `edu.cn` 域名后几乎全是高校来源；老师的 `web_search` 可以换成我们接的提供者（[验证记录](../stage0/compatibility.md) V5、V8）。

**模型知识的定位：** 可以用来想出该搜什么、怎么组织内容，但不能当出处。

## 服务兼容

适用于搜索服务、向量模型和解析服务：

- **尽量兼容所有主流服务。** 你在设置里填了哪家的密钥，就用哪家。
- **多家都配了时，按效果排序使用：** 默认顺序来自我们的实测结果，你也可以手动调整。
- **排在前面的失败或超时时，自动换下一家。**
- **中文和英文分开排序：** 中文搜索和英文搜索各有一份排序，可以同时使用多家。

目前解析只接了 MinerU（云端和本机），语义检索只接了 Voyage AI；其他服务和排序、自动切换在需要时再加。

## 关键决定

- **自建资料库，不用 Open Notebook**（10-03，你提要求，Claude 给方案）：解析器可替换（默认 MinerU），检索和引用由我们自己实现。理由见上文。
- **文字版和扫描版教材都支持**（10-03，你）。
- **在本机解析还是用云服务，由你选择**（10-03，你）：对应设置项 `parser`。
- **各类服务尽量全部兼容，配了多家时按实测效果排序，失败自动换下一家**（10-03，你；排序和切换规则由 Claude 补充）。
- **联网补充做成"来源清单 + 多搜索源 + 权威评级 + 交叉核对"的管线**（10-03，你；管线由 Claude 补充）。
- **分三批交付，先做 A（PDF 导入与出处定位）**（10-04，你选择"先完成 PDF 导入与出处定位"）：B 检索和引用、C 联网补充排在后面，没有取消。
- **导入任务由 `library` 保存，DSH 的后台任务只负责运行**（10-04）：DSH 的任务 ID 不能用来恢复；重解析生成新快照，旧引用保留；MinerU 的归一化坐标换算成 PDF 点，缺几何信息时只定位到页。
- **解析和语义检索改用在线服务**（10-04，你："先不弄本地了吧，直接用在线api吧"）：本机解析整本书近一小时，太慢；本机 GPU 加速先不做，本机解析保留为可选。
- **混合检索的默认参数**（10-04，Claude 按 38 条合成查询的基准定）：只用关键词时，换一种说法的问题 15 条只找回 1 条；混合检索加重排后，有答案的问题第一名全部正确，有无答案的判断全对。向量相似度判断不了"资料里没有"，重排的相关度可以。
- **云端分段失败只补缺页**（10-04，你反馈后段失败；Claude 实现，Codex 复核）：完成的页段单独保存；多次失败时保留已完成部分，说明是哪几页，缺页的结果不发布。

完整的决定和来源见[决策记录](../decisions.md)。
