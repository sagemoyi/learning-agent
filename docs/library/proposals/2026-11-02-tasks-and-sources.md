# 关掉就停，任务认准自己的服务，跳转后重新定级

> 来源：11-02 的外部审查（[报告](../../history/2026-11-audit/report.pdf)，括号里是报告的编号）。这里是审查建议先定下来的接口里的"任务接口"在资料库上的部分（讲义生成的部分见 [讲义](../../textbook/design.md#发布恢复和块-id)）。修复顺序见 [现在](../../now.md#修复顺序)。

## 问题

- **关掉语义检索，当前这本书还在上传（SEC-03）：** 关开关或删掉 Voyage 密钥会触发 `refresh()`，它清空排队、换掉检索器，但正在建索引的那本书用开始时拿到的检索器继续一批批上传，直到传完；只有整个插件退出才会中止。设置页显示"已关闭"，片段却还在发往 Voyage、还在花额度。
- **切换解析服务后，取消发错了地方（SEC-07）：** 在 A 服务解析时切到 B，再点取消：取消请求带着 A 的任务号发给了 B，A 那边继续解析、继续计费，本地却显示"已取消"。重启恢复时也按当前的服务去查原来的任务号。任务只存了远端任务号，没存属于哪个服务。
- **MinerU 的跳转没有上限（SEC-06）：** 请求遇到 302 就递归再请求，没有跳数限制、不查循环，每跳重新计时，整条链没有总的截止时间。服务或对象存储配置错了，导入会一直请求下去。
- **跳转到别的网站，仍按原网站定级（SEC-02）：** 加网页资料时只给输入的网址定级。可信网站的跳转链接把内容转到"只当线索"甚至被排除的网站时，内容照样作为二级来源加入课程、跳过三级确认，出处还写原网站。逐跳的网络安全检查是有的，这里缺的是"内容从哪来"的重新定级；不是已证实的内网访问漏洞。
- **任务没有总预算，费用对不到任务上（M06），各服务收到了什么说得不够清楚（M09）：** 一次性调用有重试和输出上限，但一个后台任务（导入、建索引、生成讲义）没有总的截止时间和费用上限，重试的消耗也没有记到同一个任务上。设置页的"数据与隐私"写了每个服务收到什么，没写关掉开关对已经在跑的任务有什么作用。

## 方案

1. **任务记下自己属于谁：** 每个后台任务（导入解析、建索引）开始时存下：服务（解析器或检索器的种类、规范化的地址）、不含密钥的配置版本号、远端任务号、开始时间和总截止时间。取消、查询、恢复都用任务自己存的服务；当前设置换了服务时，旧任务要么在原服务上完成或取消，要么明确标为"要重新提交"，不把旧任务号带到新服务。
2. **停用会传到在跑的任务（SEC-03）：** 每个建索引任务有自己的中止信号；关开关、删或换密钥、换服务时中止在途请求、丢掉后面的批次；每批开始前核对配置版本号。资料页和设置页分开显示"已发送 N 批""正在停""已停""远端取消没确认"。重新开启后从已完成的片段接着做。
3. **跳转有上限（SEC-06）：** 改成循环处理跳转，最多 5 跳、检查循环，所有跳共用一个总截止时间；跨域跳转不带密钥；307/308 保持原来的请求方法。
4. **按最终地址定级（SEC-02）：** 抓取层返回完整的跳转链；每一跳和最终地址都按网站规则重新定级，取最低的：落到"只当线索"或被排除的网站就拒绝，从二级跳到三级就进三级确认；存下请求的网址、最终网址、抓取时间和实际级别，出处指向真正提供内容的网址。网页、PDF、`read_web` 和 Exa 的回退都走这一套。
5. **任务的预算和记账（M06）：** 任务带总截止时间；重试、分段的模型调用和服务调用都记到同一个任务上（次数、token、页数），资料页显示。费用上限先只记录、不拦截，等有了真实数据再定上限。
6. **说清楚关掉的效果（M09）：** "数据与隐私"里每个服务写明：关掉或删密钥后，之后不再发送；已经发出的收不回；正在跑的任务会停在哪一步。

## 放弃的方案

- **关开关时等当前这本书传完再停：** 你关掉的意思就是别再发了。
- **切换服务时禁止切换，直到所有任务结束：** 解析一本大书要几十分钟；任务记下自己的服务就能放开切换。
- **跳转一律不跟：** 很多正规网站和 MinerU 的结果地址都用跳转；有上限、重新定级就够了。

## 验收标准

1. 建索引的第一批在途时关掉语义检索、删密钥、换密钥、插件退出：都不再发出新的批次，在途请求收到中止；重新开启后从已完成的片段继续，旧配置的结果不覆盖新任务的状态。
2. A 服务解析中切到 B 再取消：取消发给 A；重启后按 A 查原任务；两个服务用了同一个任务号互不影响；A 已经不可用时显示"远端取消没确认"。
3. 跳转自己指向自己、两个地址来回跳、超过 5 跳：很快失败，总耗时不超过一个截止时间；跨域跳转不带密钥。
4. 二级网站跳到"只当线索"或被排除的网站被拒绝；二级跳三级进确认；二级同域跳转照常加入，出处写最终网址。
5. 一次导入的重试和分段调用都记在这个任务上，资料页能看到。
6. `pnpm typecheck`、`pnpm test`（含 `tests/flow.test.ts`）、`pnpm build` 通过；自动测试只用假服务，不调用 MinerU、Voyage 和搜索服务。

## 风险

- 任务表加字段要迁移，老任务没有服务记录：升级时按当时的设置补上，并标"服务按升级时推断"。
- 真实服务的取消接口行为（MinerU 是否支持取消、取消后是否还计费）要查官方文档；查不到的，在页面上如实写"不确定"。
