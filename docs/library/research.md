# 资料库做深调研与设计草案

> 2026-10-04（C 的调研 10-07）· 对应 PLAN 阶段 1 的 `library` · 状态：A、B 已实现并验收，C 已实现、待你试用；资料库现在的状态和做法以 [design.md](design.md) 为准。

建议先把“选一份 PDF，等待解析，阅读原文，点击出处定位”做好，再加入混合检索和联网补充。保留已确认的自建资料库、可替换解析器和单一数据主人。下面区分外部资料的结论、当前代码的限制和本项目的建议；建议尚未成为已确认契约。

## 当前起点

骨架能导入已经解析好的 MinerU JSON，保存原件和解析结果，建立章节与页码索引，并用 SQLite 检索。学习者需要手填原文件路径和解析结果路径；点击出处只能看到识别出的文字。资料导入没有持久化任务、去重和取消，表格被压成纯文本，图片没有完整保留，片段分类主要靠标题和题号规则。

阶段 0 已在本机验收 MinerU 4.0.10 与扫描教材，也验收了 Windows 下的 SQLite 向量扩展，详见 [兼容性记录](../stage0/compatibility.md)。这只能证明技术可用，不能代替资料库产品验收。本轮没有重新发送真实教材，也没有升级本机解析器。

## 解析服务和结果格式

MinerU 的 V1 API 使用上传、提交解析任务、查询状态、下载产物的流程，服务能力由 `/v1/health` 给出。任务可有部分成功结果；超时不等于任务取消。自托管服务的任务资源索引在内存中，重启后不能继续使用原任务 ID。[MinerU V1 API 文档](https://opendatalab.github.io/MinerU/usage/http_api/)

**本项目建议：** 学习工作台自己保存导入任务和文件，DSH jobs 负责运行与进度展示。恢复时先查服务任务是否仍存在；不存在则用已经保存在资料库的原件重新提交。暂停等待、取消、失败和部分完成分别显示，不能把“提交成功”当作“资料已可引用”。保持本机已验证版本，实施前用合成文件核对该服务的实际接口和能力。

旧云精准解析接口与本地 V1 API 的请求协议不同；旧云轻量接口主要给 Markdown，不能据此假定有完整的块定位和图片包。云端适配应单独处理，具体使用哪套协议以服务探测为准。[MinerU 云 API 文档](https://mineru.net/doc/docs/index_en/)

**本项目建议：** 默认沿用你之前选择的本地解析。用户明确选云服务时才上传；失败时只在同一种数据发送范围内切换服务。把解析器包装成可替换适配器，不让教材、题库和前端直接依赖 MinerU 的响应字段。

MinerU 4 的中间结果通过 `schema` 与 `schema_version` 标识协议，页索引从零开始。结构化 JSON 与完整结果包也不同：仅有 JSON 未必包含图片；结果包应保存实际资源引用和页面几何信息。[MinerU 输出格式文档](https://github.com/opendatalab/MinerU/blob/master/docs/en/reference/output_files.md)

**本项目建议：** 完整保存原件、结构化结果和图片资源，进入自己的标准格式时统一成一基页码，并记录坐标单位与页面尺寸。原始解析块是引用的最小单位，保留其定位与标识。检索可以合并邻近块，但结果必须带回组成它的原始块；例题、题干和答案分组，保留原题数据。

## 检索和引用质量

SQLite FTS5 的 trigram 查询不能直接命中不足三个字符的子串，因此“压强”“黏度”不能只走 MATCH。[SQLite FTS5 文档](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)

**本项目建议：** 短词保留精确子串检索；较长词用全文索引；语义检索独立召回近义表达。课程范围、资料类型和教学内容过滤在召回时生效。教材默认排除习题和答案，抽题则主动请求题目分组，避免先检索再过滤造成泄题或漏召回。

sqlite-vec 提供兼容 `node:sqlite` 的加载方式，能继续使用现有数据库。[sqlite-vec Node 文档](https://alexgarcia.xyz/sqlite-vec/js.html)

**本项目建议：** 先用已验证的 SQLite 方案，不新增另一套数据库。向量服务可以独立配置；未配置或暂时失败时，全文检索仍可用。每份向量索引记录提供者、模型、维度和输入文本指纹，更换模型时另建索引，不能把不同模型的向量混查。先在合成语料上对比全文、向量和混合结果，再确定默认参数。

RRF 按名次合并检索结果，适合作为无需分数标定的初始基线；后续研究也表明它并非所有任务的最优融合方法，参数和语料会影响结果。[RRF 原论文](https://cormack.uwaterloo.ca/cormack/cormacksigir09-rrf.pdf)、[混合检索融合研究](https://arxiv.org/abs/2210.11934)

**本项目建议：** 用 RRF 建立基线，与经过标定的加权融合比较。重排模型先作为可选项，只有合成基准显示收益才作为默认。中文、公式、单位和题号分别验证，不直接照抄英文问答榜单。

OpenDataLab 的 Document Explorer 已实现关键词、向量、重排和深度阅读，可借鉴它的模块分工；它有自己的索引和知识组织体系。[项目架构](https://github.com/opendatalab/MinerU-Document-Explorer/blob/main/docs/architecture.md)

**本项目建议：** 借鉴检索与通读分工，保留本项目 `library` 的数据所有权。命中某个小节后允许取相邻段落或整节，受上下文预算限制；不把全书长期塞入每轮老师会话。

引用链接存在，并不能证明原文支持结论。ALCE 将答案正确性与引用质量分别评估。[ALCE 论文](https://arxiv.org/abs/2305.14627)

**本项目建议：** `library` 提供引用原文、定位、资源和结果中允许使用的片段集合；回答或教材的主人单元检查自己的输出。涉及数值、单位、适用条件的关键陈述分别核对。无支持或资料冲突时说明缺口，保留“待核实”。教材逐句语义核对仍归 `textbook` 做深，不能在此提前宣称完成。

## 原文阅读和导入交互

PDF.js 提供页面视口和页面渲染接口，可以在独立 PDF 阅读器上叠加来源区域。[PDF.js 页面接口](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html)

**本项目建议：** 资料页提供文件选择与拖入；先只对 PDF 的完整流程验收，同时保留“已有解析结果”入口。资料卡显示上传、排队、解析、索引、可用、失败等状态。点击出处在相邻标签页打开原 PDF 的正确页，按实际坐标高亮；缺坐标时明确降级为页定位和文本片段。旋转、缩放和跨页块需要专门验收。

书上页码与 PDF 页码分开记录。先保留当前已支持的固定偏移，让用户用两页预览校正；罗马数字前言、插页等不规则映射作为后续扩展。解析结果和原图可以对照，发现公式或表格识别有误时保留原图，并标出该片段需要复核。

## 建议按三批交付

| 批次 | 用户可试用的结果 | 主要工作 |
|---|---|---|
| A 导入和原文 | 选择 PDF 后自动解析，能看进度、重试、查看原文，出处跳到页和区域 | 本地解析适配器、持久化导入任务、内容指纹去重、完整资源保存、PDF 阅读器；保留现有合成流程 |
| B 检索和引用 | 短中文词、同义问法、公式相关问题能找回材料；回答明确带出处或说明缺口 | 全文与向量召回、融合基准、可选重排、模型切换后重建索引、引用证据接口 |
| C 联网补充 | 按确认过的来源清单找材料，审核后入库，随后能被引用 | 多搜索源、全文抓取、来源分级、抓取时间、交叉核对；云解析作为独立可选适配器 |

这些批次细化原 PLAN 的资料库范围，没有取消后两批。你已确认从 A 开始，先解决这次试用最直接的不方便，再用实际资料结构验证 B。

## 10-04 实测与决定（B 与在线服务）

你决定解析和语义检索都用在线服务（MinerU 云端、Voyage AI），本机 GPU 方案先不做。按"先测量再决定"建了 38 条合成查询的基准，结果与参数见 [验证记录](../stage0/compatibility.md#资料库在线解析与混合检索10-04)：

- 全文检索对换一种说法的问题几乎无效（15 条找回 1 条）；向量检索补上了这一块；全文 + 向量按名次融合（RRF）后排序更稳。
- 向量相似度不能判断"资料里没有"；重排模型的相关度可以（门槛 0.5），因此检索结果带 `gap` 标记，老师工具据此说明缺口而不是编造出处。
- 云端解析原先排在 C，现在提前作为默认（有密钥时）；本机解析保留。每份 200 页的限制由 `library` 自动分段处理。
- 仍属后续：检索结果的上下文扩展、引用证据接口与逐句核对、模型切换后的重建策略（现在按模型分开保存向量，换模型会自动重建）。

## 验收草案

以下是 A 的实施验收依据与 B 的后续草案。自动测试用合成资料，真实模型也只处理合成资料；你自行用教材试用是单独的验收步骤。

| 验收内容 | 通过条件 |
|---|---|
| 选择文件 | PDF 从页面选择或拖入；上传成功后即可关闭页面，重新打开能看到同一任务 |
| 文字版与扫描版 | 合成样例覆盖中文、公式、单位、表格、图、例题、习题；不能把公式丢失或空结果标为成功 |
| 任务恢复 | 超时、服务重启、程序重启、取消、部分完成均有明确状态；完成前资料不能作为完整来源使用 |
| 去重与重解析 | 同一内容再次导入不会静默重复；加入另一门课复用原资料；重解析保留旧引用，不能让教材出处失效 |
| 章节和题目分组 | 章节顺序正确，跨页题干和解答可关联；教材取材不含习题答案，题库仍能按出处取原题 |
| 点击出处 | 合成样例的每个引用都打开正确 PDF 页；有坐标的区域在不同缩放和旋转下对齐 |
| 资源保存 | 表格和图片有可用的原始表示；结果包缺资源时显示具体原因，允许重试 |
| 检索基准 | 建立至少 30 条人工标注的合成查询，涵盖短词、近义词、公式、单位、章节号和无答案问题；分别报告 Recall@5、排序与耗时，再讨论质量门槛 |
| 服务降级 | 未配向量服务、超时、维度不符时全文检索可用；模型更换后索引状态明确 |
| 协同回归 | 导入完成只在资料可用后交回主老师；打开着的页面更新；`tests/flow.test.ts`、类型检查和构建持续通过 |

10-04 你选择“先完成 PDF 导入与出处定位（推荐）”。A 的实现包含持久化任务、原件恢复、取消/重试、去重、重解析快照、完整资源保存、PDF.js 阅读、旋转缩放定位和固定页码校正。高级解析入口保留；云解析排到 C，检索质量门槛等 B 的基线结果后再讨论。

实测时确认安装版本的坐标为归一化值，几何信息位于顶层布局扩展，已统一换算成 PDF 点。74 个自动测试和真实文字/扫描 PDF 验收通过，恢复异常由自动测试覆盖；原文引用区域已用实际 PDF.js 渲染对照。浏览器自动化受本机沙箱错误阻塞，文件选择、拖入和整页交互待用户试用。公式符号与复杂题号的识别仍需原文核对，不能把解析完成当作语义核实。详见 [验证记录](../stage0/compatibility.md#资料库-apdf-导入与出处定位10-04)。

## 批次 C 调研：联网找权威资料（10-07）

> 你说"现在做上吧"。下面是动手前的调研和建议，需要你决定的事见最后一小节。实测细节见[验证记录](../stage0/compatibility.md#资料库-c联网搜索与网页抓取实测10-07claude)。

### 起点

- 老师现在没有任何联网工具：预设只挂了我们自己的工具，DSH 自带的 `web_search`、`web_fetch` 都没挂。
- 资料的数据结构已经预留了网页来源（网址 + 抓取时间）和权威级别（一级、二级、三级、只当线索）。
- DSH 自带一个抓网页的服务（`ctx.web.fetch`）：只访问公网地址（防止被诱导去访问本机或局域网），限 5 MB，只跟随同一网站内的跳转，只收 HTML 和纯文本，不收 PDF。

### 实测：搜到的是什么，能不能读准

用 Exa 搜了 6 个化工原理问题，每个取前 5 条，再分别在本机抓取全文：

- **高校网站上搜到的资料约一半是 PDF 课件**（30 条里有 16 条）。Exa 顺带给的 PDF 纯文本会把公式弄乱（例如伯努利方程变成一串散开的字母和数字），不能当出处。这些 PDF 应该走已有的 MinerU 解析，公式、页码和出处定位都和教材一样。
- **网页正文提取：** Mozilla 的 Readability 在高校老式网站上能准确取出正文；另一个候选 Defuddle 在 4 个页面上取成了导航栏。
- **本机抓不到时：** 30 条里有 3 条在本机连不上（连接被重置、连接中断、403），另有 1 条时好时坏（网站证书链不完整）；Exa 能给出它们的文字。本机抓取失败时，可以退回用 Exa 的文字。
- **发布日期：** 30 条里只有 4 条带发布日期，所以来源卡片以抓取时间为准。

### 怎么判断"权威"

- **用规则，不让模型打分：** 研究显示，大模型给网站可信度打的分和专家只有中等程度的一致（相关系数约 0.59），尤其容易把可靠的网站判成不可靠（[Yang & Menczer](https://arxiv.org/pdf/2304.00228v2)、[2025 年的对比研究](https://arxiv.org/html/2502.04426v2)）。所以按网站规则定级，模型只负责挑哪些和问题相关。
- **开源项目也没有现成答案：** Stanford 的 STORM 把"信不信这个网站"留给使用者自己写规则，默认全收；GPT Researcher 让模型挑选来源。
- **建议的规则：**
  - 级别沿用已确认的来源清单：一级是你的教材和你们学校的资料，二级是国内高校（`edu.cn`）、政府和标准网站、出版社、国家级精品课，三级是国外开放课程和正式发表的论文。
  - 文库和转载站（如中国高校课件下载中心、360doc、文库类网站）、百科、问答、论坛只当线索，即使内容是转载的高校课件。
  - 不认识的网站默认只当线索，你看过后可以把它升一级，升级的规则按课程保存。
  - 盗版资料站直接排除。

### 交叉核对

真正的核对是"某句话有没有至少两个独立的权威来源支持"，前提是先有"这句话"，也就是教材或回答里的具体陈述。所以建议：资料库记下每份资料属于哪个机构（同一所学校的几份课件、或转载自同一份课件的，算一个来源），逐句核对和教材的"逐句回查"一起做（归 [textbook](../textbook/design.md)）。

### 版权和数据外发

- 网页存到本机只供你个人学习，属于《著作权法》第二十四条的合理使用；资料卡写明作者或网站和原网址，不外传。
- 发出去的只有：搜索词（发给搜索服务），以及网上公开的 PDF 课件（发给 MinerU 云端解析）。你的教材和学习记录不会发出去。

### 建议的做法

```
老师觉得资料库不够（检索结果标"资料里没有"）
  → search_web：按本课的来源清单定向搜 + 不限网站搜，去重，按规则定级，只返回候选（不能直接当出处）
  → 老师挑几份 → propose_web_sources：资料库抓全文（网页用 Readability，PDF 用 MinerU），存成"待你确认"
  → 你在资料库页查看并确认（或删掉） → 才会被检索到、能被引用 → 交回主老师
```

- **搜索源可替换：** 先接 Exa（主）和 Tavily（备用），排在前面的失败或超时就换下一家。
- **资料库页也能直接搜：** 你可以自己输入一个主题，看候选、挑着加入，和老师用的是同一套。
- **网页资料的出处：** 写成 `[《网页标题》](cite:片段ID)`。点开时在旁边显示保存下来的正文，并附原网址。

### 验收草案

| 验收内容 | 通过条件 |
|---|---|
| 定级 | 合成的网址清单按规则得到正确级别：转载站、百科是线索，盗版站排除，不认识的网站默认是线索 |
| 搜索 | 定向和不定向的结果去重合并；排在前面的服务失败、超时、缺密钥时换下一家，并说明原因；自动测试只用假的搜索服务 |
| 抓取 | 网页取出正文；PDF 进入已有的解析流程；内网地址、超大文件、不支持的格式明确拒绝；本机抓取失败时用备用文字并标明 |
| 审核 | 没确认的资料检索不到、不能引用；确认后建索引、交回主老师；删掉不影响别的资料 |
| 出处 | 网页资料的引用能打开保存下来的正文，并附原网址和抓取时间 |
| 回归 | `tests/flow.test.ts`、类型检查和构建通过；3182 上用真实搜索服务走一遍（只搜课程主题，不发你的资料） |
