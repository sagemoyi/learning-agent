# 掌握分析（learner）

> 代码：[`packages/learner`](../../packages/learner)（规则在 `rules.ts`） · 接口：[契约](../stage0/contracts.md) §4.6、§5.1

掌握分析负责回答"你会了什么、凭什么这么说"：把作答、帮助和信号汇总成证据，按规则推算每个知识节点的掌握状态，并写出理由。知识模型的图上显示的颜色就来自这里。

判断"学会"只看一个标准：**撤掉帮助后你能独立做出来，隔一段时间还会，换一道题也会。**

## 现状

- **调研与复核：** 见[掌握分析做深调研](research.md)（Codex）和[复核](review.md)（采纳、修改、延后哪些建议）。分批：A 证据有效与可重算 → B 独立、延迟与换题验证 → C 可解释结果与快速检查。
- **A 批（规则版本 `a-1`）已实现，在 3182 上加载验收并截图核对，待试用：**
  - 掌握状态只从证据日志推算，是一份可以随时删掉重算的缓存；规则版本变了，启动时全部重算。
  - **日志完整读取：** 按游标分页读完，不再只取最早的一万条；缓存记着读到哪条日志（水位）。启动时缓存是空的、来自别的规则版本、或被清空，就全部重算，否则只补水位之后的；每条新日志的事件也走同一个补读，所以丢了一次事件，下一条会补上。状态、水位和失败记录在同一个事务里发布。
  - **失败不隐藏：** 重算出错时旧状态保留，记下原因和还没算的节点，下一次补读时再算；记日志的单元不受影响。`learner.status` 给出"算到哪条、是否落后、上次失败原因"，主老师的课程简报在状态不是最新时加一句提醒。
  - **证据有效：**
    - 同一次作答（`attemptId`）只算一次；
    - 判分取改判链的末端（一次改判必须更正这次作答的某条判分，指向别处的不生效）；
    - 题目停用或改了题干、答案后，assess 对该题已有的每份作答追加一条 `attempt.voided`，这些作答不再是证据，题目修好后的新作答照常计入；
    - 待复核的判分不计入，也不算没答；
    - 同毫秒的记录按日志编号的先后（编号在同一毫秒内递增），不看调用方给的顺序；
    - 提问按 `ref`（或会话加原文）去重。
  - **答案边界：** 作答日志的时间是交卷时刻，不是判分结束的时刻，判分的几秒里得到的讲解不算答题前的帮助；晚于交卷的帮助不影响这次作答。
  - **说明里有没计入的：** 状态带 `excluded`（记录编号加一句原因），节点详情的记录列表对被改判替代、被作废的记录写出原因；状态依据只引用真正起作用的帮助。
  - **其他沿用：** 除了全部记录的状态，还按课程分别推算一份（只用那门课的作答和改判、作废，帮助不分课程）；知识模型在课程里显示多门课共用的节点时用本课这份，本课还没有作答就显示"本课条件待验证"（10-08，knowledge C）。两个知识节点合并后，保留的节点把被合并节点的记录一起读，按记录去重，一条多标签作答只算一次；撤销合并后各自按原来的记录重算。
  - 独立答对过 → 已独立完成；第一次独立答对后至少隔 3 天又独立答对 → 已延迟验证。答对时得到过帮助（同一课时、同一测试、同一会话、同一道题，或 1 天内侧边会话里讲过）→ 有帮助完成。答过但还没答对过 → 还没答对。独立答对过、最近一次独立作答又错了 → 证据冲突。已独立完成或已延迟验证、但 14 天没有新的作答 → 待复查。侧边会话或批注里问到 2 次及以上 → 有疑点。每个状态附一句文字理由。
- **A 的已知缺口（属于 B，不是 A 的验收范围）：**
  - 现在只有侧边会话写 `help.given`，只带会话，不带课时和题目：规则里按课时、按题目匹配的判据没有生产者用到，实际生效的是一天内的侧边会话窗口，一天前讲过的完整原题过了窗口会被当成独立；主老师的讲解和测试页的帮助没有生产者。独立性要等 tutor 补帮助的记录才可靠。
  - 侧边会话的帮助取不到消息时间时，退回会话关闭的时间。
  - 整题的结果用于它的所有知识点；开卷闭卷、限时不参与判断；延迟从第一次独立答对算起，中途练习不影响；冲突后恢复一次就按旧链计算。
  - 题目停用的重复副本和真正的错题没有区分，两者的作答都作废；curriculum 复盘按停用状态判断，与它一致。
  - 改判的节点来自题目当前的知识点，题目的知识点改过后，改判可能读不到原判。
  - 超过一万条日志的其他读取（curriculum 按节点读的帮助和提问）仍用默认上限。
- **还没做：** B 独立、延迟、换题和条件；C 复查提醒读时派生、节点详情的"缺什么证据"、"这个我会，考我一下"；"有疑点"的含义和待办关闭；跨课程的证据什么情况下可以迁移（现在只是分开计算、分开显示）。
- **为什么放在后面做深：** 到那时作答、帮助、信号、批注都已经是真实数据，规则可以对着真实情况来设计。

## 掌握状态

用文字 + 颜色表示，不用百分比：
- **未探测**（空心灰）：还不知道你会不会，**不等于不会**。
- **还没答对**（琥珀色）：答过，但还没有答对过。这是最该补的地方，所以单独列出，不混进"未探测"；不用红色，也不叫"不会"。
- **有帮助完成**（蓝色）
- **已独立完成**
- **已延迟验证**：隔一段时间后仍能独立完成。
- **证据冲突**：独立答对过，后来又答错了，需要再检查一次。先错后对是正常的学会过程，按最近一次算，不算冲突。
- 另外两个附加标记：**待复查**（很久没练）、**有疑点**（在侧边会话或批注里反复问到）。

## 证据从哪来

- 只有作答能证明掌握，帮助要记账（[PLAN](../PLAN.md)"设计原则"3、4）：阅读、聊天、批注、提问都只是信号；有帮助的答对之后，还需要一次独立完成的证据。
- 各类测试算不算独立证据，见 [assess](../assess/design.md)"测试类型与独立性"。
- **掌握状态只能由证据规则算出来。** Agent 和你都不能直接把一个节点"设为已掌握"。你可以说"这个我会，考我一下"，然后走快速验证。
- 不采用模型自己报的"掌握度"。

## 关键决定

- **学习证据只追加、不修改；掌握状态由规则从证据日志推算，可以重算**（10-03，契约决定 1，你确认）：规则会改，重算比迁移数据可靠。
- **侧边会话里的讲解算作"帮助"**（10-03，你）。
- **"还没答对"成为正式状态，琥珀色，不用红色**（10-05，你："都按你方案修"）：只有"未探测"时，答错过的节点没有合适的状态，而"未探测"明确不等于不会。
- **证据冲突只指"独立答对过、最近一次独立作答又错了"**（10-05，你："都按你方案修"）：最近 3 次独立作答有对有错就算冲突时，先错后对这种正常的学会过程也会被算进去。
- **多门课共用的节点按课程分别计算，帮助不分课程；合并后透过合并读证据，不改日志**（10-08，Claude 按 knowledge 调研）：同一个身份在另一门课答对，不能直接说明本课的条件下也会；把两个节点里较好的状态拿来用会错误地升级。
- **作废用追加记录，按作答而不是按题目当前状态判断**（10-10，Grok Bot 按调研复核）：参考 xAPI 的作废语句，原记录保留，学习者看得到为什么没计入；不读可变的题目表，重放结果不变。代价是被停用的重复副本上的真实作答也不再计入。
- **缓存带日志水位，失败只报告不隐藏**（10-10，Grok Bot）：缓存可以随时重建，但"算到哪了"必须能说清；事件回调不抛错，否则会打断记日志的单元。
