# 掌握分析调研报告复核

> 2026-10-10 · 复核对象：[掌握分析做深调研](research.md)（Codex，10-09）· 范围：报告对当前代码和文档的断言、推荐设计能不能直接开发、A 批该做到哪。批注和侧边会话的复核见[批注复核](../annotation/review.md)、[侧边会话复核](../sidechat/review.md)，方法相同。
> 方法：对着 10-10 的 `feat/annotation-sidechat` 逐条读 `packages/learner`、`core` 的日志、`assess`、`sidechat`、`curriculum` 的相关代码；起点 `pnpm typecheck`、`pnpm test`（48 个文件，334 通过、2 跳过）全绿。同毫秒编号的顺序用脚本实测。外部文献只重读了直接影响本批取舍的两处（ULID 规范、xAPI 的作废语句），其余论文和开源库没有重新读取，沿用报告的引用层级，不当作已核实。

## 结论

报告对代码缺口的判断基本属实，"保留六个状态、规则可审查、不引入掌握概率、BKT / PFA / FSRS 只作对照"的方向可以直接采用。不能照搬的有四处：一处事实已过时，两处推荐的做法太重或落点不对，还有一处必须先补的底层缺口报告只当成依赖。A 批只做"证据有效、完整、可重算"，不碰 B（独立、延迟、换题、条件）和 C（解释联调、考我一下）。

## 已核实的断言

| 报告的说法 | 核对结果 |
|---|---|
| 改判取最后读到的一条，不校验 `corrects` 链；重复的 `attempt.graded` 不按 `attemptId` 去重 | 属实（`derive` 里 `regrades.set`；`assess` 现在每次作答只写一条，重复属于潜在风险，防一道即可） |
| 同毫秒的事件没有业务先后依据 | 属实，而且比报告说的更底层：`newId` 的 ULID 在同一毫秒内随机排序，实测同毫秒连续生成的编号约一半比前一个小；`core.log.query` 和 learner 都按编号排序，所以"日志先后"本身就不可靠。ULID 规范明说同毫秒顺序不保证，同时给了单调模式（同毫秒随机部分加一） |
| `entries` 每个身份最多读一万条且取最早的；全量找节点最多十万条 | 属实（`ORDER BY id LIMIT`）；超过后最新的错题、改判、帮助不参与 |
| 空缓存配已有日志不会触发重算；同版本重启不补齐遗漏 | 属实（启动只看"有没有旧版本的状态行"）；`recompute` 在事件回调里抛错时没有任何记录 |
| 详情用原判，状态用改判；`counted` 按状态的 `evidence` 列表判断，而该列表含本节点的全部帮助 | 属实 |
| `needsReview` 用最后一条已判分作答（含有帮助的、答错的）算十四天；`doubtful` 终身累计两条提问 | 属实，归 B/C，本批不改（见下） |
| 一道题的整题结果用于它的所有节点 | 属实，归 B |
| curriculum 复盘不把已停用题算证据，learner 没有对应依据 | 属实（`review.ts` 把停用题记为"待验证"，learner 照常计入） |
| `assess` 先判分再取 `submittedAt` | 属实，是答案边界缺口的根：异步判分的几秒里得到的讲解会被算成答题前的帮助 |

## 报告说错或过时的地方

1. **"侧边会话关闭时帮助默认用当时的时间"已经不成立。** sidechat A 已把 `help.given` 的 `at` 改成助手那条消息的时间（缺消息时间才退回关闭时间）。A 批不必再做这件事；只剩"消息没有时间时退回关闭时间"这个保守度不够的退路，记为遗留。
2. **"帮助来自 tutor / sidechat / 测试页"，实际只有 sidechat 写了 `help.given`。** 主老师讲解和测试页的 `via` 值契约里有，代码里没有生产者；`problemId` 也没有人填。这意味着 B 批的"帮助归因"现在没有数据可归，要等 tutor 深化补生产者，learner 不自己造。另外 sidechat 写的 `help.given` 只带会话，不带课时和题目，规则里按课时、按题目匹配的判据现在没有生产者用到，实际生效的是一天内的侧边会话窗口。
3. **"改判依据链"的描述少了一环：** assess 的 `regrade` 的 `corrects` 取的是"当前缓存的那条判分日志"，所以第二次改判指向的是第一次改判。链是 原判 ← 改判 1 ← 改判 2，不是一律指向原判，校验时要沿链走。

## 报告遗漏或需要修正的地方

1. **有效性依据要指向具体作答，不要按题目当前状态推。** 报告建议"主人追加影响旧证据效力的更正依据"，没说形式。参考 xAPI 的作废语句（一条独立的追加记录指向被作废的那条，原记录保留，恢复要重新签发）：新增日志类型 `attempt.voided`，指向被作废作答的当前判分日志。这样 learner 不读可变的题目表，旧日志重放结果不变；题目修好后新作答自然有效，旧作答不会被"恢复"。
2. **停用既可能是题错，也可能只是重复入库。** assess 的 `reviewProblem` 只有 `keep / fixed / retired`，没有原因。本批的政策是：`retired`，以及改了题干或答案的 `fixed`，作废此前所有作答；`keep` 不作废。代价是被停用的重复副本上的真实作答也不再计入，和 curriculum 现在的做法一致，比两个单元各说各的好；以后 assess 区分原因时再放宽。
3. **读取要有游标，光是加大 `limit` 不够。** `LogQuery` 需要一个"在某条之后"的游标，learner 才能分页读完；`core` 的排序依据必须稳定（上面的单调编号）。
4. **缓存要有水位，才谈得上对账。** 用 learner 自己的元数据表记"已处理到哪条日志"：启动时水位缺失、规则版本不同、状态表被清空都全量重算，否则只补水位之后的；每条新日志的事件也走同一个补读，所以丢一次事件下一次会补上。
5. **事件回调里的错误不能带出去。** `afterCommit` 里 learner 回调抛错，会从 `log.append` 的调用栈冒出来，打断 assess 交卷循环里后面几道题的记录。learner 要自己接住错误并记成"重算失败"，旧状态保留。
6. **解释里要说明哪些记录没计入。** 报告要求"排除原因可见"。状态里增加 `excluded`（记录编号 + 一句话原因），详情里被改判替代的原判、被作废的作答标出原因，状态依据只引用实际起作用的帮助。

## 对报告建议的取舍

| 建议 | 取舍 | 理由 |
|---|---|---|
| 六个状态不变，不做掌握百分比，不引入 BKT / PFA / FSRS | **采纳** | 没有校准数据；复杂模型补不了条件、归因和效力缺失 |
| 一次独立答对只说"独立完成过"，不加连续 N 次门槛 | **采纳** | 与 10-05 决定一致 |
| 完整读日志，不静默截尾 | **采纳，改成游标分页** | 见遗漏 3 |
| 去重、合法改判链、非法更正不改变状态并说明 | **采纳** | A 批核心 |
| 同时间事件按持久顺序和显式引用解歧 | **改：单调编号 + 改判链引用** | 不新增"记录序号"字段，改动最小 |
| 题目效力更正由 assess 发起、core 追加 | **改：`attempt.voided`，每个被作废作答一条** | 见遗漏 1、2 |
| 答案锁定边界（答案版本、锁定时间） | **改：作答日志的 `at` 取交卷时刻，不新增字段** | 目前一份作答只有一个版本；允许改答案时再加版本。关键是把判分耗时排除在边界之外 |
| 输入水位、同一水位发布 | **改：日志水位 + 全量在同一事务里重算** | 规则版本、配置版本、身份映射版本、目标条件快照作为输入留到 B/C |
| 失败不冒充成功，显示旧缓存状态 | **采纳，新增 `learner.status`** | 只给"是否最新、上次失败原因"，不做处理中进度 |
| 提问信号去重、重复投递不重复计数 | **采纳最小部分** | 按 `ref`（没有则会话加原文）去重；"有疑点"的含义和待办关闭留给 B/C |
| 复查提醒读时按 now 派生 | **延后（C）** | 需要存最近独立验证日期和改接口，A 只保证同一 now 同一结果 |
| 帮助按对象和答案边界归因、同课时旧帮助不永久生效、原题解答暴露、操作说明不算帮助 | **延后（B）** | 依赖 tutor 的帮助生产者（见说错的第 2 条） |
| 延迟起点、恢复链、条件匹配、新题关系、多问覆盖 | **延后（B）** | 需要 assess 的题目关系、暴露快照和分问映射 |
| 节点详情完整重做、"考我一下" | **延后（C）** | 需要 assess、tutor、planner 联调 |
| 性能测量卡片、1000 / 1 万 / 10 万条规模测试 | **部分采纳** | A 只用合成数据证明超过一页的日志完整参与，不做耗时测量，也不提前加缓存层 |
| 新增契约字段、专用"学习画像"页 | **拒绝（本批）** | 契约只补跨单元必需的：日志游标、一类日志、两个可选字段、一个状态读取 |
| 引入 pyBKT、pyKT、ts-fsrs | **拒绝** | 不新增依赖；FSRS 留给 planner 评估记忆类复查 |

## 本批（A）采用的范围

- **core / contracts：** 编号在同一毫秒内单调；`LogQuery.after` 游标；日志类型 `attempt.voided`；`NodeState` 和 `CourseState` 增加 `excluded`；`EvidenceRecord` 增加 `note`；`LearnLearner.status()`。
- **assess：** 作答日志的 `at`、`submittedAt` 取交卷时刻；`reviewProblem` 停用或改题时，对该题已有作答各追加一条 `attempt.voided`。
- **learner：** 按 `attemptId` 去重；沿 `corrects` 链取最终判分，非法更正不生效并写进排除原因；作废的作答不计入；按时间加编号排序；帮助只引用真正作用于某次作答的几条；完整分页读取；水位对账（空缓存、同版本重启、丢事件）；重算失败保留旧状态并报告；规则版本升到 `a-1`，启动自动重算旧状态。
- **知识模型详情：** 记录列表里显示 `note`（被改判替代、被作废）。

不做的在设计文档"还没做"里按 B、C 列出。独立性仍不可靠这一点要写明：主老师和测试页的帮助没有生产者，一天窗口之外的完整原题讲解不会被算作帮助，这属于 B 的依赖，A 的验收只保证日志和投影本身可信。
