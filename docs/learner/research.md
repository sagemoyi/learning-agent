# 掌握分析做深调研

> 2026-10-09 · 对应 PLAN 中 tutor 之后的 learner · 状态：调研完成；推荐规则、契约补充和验收草案尚未实现。
> 依据：[总体计划](../PLAN.md)、[掌握分析现状](design.md)、[题库与测试](../assess/design.md)、[主老师调研](../tutor/research.md)、[侧边会话调研](../sidechat/research.md)、[契约](../stage0/contracts.md)，以及下文的一手论文、官方规范和开源代码。
> 范围：掌握证据的有效性、独立性、延迟保持、换题与迁移、条件匹配、冲突、信号、跨课程使用及重算。Claude 同时实现 textbook；本轮不修改实现、依赖、构建产物、锁文件、profile 或运行进程，不验收其进行中的改动。

推荐按 **A 证据有效与可重算 → B 独立、延迟与换题验证 → C 可解释结果与快速检查** 做深。首轮采用可审查的规则，保留现有六个掌握状态；把“在哪种条件下、哪些题上做到、还缺什么验证”写清楚。BKT、PFA、深度知识追踪和 FSRS 都有用途，但当前不具备把它们的输出解释为这个人的长期掌握程度的校准依据。

## 1. 推荐结论

| 问题 | 推荐项 | 取舍和边界 |
|---|---|---|
| 判断对象 | 知识身份加课程、测试条件和实际考查范围 | 全局记录可供参考，不能自动证明另一门课或更严格条件下也会 |
| 成绩与掌握 | assess 保存题目和判分；learner 判断证据能支持什么 | 不重新判题，不以模型判分的把握程度充当掌握程度 |
| 一次答对 | 保留“已独立完成”，明确只完成过哪项任务 | 不改成“已稳定掌握”，不要求为了变色机械刷三道题 |
| 延迟验证 | 从最近一次已知相关练习或教学暴露起计，记录实际间隔 | 三天是骨架参数，不是普适的科学过关线 |
| 换题验证 | 原题复现、改数字、同类新题、变情境分别说明 | 新 problemId 不自动代表迁移；新题也不自动代表远迁移 |
| 帮助 | 按实际发生时间、答案锁定边界、对象和帮助内容归因 | 操作说明不算概念帮助；允许的计算器不自动算老师提示 |
| 证据冲突 | 保留“独立答对过、最近一次有效独立作答又错了” | 查题目、条件和判分，再检查能力；不抹掉历史成功或断言已经不会 |
| 提问与自报 | 只生成有依据的检查线索 | 求助次数、批注数量、阅读完成和“我会了”不升级或降级掌握状态 |
| 题目纠错 | 主人追加影响旧证据效力的更正依据 | 不删原日志，不仅靠当前可变的题目状态重算历史 |
| 复查 | learner 给证据缺口和到期依据，planner 安排任务 | 过期不是答错；近期有帮助练习不能刷新独立能力的有效日期 |
| 工程 | 一个纯规则投影加一份可恢复缓存，完整读日志 | 不自建作答库、帮助归因 Agent、第二套题池或调度器 |

上述是研究后的应用建议，尚未采纳为契约或产品行为。既有决定继续成立：证据只追加；掌握状态可重算；跨单元通过服务；题池分开；一轮做深后统一试用。实施者按既有授权确定精确字段和参数，并记录采用项。改变这些方向仍需先讨论。

## 2. 骨架核对：真实缺口在哪里

下表来自 10-09 工作树的静态阅读，不代表已经复现或修复。主要入口是 [rules.ts](../../packages/learner/src/rules.ts)、[learner/index.ts](../../packages/learner/src/index.ts)、[evidence.ts](../../packages/learner/src/evidence.ts)、[证据类型](../../packages/contracts/src/schema/evidence.ts) 和 [规则测试](../../packages/learner/test/rules.test.ts)。

| 位置 | 当前行为 | 做深时要解决的反例 |
|---|---|---|
| rules.ts 的判分整理 | 读取 attempt.regraded，待复核的作答不参与判断 | 最后读到的一条改判胜出，没有校验 corrects 链；重复 attempt.graded 没按 attemptId 去重；同毫秒事件缺业务先后依据 |
| rules.ts 的独立性 | 没匹配到 help.given 就算独立 | 不读 testKind、conditions、题目暴露或帮助归因是否完整；缺帮助记录不能证明从未得到帮助 |
| helped | 同课时、测试、会话或题目命中；侧边帮助还有一天窗口 | 同课时的旧帮助可永久影响后续新题；一天前讲过完整原题，过窗口后可能被当独立；两者都不能只靠时间窗修正 |
| derive 的延迟判断 | 相对第一次独立答对，另一次答对隔三天即 retained | 原题重复、中途刚练过、刚看过解答、冲突后恢复，均未单独检查 |
| derive 的条件 | 日志有测试条件，规则未使用 | 开卷答对不能直接证明闭卷会；不限时成功不能证明限时表现 |
| derive 的节点归因 | 一道题的整题 verdict 用于它的所有 nodeIds | 多问题只错单位时，其他知识点也算错；整题正确也未说明每个标签是否真的被考到 |
| needsReview | 以最后一条已判分作答的日期算十四天 | 有帮助的答对或答错也会延后“待复查”；应看最近的有效独立验证 |
| doubtful | 一生累计两条 signal.question 即有疑点 | 好奇追问、一次总结包含多个问题、已经解决的问题无法区分；终身标记不能说明当前疑点 |
| learner 的重算触发 | 新日志、身份变化、启动发现旧规则版本 | 空缓存配已有日志没有旧版本行可触发；相同版本启动不补齐遗漏；时间流逝、目标条件变化没有对应更新 |
| entries 和 core.log.query | 每个身份最多读一万条，按 ID 升序取最早部分；全量找节点最多十万条 | 达上限后最新答错、改判或帮助可能不参与；增加常量不能证明全量重算 |
| evidence 和 describeEvidence | 列原始判分；“计入”按状态 evidence 列表判断 | 状态用改判，详情仍显示原判；改判本身没列进状态依据，所有节点帮助又被一并列入，不能解释具体是哪条改变结论 |
| [sidechat 关闭](../../packages/sidechat/src/index.ts) | 关闭总结时追加帮助，默认 at 为当时 | 帮助先发生、作答后提交、总结最后关闭时，帮助时间晚于作答；不能靠“日志先后”判独立 |
| [assess.record](../../packages/assess/src/index.ts) | 判分后创建 attempt 和 attempt.graded，使用当前时间 | 异步判分期间得到的讲解可能被错误归到已交出的答案；须区分答案锁定、帮助发生和落库 |
| [curriculum 复盘](../../packages/curriculum/src/review.ts) | 已停用题在复盘里不算证据 | learner 没有相同效力依据，仅处理改判；同一道坏题可能在两个单元产生不同结论 |

现有良好基础应保留：规则是纯函数；状态有规则版本；帮助跨课程参与；合并按日志 ID 去重；撤销合并不改日志；待复核不判成不会；先错后对不叫冲突。做深重点是补足输入的可信语义，不另写一套成绩和学习记录。

## 3. 研究证据及适用范围

### 3.1 成功表现、长期学习和估计的不确定性分开

Soderstrom 与 Bjork 的整合综述区分练习中的表现与延迟保持、迁移反映的学习。本次已核对作者全文中的练习安排、帮助、元认知和结论：练习时的顺畅表现可能与延迟结果分离；难度带来的收益也有学习者能否克服困难等边界。这不能据此给中文理工学习定最佳天数。[Learning versus performance（2015，作者全文）](https://bjorklab.psych.ucla.edu/wp-content/uploads/sites/13/2016/11/soderstorm_ra_learningvsperformance.pdf)

Pelánek 的 2018 年论文进一步区分“知识达到什么程度”和“对估计有多大把握”，并用模拟数据讨论掌握门槛。作者明确不推荐直接把其 LogisticHMM 原型搬进产品。[Conceptual Issues in Mastery Criteria（作者全文）](https://www.fi.muni.cz/~xpelanek/publications/mastery-modeling.pdf)

**应用建议：** “独立答对一道题”是一个有范围的事实；“延迟后也会”“换情境也会”是另外的证据。记录不足、条件不匹配、判分存疑都应解释为缺哪项证据，不能把它们混进“不会”或压成假精确百分比。

### 3.2 提取练习有益，但不能用同题重做证明广泛能力

Roediger 与 Karpicke 的两项散文记忆实验比较重复学习和无反馈提取：五分钟后与两天、一周后的结果不同，延迟测试更能显出提取练习的保持收益。研究对象是记忆任务，本报告未核对完整方法，不外推化工计算的具体收益。[Test-Enhanced Learning（原论文官方摘要）](https://www.psychologicalscience.org/journals/psychological-science/j.1467-9280.2006.01693.x/)

Pan 与 Rickard 的元分析覆盖 122 个实验、192 个迁移效应量；总体有迁移收益，但类别差异明显，问题解决类别不能由总体效果推断出稳定收益，调节因素的关系也不能一律解释为因果。[Transfer of Test-Enhanced Learning（论文全文）](https://pdf.retrievalpractice.org/transfer/Pan_Rickard_2018.pdf)

**应用建议：** 重做原题可以学习，也能证明这次能复现；它不能自动证明能选用公式解决新情境。验证题要对齐目标能力，记录改变了什么。一次同类新题成功只能说明对应的近迁移范围，不写“任何实际问题都会”。

### 3.3 间隔没有全领域统一的最优常量

Cepeda 等把 1354 名参与者分到 26 种间隔与保持期限组合，学习 32 条事实；第一次练到每条能回忆一次，第二次有答案反馈，最终无反馈测回忆与识别。研究以完成各阶段者的结果分析，长间隔的未完成率更高。最优间隔随预期保持期限变化；它不是一个固定的天数或固定比例。本次已核对方法、结果与教育含义，任务仍是事实记忆。[Spacing Effects in Learning（2008，大学托管全文）](https://labs.biology.ucsd.edu/rifkin/courses/bieb100/f14/Cepeda_et_al_2008_Psychological_Science_Spacing_Effects_in_Learning_A_Temporal_Ridgeline_of_Optimal_Retention.pdf)

**应用建议：** 首轮可以保留三天作为兼容骨架的保守起点，但标为待校准的政策参数。记录实际间隔、最近相关练习和讲解；考前一周与长期学习不应宣传使用同一科学最优复查周期。安排何时复查由 planner 负责。

### 3.4 自我判断与提问是检查线索

Koriat 与 Bjork 的配对词实验发现，学习时答案可见引发的联想会影响对以后回忆的判断；学习当下的把握不能直接替代撤掉答案后的表现。其范围是记忆判断，不是“所有自报都错误”。[Illusions of competence（作者全文）](https://bjorklab.psych.ucla.edu/wp-content/uploads/sites/13/2016/07/Koriat_RBjork_2005.pdf)

**应用建议：** 学习者说会了，系统应提供短检查；说不会可以优先教学，但不凭这句话生成一条已判分作答。提问多可能是积极思考，不能据此判能力下降。帮助提供与归因沿用 tutor/sidechat 的专门调研，learner 不重复做回复分类。

### 3.5 预测下一题答对，不等于已证明掌握

Pelánek 的 learner modeling 综述强调知识类型、数据、用途和参数稳定性共同决定模型选择；预测好不足以证明隐藏参数可以解释为真实知识。[Bayesian Knowledge Tracing, Logistic Models, and Beyond（作者全文）](https://www.fi.muni.cz/~xpelanek/publications/umuai-overview.pdf)

Pavlik 等的 PFA 将成功和失败次数用于逻辑回归，并讨论多知识成分的预测。它为行为数据建模，不为本项目的帮助归因、来源有效性和延迟证据提供现成结论。[Performance Factors Analysis（论文全文）](https://files.eric.ed.gov/fulltext/ED506305.pdf)

Doroudi 证明部分简单停止规则也隐含特定 BKT 假设；简单规则并非没有假设，“连续三次正确”也不是普适真理。原文讨论单次失误可能使连续正确规则造成不必要惩罚。[Mastery Learning Heuristics and Their Hidden Models（可检索全文）](https://pmc.ncbi.nlm.nih.gov/articles/PMC7334722/)

**应用建议：** 采用能说明假设和证据的规则，不以复杂算法名增加可信度。阶段是否过关仍按 assess/curriculum 已确认的蓝图与复盘规则，不以 learner 的一个标签替代。

### 3.6 新近 KT 结果也需要区分评价目标

pyKT 的 NeurIPS 2022 论文指出，预处理和评价协议差异会使知识追踪结果不可比，错误设置可能导致标签泄漏。它提供预测基准，未证明上线以后提高长期学习。[pyKT（会议论文与摘要）](https://papers.neurips.cc/paper_files/paper/2022/hash/75ca2b23d9794f02a92449af65a57556-Abstract-Datasets_and_Benchmarks.html)

2026 年的门槛研究比较六种 KT 模型、四组公开数据和十二个门槛，指出相同数字不能跨模型直接迁移。全文明确属于观察日志分析；没有随机干预，主要结果是越过门槛后的有限次作答，不是长期保持，也没有 LLM 辅导系统。[One Mastery Threshold Does Not Fit All Knowledge Tracing Models（预印本全文）](https://arxiv.org/pdf/2610.00095)

**应用建议：** 后续若评估概率模型，要同时看误判、放行、练习负担及后续独立新题表现。训练和评价按时间、原题家族及课程分开，不能把同一道题的不同知识标签拆到两边，或拿未来改判信息预测过去。

### 3.7 解释要绑定用途与条件

AERA、APA、NCME 的 2014 年测试标准第一章把效度放在“证据是否支持特定用途下的结果解释”，而非题目自身的抽象属性；不同解释需要各自的支持证据。这是评价原则，本报告不以它作为本地学习软件的认证要求。[Standards for Educational and Psychological Testing（官方全文，第 11 页起）](https://www.testingstandards.net/uploads/7/6/6/4/76643089/standards_2014edition.pdf)

**应用建议：** 开卷计算成功、闭卷记忆成功和限时综合任务成功分别解释。允许的辅助工具是任务条件的一部分；“独立”指不依赖针对该作答的教学支持，不等于禁止所有工具。

Bull 与 Kay 的 SMILI 框架给开放学习者模型提供设计比较方法。本次只核对出版社摘要，没有把其框架当作界面效果已经得到验证。[SMILI（2016，官方摘要）](https://link.springer.com/article/10.1007/s40593-015-0090-8)

**应用建议：** 状态可查看依据、可质疑判分、可要求再检查；学习者能纠正事实，不能直接把节点设为掌握。图的颜色来自同一份解释，不能由前端再推导。

### 3.8 直接看数学任务：训练收益不等于个人过关依据

Rohrer 等的预注册整群随机试验覆盖 54 个七年级班、787 名学生。约四个月的交错/分块练习后，两组做同一复习；约一个月后测未出现在研究练习中的题，平均成绩约为 61% 与 38%，d = 0.83。全文有两个特别相关的细节：练习允许求助和订正，所以练习上的 95% 正确被作者视为执行情况，不是独立表现；最终测试限时 25 分钟且允许计算器。研究也没有实测做题耗时，交错的收益包含间隔等因素，不能推断每单位时间效率或全部机制。[A Randomized Controlled Trial of Interleaved Mathematics Practice（2020，作者提交全文，方法与限制）](https://files.eric.ed.gov/fulltext/ED595322.pdf)

Rawson 等直接检验数学程序的重复再学习：三个实验共 431 名大学生，练四类概率题。跨三次练习各正确一次，与一次练习各正确三次相比，一周后新题的合并优势仅为 d = 0.28，95% CI [0.08, 0.49]。本次只核对出版社摘要；其二次分析也没有发现一次正确显著提高后续成功的可能，不能把这句话推广成所有正确表现都无信息。[All Good Things Must Come to an End（2020，官方摘要）](https://link.springer.com/article/10.1007/s10648-020-09528-y)

**对 learner 的推论：** 要分别记录训练完成、撤去教学帮助后的表现和延迟新题表现。数学学习确有相关干预证据，但不能由这些群体效果推出“一人三题正确即可过关”。如果目标包含选用关系式，题目标题、任务指令或上一题已经把关系式告诉学习者，那么只能证明在该提示下执行；这属于测量范围建议，不是上述试验直接验证的本产品判定规则。练习怎么安排仍归 planner/教学单元。

### 3.9 关键建议的支持强度与替代项

本报告不把“有论文谈过相关主题”当作每条规则都已经得到验证。这里的“直接支持”指研究支持区分或边界，不意味着已验证本产品的算法。

| 建议 | 依据到哪一层 | 最强替代项与取舍 |
|---|---|---|
| 练习表现、延迟保持与换题应用分别解释 | §3.1、§3.2、§3.8 有直接研究支持；具体六状态是项目设计 | 全部压成一个掌握分较简单，但丢失已经确认的能力范围和证据缺口 |
| 一次正确只表述一次独立完成 | 测量原则与数学任务边界支持限制外推；一次给此标签是产品政策 | 连续 N 次正确能抑制偶然成功，但 N 与任务相关，且可能惩罚失误；首轮不设一个普适 N |
| 延迟从最近一次明确相关练习/教学起计 | §3.3 的保持间隔从最终学习阶段起计；推广到自然课程是推论 | 从首个成功起计更宽松，但会把昨日强化后的成功写成未强化的长间隔保持；不能反过来把每次页面访问都算强化 |
| 用同类新题补足延迟验证 | §3.2、§3.8 支持关心题目变化；固定用哪种题是测量政策 | 原题保持也有价值；将它保留为具体证据，但不据此证明目标要求的新题应用 |
| 成功后一次可比失败显示冲突 | 已确认的 10-05 产品决定；没有研究证明一次失败就失去能力 | 多数票/概率平滑可降低噪声，但会隐藏最新失败；保留冲突作为检查提示，先复核评分与条件，不能当作能力归零 |
| 冲突恢复后重新检查当前延迟保持 | 保守的应用建议；没有本产品干预或诊断准确性验证 | 恢复一次即借用旧延迟证据更省题；首轮推荐恢复与保持分开，同时保留全部历史成功，观察额外负担 |
| 三天、十四天、快速检查一至两题 | 兼容或交互预算，未由引用研究确定 | 自适应间隔与题数有潜力，但需要效果、负担和校准数据；不能以算法名字替代这些数据 |
| 完整日志、稳定边界、合法修订链 | 项目契约与软件一致性要求；可用反例和回放验证 | 只看最近若干记录便宜，但会丢迟到帮助和更正，无法满足当前可重算约定 |

首轮接受的是有范围的证据描述，而不是以规则命名代替真实性。选题、评分和帮助归因不准确时，规则再严也不会得到准确掌握结论；因此后续要分别审查这些输入质量，不能只验状态枚举。

## 5. 推荐的证据投影

### 5.1 一个可重放过程

推荐“完整原始日志 → 校验与有效修订 → 每个知识点的作答支持 → 条件、帮助与暴露分类 → 状态和缺口”。每一步保留引用和排除原因；记录存在不等于它可以证明任何能力。

1. **确定输入快照。** 包含日志读取边界、知识身份映射版本、规则与配置版本、解释所用课程/目标条件及显式 now。回放历史时只能用当时已经存入的记录，不能偷用未来复核结论。
2. **核对事件身份。** 按日志身份去重，同一作答只保留一个有效的原始判分及合法修订链；修订必须指向正确的作答/原日志。同时间事件用持久化顺序和显式引用解歧，不把 ULID 随机尾部当因果顺序。
3. **决定证据效力。** 待复核、题目缺条件、评分依据失效等不能产生肯定或否定掌握结论；旧判分和更正都可见。失效理由、作用范围与恢复依据由 assess 提供。
4. **确定实际考查。** 整题结果、分问结果和知识点映射相匹配；无映射时只写整题表现，列该节点待单独验证，不把综合失败全摊给所有节点。
5. **推导并解释。** 只用适用的证据判断当前状态；附上其他条件下的成功、延迟/换题缺口、待检查和依据。新的帮助或复核迟到后，重算受影响记录和节点。

“日志是唯一输入”需要保住：影响掌握的判分、效力更正、帮助和作答条件应进入追加日志或引用不可变快照。知识身份由 knowledge 解析。不能偷偷让规则读取可变题干、当前题目 status 或今天的目标文本来改写昨天的表现。

规则先不做按帮助等级折算的分数、时间加权掌握率或贝叶斯融合。它们不能弥补原题重复、条件缺失和错误归因。

### 5.2 有效、独立、新题是不同判断

| 维度 | 推荐区分 | 作用 |
|---|---|---|
| 效力 | 可用 / 等复核 / 已失效 / 输入不足 | 决定这条能不能支持状态 |
| 帮助 | 无针对性帮助的记录支持 / 有帮助 / 归因未完成 | 决定能否声称独立 |
| 题目关系 | 原题复现 / 同原题改编 / 同类新题 / 明确变情境 / 未知 | 决定新题与迁移证据的范围 |
| 时间 | 即时 / 达到记录中的延迟要求 / 近期暴露不明 | 决定保持证据和缺口 |
| 条件 | 与目标条件匹配 / 其他条件 / 条件未知 | 决定本课当前目标能否用它 |
| 覆盖 | 直接考查该点 / 综合关联 / 缺映射 | 决定能否归到具体知识点 |

这些是派生说明，不建议把所有组合扩大成几十种 MasteryState。某次允许公式表的独立成功仍是一条真实成功；若目标考的是公式记忆，则它不支持该记忆目标。题目未被系统见过，只能说明“按已记录的暴露判断是新题”，不承诺知道学习者在系统外做过的全部题。

## 6. 帮助归因：以作答边界为准

### 6.1 时间和对象

沿用 [tutor 对共同依赖的说明](../tutor/research.md#8-帮助检查与课时收尾)：assess 固定答案版本和锁定时间；tutor/sidechat 保存实际提供的帮助和原回复依据；core 保存发生时间与追加顺序；learner 负责将它们匹配。

- 答案锁定之前针对本题提供的提示、步骤、解答或答案，影响这份作答的独立性。
- 交卷之后才提供的帮助不能影响已经锁定的答案；判分尚未完成也一样。之后若允许修改答案，要有新的答案版本及边界。
- 帮助先发生、晚记账，应按发生时间回算；没有发生时间且有可信关联时，标待核对，不把追加得晚当作“没有帮助”。
- 相同知识点在另一门课给过的相关帮助也参与判断，但不能仅因 nodeId 相同把所有旧教学永久归给每一道新题。
- 对具体原题的完整解法或答案暴露长期保留其关系；等待二十四小时不使原题变新。普通概念讲解不能因此让学习者永远无法独立验证。

ADL 的规范分别定义发生时间与 stored，并明确迟到记录可能有两种时间。这支持上述记录语义，不提供本项目的匹配算法；引用见 §4。

### 6.2 可执行的关联优先级

优先使用“答案版本/作答 → 题目身份及原题家族 → 当前测试 → 当前教学任务与节点”。会话与课时只作范围提示；同一长会话可能跨好几道题，不能命中 sessionId 就永久算帮助。

有明确本题关联时直接归因。只有概念和时间关联时，进入有说明的近期支持判断；缺关联或归因尚未完成时保留待检查。等归因完成再产生肯定独立结论；不要每次等待整个侧边会话关闭。

首轮保留已有 HelpLevel 四档，等级用于说明实际获得的支持，不预设“提示扣 0.2、答案扣 1”的权重。操作类说明、题目文字澄清、允许工具与内容提示的边界由 assess 的动态政策判断；learner 消费已登记结果，不能让前端或模型以“只是一句提示”豁免。

用户退出测试去求助仍被允许，实际获得帮助要留下记录。概念帮助不应被伪装成单纯更换测试名称；原测试和答案版本的条件保留。发生后已补账的帮助，重算失败时不能继续把缓存当作已经确认独立的最新结论。

这里的“归因完成”须限定为本次作答边界内已记录的相关交互已处理，不能要求证明系统外从未获得帮助。没有候选帮助的正常作答，在可核对的系统记录范围内可以判独立；有可信候选帮助尚未处理时，只暂缓受影响作答。另一个无关节点的会话还开着，不应挡住本题。迟到帮助仍会更正结论。首轮需要生产者说明这一边界，不需要 learner 增设一个判断学习者全部生活经历的模型。

## 7. 正式规则的推荐起点

### 7.1 六个状态保留，结论范围缩清楚

以下顺序作用于同一个知识点、课程和适用条件下的有效记录。输入不足另外显示缺口，不增加一个可被误读为掌握的状态。

| 顺序 | 判断 | 状态与解释 |
|---|---|---|
| 1 | 没有可用于本范围的已确定作答 | 未探测；另列“已有作答等复核”“其他条件有证据”等原因，不写“还没有作答”掩盖已有记录 |
| 2 | 有过有效独立成功，最近一次可比的有效独立作答失败或部分正确 | 证据冲突；展示一条成功与当前失败、条件和未做到的要求 |
| 3 | 最新独立验证成功，且当前验证链包含合格延迟证据 | 已延迟验证；说明间隔、题目关系、条件和实际覆盖 |
| 4 | 有有效独立成功 | 已独立完成；说明是原题复现还是新题，是否仍缺延迟或变情境验证 |
| 5 | 没有有效独立成功，有明确帮助下的成功 | 有帮助完成；下一次应撤掉针对性支持验证 |
| 6 | 有有效的失败/部分正确，没有以上成功 | 还没答对；部分正确保留做到和没做到的内容，不改写成完全不会 |

一次选择题答对可以记一次独立完成，但如果能力目标要求解释适用条件或计算，仍缺那些证据。不能凭题型猜中率推算出这个人真实掌握概率，也不能自动忽略所有选择题。

缺帮助归因、缺条件或缺知识映射的成功可显示“这题答对了，还不能判断该项是否独立完成”，暂不升级。不能把所有老数据一律认成无效：兼容读取保留骨架当时的结论和规则版本，正式规则列出缺失信息，补一次短验证；不让程序或模型替旧记录编造时间、条件和家族。

### 7.2 延迟保持的可执行定义

推荐新增一条延迟验证证据时满足下列要求；已经成立的历史延迟证据与当前是否有新延迟证据分别保存：

1. 有一次有效独立成功作为基线；当前作答也是有效独立成功，目标能力、条件与范围可比。
2. 间隔达到登记的政策要求，实际时长可追溯。
3. 当前作答之前的最近一次已知相关练习、针对性讲解、解答暴露作为间隔起点；不能越过中途教学，仍拿最早成功当起点。
4. 当前不能是刚看解答后的原题复现。原题、同类新题和变情境的保持分别说明；推荐正式节点的延迟验证用未暴露解答的同类新题。
5. 发生有效独立失败后，保留历史延迟成功，但恢复成功先证明恢复；再经过合格间隔验证当前保持，不立即借用失败之前的旧链升级。

第 5 项比骨架测试“对→错→隔五天对即 retained”更严格，属于需在实施时明确记录的行为细化，不是本轮已经变更的规则。保留 10-05 的冲突定义；不用“最近三题多数票”推翻它。

并非要求系统证明这几天学习者绝对没有学过。只按可记录的范围声称“距最近一次已知相关练习四天”；系统外学习可以由学习者补充，属于声明依据。若近期帮助尚待归因，当前链保留缺口。纯阅读不能证明掌握；已知的相关讲解或解答展示可以影响延迟解释，这是暴露条件，不是阅读加分。

#### 连续学习中的暴露边界

“最近相关暴露”不能用整门课程最后打开时间，也不能只用相同 nodeId。它要关联这次验证的具体能力要求及内容，并说明观测到了什么。这是首轮政策建议，尚未有自然学习日志上的误判率验证。

| 观测 | 对这次新延迟证据的处理 |
|---|---|
| 做过直接考查相同能力的题，或展示了对应关系式、关键步骤、解答 | 记录为相关练习/教学暴露，按实际发生边界计时；练习结果是否正确另记 |
| 只打开课程页、搜索到标题，或后台生成教材 | 不凭访问/生成事件重置；没有依据证明对应内容已向学习者展示 |
| 大段材料可能涉及此点，但没有可核对的片段与能力关系 | 列为待确认的潜在暴露；不批量重置所有标签，也不能声称已核实没有强化 |
| 同一综合题只涉及其中一个目标的关键教学步骤 | 只影响有依据的对应要求；不能连同所有先修点一起重置 |
| 学习者补充“刚在别处练过” | 作为自报暴露依据，显示其来源；不伪造为系统内已判分作答 |

已经在第四天得到合格延迟证据，第五天继续练习，不因此抹掉第四天的事实或自动降回“已独立完成”。第五天的即时成功只是没有新增更长间隔的证据。历史保持、最近独立检查日期、当前相关暴露分别解释；只有有效失败、判分/效力更正或适用范围变化等改变结论的依据才进入对应规则。

若学习者天天练同项能力，只能说明持续练习中的表现，暂时缺少脱离近期强化的延迟检查；系统不要求为了颜色停止正常学习。是否在合适日期安排一题，由 planner 根据目标与负担决定。不能通过降低间隔或忽略已知解答暴露把缺口隐藏起来。

### 7.3 换题与迁移

推荐先复用 assess 的 sourceKey、adaptedFrom、题目出处及组卷快照；补足关系和暴露快照，首轮不增加向量“题目相似度判定器”。

| 关系 | 合成例子 | 能支持的结论 |
|---|---|---|
| 原题复现 | 同一水槽深度题重做 | 这道题当前会复现；不证明独立新题应用 |
| 同原题改编 | 只把水深 2 m 换为 3 m | 数值变化下执行原过程；不自动当新情境迁移 |
| 同类新题 | 另一出处的储油罐底表压计算 | 对所考查的相同概念有近迁移证据 |
| 变情境 | 给绝压求液面压力，需识别压强基准和边界 | 该明确变化下的应用证据，前提是评分确实覆盖选条件和推理 |
| 综合任务 | 自选关系式，分清表压与绝压，再完成多步求解 | 对应目标任务的综合应用；不自动替所有先修点补独立证据 |

两个不同 ID 可能来自同一原题或同一份讲义转载。来源未知时标“题目关系未确认”，保留实际成功，不自称通过迁移。只有 adaptedFrom 能追溯的先用明确家族关系；不同出处无法证明教学独立，需按验收蓝图审查。

本次测试第一次显示题干，是该作答必要输入；不能因为 assess 在交卷时写 problem.seen，就把该题的首次作答追溯判成“以前见过”。“发布时未见过”“作答前已有答案暴露”“同一作答过程里展示题干”“交卷后看答案”要分别定位。组卷的 fresh 快照提供起点，后续迟到暴露记录仍须对账。

不强制每节点固定测四种题，也不耗用测试预留题做所有随手检查。快速检查走练习池；阶段、模拟考与结课保持既有题池约束。

### 7.4 条件与实际考查

首轮推荐以规范化条件快照匹配，保留书本、计算器、公式表、限时及能力要求。对于“不限时”“不同长度试卷的时长”，不能只比较分钟数决定谁更严格；不同任务也不能自动比较。

默认不由模型判断“闭卷当然覆盖开卷”。明确同一任务且允许做条件包含推理时，由程序使用可审查规则，并保留为何兼容。公式表允许使用而目标要求正确选式时，表不算帮助；目标要求记住公式时，带表的答对不足以支持该目标。

实际考查还包括题目给予的策略线索：目标只要求代入计算时，题目明确给式可以匹配该目标；目标要求辨认何时使用关系式时，标题/指令已经指定关系式就缺这项证据。允许查一张含多种公式的表，与老师指出“本题就用这一式”也不同。由蓝图和评分要求规定考查范围，learner 读已登记依据，不看标题关键词临时猜是否算帮助。

多问题使用现有 Grading.parts 时，还需要 assess 提供“哪一问实际考哪些点”的映射。部分正确只说这次没完全做到要求，不给每个点平均分。没有可靠映射的整题失败记录为综合任务缺口；先用既有单点题查哪里有问题。不从自然语言 rationale 中临时猜每个 nodeId 的分数。

对知识本身的定义、适用条件发生实质变化，应由 knowledge 判断身份或版本的影响；learner 不因为标题没变就无条件继承旧能力。

### 7.5 参数不冒充研究结论

| 参数 | 推荐起点 | 依据与验证方式 |
|---|---|---|
| 延迟最小间隔 | 可暂沿用三天，绑定政策版本 | 兼容骨架，未经中文理工校准；记录小时级实际间隔，测试边界，统一试用后看保持任务 |
| 无新独立验证的复查提醒 | 可暂沿用十四天 | 提醒策略，不是遗忘判定；从有效独立验证算，planner 后续按期限和负担调整 |
| 帮助一天窗口 | 不保留为独立性的唯一判据 | 以对象、答案边界和教学暴露为主；不足信息标待核对；保留时间窗只能作辅助线索 |
| 两次问题即 doubtful | 不保留为终身能力推断 | 保留问题记录，用原话及具体待检查状态说明；重复投递不重复计数，检查完成可消除当前待办 |
| 独立成功次数 | 一次可用“已独立完成”，稳定范围由额外验证说明 | 不给一次成功贴“稳定掌握”；不新增无数据支持的连续三题硬门槛 |
| 快速检查题数 | 默认一项能力先一题，缺覆盖时最多补一题 | 交互负担的拟议预算，不是诊断准确性结论；不足时说明，继续测试由学习者和老师决定 |

三天、十四天和检查预算都是拟议默认值。能随部署或学习者选择变化的项按 Config、volatile 和 settings 插槽提供；不散落在提示词或多个包里。改政策时须更新版本、重算并说明改变了哪些判定，不偷偷重写日志。

## 8. 信号、复查和跨课程

### 8.1 信号不改成绩，也不独自证明掌握

问题、候选误解、自报会/不会，要有原消息依据、可信节点和去重身份。模型自己的解释、引用的错误观点、老师提出的假设不能冒充学习者信号。

提问记录可以展示；“有疑点”应说明具体待检查内容及是否已检查。一次总结列了五个问题，不等于五次独立误解；相同消息重放也不是新的疑点。后续短题成功可以关闭该条当前待办，旧信号仍留在日志里。若要表达“已澄清”，由信号的主人追加澄清/检查结果关联，不改旧原话。

learner 给“哪些状态缺什么证据”；tutor 保存教学检查请求；assess 发布和判题；planner 决定排在什么时候。首轮复用 tutor 拟议的检查请求，不让 learner 另养一个同内容的检查队列。

### 8.2 复查提醒随时间读出

推荐缓存证据推导的事实与最近独立验证日期，查询时用显式 now 派生“待复查”。到期不需要先伪造一条学习日志；应用关闭几天后再打开，也能读到正确提醒。页面可在可见时更新，planner 每次决策都重新判断，不以旧缓存中的布尔值安排动作。

这能先避免新增长期定时进程。未来若要主动提醒，排程归 planner；本报告不创建提醒、后台任务或本地计时器。过期仍保留历史独立/延迟验证事实，不把时间流逝算成失败。

事件与缓存失效要看课程视图、条件、解释和证据是否改变，不能只比顶层 state。现有前端默认监听所有 learning/ 推送可以刷新日志变化；这不能补偿应用离线期间的时间变化。

### 8.3 跨课程保留参考，验证当前范围

保留 10-08 已确认的按课程计算。首轮不自动复制另一门课的成功来升级本课，帮助仍跨课程按相关性参与。其他课程的有效成功可帮助 tutor 缩短摸底、优先出一题验证，不能跳过所有检查。

未来若增加迁移建议，至少核对相同知识身份、定义/适用条件版本、任务要求、允许工具、题目关系、近期证据与未解决冲突；条件未知不是匹配。建议带原作答引用，由本课短验证形成自己的证据。语言相似或节点合并不是验证本课能力的依据。

全局图可以概括“在其他课程完成过”，但全局 retained 不能通过 A 课一次成功加 B 课一次成功拼成“本课隔三天也会”。全局与课程结果共享规范化证据入口，各自在明确范围内推导。

### 8.4 合并、撤销与能力范围

保持现有透过身份读原日志、按日志 ID 去重。一次多标签作答被多个旧身份读取，只算一次对应作答/评分单位；不能凑成两次独立成功。

合并只统一身份，不加强记录的条件、效力或迁移范围。撤销后按原节点归属重算，不把保留节点的好状态复制给被撤销节点。被合并节点的旧解释仍可追到原题和当时名称。

仅根据 requires 边推测先修会了，仍是摸底线索，不成为正式掌握证据；完整任务成功也不自动染绿整条先修链。

## 9. 可解释结果和“这个我会，考我一下”

### 9.1 依据与排除原因一起显示

推荐复用知识节点详情和现有 evidence 接口；首轮不加一张独立“学习画像”大屏。节点说明包含：

- 当前结论及范围，例如“闭卷、可用计算器，独立完成过一道静压强新题”。
- 实际支持它的作答、最终判分及改判链，能打开题目/测试结果。
- 最近一次独立验证和实际延迟；帮助、原题复现及其他条件的记录分别说明。
- 还缺什么，例如“还没在不带公式表时检查”“新情境还没测”“最新题目的评分待复核”。
- 不能计入的记录及原因，原始判分仍可查看，不把最终改判藏在一条无关的“更正”标签后。

建议替换含糊的 counted 布尔含义：区分“支持当前结论”“构成当前冲突”“等待/排除”“背景信号”。不一定立刻删除该字段，但调用方必须知道它不是“所有证据都证明掌握”的标记。理由引用具体有效记录，不把本节点全部帮助都列为当前作答的依据。

用户文案不出现内部 ID、统计模型名或缓存版本；开发日志和详情中的审查元数据另有位置。举例：“三天前独立做对了储油罐的题；今天这道题漏了液面压强，先核对条件，再用新题确认。”不是“掌握 82%”。

### 9.2 快速检查是既有测试流程的小入口

学习者在节点详情点“考我一下”或告诉老师，检查请求关联当前课程、节点、目标条件和自报原文；同一请求重试不重复发测试。assess 从练习池选未用过、答案有依据、能直接考查该点的题；没有合格题就说明缺题，交主老师补题，不拿教材例题和模型即兴问答绕过题库。

默认一题，覆盖不足时可补一题；测试期间遵守独立政策。答对只增加这次证据，不能通过一个按钮标掌握，不能因为题名叫“复查”就自动 retained。归因未完成、开放题待复核或申诉中时显示处理中。

完成后由 assess/tutor 的既有任务和 handoff 机制接回，不由 learner 自己给老师会话发消息。关闭请求应引用正式测试结果；聊天里的答案未经 assess 保存与判分不能构成正式作答。

改变节点详情的界面时按 [learning-ui-review](../../.agents/skills/learning-ui-review/SKILL.md) 做三种宽度、深浅两色截图，并保留审美复核点。本轮没有界面设计或截图验收。

## 10. 数据归属与最小契约补充

这些是拟议语义，不是已经存在的表名或服务方法。优先复用现有字段与服务；公开契约只补跨单元真正需要的内容。

| 内容 | 主人 | 最少需要保存/提供什么 |
|---|---|---|
| 原始证据及读取游标 | core | 稳定事件身份、发生时间、记录顺序/读取水位、更正引用、生产者去重依据；完整分页，不能默默截掉尾部 |
| 答案、判分和知识点覆盖 | assess | 锁定答案版本/时间、题目及评分快照、分问与节点映射、最终有效改判链 |
| 题目关系与暴露 | assess；textbook 只登记实际展示 | sourceKey/adaptedFrom 等家族依据；暴露发生边界、场景、题干/解答的区别；组卷时的新题依据 |
| 题目/证据效力更正 | assess 发起，core 追加 | 指向受影响的题目版本/作答/日志，为什么暂停、失效或恢复；能回放，保留旧依据 |
| 帮助和待归因内容 | tutor/sidechat 等实际提供帮助的单元 | 原回复、可信对象、发生边界、帮助等级、归因状态与修订；原始内容不在 learner 复制一份 |
| 检查请求 | tutor 与任务服务协作 | 原信号、当前状态、关联测试/结果；learner 只给缺口，不重复存待办 |
| 知识身份及范围版本 | knowledge | 合并映射及其版本；定义/条件变化的解释，不由 learner 修改知识点 |
| 正式掌握投影 | learner | 规则/配置版本、输入水位、范围、有效依据、排除原因、验证缺口、最近独立证据和计算时刻 |
| 复查安排 | planner | 使用 learner 的证据缺口、目标期限、可用题及负担；实际任务仍由其主人保存 |

三组依赖应在做深前一起定：

1. **答案与帮助的时间边界。** 已有 NewLogEntry.at 可以保存发生时刻，但仍缺持久记录顺序及答案锁定边界；不能只改帮助生产者的 at 就宣称全部解决。
2. **证据失效与更正。** 题目停用可能只是重复入库，也可能是题错了；两者对旧有效答案的意义不同。首轮可先按已有“停用不算”的保守政策追加影响依据，说明为何；长期细分要由 assess 决定。修题恢复不能无条件让全部旧答案重新有效。
3. **条件、暴露与覆盖快照。** 当前日志有 testKind/conditions，组卷有 fresh，题目有 adaptedFrom；这些可复用。缺字段时不能补一个模型结论代替明确来源。

数据采用不可变引用时，要保证对应快照真实保留。只放当前题目 ID，而题干、答案或节点标签以后能改，不算可重放。重算可以分批，但发布一份状态时应有同一输入水位；失败不能留下半旧半新的“完成”结果。

空缓存启动、丢掉一次内存事件、同版本重启，都需要从日志水位对账。增量投影和全量投影给相同结果；节点合并、撤销、补账、改判和政策变化应找到受影响范围。各单元仍经契约调用，learner 不直接查询 assess 的表。

## 11. 按 learning-simplify 的候选清单

以下只交候选和证据，不动代码。依据是 [rules.ts](../../packages/learner/src/rules.ts)、[服务定义](../../packages/contracts/src/services.ts) 及对生产调用方的检索。

| 候选 | 生产者与使用者证据 | 可减少什么 | 损失/风险与结论 |
|---|---|---|---|
| 同一会话/课时永久帮助与一天窗口并列的判据 | rules.helped 生成，derive 用于全部和各课状态 | 用统一的“对象+作答边界+暴露关系”替换交叉补丁 | 缺归因的新旧数据须保留未知；推荐替换规则，保留 LogContext，不删上下文契约 |

| 缓存中的 needsReview 布尔值作权威时间事实 | derive 在重算时生成，states/API 对外提供 | 保留证据日期，读时派生，免去为时间流逝全库刷新 | 接口兼容可继续返回该布尔值；需要显式 now 和页面更新时间策略；推荐消除持久布尔值的权威性 |
| 顶层全局状态与课程状态的重复规范化 | deriveState 对全量及每课程重复整理判分与帮助 | 一次整理有效事件，再按范围投影；少维护改判/去重的两条路径 | 全局图和课程页都在用，不删除任何范围；须证明共享整理没漏跨课帮助 |
| “最后读到改判”加原判详情两套解释 | rules 使用改判；describeEvidence 显示原 verdict；知识页调用 evidence | 共用最终有效判分解释，统一依据与更正链 | 原判仍要能审查；不能直接覆盖历史；推荐共用投影而不是改日志 |
| 提高日志 limit 作为规模修复 | learner.entries、recompute、core.log.query 提供上限 | 用完整分页/游标读替掉散落的固定上限 | 不能改成只看最近 N 条丢掉原证据；先保障完整性，再测性能 |

**打回的候选：** 删除 learner_states（已有全局图、节点详情和课程复盘依赖状态查询）；合并各课结果只存最好状态（违背 10-08 决定）；去掉规则版本（无法解释重算差异）；去掉 attempt.regraded（违背追加证据）；由前端自己算颜色（产生第二套规则）；引入 pyBKT“省掉规则”（帮助、效力、条件与解释胶水仍需维护）。

上述取舍不以代码行数少为唯一理由。没有新增依赖能净减少这些业务规则，所以首轮推荐复用本机已有技术。

## 12. 分批范围与验收草案

### A：完整、有效、可重算的证据

- 定义发生时间、答案边界、去重和改判链，题目错误/失效有追加依据；旧事件不能因重放重复升级。
- 完整分页读取，不丢最新记录；空缓存、同规则版本重启、丢事件后能对账。
- 全量与增量结果一致；同一日志和身份快照在同一 now 下结果相同。不同 now 只改变时间说明，不修改历史证据。
- 合并与撤销保留原日志，不把一条多标签作答计成多次独立成功。
- 有处理中、失败和旧缓存状态，部分重算失败不能冒充全部成功。

**A 的完成不代表独立性已可靠。** 若 tutor/sidechat 的实时帮助与 assess 的答案边界还未实现，只能验收日志和投影工程；该依赖明确列为未完成。

### B：独立、延迟、新题和条件

- 相关帮助跨单元、跨课程归因；晚记帮助能修正状态，交卷后的讲解不污染旧答案。
- 延迟记录实际间隔和起点，中途练习或暴露不能被越过；冲突后的恢复与重新延迟验证分开。
- 原题、同原题改编、同类新题和明确变情境有依据；不按 ID 不同认迁移。
- 开卷/闭卷、工具、时限与目标范围相匹配；条件未知说明缺口。
- 多点综合题有可靠覆盖时按评分单位归因，没有时保留综合表现，不能把每个点全判会/不会。
- 保持“先错后对不冲突”，以及“对后独立错才冲突”的确认方向；不引入假掌握概率。

**B 需要少量人工审查合成案例。** 程序通过只能证明规则执行正确，不能证明知识标签、变情境的教学有效性或模型判分准确。

### C：解释、检查和使用方联调

- 节点详情、课程图、全局图、老师简报、阶段复盘和课程报告使用相同的有效证据说明；本课与其他课区别明确。
- 最终判分、改判、失效、帮助及排除原因可追溯；显示记录不足，不把待复核写成未作答。
- “考我一下”复用练习池、真实提交与判分；缺题可读，不重复发布、不绕过独立政策。
- 到期提醒在查询/重新打开后正确出现；有帮助练习不能把独立复查日期往后推。
- 前端按 UI 技能截图；GPT 调整的界面保留 Claude/用户审美复核点。整轮做深后统一试用。

### 反例矩阵

以下全部使用自编合成题、合成日志、假模型/时钟；是未来验收要求，本轮没有运行。

| 情境 | 应观察的外部结果 |
|---|---|
| 只有阅读完成、批注、提问、聊天或自报 | 掌握不升级；必要的检查线索另列 |
| 只有“不会”自报，没有正规作答 | 不生成已判分证据；走教学或短检查 |
| 正式测试里的“不会”按钮 | 使用 assess 保存的真实放弃作答；范围与判分可查，不与一般自报混淆 |
| 第一条是 pending-review，后来改判为正确 | 待复核不算不会；合法改判后才产生相应证据，两条都在 |
| 一条原判、两次更正，后一次指向错误的作答 | 非法更正不改变状态；能说明依据链有问题 |
| 重复日志投递、同 attemptId 两条原判、多节点读取同日志 | 不多计独立成功；记录身份与评分单位可核对 |
| 同毫秒帮助、交卷与改判；延迟补账 | 按持久顺序、答案版本和引用解歧；随机 ID 排序不决定结论 |
| 帮助先发生，答案随后锁定，侧边总结最后关闭 | 当前作答记有帮助；重算后的详情能指出是哪次帮助 |
| 答案锁定后，判分返回前得到讲解 | 之前的作答不被讲解污染；之后的修改答案另算 |
| 同课时十天前讲过概念，今天另一题无针对性帮助 | 不因 lessonId 相同永久算有帮助；仍检查间隔和近期暴露 |
| 昨天讲过原题完整答案，隔一天或一周又做同题 | 不自动变成独立新题；复现事实和解答暴露关系都在 |
| 今天只问“在哪里上传照片”，没有内容帮助 | 不降低独立性；操作说明不计作概念帮助 |
| 允许计算器却得到老师给出的关键计算步骤 | 工具允许与教学提示分别判断；不能混成“可用计算器所以独立” |
| A 课得到相关帮助，B 课做同知识点的同题 | 不因分课程遗漏帮助；B 课有自己的证据范围 |
| 第一天正确，第四天又正确，但第三天练过/看过解答 | 不凭距第一次三天自动 retained；显示真实最近暴露间隔 |
| 已有合格延迟成功，次日继续练习；或只打开课程首页 | 历史延迟证据保留；分别显示新练习与最近相关暴露，不凭访问降级或重置所有节点 |
| 每天都在练相同能力，没有脱离近期强化的检查 | 正常教学继续；说明缺少这类延迟证据，不要求停止学习或伪造验证通过 |
| 给了公式才做对，但目标要求自行选式；另一目标只考代入 | 两种实际覆盖分开；不把允许公式表、已指定策略和针对性教学提示混为一谈 |
| 旧题换数字、换 ID、同题从另一份讲义导入 | 家族依据一致时不算全新情境迁移 |
| 首次测试显示题干，交卷后写 problem.seen | 不倒推成作答之前已练过；以暴露和组卷快照说明 |
| 有独立成功，随后有效独立失败，再即时成功 | 失败期间冲突；即时成功说明恢复，不自动借旧链证明当前延迟保持 |
| 先失败后独立成功；或最新失败判分被合法更正 | 先错后对不冲突；合法更正后按有效判分解释，历史失败仍可审查 |
| 原成功开卷，最新失败闭卷；或目标改闭卷 | 不把不可比条件写成同条件冲突；闭卷当前结果和开卷历史成功分别说明 |
| 综合题只错单位或一问，标签含三个知识点 | 有映射时定位对应要求；无映射不把三点全判失败 |
| 被报告题错，核查后停用；另一道只是重复副本停用 | 根据主人给的证据效力依据处理；不靠同一 status 猜全部历史失效原因 |
| 十四天无新独立证据，其间多次有帮助练习 | 独立复查日期不被延后；待复查不等于已忘记 |
| 应用关闭跨过复查边界，回来时无新日志 | 查询能读出待复查；不要求先做一条无关作答 |
| 两次好奇问题；同总结重放；误解后有正式成功检查 | 不因次数终身判疑点；待办去重，检查结果关联，旧原话还在 |
| 只有其他课程成功，本课没有匹配条件的作答 | 本课条件待验证；不复制好状态，也不写本课不会 |
| 合并两个节点、撤销；同题同时标两节点 | 全量回放一致，原归属可查，不凭合并制造第二条成功 |
| 清空状态表、启动；日志超过一万条且最新是失败/更正 | 可补齐所有状态，最新证据参与，不静默取最早一万条 |
| 新规则/配置、目标条件、身份版本变化；重算中途失败 | 输入与版本明确；成功时一致，失败不发布半套新结论 |

### 测试、模型评价和学习效果分开

实施自动测试用 tests/harness.ts，在模型、时钟、网络和 DSH 传输边界用假的，保持 tests/flow.test.ts 通过。重点断言原日志未变、最终证据引用、详情内容、课程视图与外部事件，不只断言一个枚举。加契约、Config 或插件加载变化后，按接手约定跑类型检查、相关与全套测试、构建及 3182 真正加载。

规则测试可以使用预先给定真值的有限案例矩阵；不得按自己的实现反推期望。合成资料另准备可人工判断的原题/改编/变情境组、多点分问组和帮助时间线，审查映射是否合理。帮助分类准确性归 tutor/sidechat 评价，判分准确性归 assess；learner 报告输入缺失和归因未定的比例，不把这些变成模型正确率。

若以后比较统计模型，先冻结预测时点与独立新题的外部结果，再做时间与题目家族隔离。报告误放行为、误拦行为、检查负担、延迟成功、条件匹配和解释错误；校准不足时不发布个人百分比。合成数据只能测规则和故障，不能证明真人学习效益或足够拟合一个人的知识模型。

### 调用量、成本与规模检查

推荐的 learner 判定每次 **零模型调用、零外部 API 调用**；这是方案定义，不是已测成本。判题和帮助归因的模型请求仍分别归 assess、tutor/sidechat；不能写成完整学习流程免费。

源码中每条作答会扫描帮助，单节点一次独立性整理最坏约为 A×H 次匹配（A 为作答数，H 为帮助数），各课重复整理还会增加工作。states(nodeIds) 目前先读取全部状态行再过滤。它们是静态复杂度观察，尚未测得本机瓶颈；不据此提前加缓存层或迁移数据库。

实施时按 [learning-perf](../../.agents/skills/learning-perf/SKILL.md) 先写测量卡片。建议用独立的合成数据检查一千、一万、十万条日志，既测“一个点历史很长”，也测“很多点、少量历史”；另测跨课帮助、多次合并和迟到改判。固定读取水位与结果真值，分别测单条追加到可读状态、全量重算、指定节点查询、内存和日志读量，报告中位数与尾部耗时。先确保第 10001 条和第 100001 条参与，再一次只改一个瓶颈。

本轮没有性能测量，也没有启动 3184。将来测量不得往 Claude 共用的 3182 灌大量日志；规模数据与进程按项目约定隔离。

## 13. 接续顺序与尚未解决的事项

learner 的开发顺序仍在 tutor 之后；本报告不改变 Claude 当前的 textbook 实现安排。调研入口只写入本单元设计文档；共享 PLAN、decisions、compatibility 留给实施节点统一维护，避免与并行开发互相覆盖。建议尚未成为新决定，不追加“已采纳”的记录。

接续时先读取当时工作树，按 [learning-handoff-review](../../.agents/skills/learning-handoff-review/SKILL.md) 验收真实起点，并重新核对以下依赖是否已落地：

1. tutor/sidechat 帮助的发生时刻、实际暴露、去重与归因完成依据；assess 答案锁定版本。
2. assess 的分问与节点映射、题目家族、暴露快照、题目效力更正；不能把本报告中的拟议字段当作已有 API。
3. core 的完整日志分页、稳定记录顺序、输入水位；knowledge 的身份与范围版本。
4. planner 对快速检查和复查的安排；本轮 learner 只研究证据缺口，不提前实施 planner。

推荐先 A，再落实共同依赖后做 B，最后做 C 的使用方联调。实施者记录三天/十四天是否沿用、恢复链如何判、旧数据如何解释、哪些条件允许推断兼容、哪些综合题缺映射时仅列待验证。没有足够资料的项应保留缺口，不为了把图染绿让模型补出“无帮助”或“已迁移”的事实。

### 首轮必须与可以延后的边界

§10 的信息归属表覆盖最终需要解决的语义，不代表一次实施就要建完所有机制。第一轮正式结论应满足以下最小边界：

| 优先级 | 必须成立 | 缺失时的降级 |
|---|---|---|
| A | 日志完整，去重与最终有效判分可核对，更正不破坏原记录 | 不发布依赖截断或非法更正的肯定结论；已有事实可以显示，但说明投影尚未完整 |
| A/B | 本次答案锁定边界与已记录相关帮助的处理边界明确 | 暂缓受影响作答的独立判断，不暂缓全部课程，也不推测系统外帮助 |
| B | 能说明作答条件与直接考查的能力 | 先支持有明确范围的单点/评分要求；多点综合题映射不足时只报告整题表现 |
| B | 声称新题或延迟时，有题目关系、答案暴露及实际间隔依据 | 仍保留这次正确；关系或暴露不足时不产生新题/延迟的更强结论 |
| C | 同一份有效证据供详情、课程结果和调用方解释 | 先让现有入口解释清楚；不要求新建画像页才能交付 |

可延后：所有综合题的细粒度诊断、自动识别不同来源的同题、全教材浏览的暴露采集、条件之间的自动包含推理、跨课自动免测、概率追踪与个性化遗忘模型。首轮分别用明确映射、已知家族、实际教学记录和规范化条件解决可知部分。数据不足的能力范围留待检查，不能把这些后续项变成 textbook 本轮实现的必备需求。

判断何时增加复杂机制：已经发现仅靠上述最小边界仍频繁误判、过度拦截或增加检查负担，而且能指出具体案例与对应机制。先记录例子和缺口，再决定补哪一项；不能为了设想中的完美掌握模型扩大所有单元。

需要先讨论的方向变化包括：用阅读/聊天直接证明掌握、显示个人掌握概率、允许手工设为掌握、取消跨课条件验证、破坏题池分离、删除历史证据，或让 learner 自动改课程路线。首轮选择可解释规则、复用既有单元和补齐事实边界不需要引入这些方向。

## 14. 调研边界

- 已核对项目计划、learner 源码、生产调用方、相关测试和跨单元契约；没有接续或验收 textbook 实现。论文与远程代码的读取层级在对应段落标出：摘要、全文、文档或源码，不以链接存在声称读完。
- 保持与提取的经典研究多为事实、散文和词对；补充的数学任务有正向干预结果，也有重复再学习收益较小的边界。迁移元分析有任务差异，KT 常用公开作答日志。这些帮助制定测量和失败边界，不能确定本产品中文化工能力的误判率和长期收益。
- 2026 年门槛预印本采用观察日志，缺随机与纵向干预；报告不把其数字变成产品默认门槛。主老师的 AI 帮助效果证据留在 tutor 调研，不重复当作 learner 已有效。
- 没有安装或评测 BKT、PFA、pyKT、FSRS，没有新增付费服务。成本与规模部分为方案和静态分析，没有本机耗时、用户效果或费用实测结论。
- 没有运行类型检查、测试、构建、DSH 重启、真实模型、截图或规模测量；仅改研究文档不能声称代码起点为绿。为了不影响并行实现，不改其工作树、产物和进程，不提交或回退他人的改动。
- 正式字段、状态解释、参数、分批与反例都是后续开发草案。规则只能判断已知范围，无法保证学习者在系统外没有看过题或得到帮助；显示已记录的依据和未知范围，避免伪造确定性。
