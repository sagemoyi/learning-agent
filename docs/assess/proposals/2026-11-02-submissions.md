# 一份答卷只算一次，最后一版作答不丢

> 来源：11-02 的外部审查（[报告](../../history/2026-11-audit/report.pdf)，括号里是报告的编号）。这是审查建议先定下来的四个接口里的"提交接口"。修复顺序见 [现在](../../now.md#修复顺序)。

## 问题

- **同一份卷子能交两次（L01）：** `submit` 只在开头检查测试是不是"进行中"，然后逐题等判分，全部判完才结束测试。两个标签页同时交、手动交卷和到时自动交卷撞在一起、网络重试，都会让同一道题记两条作答和两条 `attempt.graded`，掌握说明里变成"独立答对 2 次"。判到一半中断再交，已经记下的题又记一遍。`assess_attempts` 没有按测试和题目的唯一约束。
- **自动保存失败没人知道（FE-01）：** 作答页先把这道题移出"未保存"，再发保存请求；请求失败被 `catch` 吞掉，页面不提示也不重试。交卷前的 `flush` 只处理还在计时的保存，已经发出去、还没回来的不等，于是交卷可能比最后一次保存先到服务器；照片的"确认识别结果"也可能还没存上。
- **题目改了，旧试卷跟着变（L09）：** 题目原地修改，作答只记题目 ID。老师纠错把答案从 2 改成 99 后，原来那份试卷显示"你答 2，判对，参考答案 99"。
- **判分慢被算成学习者超时（L13）：** 超时和用时按判分全部结束的时间算。59 秒交卷、模型判了 90 秒，记"超时 1 分钟"。设计文档写的"时间是交卷时间（判分慢也不变）"只对证据日志成立。
- **撤回的卷子露了答案，题却还算新题（L08）：** 测试不是"进行中"就返回参考答案，撤回（`abandoned`）也算；撤回时不记"见过"，下次组卷这道题还当没见过的新题。"考我一下"点"不做了"会记见过，老师撤回没有。

## 方案

1. **交卷先冻结，再判分（L01、L13）：**
   - 交卷请求带一个提交 ID（页面生成，重试用同一个）。一个短事务把测试从"进行中"改成"已交卷"（契约里已有 `submitted` 状态），同时存下每道题的最终作答、作答当时的题目版本、交卷时间和提交 ID；状态已不是"进行中"的，返回已有的提交，不再判。
   - 事务提交后逐题判分；作答按（提交 ID、题目版本）唯一，重试和重启只补没判完的题。启动时把"已交卷、没判完"的测试接着判完。
   - 用时、超时只按冻结时的交卷时间算；另记判分完成时间，只用于显示"判分用了多久"。
   - 模型判分不在数据库事务里等。
2. **题目版本（L09）：** 题干、答案、评分要点、出处、计算过程合成一个不可改的题目版本；`saveProblem` 改题时写新版本，题目 ID 不变。试卷和作答指向当时的版本，历史试卷显示当时的题和答案，另外注明"这道题后来改正过"。改正之后旧作答算不算证据，按 [有效证据](../../learner/proposals/2026-11-02-effective-evidence.md) 的规则。
3. **答案什么时候能看（L08）：** 按状态分别定：进行中不给；已交卷、判完给；还没打开就撤回的不给，题也不记见过；打开过再撤回的不给答案，题记为见过（和"不做了"一样）。
4. **自动保存（FE-01）：**
   - 每道题有自己的保存队列和版本号，收到这个版本的成功回复才算保存，乱序回来的旧回复不改状态；
   - 保存失败在题目旁显示"没保存上"和重试，输入留着；
   - 交卷、识别照片、离开页面前等所有排着的和在路上的保存；交卷请求同时带上每道题的最终作答和确认状态，由服务器一次核对、冻结。

## 放弃的方案

- **只给"交卷"按钮防连点：** 挡不住两个标签页、到时自动交卷和网络重试，也挡不住判分中途进程重启。
- **判完分再一次写所有作答：** 判分要调用模型，可能很久；期间测试还是"进行中"，问题照旧。
- **作答里复制一份题干和答案代替题目版本：** 每份作答都复制，改判、申诉、证据重算时还要比对哪份是哪版；版本可以共享，也能回答"这次改了什么"。

## 验收标准

1. 同一份卷子并发交两次、交卷判到一半中断后重交：每道题只有一条作答和一条原始判分记录，掌握说明只算一次。
2. 交卷后再改草稿或改正题目，这次提交的作答、题目和参考答案不变；历史试卷注明后来的改正。
3. 判分延迟从 0 增加到几分钟，用时和超时不变。
4. 没打开就撤回的测试不返回答案、题不记见过；打开过再撤回的，下一次自动组卷不把这些题当新题。
5. 模拟保存请求失败、乱序、交卷时保存还在路上：最后一版作答都在，失败时页面显示"没保存上"；照片的确认状态以交卷时页面上的为准。
6. 老库里的题目和作答升级后照常显示，旧作答指向迁移时生成的第一个版本。
7. `pnpm typecheck`、`pnpm test`（含 `tests/flow.test.ts`）、`pnpm build` 通过；3182 上合成课程走一遍作答、交卷、纠错、撤回。

## 风险

- 改表要迁移，按 [core](../../core/design.md#数据库和升级) 的升级规则写。
- 摸底（一次答一题的 `answer`）有同样的"检查后等判分再写"的窗口，要一起改。
- 限时测试到时自动交卷时，页面上还没保存的输入以服务器最后收到的为准；这条规则要在测试页上写明。
