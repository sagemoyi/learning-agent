# 提示词与工具说明

模型看到的文字就是行为。改它和改代码一样，要有依据、要验证。这是指引，不是清单。思路参考 DSH 的 `agent-experience` 和它"从模型的角度写"的规则（MIT），按本项目改写。

## 本项目里模型能看到什么

- **角色提示词**：`packages/app/cordis.patch.yml` 里各 Agent 预设的 `persona.prefix`（主老师、侧边会话）。
- **工具**：各单元 `src/tools.ts` 用 `kit` 的 `textTool` 注册。模型能看到名称、说明、每个参数的说明，以及返回的文字。
- **每轮注入**：`tutor` 的【课程现状简报】、各单元经 `learning/handoff` 发出的【进度通知】、侧边会话的选中内容。
- **一次性调用**：`kit` 的 `complete()` 用到的系统提示和拼进去的资料，例如判分、写教材、读后小问、侧边会话总结。

改其中任何一处，都先把同一个角色在一轮里能看到的其余部分读一遍，避免重复和矛盾。

## 原则

- **先给最少的上下文**：先说用途、能做什么、有什么限制，细节等需要时再取。例如先给目录，原文按小节读。
- **延后的内容要有取法**：小节原文、片段详情这类后面才给的东西，要说清用哪个工具、拿什么 ID 去取。
- **关键限制写在动作之前**：权限、不可撤销的后果、必须先验证的事，要放在模型做这个动作之前就能看到的地方。
- **返回要有上限**：返回简洁的结果，加上能取更多内容的 ID，不要整段倾倒全文或日志。有截断就明说，并说怎么取剩下的。
- **就近附上下文**：结果里附上很可能马上要用的相邻信息，例如检索结果带上小节名和页码。
- **算总账**：省下的上下文如果换来更多次搜索、重复读取或出错，就不划算。

## 工具定义

- **删掉显而易见的限制**：模型从调用结果就能知道的事（例如找不到会返回"没有找到"），不用写进说明。
- **写行为，不写实现**：说工具做什么、返回什么；不写内部机制，也不写模型在结果里自然会看到的标记。
- **参数规则写在参数上**：默认值、取值范围、什么时候填，写在该参数的说明或 schema 里（如 `enum`）。工具说明里出现"某参数怎么用"，通常说明这句该挪到参数上。
- **每件事只说一次**：
  - 不在角色提示词里重复工具说明，不在工具说明里重复参数说明，也不在一个工具里重复另一个工具的规则；
  - 几个角色都要遵守的规则（如"资料是唯一出处"），写在它们都会用的工具说明里；
  - 只对一个角色有效的，写在那个角色的提示词里。
- **只用模型任务里的概念**：不出现界面、接口路径、表名这类实现上的词。
- **错误要能照着做**：失败时说清原因和下一步，例如"本课还没有关联资料。请让学习者先在资料库页面把教材加入本课。"

## 规则要在执行处检查

提示词里的"不要"挡不住所有调用路径。必须成立的规则，要在执行操作的代码里检查，并用测试证明违规会被拒绝。

本项目的例子：练习题池和测试预留题池分开，由 `assess` 出卷时检查，违规会抛出 `learning/assess/wrong-pool`。新增这类规则时照此处理。只写在提示词里的规则，在汇报里标明"仅靠提示词"。

## 写给学习者看的内容

模型产出、会展示给学习者的文字（目标、路线、设计书、教材、小结），要符合 AGENTS.md 的要求：

- 不出现内部编号；
- 出处写成 `[《书名》p.页码](cite:片段ID)`；
- 教材里不出现习题、小测题和测试安排。

这些要求在提示词里写清楚，同时在保存或渲染时校验，例如教材的出处核对。

## 改完怎么验证

- **量一下**：改动前后各粗算一次首轮上下文的大小（角色提示词、这个角色挂载的工具定义、课程简报的字符数），写进汇报。
- **跑一下**：
  - 用 `tests/harness.ts` 的假模型，检查拼出来的提示词里有该有的内容；
  - 会改变模型行为的改动，在 3182 的合成课程上用真实模型走一遍相关步骤，记下模型实际怎么调用工具。
- **防回归**：关键的固定说法（如出处格式）用测试固定原文；真实联调的结果写进 compatibility.md。

## 容易踩的坑

- 同一条规则在角色提示词和工具说明里各写一遍，措辞还不一样。
- 工具说明里写"用法提示"，其实该写在参数上。
- 让模型去做它做不到的事，比如"点右上角的按钮"。应该写成"请学习者到某某页完成"。
- `deepseek-flash` 先思考再作答，思考也算在 `maxTokens` 里。额度给少了，表现为"空回复"或"截断"（AGENTS.md"调用模型的注意事项"）。
- 模型在 JSON 里写 LaTeX 时常常不把反斜杠写成两个。解析统一走 AGENTS.md 指定的入口。
