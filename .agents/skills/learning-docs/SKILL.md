# 文档写法

把约定写够，再删掉推理过程、重复和装饰。这是指引，不是脚本。思路参考 DSH 的 `dsh-prose-standard`、`dsh-trim-cot-leakage` 和 `dsh-doc`（MIT），按本项目改写。

## 各文档管什么

每件事只有一个家。别处要提到时，写一句结论，再链接过去，不复制整段解释。

| 文档 | 管什么 | 写法 |
|---|---|---|
| AGENTS.md | 所有助手随时都要遵守的规则和本地环境 | 写现状；一条规则一两句，细节链接到技能 |
| `.agents/skills/` | 某一类工作的做法 | 写现状；是指引，不是清单 |
| PLAN.md | 总览：设计原则、单元地图、技术底座、模型策略、开发路线、当前进度 | 写现状；单元的细节链接到单元设计文档 |
| `docs/<单元>/design.md` | 一个单元的设计：管什么、现状、怎么运作、关键决定、待定问题 | 写现状；"现状"分清已验收、骨架、待试用、还没做；关键决定写日期和来源，有记录时写放弃了什么 |
| journey.md | 跨单元的学习流程 | 写现状；单元内的细节链接过去 |
| decisions.md | 决策记录 | 按日期追加，写明来源；被后来的决定取代、修改或了结的行，在末尾注明是哪天的哪条 |
| `docs/history/` | 冻结的旧记录 | 不再修改 |
| contracts.md | 单元之间的契约；§11 记骨架阶段的补充和临时偏离 | 写现状；偏离要写原因和待确认的事 |
| compatibility.md | 实测了什么、结果如何、发现了什么限制 | 按时间分节；只写结论，脚本和数据放 `.scratch/` |
| throughts.md | 用户原话 | 只追加，不改写，保留原有的写法和错字 |
| README.md | 怎么装、怎么启动、怎么用 | 写现状；每条命令都实际跑过 |
| 代码注释 | 代码表达不了的约定和原因 | 见下文 |

## 保住完整的意思

删改一段话之前，先列出它包含的每个意思，逐个保住：

- 谁、做什么；
- 条件、时机、先后顺序；
- 必须、可以还是不得；
- 例外，以及"不会发生什么"的保证；
- 归谁负责、有什么副作用、失败了会怎样。

只删修饰、重复和叙述。字数少了不等于更好。

## 现状文档只写现状

AGENTS.md、README、PLAN、单元设计文档、契约、技能、代码注释，描述的是当前的代码。

- 不写变更经过：避免"原来、以前、改成、现在、这次、本轮、新增了"这类说法。
- 不引用读者看不到的东西：会话里说的"方案 B""第 3 条"、没提交的草稿。
- 变更经过放进决策记录、compatibility.md，或者提交说明。

检验方法：一个只看得到当前仓库的人，能不能找到每个引用、核实每个说法？不能，就改写成现状，或者删掉。

修好的问题，在注释里写成"没有 X 时会发生 Y"，不写"以前会 Y"。

## 只写验证过的操作

README、AGENTS.md、技能里的每条命令、配置、默认值和错误提示，都要在当前代码上实际跑过，或者查过代码。

- 跑不了的（缺密钥、要用付费服务），写明谁来验证，不凭记忆写。
- 复现不了的说法，要么删掉，要么改正；不要改测试去迁就文档。

## 代码注释

- 写代码表达不了的东西：约定、不变量、竞态顺序、归属、安全边界、出人意料的失败行为、不明显的原因。
- 不复述代码，不叙述控制流（"先……然后……"），不讲解测试的流程。
- 模块开头用一两句说清职责和依赖；复杂的原因链接到文档。
- 空的 `catch` 要写明为什么可以忽略。
- 注释用英文，和现有代码保持一致；文档和写给学习者看的文字用中文。

## 审查或精简的步骤

1. 明确范围（哪些文件）。没给范围就先问。
2. 先读权威来源（代码、测试、契约），再判断一段话对不对。
3. 逐段决定：保留、补充、精简、改写，还是推迟。只在任务允许修改时才动手。
4. 先改"家"，再改引用它的地方。
5. 跑检查：
   - `git diff --check`；
   - 改了命令就重跑一遍；
   - 改了技能就跑 `pnpm vitest run tests/skills.test.ts`。
6. 汇报：看了哪些文件、改了什么、有意保留了什么、推迟了什么。

## 校准例子

**保住每个意思**

- 原文："长的小节按小标题分成几部分写；某部分被截断就对半拆开重写；同一课时连续两次失败就交还学习者。"
- 删过头："教材分部分生成。"丢了截断后的处理和失败后交还这两件事。

**变更经过改成现状**

- 原文："资料库现在改用云端解析了，原来是本机。"
- 改后："资料库的设置项 `parser` 为 `cloud` 时，PDF 上传到 MinerU 云端解析；为 `local` 时用本机 MinerU。"

**看不到的引用**

- 原文："按方案 B 的默认值。"
- 改后：直接写出默认值，或者链接到决策记录里对应的那一行。

**修复写成"没有 X 会怎样"**

- 原文："以前教材会把习题写进去。"
- 改后："写教材时只给模型教学部分；资料里留着习题和答案时，模型会把习题写进教材。"

**删掉流程叙述**

- 原文：`// 先检查列表是否为空，为空就返回，否则继续`
- 改后：直接删掉。如果提前返回是为了保护某个不明显的约定，只写这个约定。

**适用范围的说明要留着**

技能里"这是指引，不是清单"这类话会改变助手使用技能的方式，不能当作废话删掉；删的是反复劝说的那几段。
